# 公交车交易触发修复

2026-09-16：修复完成，已重新编译 `Assemblies/Sexslavecraft.dll`。维护者已手动进行游戏内验证，确认修复有效，并授权提交。

## 原因

`Harmony_BusTrade.cs` 的交易后补丁存在两个直接阻断点：

- 按字符串查询 `Sex` 和 `Rape`，但本机 RJW 1.6 注册的对应地图任务是 `Quickie` 和 `RandomRape`。原查询使用 `GetNamedSilentFail`，找不到定义时直接退出，不产生缺失定义报错。
- 自愿分支要求双方都通过 `xxx.can_fuck`。这个接口检查插入器官能力，不代表角色能否参与互动；普通女性即使通过 `can_be_fucked`，也会被原条件排除。

已核对本机游戏程序集：`TradeDeal.TryExecute(out bool actuallyTraded)` 的补丁参数正确，来访商队交易者是 `Pawn`；`Dialog_Trade` 关闭时不会另行覆盖双方任务，因此没有添加延迟调度机制。

## 修改

- 使用 RJW 提供的 `xxx.quick_sex` / `xxx.RapeRandom` 定义；自愿分支对每个参与者接受 `can_fuck` 或 `can_be_fucked`，其余分支继续使用原有 RJW 能力检查。
- 在启动前确认双方已生成、同地图、15 格内、未倒地、未征召、无精神状态或战斗，没有正在进行的互动或不可中断任务，并且发起方能预约并到达对方。
- 接受方等待改为 600 tick 的 `Wait`，给走近过程留出时间；到达后的接受任务交由 RJW 驱动创建。
- 用 `StartJob` 直接启动事件任务并检查当前任务引用，避免 `TryTakeOrderedJob` 在 Shift 排队或沿用已有同类任务时返回成功却未启动新任务。仅在实际成为当前任务后显示触发消息；预约失败允许正常结束。启动失败时只清理本次当前或排队任务，不结束已经替换它的其他工作。
- 增加 `[SSC BusTrade]` 详细日志，记录能力不符、距离、预约、任务拒绝等原因。日志由现有 SSC 详细日志开关控制。

交易成功且实际交换物品、由公交车本人担任谈判员的前提，以及原有概率和交易成长计算保持不变。

## 验证

专项行为回归位于 `Tests/BusTrade`，直接编译生产补丁，并接入发布脚本。修复后 30/30 项通过；同一套用例加载修复前的源码时仅 10/30 项通过，能够复现定义缺失、女性资格误判和任务启动失败的缺陷。原有 `Tests/InteractionProtection` 的 27 项行为保护回归也通过，本轮共 57 项通过；使用本机 RimWorld、RJW、Harmony 和动画依赖的 Release 编译通过。

这些测试模拟交易输入和任务接收结果，不运行 Unity、完整 RJW 动画或游戏 AI，不能代替游戏内验证。

维护者已确认本次修复在游戏内有效。以下保留后续复查方法：让同地图上、状态正常的公交车角色本人向商队头领完成一笔实际交易。恶堕达到 20% 时会进入自愿分支，预期获得 `Quickie` 任务，随后由 RJW 创建对方的接收任务。取消或无实际交换的交易应不触发。若再次出现未启动问题，打开 SSC 详细日志并查找 `[SSC BusTrade]`，可区分能力、可达性和任务接收问题。
