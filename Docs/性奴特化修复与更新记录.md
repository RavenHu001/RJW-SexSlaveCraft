## 一、背景与目标

对模组的「性奴特化」系统做全面检查，并修复以下两类问题：

1. **严重 bug（玩家实测报告）**：调教面板中切换性奴特化时，所有已存在的特化 hediff 被删除、进度清零。
2. **实现缺陷（代码审查发现）**：公交车进度双轨互相覆盖；凝胶注入的 hediff 无法继续训练；奶牛 Doop 挤奶路线拿不到进度等。

同时按需求将尚未实装的「宠物猫 / 宠物兔」特化在玩家可见位置标记为未完成（不补实现）。

## 二、切换特化删除 hediff 的严重 bug（已修复）

### 原问题机制

`CompSexSlaveTraining.SetSpecialization`（`Sexslavecraft/Comps/Comp_Train.cs`）：

- 切换类型时 `specializationProgress = 0f`（进度永久清零）；
- `RemoveInactiveSpecializationStates` 会删除**其他类型**的全部 hediff（含终极 `*_Final`）；
- 切到「无」删除一切；
- 重选当前类型时 `Ensure*HediffFromSpecialization` 用 progress 无条件覆盖严重度，把凝胶注入的高严重度降级回 0.01（阶段倒退）。

### 修复方案（按用户确认的设计）

1. **每类特化独立进度**：新增 `perTypeProgress` 字典（`Comp_Train.cs`），切换时保存旧类型进度、恢复新类型进度，不再清零。
2. **终极 hediff 永不删除**：`RemoveInactiveSpecializationStates` 只移除未完成的「基础」hediff，`*_Final` 一律保留（含切到「无」时）。
3. **终极化方向在面板中不可再选**：持有 `*_Final` 的方向在特化菜单中禁用并标注「（已终极化）」。
4. **奶牛储奶量不丢**：奶牛 hediff 移除前把储奶仓充能存入 `savedCowReservoirCharge`，切回时经 `HediffComp_CowMilkReservoir.SetCharge` 恢复。

### 行为变化

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 公交车 50% → 切奶牛 | 公交 hediff 删除，进度清零，切回从 0 开始 | 公交进度存入独立槽位，切回时 50% 恢复 |
| 终极公交车（凝胶注入）→ 切奶牛 | 终极 hediff 被删除 | 终极 hediff 永久保留，与奶牛共存 |
| 终极化后重选该方向 | 可重选（会被降级） | 面板选项禁用，标注「（已终极化）」 |
| 奶牛储奶仓 → 切其他特化 | 充能随 hediff 删除丢失 | 充能暂存，切回恢复 |

### 涉及文件

- `Sexslavecraft/Comps/Comp_Train.cs`（SetSpecialization / RemoveInactiveSpecializationStates / 新增字段与保存）
- `Sexslavecraft/Hediff/HediffComp_CowMilkReservoir.cs`（新增 SetCharge）
- `Sexslavecraft/ITab/ITab_SexSlaveTraining.cs`（面板禁选、标签、进度显示）
- `Sexslavecraft/common/StringAndDefOf.cs` + `Languages/ChineseSimplified/Keyed/SSC_Keys.xml` + `Languages/English/Keyed/SSC_Keys.xml`（新增翻译键）

## 三、公交车进度双轨互相覆盖（已修复）

### 原问题机制

公交车的经验来源分两条互不相通的轨道：

- **progress 轨道**：性交每次 +5%（`TryGainBusProgressFromSex`，经 `Harmony_PersonalityExcretion` patch `SexUtility.ProcessSex`）；
- **hediff 严重度轨道**：每日调教 +`corruptionGain*0.5`（`ConditioningUtility.ExecuteOutcome`）、交易 +0.10~0.175（`Harmony_BusTrade` → `IncreaseBusHediffSeverity`）。

而 `EnsureBusHediffFromSpecialization` 每次都用 progress **无条件覆盖**严重度 → 交易/调教攒的严重度在下一次性交后被洗掉，反之 progress 也永远不涨。两条线各算各的。

### 修复方案

1. **单轨化**：`ConditioningUtility.IncreaseBusHediffSeverity` 改为直接写入 `comp.AddSpecializationProgress`，hediff 严重度改为由 progress 派生（方法名与签名不变，调用方无感）。
2. **双向同步**：`EnsureBusHediffFromSpecialization` / `EnsureCowHediffFromSpecialization` / `EnsurePetHediffFromSpecialization` 改为取最大值互相同步（严重度 ↔ progress）：
   - 新增 hediff 时：严重度 = `max(0.01, progress)`；
   - 已存在 hediff 时：`severity = max(severity, progress)` 且 `progress = max(progress, severity)`。

### 行为变化

- 交易/每日调教收益不再被性交同步洗掉；
- **旧存档迁移**：旧档中 hediff 严重度高于 progress 的部分（此前交易/调教积累的）会在下一次同步时自动并入 progress；
- 凝胶注入的高严重度 hediff 不再被降级（阶段不会倒退）。

### 涉及文件

- `Sexslavecraft/common/BusSpecializationUtility.cs`
- `Sexslavecraft/common/ConditioningUtility.cs`
- `Sexslavecraft/common/PetSpecializationUtility.cs`

## 四、凝胶注入的 hediff 无法继续训练（已修复）

### 原问题机制

- 凝胶（`CompPersonalityStore`）注入路径 `InheritEverything` 已恢复 `specializationType/specializationProgress`；
- 但若源小人本身是「有 hediff 但 comp 类型为 None」的状态（旧存档、或此前经 bug 路径注入），提取出的凝胶就是 `type=None + tags{Bus:100%}`，注入后 comp 仍为 None；
- 所有经验来源均以 **comp 类型** 为门控（`comp.IsBusSpecialized` / `comp.IsCowSpecialized` / `comp.specializationType == PetDog`），hediff 存在与否不影响判定 → 性交、交易、产奶、动物训练全部静默失效，且该状态会随凝胶一代代遗传。

### 修复方案：对账入口 `ReconcileSpecialization`

`CompSexSlaveTraining.ReconcileSpecialization(Pawn)`（新增，`Comp_Train.cs`）：

1. **自动认领**：comp 类型为 None 但有特化 hediff 时自动补设类型（终极致优先，顺序：公交 → 奶牛 → 宠物狗 → 宠物猫 → 宠物兔；再按基础态同序）；
2. **双向同步**：按认领/当前类型调用对应 `Ensure*HediffFromSpecialization`；
3. **互斥清理**：清理其他类型的「基础」hediff（终极 hediff 永不删除），被清奶牛 hediff 的储奶量顺带暂存。

调用点：

- `CompTickRare`（每 250 tick）——所有带 comp 的小人自动对账，**旧存档死锁状态进游戏数秒内自愈**；
- `InheritEverything`（凝胶注入结尾）——注入后立即认领，进度自动追平 tag 严重度。

### 行为变化

- 凝胶注入（含坏凝胶、旧凝胶）的特化立即被认领，面板显示正确，经验获取全部恢复生效；
- 兔分身（`RabbitCloneUtility` 直接拷贝 comp 状态）也会在下次 tick 自动补齐 hediff。

### 涉及文件

- `Sexslavecraft/Comps/Comp_Train.cs`
- `Sexslavecraft/common/ExcretionUtility.cs`

## 五、宠物猫 / 宠物兔：玩家可见的「未完成」标记（按需求，不补实现）

- 特化选择菜单与当前标签中，宠物猫/宠物兔选项附加「（未完成）」后缀（新增翻译键 `SSC_ITab_SpecializationUnfinishedSuffix`）；
- 其他特化（公交/奶牛/狗）不受影响；
- **已知事实**：宠物猫/宠物兔目前没有任何经验来源（亲昵 job 明确不加经验，`PetSpecializationUtility.cs` 注释为「等经验来源敲定再接」），进度恒为 0.01，终极配方（要求 100%）实际不可达成——此为设计现状，非本次修复范围。
