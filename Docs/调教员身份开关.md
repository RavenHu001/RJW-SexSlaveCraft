# 调教员身份开关

日期：2026-09-16。状态：已实现、提交并经维护者确认实机有效；身份开关、菜单修复及绑定身份保护已随 [2.3.0](https://github.com/RavenHu001/RJW-SexSlaveCraft/releases/tag/v2.3.0) 正式发布。

## 规则

| SSC 身份 | 调教员身份 | 总栏操作 |
| --- | --- | --- |
| 主人 | 固定开启 | 勾选、不可修改 |
| 未选择 | 固定关闭 | 未勾选、不可修改 |
| 性奴 | 保存个人选择，默认关闭 | 可修改 |

只保存 `slaveTrainerEnabled`，通过 `SSCIdentityUtility.IsTrainer` 统一计算有效身份。切换身份时保留性奴个人选择，不继承主人固定开启状态。开关不自动修改工作优先级、接受调教开关、主人绑定或正在执行的任务。

2026-09-16 后续修复：已有主奴绑定时禁止切换 SSC 身份，包括已绑定性奴和仍有绑定性奴的主人；身份按钮禁用并显示原因。性奴的调教员个人开关仍可操作。无绑定角色可以切换身份；此限制防止身份往返删除锁链、主人关联和成长进度，身份系统的进一步调整保留在未来规划中。Release 编译和 30/30 身份回归通过，维护者确认实机修复有效并授权提交，尚未正式发布。

## 指派及运行入口

- 菜单及 `TryAssignTrainer` 共用 `CanAssignTrainerTo`：自由殖民者范围、工作开启、存活且未倒地、具备调教员身份、不是目标本人，并遵守主人约束。仍可从已指定对象改选其他合法对象。
- `IsAllowedTrainer` 在开放调教和公交车分支之前检查身份；自动工作和强制命令均生效。日常 JobDriver 在预约及启动接受方前再次检查，防止排队/走位期间停用后继续开始；已实际开始的调教照常结束。
- `selectedTrainer` 保存原指派；停用时不清空，界面显示身份停用。显式允许其他人时继续遵守原有开放规则；否则不将停用当成未指定而开放接替。
- `GetActiveAssignedTrainer` 不依赖工作开关或倒地状态，避免临时工作条件影响同床和归属。工作/身体条件不足在指派名称中另行提示。
- 绑定和读档仍可写入默认主人指派，不依赖临时工作条件。主人固定具有调教员身份，但新指派菜单仍检查原有工作条件。
- 新绑定仪式排除停用的指定对象；开启调教员的性奴不会因此获得仪式主人角色。

## 同床与其他关联

调教员同床关系使用有效指派，主人同床分支保留。2.3.0 原版和 Mint 共用独立身份标签：空床显示全部实际身份；有人时按已分配者及直接关系并集筛选，并显示筛选后角色的全部身份。标签与独立许可状态分开，详见 [主奴同床优化](主奴同床优化.md)。

不强制解除已有床位，不删除已经记录的共同睡眠记忆；停用后不新增调教员同床经历。原版奴隶性奴仍需先有有效床伴才能加入殖民者床。

`GetResolvedMaster` 的无主回退只返回有效调教员，宠物及公交车归属查询随之生效；有主仍优先实际主人。行为保护中的指定调教员仅用于日志，不改其规则。人格排泄、人格植入共用调教工作类别，但不增加日常调教的身份门槛。

新克隆体的性奴调教员开关从关闭开始。人格凝胶不携带该个人开关；恢复 SSC 身份后采用当前身体保存的性奴开关，并按主人/未选择的固定规则计算有效身份。

## 旧档迁移

`trainerIdentityInitialized` 区分缺字段与明确关闭。游戏初始化且 Pawn 引用恢复后，扫描地图、世界及临时 Pawn，并补充由指派引用持有的对象：仅为旧档中已被指定的 SSC 性奴开启资格；未选择身份不提权，主人通过固定规则有效。

迁移标记保存在各 Pawn 上，新 Pawn 默认已初始化、开关关闭；后续加载不会覆盖手动关闭。迁移只在初始化时执行，无每 tick 扫描。

## 指定调教员按钮红字修复

点击按钮后，日志先出现 `Collection was modified`（`384083AD`），位置为 `GetTrainerCandidates`；随后出现鼠标位置栈不为空。原版 `FreeColonists` 调用 `FreeHumanlikesOfFaction`，会清空重填同一临时结果。外层枚举该列表时，`CanAssignTrainerTo` 再次读取进行成员检查，导致枚举失效。

候选枚举现先复制快照，指派资格仍使用原有规则。总栏滚动区域及八个内部列表通过 `try/finally` 成对结束，异常继续由原版报告，不再因遗漏清理引发连续鼠标栈错误。

测试模型已修正为每次分类查询重建共享缓冲区，旧代码复现四项集合修改失败，修复后 23/23 通过。Release 编译通过，最终 DLL 的一个 `EndScrollView` 与八个列表 `End` 均已验证位于 finally 处理器中。维护者确认实机测试未发现问题，授权提交。

修复 DLL 已同步并核对哈希，替换前备份位于 `.builds/trainer-identity/before-trainer-menu-fix-20260916-174052`。本次未修改身份规则或语言文件，完全重启游戏后生效。
