# 主奴同床优化

日期：2026-09-16。状态：已实现，尚未发布；实测红字修复并同步本机游戏目录后，维护者反馈目前没有问题，同意提交。

## 已确认的范围

1. 额外同床许可仅适用于 SSC 身份为性奴的角色。未绑定时对应指定调教员；已有锁链后只对应绑定主人，即使允许其他人调教也不改变同床对象。
2. 普通原版奴隶不受这套额外许可、标记和心情机制影响。仅有恶堕或特殊关系不等于获得性奴身份。
3. 移除全局恋爱判定补丁。原版恋人、配偶同床照常，不禁止性奴与原版配偶同床。
4. 医疗和死眠优先；普通休息时优先尝试允许对象的床。该床不可用时保留原版找床结果。
5. 床位分配列表的已分配/未分配行都可显示“性奴”标记，悬停说明主人或调教员、恶堕门槛及规则。
6. 保留六档数值，将同床效果改为实际共同睡眠结束后的记忆，持续 1 天，不叠加。主人与调教员使用不同文案。

保留当前恶堕严格高于 0.1% 的门槛。原版奴隶和自由殖民者中的 SSC 性奴均可使用这项额外许可；囚犯仍遵守原版限制。

本轮不增加轮换、陪睡名单、同步作息或共同睡眠时长系统。只在双方确实同时睡着后记录本次共同睡眠，清醒躺卧和仅有同床分配不算。

## 实现

- `SSCSharedBedUtility` 只解析身份/对象及额外许可。删除全地图普通床回退扫描和复制的环境检查。
- `CanUseBedNow` 前缀仅为合格对象的普通床调整本次奴隶床分类参数；不修改 Pawn 的实际身份，继续执行完整原版方法。
- `BedOwnerWillShare` 仅补充床位共享许可；找床调用原版 `RestUtility.IsValidBedFor`，环境、体型、可达、禁用和预留检查由原版处理。
- `CanAssignTo` 仅替换原版方法中的奴隶身份分类查询，保留原版其余分配逻辑和拒绝理由。
- 界面标记只接入床位分配窗口的姓名绘制，不修改全局名字，也不影响其他建筑的分配界面。
- `SSCSharedSleepRecord` 随 Pawn 训练组件存档。在实际共同睡眠时记录对象与阶段；结束躺卧时生成一次记忆并清空记录。同类主人/调教员记忆互相替换，不因多次休息或换对象叠加。
- 原有双方负面卧室/营房记忆免除保留，改用已经发生的共同睡眠记录，避免另一方提前起床导致记录丢失。主人/调教员不新增一份同床心情奖励。

| 条件（从上往下匹配） | 心情 |
| --- | ---: |
| 与本次对象有 `SSC_FlawedLovers` | +13 |
| 恶堕 ≥ 50% | +9 |
| 恶堕 ≥ 30% | +5 |
| 其余且好感 < 30 | -6 |
| 其余且好感 < 50 | -3 |
| 其余且好感 ≥ 50 | +2 |

`SSC_FlawedLovers` 仍可决定记忆的最高档，但不再因此被当作原版恋人，也不能越过性奴身份与当前对象条件。

## 验证

- 使用本机 RimWorld、RJW、动画框架和 Harmony 依赖完成 Release 编译。
- 新增 [SharedBed 回归](../Tests/SharedBed/README.md)，真实 Harmony 2.4.2 + 最小生命周期模型：51/51 通过。
- 另用游戏实际使用的 Harmony 2.4.1 和本机 `Assembly-CSharp.dll`，在独立 .NET Framework 进程验证 9 个补丁类、10 个实际方法的安装成功，包括分配与界面 transpiler；没有执行游戏方法，也没有启动游戏。
- 提供简中、繁中、英文、俄文的分配标记提示，以及新增调教员记忆翻译。

维护者在修复同步后反馈目前没有问题。具体字体/缩放、真实存档中途保存读取和跨模组组合的逐项覆盖未单独记录；测试模型的序列化检查不能代替真实 Scribe 存档往返。

没有修改原版关系、已有床位归属或旧存档文件。失去额外许可后，后续床位使用重新由原版及当前有效许可检查；不主动批量迁移床位。
