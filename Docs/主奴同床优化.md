# 主奴同床优化

日期：2026-09-16。状态：初版与 Mint 兼容已提交；本轮关系并集、动态标签及空床分配修复已通过自动检查，维护者确认游戏内无问题并授权提交，尚未发布。

## 已确认的范围

1. SSC 性奴的绑定主人和当前指定调教员同时是有效床伴，同一人去重；对象失效不会取消另一个有效对象。沿用当前调教员指派规则，不额外放宽调教权限。
2. 普通原版奴隶不会仅因奴隶身份获得额外床位身份许可、性奴标签或睡后心情。仅有恶堕或特殊关系不等于获得性奴身份。
3. 移除全局恋爱判定补丁。原版恋人、配偶同床照常，不禁止性奴与原版配偶同床。
4. 医疗和死眠优先；普通休息依次尝试自己的已分配床、主人床和调教员床，每张床都经过原版完整检查，全部不可用时保留原版找床结果。
5. 原版与 Mint 分配列表共用动态标记：空床显示主人/性奴；有分配人员时显示其自身及直接 SSC 床伴的身份。调教员标记仅从本床已分配性奴反查，多人取直接关系并集，不递归扩展。同一人的多种身份合并为一个标签。
6. 保留六档数值，将同床效果改为实际共同睡眠结束后的记忆，持续 1 天，不叠加。主人与调教员使用不同文案。

保留当前恶堕严格高于 0.1% 的门槛。原版奴隶和自由殖民者中的 SSC 性奴均可使用这项额外许可；囚犯仍遵守原版限制。

本轮不增加轮换、陪睡名单、同步作息或共同睡眠时长系统。只在双方确实同时睡着后记录本次共同睡眠，清醒躺卧和仅有同床分配不算。

## 实现

- `SSCSharedBedUtility` 只解析身份/对象及额外许可。删除全地图普通床回退扫描和复制的环境检查。
- `CanUseBedNow` 前缀仅为合格对象的普通床调整本次奴隶床分类参数；不修改 Pawn 的实际身份，继续执行完整原版方法。
- `BedOwnerWillShare` 仅补充床位共享许可；找床调用原版 `RestUtility.IsValidBedFor`，环境、体型、可达、禁用和预留检查由原版处理。
- `CanAssignTo` 仅替换原版方法中的奴隶身份分类查询，保留原版其余分配逻辑和拒绝理由。
- 候选展示独立于实际分配资格，普通多人床补充地图上的 SSC 性奴。原版奴隶身份的性奴不能直接分配空殖民者床，须先分配主人或指定调教员，再加入符合恶堕门槛的性奴。保留已有床位归属的身份例外；殖民者身份的性奴按原版规则分配。
- 界面标记只接入床位分配窗口的姓名绘制，不修改全局名字，也不影响其他建筑的分配界面。
- 当前仍是软限制：没有标签不隐藏角色行、不额外拒绝原版合法分配，也不解除已有归属。本轮不添加硬限制设置。
- `SSCSharedSleepRecord` 随 Pawn 训练组件存档。在实际共同睡眠时记录对象与阶段；结束躺卧时生成一次记忆并清空记录。同类主人/调教员记忆互相替换，不因多次休息或换对象叠加。
- 原有双方负面卧室/营房记忆免除保留，改用已经发生的共同睡眠记录，避免另一方提前起床导致记录丢失。主人/调教员不新增一份同床心情奖励。
- 主人和调教员都实际同睡过时仅保留主人记忆；主人先醒后不被调教员记录覆盖。两位实际同睡对象均保留负面房间记忆免除，无需新增存档字段。

## 空殖民者床分配修复（2026-09-16）

移除“空床允许性奴先分配”的身份例外：即使恶堕达标，原版奴隶身份的性奴也不能直接分配空殖民者床。操作顺序为先给性奴指定调教员，再将该调教员或绑定主人分配到普通多人床，最后加入性奴。殖民者身份的性奴继续按原版规则分配；已有归属不被强制解除。

回归覆盖空床拒绝、主人或调教员先分配后允许加入、加入前移除床伴后恢复拒绝，以及殖民者身份对照。四语悬停提示同步说明分配顺序。该修复随本轮关系与标签调整一并提交，不提升版本号或生成正式发布包。
