## 3. 共用资格与结果入口

### 3.1 查询与升级

提供只读的资格报告和下一档查询，供菜单、仪式角色、接单和结果使用。不要把当前医生／主持者的可行动状态并入通用受塑资格，手术患者可以倒地或已麻醉。

1. 检查活体、数据、人形肉身、成年及途径身份。
2. 从 `allTraits` 检查所有实际持有的 Beauty，包含受抑制条目；任一 ≥2 直接拒绝，保留模组更高档。
3. 对其他特质调用原版 `Beauty.ConflictsWith(other.def)`，不删除冲突项，也不手动重写标签判断。
4. 拒绝基因来源、受抑制、重复或未知等级的 Beauty；普通无 Beauty 是合法起点。不要把基因对 `PawnBeauty` 的数值偏移当成基因授予 Beauty 特质。
5. 存在共用反应时不允许开始。固定下一档为 `-2→-1→无 Beauty→+1→+2`，所需等级定义必须存在；“无 Beauty”不是一个 degree 0 的新 Trait。

写入只操作已确认的单个普通 Beauty；用原版 RemoveTrait／GainTrait 与正常通知，并核对实际写入。不要调用[通用 AddOrUpdateTrait](../../Sexslavecraft/common/TraitUtility.cs)，该函数会清除所有同名条目，不符合本功能的保守兼容边界。实际写入异常只红字报错，不恢复旧值、不退款或自动重试。

### 3.2 最终资格与共用反应

正常结果入口中：目标为空、死亡／销毁时跳过医美效果；有效活体失去升档资格则固定失败，不抽签；允许升级才走当前途径的原版成败判定。拒绝新开始与应用失败反应分开，不能因目标已在恢复期而漏掉正常结果中的失败反应。跳过医美效果不要求屏蔽原版的结束／失败信息，不因此重写整段结果回调。

共用入口接收本途径的成败与严重度，成功升一档后施加反应，失败不改 Beauty。不存在反应时新建；已有同种反应时只保留正常单实例并取严重度较高者，不累计四种数值。无结果回调的取消不调用它。错误日志应含功能、目标及异常，不建立日志驱动的恢复系统。

Hediff 使用 `HediffWithComps` 和原版 `HediffCompProperties_SeverityPerDay`，`severityPerDay=-0.10`、`showDaysToRecover=true`；阶段阈值 0／0.20／0.50，`painOffset` 为 0.05／0.10／0.20，`WorkSpeedGlobal` 倍率 0.95／0.85／0.70。不继承成瘾基类、不挂化学需求或额外治疗修正。四种结果严重度仍从完整规划维护。

## 4. 原版手术的具体接入

### 4.1 Def 与正常执行

RecipeDef 继承当前原版 `SurgeryFlesh`，设置整体手术目标，`targetsBodyPart=false`；研究前置为新研究，工作量和技能按草案。技能写 `Medicine`，工作速度用 **`MedicalOperationSpeed`**，不能照搬现有部分 SSC XML 中将 `MedicalSurgerySuccessChance` 填作工作速度的写法。

分开定义普通原液 `Purple_Aphrodisiac_Nanofluid` 10 和药物 3；药物允许 `MedicineIndustrial`、`MedicineUltratech`，排除草药；固定／默认过滤器与两项需求一致。原液按配方原料消费，不调用普通吞服 Doer，不叠加负荷、药物需求或催情效果。保持原版麻醉与消费流程，失败和成功均不二次扣料。

`AvailableReport` 先遵循父类报告，再补本功能资格及翻译原因。`AvailableOnNow` 和 `CompletableEver` 直接沿用父类，不重复覆盖医美资格；年龄、种族等原版限制尽量由 Def 与父类承担。原版缺药隐藏与重开更新照常。

原版 `Notify_IterationCompleted` 仅在 `CompletableEver` 通过后调用 `ApplyOnPawn`。若将上限、冲突或恢复状态等动态医美资格重复放进这里，工作中发生资格变化会直接跳过结果入口，无法兑现“有效活体最终资格失效按失败结算”。因此菜单、接单和结果各用自己的必要入口，不增加这一层拦截；也不把完成检查误当成消费前免费拒绝。

接单补充限定在新配方：保留原版 `PawnAllowedToStartAnew=false`，原版允许时再检查患者与医生的本功能条件。医生仍由原版医疗许可、技能和调度决定，不另写工作扫描。该补充不暂停账单，不管理账单生命周期。

### 4.2 复用成功率、替换失败效果

新 `SurgeryOutcomeEffectDef` 继承原版 `SurgeryOutcomeBase` 的 **comps**，保留它们的计算顺序与 98% 限幅；用 `outcomes Inherit="False"` 覆盖结果表：

| 顺序 | 结果 | 处理 |
| --- | --- | --- |
| 1 | 原版 `SurgeryOutcomeSuccess` | 唯一医疗成功抽签，使用原版质量 |
| 2 | 新医美失败结果，`failure=true` | 成功项未选中后直接接住，不再抽随机数；共用入口施加 0.25，无致死／伤害结果 |

`Recipe_BeautyEnhancement.ApplyOnPawn` 先检查最终资格，再调用 `CheckSurgeryFail` 一次；返回失败即结束，不能再次应用 0.25。返回成功才写 Beauty、施加 0.05，并沿用正常手术记录／故事接口。`addsHediff`、`addsHediffOnFailure` 不再配置同一反应，避免与 worker 重复。

新失败类可继承 `SurgeryOutcome`，只实现确定性失败效果和正常失败文本，不调用原版伤害函数。它不是新的成功率算法。若直接继承 `SurgeryOutcome_Failure` 会带入伤害／手术失误记忆等行为，不能无检查地套用。

## 5. 原版仪式的具体接入

### 5.1 定义、分配和质量

新 Precept／Pattern 指向独立 Behavior 和 Outcome。`requiredMemes` 指定 `SSC_Meme_MasterSlaveOrder`；无研究前置，目标沿用原版仪式点／祭坛过滤。角色 ID 可用 `host`、`recipient`，均 `required=true`、`maxCount=1`、不可替代，禁止同人占两槽；不要求领袖、主从绑定或 SSC 身份。

角色类覆盖 `AppliesToPawn`，调用统一资格并返回原因；必需角色核对同一文化。注意原版部分候选预检不会传入 `precept`，这时只做能够确定的个人条件，不能因空上下文排除所有候选；实际开始用完整 ritual／assignments 再查文化及组合。

行为 worker 在 `CanStartRitualNow` 中保留原版拒绝，再补模因／材料报告；`TryExecuteOn` 在调用父类前检查当前两槽及供料。`PawnCanFillRole` 的 `role==null` 分支补充成年玩家殖民者／奴隶观众条件；不重写原版候选池、分配控件或强制填槽逻辑。

两名必需角色设置 `countsAsParticipant=false`，使其不参与观众人数质量计算，仍正常进入仪式 Lord。观众人数使用原版 `RitualOutcomeComp_ParticipantCount`；该组件本身已有出席统计和半程判定，不需要复制 SSC 观众组件或另写计时器。

| 质量项 | 直接使用的配置 |

| 基础 | Outcome Def `startingQuality=0.40`，默认质量范围 0～1 |
| 医术 | `RitualOutcomeComp_PawnSkill`，`roleId=host`、`skillDef=Medicine`；曲线按完整规划 |

`givesDevelopmentPoints=false`、`allowAttachableOutcome=false`，不挂绑定／训练奖励；心情 memory 如无已确认设计则不新增。不能因复用原版 worker 而无意带入文化发展点或附加奖励。

### 5.2 已确认供料方式与必经阶段

**维护者已确认：用原版搬运预放材料，再由必经阶段就地消费。** 首版不新增自动收集材料的 JobDriver、仓库扫描扣料、专用容器或供料窗口。

玩家用原版储存／搬运把两种材料放到仪式点的原版活动范围内。材料查询使用原版活动范围判断，并检查当前地图、已生成、未禁止、可达及未被其他工作独占等正常条件。候选数量和缺料提示均读取实际地面堆，不计其他地图、角色背包或不可访问的库存；供料范围不另发明固定半径。

预检和实际消费用同一筛选规则。开窗及开始只查数量，不长期预留；集合后消费时重新取得当前堆，先确认原液 20 和草药 2 同时足量，再按实际堆拆分消费。多场竞争时由先实际消费的一场取得材料，后场重新检查不足即停止，不增加材料锁或补偿事务。

拟用原版阶段框架表达：

| 阶段 | 做什么 | 如何进入下一步 |
| --- | --- | --- |
| 集合 | 原版站位、到场和观众调度；阶段进度为 0 | 两个必需角色到场后正常转换 |
| 必经材料阶段 | `essential=true`，阶段进度为 0；在退出该阶段的 `preAction` 中一次就地消费 | 正常消费后进入正式阶段；缺料走原版取消，无效果 |
| 正式阶段 | 原版持续／出席与取消流程，约 5000 tick，即两个游戏小时 | 达到正式时长后由原版应用结果 |

`preAction` 的真实时机是**退出当前阶段前**。消费动作应挂在中间材料阶段的转换上，不挂在构图、窗口查询、读档、最终结果或每 tick 回调里。准备阶段用局部 `RitualStage` 子类返回 0 进度，正式阶段用原版进度，避免集合时间吃掉正式时长。

正常缺料要请求原版取消（必要时使用原版 `ApplyOutcome(... cancelled:true)`），并给出原因；不能只从 void 消费方法返回就宣称已经阻止阶段推进。保留 `ApplyOnFailure=false`。部分消费抛异常只报红字，不加退款、回滚或恢复；原版的阶段数据及载入路径承担正常保存，不复制独立“已施用”账本。

原版最后一阶段的结果调用与 essential 结束标记存在顺序差异：不要只把最终正式阶段标为唯一 essential，再假定其结束标记一定先于结果。材料阶段作为前置 essential 保证消费先于结果；正式时长用原版时长／结束触发配置约束。具体转换顺序和 0 观众、长集合、读档仍须实机验收。

### 5.3 读取结果，不重写概率算法

结果 worker 继承 `RitualOutcomeEffectWorker_FromQuality`：

- `Apply` 直接继承父类，不再仅为死亡保护覆盖它；质量计算、发信和正常收尾沿用原版。
- `GetOutcome` 在正常结果入口发现业务资格失效或受塑对象为空／死亡／销毁时直接返回已配置的失败项；可升级时调用 `base.GetOutcome`，保留原版的一次抽取。选中失败项本身不施加反应。
- `ApplyExtraOutcome` 读取这次已选结果，由共用入口统一判空、死亡及销毁；对象无效时不升级、不施加反应，只返回必要说明，允许原版照常给出结束／失败信息。有效对象才应用 Beauty／0.15 或 0.60；不另调用 Rand，不再消费材料。

其他必要自定义继续保留：窄范围接单补充、专用手术失败效果、仪式角色与行为、准备阶段零进度以及就地消费动作。此次只减少重复的资格／死亡保护入口，不移除这些表达既定玩法所需的扩展，也不改变材料、成功率或反应数值。

原版质量／概率显示继续使用原版入口。业务失效是最终固定失败，不把它做成持续的质量惩罚，不在准备窗口强行预知未来状态。目标离图、角色离场和取消由原版判断是否结束；没有结果回调时不补发反应或升级。
