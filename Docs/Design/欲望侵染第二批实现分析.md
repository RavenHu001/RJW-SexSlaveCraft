## 1 本批交付范围

第二批将已经开启的侵染接到真实普通双人完成事件：普通 RJW 和原版 Lovin。每个方向先选择一次 PNA 来源，再应用侵染恶堕；同时让既有 PNA 来源偏好识别实际可用的侵染能力。

身体部位凭据／20% 开发留在第三批，四档心情／社交记忆留在第四批。第二批不提前创建这两批的存档、空记忆或占位部位收益；完成快照可以预留扩展位置，但只采集本批实际需要的数据。第一批通用框架继续负责开关、身份及人格归属，侵染效果工具负责其自身公式，不向公共开关定义中塞入 PNA 专用结算。

| 内容 | 本批结果 |
| --- | --- |
| 普通 RJW | 主人在发起或接受端均可施加；真实双人相互自慰可纳入 |
| 原版 Lovin | 由唯一原发起端成功完成适配；RJW 替换为普通驱动时走普通入口 |
| 侵染 PNA | 归一化负荷 +0.08，即原始严重度 +0.16；补满已有合法需求 |
| 已有普通成瘾 | 基础 D+0.02，输入后达到当前末期门槛时另加 0.20，合计 +0.22，上限 1 |
| 恶堕 | 额外 +0.01，按当前评分模式和当前锁链阶段限制 |
| 来源偏好 | 沿用现有 ×1.25／戒断 ×1.50；产出者或有效侵染者满足其一即可，不叠乘 |

普通产出者原有 RJW 完成补给保持：负荷 +0.02、已有需求 +0.10、已有成瘾基础 +0.01／末期合计 +0.21。普通产出者本身不因本批扩大到原版 Lovin。

普通事件上下文保存原参与者、原驱动／Job 引用及 loadID、原训练组件、双方人格 token、身份、目标恶堕需求实例，以及本次两个方向的来源计划。PNA 与恶堕应用后都核对上下文。第四批需要的 C／O 应在同一原结算前边界增加；第三批实际部位凭据仍须在场景建立时另行记录，不能靠完成时重解析补造。

快照是一次完成调用内的局部对象，不写入 Pawn／凝胶，不保存运行时 token。任务进行中保存仍沿用开始凭据；读档后到达真实完成入口时，采集恢复后的当前人格与组件。这里的语义是“完成时开启且有效即可结算”，不新增整场持续开启或从开始累计时长的要求。若以后要求整场同一人格，需另行定义中途失效与存档恢复契约。

## 4 普通 RJW：准备、执行、认领、分发

建议扩展现有补丁类，仍只挂同一个 `SexUtility.ProcessSex`：

```text
Prefix：只读验证本次真实完成候选 → 占用该任务的临时重入标志 → 捕获局部快照
RJW 原 ProcessSex
Postfix：原方法确实执行并正常返回 → 核对原归属 → 消费原持久化认领
         → 原训导官完成奖励 → 再核对上下文
         → 逐方向择强 PNA → 再核对上下文 → 合法侵染的恶堕
Finalizer / finally：释放此次临时重入标志，不吞掉原异常
```

需要将现有认领函数的候选校验提取为共用内部读取，避免 Prefix 和 Postfix 各复制一份易漂移的规则。Prefix 不提前设置 `TrainerProgressClaimed`；原方法被跳过、抛异常或不是有效完成时不得发奖。临时重入标志与持久化已处理标志分别负责调用中和调用后去重，不能互相代替。

仍使用存档键 `sscTrainerSexProgressClaimed`。虽然名字带 Trainer，它当前已经认领整场经验和 PNA；不改键，不再给侵染增加第二个“已领取”字段。无侵染资格或无来源的普通完成也会认领，之后打开开关不能重放旧完成。原认领成功后发生异常，不回滚认领、不重试收益。

`__state` 必须和原驱动、Job、loadID、SexProps 及实际 initiator／recipient 对应。不要用受反向姿势影响的 `props.pawn/partner` 作为实际发起方向。嵌套 `ProcessSex` 只拒绝 SSC 的重复分发，保持 RJW 原结算的原有调用语义。

侵染失效不能提前吃掉普通训导官奖励或既有产出者路径。需要区分“整个完成归属失效”和“某方向侵染资格不满足”：后者仅无侵染，原本合法的弱来源仍按原规则处理。

## 5 原版 Lovin：独立的完成适配器

本机 RJW `PATCH_JobDriver_Loving_Cleanup.on_cleanup_driver` 是 `JobDriver.Cleanup` 的成功前缀：它在这个前缀里临时创建 `SexProps`，设 `isCoreLovin=true`，并调用 `ProcessSex`。因此，只在 Cleanup 后缀捕获快照，已经晚于 RJW 记忆／特质等原结算。

建议扩展已有 `SSCRestrictionJobCleanupHook`，保持如下顺序：

1. 先执行已有未开始任务的条件修正，再于 RJW Cleanup 前缀之前取得快照和临时完成占用。使用已核对的 RJW Harmony owner 做明确顺序约束，落地时读取真实补丁列表确认；仅写 `Priority.First` 不能替代顺序检查。
2. 仅接受原发起端、Started、未拒绝、相互配对的原任务／编号、发起端 `ticksLeft <= 0` 和 `Succeeded`。接收端强制成功、走床、失败及中断均不认领。
3. Cleanup 原方法正常执行且最终结束条件仍成功，才消费 Lovin 独立的持久化完成标志，再调用共用侵染分发。正常 Cleanup 的收尾与任务替换要按捕获的归属区分；不能在后缀重新寻找“现在的另一个 Lovin”当成原场景。
4. `isCoreLovin` 的 ProcessSex 在普通适配器中明确跳过；它的侵染只能由 Lovin 适配器领取。原版被 RJW override 换成普通驱动时，旧 Lovin 不能再发。
5. Finalizer 释放临时占用。Lovin 新认领字段随 JobDriver 存档，旧档缺字段默认未处理，但仍须同时满足既有真实开始和成功完成条件。

普通产出者单独在原版 Lovin 仍无补给；开启且有效的主人在 Lovin 施加侵染时可使用强来源。同一来源兼有普通产出能力也只输入一次强来源。

## 6 每方向 PNA 来源择强

来源选择同时检查原快照资格和写入时资格；后续才打开的开关或替换的人格不凭旧快照补领。必须在调用 `ApplyExposure` 之前选定来源，不能先输入弱来源再补强来源。

| 场景／来源情况 | 选中来源 | 负荷／需求 | 已有成瘾基础／末期合计 |
| --- | --- | --- | --- |
| 普通 RJW，有效侵染 | MasterInfestation | +0.08／补满已有合法需求 | +0.02／+0.22 |
| 普通 RJW，同时有效侵染和普通产出 | MasterInfestation，一次 | 同上 | 同上 |
| 普通 RJW，侵染不准入但原普通产出合法 | ProducerSex | +0.02／+0.10 | +0.01／+0.21 |
| 普通 RJW，无合法来源 | 无输入 | 0 | 0 |
| 原版 Lovin，有效侵染 | MasterInfestation | +0.08／补满已有合法需求 | +0.02／+0.22 |
| 原版 Lovin，仅普通产出 | 无输入 | 保持原范围 | 保持原范围 |

“较强”是来源规则优先级，包含剂量、需求和成瘾规则；不只是对两个 dose 取最大值。强来源调用后不再回退补一次弱来源，否则会把部分成功的暴露变成双发。若回调使事件／人格上下文失效，停止剩余分量；若只是 PNA 分量未产生效果而整个侵染资格仍有效，则继续合法恶堕。不能把 `Accepted=false` 一概解释成其他分量也失效。

首次成瘾仍仅由满负荷建立，初值 1，不追加本次 +0.02／+0.20；输入前已有成瘾才进入强化。有有效链时增加保护负荷，不建立普通成瘾或强行创建需求。满负荷时实际负荷增量可为零，但仍是真实正暴露，需求与已有成瘾按来源正常处理。

PNA 核心只掌管接收身体，其现有校验不认识来源人格或旧事件。建议为 `ApplyExposure` 增加可选只读继续条件：在健康写入、协调、需求重建等可能执行外部回调的边界再次核对上下文；失败就停止余下写入。旧物品／武器／调试调用不传该条件，行为保持。核心不直接读取主人开关／Job，也不回滚已合法写入的身体负荷。

## 7 恶堕与来源偏好

侵染目标须为另一名存活有效人形、非空壳、非当前主人，具备必要人格组件和现有 `Need_Corruption`。实际 PNA 还保留肉体准入。资格查询不创建需求、资格、成长、绑定或标记。

恶堕写入前重读原需求实例及当前数值；新评分用 `TrainingOutcomeUtility.GetChainCap(target)`，旧评分用该需求 `MaxLevel`。只接受有限数值和正增量：

```text
cap = useOldScoring ? need.MaxLevel : min(need.MaxLevel, GetChainCap(target))
gain = max(0, min(0.01, cap - need.CurLevel))
```

通过 `CorruptionUtility.AddCorruption`／`Need_Corruption.SetCorruption` 写入，保留历史最高与既有派生特质。当前值已高于阶段上限时增量为零，不在侵染入口倒扣。不要调用会推进绑定的 `ProcessCorruptionProgression`。有效链目标继续获得合法恶堕增量，PNA 保护分流不取消它；恶堕到上限也不阻止 PNA。

来源偏好继续使用 `AttractionPreference_SSCPna` 和原 key。将来源条件扩为“普通产出者，或对该观察者可合法侵染的已开启主人”。`IsPnaProducer` 本身保持原义，避免将人格能力伪装成身体产出记录。

普通成瘾观察者 ×1.25，戒断观察者 ×1.50；三种目的保持原行为，双重来源只命中一次。目标关闭、空壳或人格处理中时不按侵染加权；仍具备原身体产出能力时可继续作为普通来源。观察者为主人／有效链保护者等既有排除规则保留；纯侵染源对没有恶堕需求而不能接收侵染的观察者不额外加权。所有评价和悬停保持只读。

## 8 实施与验证顺序

建议在同一分支内按四步落地，最后统一交付第二批测试版：

1. **完成上下文与原分发保持。** 先重构候选校验、局部快照与重入保护；暂不增加收益，证明原训导官和普通产出者仍只各领一次。
2. **普通 RJW 侵染。** 加目标准入、方向择强、PNA +0.02 基础强化和恶堕；补原结算／健康回调中的 token、组件和需求实例保护。
3. **Lovin 适配与保存。** 完成前缀顺序、双端唯一认领、读档恢复和 override 互斥；保持普通产出者旧范围。
4. **来源偏好与整体回归。** 原偏好识别扩展，补解释与只读检查；构建、全量回归、同步测试版并更新本批实际结果。

优先扩展链接真实 `SSCRestrictionJobGuard`、完成补丁和 Lovin 守卫的 `Tests/InteractionProtection`，以及执行真实 PNA 输入的 `Tests/PnaLoad`；恶堕沿用身份／需求宿主。跨层用例必须跑真实分发、真实效果工具和真实 PNA 核心，不能只记录某个替身被调用一次就当成整链通过。现有第一批“开关本身不产生药效”测试保留；旧预留 MasterInfestation 基础 0 的断言更新为 0.02。

自动验收至少覆盖：

- 主人在两端、反向姿势、双方主人、双方非主人、关闭、缺恶堕需求、空壳与无效人格；相互自慰和单人行为的区别。
- 日常／仪式／自我调教／人格排泄排除；准备、拒绝、取消、中断、未结束倒计时、错误参与者和错误 Job。
- 原方法被跳过／抛异常、原结算内重入、分发内重入、重复完成；认领后异常不能补领。
- 回调同 Comp 换人格且身份／开关相同；替换需求、移除来源、目标变主人、切换锁链和任务归属。
- 原产出者 +0.02／+0.10／+0.01，侵染 +0.08／补满／+0.02；双重来源一次；跨末期 +0.22；满负荷正暴露；首次成瘾和有效链分流。
- 新评分无链 0.12、各阶段上限、0.115→0.12、已满／超限零增量；旧评分不新增 12% 上限；历史最高与绑定不变。
- Lovin 发起／接收、失败、重复 Cleanup、`isCoreLovin` 转接、override 替换、中途保存读档后一次完成；仅普通产出者的 Lovin 仍无新补给。
- 偏好三目的、正常／戒断、单／双来源、关闭、免疫、无适用需求；多次解释不产生状态写入。

实机重点为：一次普通完成的 +8% 负荷、恶堕 +1 个百分点及上限，已有成瘾 +0.02／末期 +0.22、需求补满、主人整套豁免、有链分流、反向参与、真实原版 Lovin 和中途读档。第三／四批的部位与记忆收益不列为第二批通过条件。
