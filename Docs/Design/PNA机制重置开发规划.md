## 1 为什么独立、如何划分职责

PNA 已同时用于摄入、枪械、手术和身体产出，其多阶段负荷和成瘾不应由一次普通性交驱动管理。独立后可以先用既有物品测试慢性、急性与恢复，主人侵蚀只作为后续小剂量来源接入。

| PNA 重置负责 | 主人侵染负责 |
| --- | --- |
| 身体 PNA 负荷、阶段、消退与满值 | 主人个人开关、ITab 与主人可见标记 |
| 满值后的渴求、长期性欲、恢复 | 普通性交真实完成、双端方向和认领去重 |
| 普通／浓缩摄入、武器剂量与补充 | 小剂量输入及来源自己的准入／主人对象豁免 |
| 锁链基础保护、对象状态迁移 | 少量恶堕、实际部位弱开发与来源记忆 |
| PNA 旧档、调试与专项验收 | 主人开关凝胶流转、克隆排除 |

PNA 核心不读取主人开关、当前性交 Job、来源记忆或调教评分，不建立／抢占主从关系；也不直接发恶堕、部位经验、主人经验或好感。成瘾供给者偏好已由独立 RJW 条目读取观察者成瘾和普通产出资格，负荷核心不反查开关或 Job；未来仅需接入实际可用的主人侵染来源。

主人身份全局 PNA 药效免疫已在玩法第一步 `44dcbc6` 实现并获实机确认，取代早期仅主人侵染入口豁免的方案。成为主人清除既有受药状态、保留身体产出，退出不恢复旧药效；见[补全方案](PNA玩法效果与性交补给补全分析.md#5-主人全局药效免疫)。

### 3.1 需求条的实现归属（2026-10-14 本机核查）

`Need_PNA` 是本模组通过 XML 定义的需求项目，需求框架、条形界面与化学满足度行为来自原版，并非 SSC 新写了一套需求系统：

上述代码已通过本机 Assembly-CSharp.dll 反编译核对，MVID 见第 14 节；XML 为项目作者定义，不替代当前模组加载顺序合并后的实机结果。P2 已实现满值建成瘾、指定来源补充与原版恢复，需求条继续复用原版。

## 5 慢性稳定与急性恢复

### 5.1 已确认的缩短周期测试方案

2026-10-13 维护者确认采用缩短方案：增加基础清除、加快比例清除，并把普通侵蚀输入从 0.06 调到 0.08；这是已选定的开发测试初值，尚未实机平衡。

- `L <= 0.97`：基础与比例两部分共同清除，`dL/dt = -(0.03 + 0.20 × L) / 天`。
- `L > 0.97`：保持固定快速清除，`dL/dt = -0.25 / 天`，跌到 0.97 后转回上式。
- `L <= 0.005`：移除负荷 Hediff，结束极低量条目；不再使用纯比例清除形成很长的微量拖尾。
- 新输入先结算已过去的时间，再加有限正剂量并钳制到 1；自然消退不授予新成瘾。

可在既有健康更新节奏处理，不新增每 tick 全地图扫描。若使用原生逐 tick 更新，不能又在输入／读档补算同一段时间；若使用保存时钟的补算，需保留离图、商队和长期暂停的真实时间约定。两种实现不能混用导致重复清除。

跨越末期门槛的一段时间应分段处理，而不是按起始阶段对整段时间扣减。数学参考：

```text
慢性清除(L, dt) = max(0, (L + 0.15) × exp(-0.20 × dt) - 0.15)

若 L0 > 0.97：
    tHigh = (L0 - 0.97) / 0.25
    dt <= tHigh 时：L1 = L0 - 0.25 × dt
    否则：L1 = 慢性清除(0.97, dt - tHigh)
否则：
    L1 = 慢性清除(L0, dt)

L1 <= 0.005 时移除
```

dt 为游戏天；从满停输入整一天约剩 L=0.789252，不能整天按末期速率减到 0.75。等于 0.97 时后续按慢性一侧积分，不在门槛停住。原始严重度 S=2L 下，慢性清除等价于 `dS/dt = -(0.06 + 0.20 × S) / 天`，不能把归一化基础量 0.03 原样当成原始严重度扣除。

以上补充已于 2026-10-14 确认，只作用已存在的实际需求，未成瘾时不强行新建 Need_PNA。若有效满值建立成瘾后由原版创建了需求，首次设为满值而不是留下随机初始量；已有需求不额外重置，仅接受本次来源补充。缺少合法需求时不强行添加，长期 SexFrequency 仍按成瘾记录生效。

## 7 共享输入与确定性成瘾

P2 在现有 PNA 专用暴露工具中按以下顺序处理：

1. 校验目标健康载体、当前锁链分流、输入来源及有限正剂量，补齐本体负荷已过去的清除。
2. 读取现有实例；缺失时旧负荷按零处理，新建后精确写实际输入值，不把 Def 初始严重度再当一份隐藏剂量。
3. 加实际 PNA 剂量并钳制，检查本次有限正剂量输入后是否处于满值；确认参与者仍有效且未因回调转入锁链保护。
4. 满值且无成瘾时建立一份渴求；已有成瘾不重建、不叠加因子；再次服药由原版增加已有成瘾严重度（2026-10-14 最终确认）。
5. 按来源补充实际需求，返回实际输入、是否达满／建立成瘾以及普通／锁链分流结果。输入的场景去重由调用者负责。

成瘾首次建立由有效正剂量输入后的满值触发：输入前已满但尚无成瘾，也可由这次真实输入建立；即使本次额外负荷因上限被钳掉，也不把真实暴露等同于零剂量。读取健康页、构建 ITab、自然消退、旧档钳制都不发新成瘾。调试增加负荷应走同一工具；外部直接改严重度或绕过入口的第三方兼容需单独适配，不声称已全覆盖。

现有普通／浓缩 `CompDrug` 的 25%／50% 成瘾判定要被 PNA 专用分支替换，避免未满提前成瘾。仅设 `addictiveness=0` 会让原版摄入分支提前返回并丢补充，不能据此宣布完成接入。保留其他药物原逻辑，已有成瘾则放行原版服药分支，使用物品配置的严重度增量（普通液默认 +0.1，浓缩液 +0.2）和原版需求补充。

药物输入 PNA 与补充，枪械保留各自伤害／治疗；性奴强化由统一负荷阶段提供，不再发旧 Buff。两者都不发主人性交记忆、部位经验或主人实践经验。产出者已复用普通完成后缀的一次认领，未来主人侵染接入同一分发并择强调用；PNA 核心只处理输入，不自行认领任务。

## 8 长期渴求与停止补给后的恢复

- 新建时成瘾严重度 D=1；不重复建立已有实例。
- 使用原版 `HediffComp_SeverityPerDay`，D 每天减少 0.1，不要求低负荷或戒断。完整 D=1 完全断供约 10 个有效健康更新日后解除，D 到零由原版移除，需求相应撤销。
- 再次服药直接执行原版 `CompDrug.PrePostIngested`：已有成瘾增加物品配置的 `existingAddictionSeverityOffset`（普通液默认 +0.1，浓缩液 +0.2），并按原版体型／耐受修正补充化学需求。一次摄入事件增加一次，不按份数倍增；原版 Def 上限仍限制 D。

- 普通档性欲 ×1.25；戒断档性欲 ×1.75、操控能力 ×0.85、Vulnerability +0.30，戒断心情 -18。均与负荷阶段正常叠加，不增加恢复门槛、动态插值或额外计时器。

负荷和成瘾分别更新。已有成瘾的普通／浓缩液由原版分别加 D+0.1／+0.2，产出者性交基础 D+0.01；所有真实来源输入后处于末期（L≥0.97）再额外 +0.2，调试及首次建立除外，满值截断不抹除真实输入。产出者末期基础与额外合计 +0.21，一次写入。主人侵染也须有基础成瘾增量已获维护者确认，基础值已确定 D+0.02、末期合计 +0.22；事件及增量已在侵染第二批接入并获维护者实机确认；旧预留分支的基础 0 已被取代。无输入时原版恢复持续进行。

## 9 自动补给与实际物品使用

保留化学需求时，原版会按药物政策实际寻找并消耗 PNA，包含地图与旅队；其筛选不比较普通／浓缩的安全性。两种同 Chemical 物品目前都可能被选择，所以不能期待原版自然优先普通液。

2026-10-14 维护者明确当前不做自动补给限制：不增加仅普通液筛选，不增加预计负荷 0.90 暂缓规则。地图／旅队化学需求补给、药物计划、娱乐摄入和狂欢均沿用原有入口及药物政策等判断，不为 PNA 增加专用候选过滤。手动与自动使用的剂量及满值成瘾规则一致。

原版不会自然优先普通液，浓缩液也可能被自动选中并造成高负荷；这是保留原有行为的结果，不记为待实现的过滤。P2 仍须核查地图／旅队实际物品摄入与来源适配是否执行一致规则。

因玩家药物政策或缺少物品而断供时可能有戒断心情，但应能逐步恢复；不新增必须完成特殊事件才能解除的锁定。测试还要覆盖多来源接触令负荷持续偏高、普通与浓缩自动补给、末期真实输入加深已有成瘾的情况。

## 10 锁链基础保护与性奴后续

必须按实际锁链识别扎根对象，不能只看 Slave 身份、历史特质或 `HasEstablishedSexSlaveState`；后者会把恶堕大于零的未绑定者也算进去。现行查询允许零阶段有效链，要求 LinkedPawn 引用有效且未销毁／丢弃；无效残链不产生保护，不新增绑定准入。

当前保护与正面效果均已实现并验收：

- 有效链对象进入五档性奴负荷，不添加普通负荷负面或新成瘾。两种旧枪械 Buff 已停止发放、拒绝重新添加，并在既有身体协调中清理；链枪保留治疗、命中特效与无伤。
- 2026-10-14 维护者确认：绑定时直接清除 PNA 成瘾／成瘾 Hediff，普通 PNA 状态转换为同原始严重度的性奴 PNA 状态；解绑时再转换回同严重度的普通 PNA 状态。负荷及未结算有效时间不重置，旧成瘾不恢复，也不因转换补建新成瘾。
- 视图隐藏不负责停用能力：需要实际移除／中性阶段并使健康缓存重算，不让残留的负面 CurStage 继续作用。
- 性奴正面阶段、统一剂量、心情与清除已完成；个人“主动摄入维持”仍是[未来规划第 25 项](未来内容开发规划.md#25-新版-pna-的性奴正面效果与主动补给)的可选待设计内容，不通过恢复成瘾／需求条驱动。

`makeImmuneTo/PNA_Addiction` 会被原版免疫查询读取，但药物成瘾与直接添加不据此拒绝，不能替代这里对这些入口的显式保护。新链状态、解绑、旧档／外部链变化均要重评估；PNA 工具自身不改绑关系。

## 11 PNA 仅属于当前身体；空壳与克隆规则已确认

2026-10-14 维护者确认统一原则：**所有 PNA 相关 Hediff 完全只限于当前这具身体本身。** 当前负荷、性奴负荷、成瘾、两种枪械强化、意识抗性快照及两种 PNA 产出记录均属于身体；此前已确认 Need_PNA 及满足度同样不随人格搬迁。不增加人格凝胶中的 PNA 保存字段，原恶堕和记忆仍按其人格机制处理。

- 人格采集不把原身体的 PNA 搬走；植入不把来源 PNA 带到宿主，也不以来源值替换宿主已有身体状态。人格恢复后仍按最终实际有效锁链分流。
- 空壳身体照常进行健康更新，负荷继续消退、成瘾继续恢复；冷冻／暂停沿用原规则。
- 空壳的化学需求沿用原版合法准入及更新，不专门隐藏、冻结或强行添加，不额外改寻药 AI。
- SSC 新生克隆是另一具身体，不继承来源当前 PNA 负荷、成瘾或满足度：负荷从零开始，无成瘾，需求由原版按实际状态决定是否存在。
- SSC 克隆成熟复制只过滤来源 PNA，保留克隆自己暴露后获得的负荷、成瘾及满足度；仍服从克隆身体最终有效锁链保护。
- 维护者明确当前 SSC 克隆系统没有开放入口，不存在需要本批回溯处理的旧克隆案例，因此不开发旧克隆迁移或来源追溯清理。
- 只处理 SSC 自己的相关流程，其他模组克隆兼容不纳入本批。

P2 已做人格标签的最小 PNA 排除。P3 已扩展八类身体排除清单，在 SSC 新生清理／成熟复制前过滤来源，并在新生、成熟与人格植入结束后核对最终身体和原版需求准入。仅新生合法 PNA 需求使用原版初值，成熟及植入保留合法自身现值。详见[P3 实现与测试](../Development/Verification/PNA机制重置P3实现与测试.md)，本批已获维护者实机确认。

### 16.2 共享输入顺序

### 16.3 摄入适配

本机原版调用顺序为 `PrePostIngested → outcomeDoers → PostIngested`。原 `IngestionOutcomeDoer_GiveHediff` 虽收到 `ingestedCount`，却没有用其乘剂量；只改 XML 严重度不能满足已确认的实际份数规则。用 PNA 专用 Doer 替换两种物品的原负荷 Doer，原负荷效果不并存，保留娱乐和其他效果；后续单份修正已移除营养值。

现有 P1 药物补丁只拦截有链对象，P2 要覆盖纳入适配的普通 PNA 摄入，避免未成瘾对象在 Doer 执行前触发 25%／50% 随机成瘾。已有成瘾直接放行原版严重度增加及化学需求补充；Doer 处理身体剂量时跳过本次已由原版完成的需求补充，避免重复。修改仅针对 PNA，其他药物保留原流程；第三方新增 PNA 来源需显式接入，不能据此宣称所有外部来源都已覆盖。
