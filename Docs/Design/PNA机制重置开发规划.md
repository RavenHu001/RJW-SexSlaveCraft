## 1 为什么独立、如何划分职责

PNA 已同时用于摄入、枪械、手术和身体产出，其多阶段负荷和依赖不应由一次普通性交驱动管理。独立后可以先用既有物品测试慢性、急性与恢复，主人侵蚀只作为后续小剂量来源接入。

| PNA 重置负责 | 主人侵染负责 |
| --- | --- |
| 身体 PNA 负荷、阶段、消退与满值 | 主人个人开关、ITab 与主人可见标记 |
| 满值后的渴求、长期性欲、恢复 | 普通性交真实完成、双端方向和认领去重 |
| 普通／浓缩摄入、武器剂量与补充 | 小剂量输入及来源自己的准入／主人对象豁免 |
| 锁链基础保护、对象状态迁移 | 少量恶堕、实际部位弱开发与来源记忆 |
| PNA 旧档、调试与专项验收 | 主人开关凝胶流转、克隆排除 |

PNA 核心不读取主人开关、当前性交 Job、来源记忆或调教评分，不建立／抢占主从关系；也不直接发恶堕、部位经验、主人经验或好感。对侵蚀开启者／具备能力者的偏好是两者的可选适配，核心只提供只读渴求查询。

普通侵蚀中的主人对象免疫是该入口的规则，不扩成所有 PNA 物品／枪械给主人免疫。后者的专属待遇尚未设计。

## 2 已确定的规则与后置范围

- 现有 PNA 影响重做为多阶段 Hediff，支持长期慢性存在和急性快速积累，末期参考旧负面效果。
- 低频普通接触主要维持慢性；更高频率、集中接触或药物等高剂量输入才能堆满。不能使用每天固定扣除、使任何正净增量都必然无限堆满的唯一衰减方案。
- 普通对象达到一次 PNA 满值后获得渴求／依赖，其长期作用为增强性欲；PNA 回落后不立即失去这项作用。
- 依赖可通过长期停止补给逐渐消退，不写成永久不可解除；重复满值不叠加多份依赖或性欲加成。
- 有锁链性奴视为微械已扎根，不形成这种成瘾，PNA 对其总体为正面。完整正面阶段及可选主动摄入维持效果，后置开发。P1 使用无普通能力惩罚的独立性奴负荷载体承接同严重度转换，暂共用基础负荷清除，不预先定义完整正面收益。
- 源于主体液的 PNA 输入、身体开发和少量恶堕仍由侵染规划规定；PNA 堆满不要求恶堕达到 30%，不突破无锁链 12% 恶堕上限。
- 是否偏好正在开启侵蚀或具备能力的角色仅为可考虑方向，不是首版验收要求。

## 3 采用已有记录、避免重复保存

建议继续使用 `Hediff_PNA_Debuff` 作为负荷记录，保留原始严重度上限 **2**，用 `L = Severity / 2` 表示 0～1 负荷。这样不为归一化界面增加另一条保存值，也减少旧档数值转换。以下阈值与剂量均先按 L 表达，实际写入再乘 2。

| 记录 | 职责与保存建议 |
| --- | --- |
| PNA 负荷严重度 | 当前实际身体状态，唯一阶段依据；不另存含量、活性或侵蚀经验 |
| `PNA_Addiction` | 沿用 DefName，游戏中名称后定；保存一份依赖及其恢复进度 |
| 原 `Need_PNA` | 沿用原版合法需求准入、`Need_Chemical` 与补充满足度，每日下降 0.333；当前不增加自动补给限制 |
| 恶堕需求 | 使用原当前值／历史值，与 PNA 负荷和依赖严重度无互相替代 |

不增加永久“曾堆满”布尔：依赖存在时已足够防止重复建立。2026-10-14 最终确认取消“不重置恢复进度”限制，已有依赖服药沿用原版增加严重度；不重复创建或叠加因子，完全解除后再次有效达满可重新建立。负荷和依赖不要求 `CompSexSlaveTraining` 作为保存载体，必要健康／需求准入仍按实际角色判断。

### 3.1 需求条的实现归属（2026-10-14 本机核查）

`Need_PNA` 是本模组通过 XML 定义的需求项目，需求框架、条形界面与化学满足度行为来自原版，并非 SSC 新写了一套需求系统：

- [NeedDefs.xml](../../Defs/NeedDefs/NeedDefs.xml) 继承原版 `DrugAddictionNeedBase`，实现类直接指定 `RimWorld.Need_Chemical`；本模组没有自定义 PNA Need 类。
- [HediffOfAddiction.xml](../../Defs/HediffDefs/HediffOfAddiction.xml) 的 `PNA_Addiction` 使用原版 `Hediff_Addiction`，以 `chemicalNeed=Need_PNA` 关联需求；[ChemicalDef.xml](../../Defs/ChemicalDefs/ChemicalDef.xml) 将 PNA 化学物关联到该依赖。
- 原版 `DrugAddictionNeedBase` 设置 `onlyIfCausedByHediff=true`；`Pawn_NeedsTracker.ShouldHaveNeed` 检查健康状态是否启用需求及其他合法准入，`AddOrRemoveNeedsAsAppropriate` 负责生成／撤销，`AddNeed` 按 `needClass` 创建实例。
- 原版 `Need_Chemical.NeedInterval` 按 Def 的每日下降值更新满足度，冻结时不下降；满足度 <=0.01 时判为戒断。新实例原版初值随机为 0.8～1，P2 才按已确认规则将首次新生成的 PNA 需求设满。
- `Need_Chemical` 没有自定义绘制方法，继承原版 `Need.DrawOnGUI` 绘制需求条；SSC 的 P1 链保护只清除依赖并调用原版需求刷新，不自行画条或强行创建需求。

上述代码已通过本机 Assembly-CSharp.dll 反编译核对，MVID 见第 14 节；XML 为项目作者定义，不替代当前模组加载顺序合并后的实机结果。P2 需要实现的是满值建依赖、指定来源补充与恢复规则，需求条继续复用原版。

## 5 慢性稳定与急性恢复

### 5.1 已确认的缩短周期测试方案

2026-10-13 维护者确认采用缩短方案：增加基础清除、加快比例清除，并把普通侵蚀输入从 0.06 调到 0.08；这是已选定的开发测试初值，尚未实机平衡。

- `L <= 0.97`：基础与比例两部分共同清除，`dL/dt = -(0.03 + 0.20 × L) / 天`。
- `L > 0.97`：保持固定快速清除，`dL/dt = -0.25 / 天`，跌到 0.97 后转回上式。
- `L <= 0.005`：移除负荷 Hediff，结束极低量条目；不再使用纯比例清除形成很长的微量拖尾。
- 新输入先结算已过去的时间，再加有限正剂量并钳制到 1；自然消退不授予新依赖。

可在既有健康更新节奏处理，不新增每 tick 全地图扫描。若使用原生逐 tick 更新，不能又在输入／读档补算同一段时间；若使用保存时钟的补算，需保留离图、商队和长期暂停的真实时间约定。两种实现不能混用导致重复清除。

跨越末期门槛的一段时间应分段处理，而不是按起始阶段对整段时间扣减。数学参考：

```text
慢性清除(L, dt) = max(0, (L + 0.15) × exp(-0.20 × dt) - 0.15)

若 L0 > 0.97：
    tHigh = (L0 - 0.97) / 0.25
    dt <= tHigh 时：L1 = L0 - 0.25 × dt
    否则：L1 = 慢性清除(0.97, dt - tHigh)
否则：
    L1 = 慢性清除(L0, dt)

L1 <= 0.005 时移除
```

dt 为游戏天；从满停输入整一天约剩 L=0.789252，不能整天按末期速率减到 0.75。等于 0.97 时后续按慢性一侧积分，不在门槛停住。原始严重度 S=2L 下，慢性清除等价于 `dS/dt = -(0.06 + 0.20 × S) / 天`，不能把归一化基础量 0.03 原样当成原始严重度扣除。

## 7 共享输入与确定性依赖

P2 在现有 PNA 专用暴露工具中按以下顺序处理：

1. 校验目标健康载体、当前锁链分流、输入来源及有限正剂量，补齐本体负荷已过去的清除。
2. 读取现有实例；缺失时旧负荷按零处理，新建后精确写实际输入值，不把 Def 初始严重度再当一份隐藏剂量。
3. 加实际 PNA 剂量并钳制，检查本次有限正剂量输入后是否处于满值；确认参与者仍有效且未因回调转入锁链保护。
4. 满值且无依赖时建立一份渴求；已有依赖不重建、不叠加因子；再次服药由原版增加已有成瘾严重度（2026-10-14 最终确认）。
5. 按来源补充实际需求，返回实际输入、是否达满／建立依赖以及普通／锁链分流结果。输入的场景去重由调用者负责。

依赖首次建立由有效正剂量输入后的满值触发：输入前已满但尚无依赖，也可由这次真实输入建立；即使本次额外负荷因上限被钳掉，也不把真实暴露等同于零剂量。读取健康页、构建 ITab、自然消退、旧档钳制都不发新依赖。调试增加负荷应走同一工具；外部直接改严重度或绕过入口的第三方兼容需单独适配，不声称已全覆盖。

现有普通／浓缩 `CompDrug` 的 25%／50% 成瘾判定要被 PNA 专用分支替换，避免未满提前成瘾。仅设 `addictiveness=0` 会让原版摄入分支提前返回并丢补充，不能据此宣布完成接入。保留其他药物原逻辑，已有依赖则放行原版服药分支，使用物品配置的严重度增量（默认 +0.1）和原版需求补充。

药物只输入 PNA 与补充，枪械另外保留各自伤害／治疗／强化；两者都不发主人性交记忆、部位经验或主人实践经验。普通侵蚀仍独立认领一次后调用，不把 PNA 核心做成性交补丁。

## 8 长期渴求与停止补给后的恢复

沿用 `PNA_Addiction` DefName 和原版 `Hediff_Addiction`／`Need_Chemical`。原版依赖必须有第 0 档未戒断、第 1 档戒断；2026-10-14 维护者确认保留两档 SexFrequency ×1.25 长期加成，与身体负荷按原有属性机制乘算。多阶段负荷不使用这份依赖严重度来选阶段。

- 新建时依赖严重度 D=1；不重复建立已有实例。
- 使用原版 `HediffComp_SeverityPerDay`，D 每天减少 0.125，不要求低负荷或戒断。完整 D=1 完全断供约 8 个有效健康更新日后解除，D 到零由原版移除，需求相应撤销。
- 再次服药直接执行原版 `CompDrug.PrePostIngested`：已有成瘾增加物品配置的 `existingAddictionSeverityOffset`（默认 +0.1），并按原版体型／耐受修正补充化学需求。一次摄入事件增加一次，不按份数倍增；原版 Def 上限仍限制 D。
- Need_PNA 每日下降 0.333，满满足度约 2.97 天进入戒断；满足度不决定恢复准入。没有合法需求也可随原版健康更新恢复，暂停身体由原版调度处理。
- 两档长期性欲保持 ×1.25，直到依赖消除；戒断心情 -18 仅在原版戒断档生效。无需动态插值或额外计时器。

负荷和成瘾分别更新。每天一次普通侵蚀的负荷谷约 21.13%，可以维持慢性负荷，但不再锁住依赖。枪械和普通侵蚀继续采用已确认需求补充，不额外设计成瘾严重度增量；原版服药增加只由摄入成瘾品触发。在当前 -0.125/日、默认 +0.1/次下，每日一次服药仍净恢复约 0.025，两次约净增加 0.075（受上限限制）；这是现有 PNA 参数配合原版机制的结果，不另加维持规则。

长期性欲与负荷因子乘算：L 处于深度档时 ×3.25 ×1.25 = ×4.0625，末期 ×4 ×1.25 = ×5，还会与 RJW 既有性格等来源叠加。第 4 节最高 ×4 指普通负荷自身因子，不新增总倍率截断或动态插值。需验证需求下降、日常任务与精神崩溃变化，不能只检查健康页。

## 9 自动补给与实际物品使用

保留化学需求时，原版会按药物政策实际寻找并消耗 PNA，包含地图与旅队；其筛选不比较普通／浓缩的安全性。两种同 Chemical 物品目前都可能被选择，所以不能期待原版自然优先普通液。

2026-10-14 维护者明确当前不做自动补给限制：不增加仅普通液筛选，不增加预计负荷 0.90 暂缓规则。地图／旅队化学需求补给、药物计划、娱乐摄入和狂欢均沿用原有入口及药物政策等判断，不为 PNA 增加专用候选过滤。手动与自动使用的剂量及满值依赖规则一致。

原版不会自然优先普通液，浓缩液也可能被自动选中并造成高负荷；这是保留原有行为的结果，不记为待实现的过滤。P2 仍须核查地图／旅队实际物品摄入与来源适配是否执行一致规则。

因玩家药物政策或缺少物品而断供时可能有戒断心情，但应能逐步恢复；不新增必须完成特殊事件才能解除的锁定。测试还要覆盖多来源接触令负荷持续偏高、普通与浓缩自动补给加深已有成瘾的情况。

沿用 P1 输入校验与未结算负荷清除。完成本次加量后重新核对有效身体、实际锁链和健康实例；普通对象最终满值且没有依赖时，创建 D=1 的一份 `PNA_Addiction`。创建后再核对链保护，刷新原版合法需求；只把本次新生成的需求设满。已有需求按来源补充；已有依赖服药增量由原版处理，共享输入不重复创建。满值时实际增量为零的真实正输入仍可触发缺失依赖，但枪械需求补充按实际有效增量计算。

新建依赖结果用于一次通知与调试反馈，重复满值不重发新成瘾提示。读取、自然消退、迁移及外部直接改严重度均不触发新依赖。调试有效加量和补满动作随共享入口采用 P2 新规则。

### 16.3 摄入适配

本机原版调用顺序为 `PrePostIngested → outcomeDoers → PostIngested`。原 `IngestionOutcomeDoer_GiveHediff` 虽收到 `ingestedCount`，却没有用其乘剂量；只改 XML 严重度不能满足已确认的实际份数规则。用 PNA 专用 Doer 替换两种物品的原负荷 Doer，原负荷效果不并存，保留营养、娱乐和其他效果。

现有 P1 药物补丁只拦截有链对象，P2 要覆盖纳入适配的普通 PNA 摄入，避免未成瘾对象在 Doer 执行前触发 25%／50% 随机成瘾。已有依赖直接放行原版严重度增加及化学需求补充；Doer 处理身体剂量时跳过本次已由原版完成的需求补充，避免重复。修改仅针对 PNA，其他药物保留原流程；第三方新增 PNA 来源需显式接入，不能据此宣称所有外部来源都已覆盖。

不能只将 `addictiveness` 清零：原 `PrePostIngested` 会提前退出且 `PostIngested` 中部分原行为也读取药物成瘾属性。实现时保留该属性所服务的其他语义，专门替换 PNA 成瘾／补充分支。

两种 PNA 在 `<ingestible>` 明确 `defaultNumToIngestAtOnce=1` 和 `maxNumToIngestAtOnce=1`，沿用原版药物单份摄入配置。资源基类缺少这两项会导致手动任务默认取 20 份、按营养需要一次摄入多份；维护者已确认异常一次实际 14 份。实际份数 Doer 保留，不通过代码把真实多份虚报为一份。已核对原版支持零营养药物，两种 PNA 移除 Nutrition，服药不补充食物需求；默认及最大单份配置仍保留。

### 16.4 枪械适配

低阶枪以原始 `min(0.15 / 既有意识除数, 1)` 计算，再除以 2 传给共享入口；高阶普通负荷参数仍对应 L +0.25，武器继续禁用。意识为 1 时低阶每次 +7.5%；保留意识下降后单次剂量增大的既有反馈，不把提高基数理解成固定每次 +15%。

实际有效链决定保护口径，不能由无效残链单独触发性奴保护。治疗／战斗强化分支继续按原设计执行，不额外设计完整性奴收益。

当前输入位于 `ApplySpecialEffectsToPart`，原版伤害传播可多次调用该部位回调。需要按同一次 `Apply` 的局部执行范围认领首次有效回调，后续同次部位传播不重复输入；两个独立命中即使同 tick 仍分别输入。完全护甲偏转未进入有效回调时不凭空新增 PNA，不改变既有穿甲语义；伤害、治疗与强化不随 PNA 去重被一起删掉。

### 16.5 依赖恢复与显示

保留 `Hediff_Addiction` 和第 0／1 档，使用原版 `HediffCompProperties_SeverityPerDay`／`HediffComp_SeverityPerDay`，每日配置 -0.125。原版负责 200-tick 调度、D 更新、恢复进度／天数及耗尽移除；不再添加速率补丁、负荷／戒断门槛或恢复计时器，没有合法需求也使用原版组件。

旧档的原版组件速率在初始化校正到当前 XML 值，D 不重置；不新增累计恢复天数、最近补给时钟或永久曾满标志。普通档沿用原版无标签、括号显示已恢复百分比，恢复天数使用原版文案，移除冗长的自定义暂停提示。具体检查及实机复测见[原版恢复调整](../Development/Verification/PNA成瘾原版恢复调整.md)。

原版需求首次随机 80%～100%，新规则首次设满；每日下降 0.333，原版满足度 <=1% 时进入戒断，满需求约 2.97 天。新满负荷／D=1 完全断供约 8 个有效天解除依赖，与负荷衰减并行；-18 心情大约从第三天持续到依赖解除。实际补给与冻结可改变时长，该压力是首轮实机平衡重点。

### 16.6 必要保存兼容与验收

保持现有 DefName、依赖类、负荷严重度与需求保存字段。旧合法 D 和需求满足度原值保留，非法值清理、重复依赖取合法单份而不相加；新 D=1 初值不覆写旧值。移除有效链仍同严重度转回普通负荷，不恢复或补建依赖。

PNA 身体归属已经确认：检查人格采集和恢复的通用 `hediffTags` 路径，最小排除 PNA 负荷／依赖并拒绝旧人格快照中的同类标签，不迁移 Need_PNA 值；完整空壳和克隆规则仍按 P3 决策开发。

建议顺序：共享满值建依赖及恢复 → 摄入与药物补丁 → 枪械与一次命中输入 → 旧档及最小身体归属适配 → XML／四语 → 构建和针对性回归 → 本机测试版与实机验证。

P2 会修改 C#，需要运行相关测试并构建；纯 XML 数值断言只做相应格式／字段检查。重点验收：未满不随机成瘾、恰满／满值截断、重复输入不重复建立、再次服药加深已有依赖、解除后再满、实际多份摄入且修正一次、枪械传播不重复／同 tick 独立命中、原版无门槛恢复与暂停、旧速率字段不再生效、首次需求设满但旧需求不重置、地图／旅队原有补给、链回调分流、旧满不补建及存读档幂等。

本节记录 P2 实现方案和本机源码依据，已据此实施测试批；最终构建与自动验证结果见[P2 实现与测试](../Development/Verification/PNA机制重置P2实现与测试.md)，实机验收待维护者反馈。
