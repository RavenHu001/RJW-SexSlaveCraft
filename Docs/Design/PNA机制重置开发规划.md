## 1 为什么独立、如何划分职责

PNA 已同时用于摄入、枪械、手术和身体产出，其多阶段负荷和依赖不应由一次普通性交驱动管理。独立后可以先用既有物品测试慢性、急性与恢复，主人侵蚀只作为后续小剂量来源接入。

| PNA 重置负责 | 主人侵染负责 |
| --- | --- |
| 身体 PNA 负荷、阶段、消退与满值 | 主人个人开关、ITab 与主人可见标记 |
| 满值后的渴求、长期性欲、恢复 | 普通性交真实完成、双端方向和认领去重 |
| 普通／浓缩摄入、武器剂量与补充 | 小剂量输入及来源自己的准入／主人对象豁免 |
| 锁链基础保护、对象状态迁移 | 少量恶堕、实际部位弱开发与来源记忆 |
| PNA 旧档、调试与专项验收 | 主人开关凝胶流转、克隆排除 |

PNA 核心不读取主人开关、当前性交 Job、来源记忆或调教评分，不建立／抢占主从关系；也不直接发恶堕、部位经验、主人经验或好感。对侵蚀开启者／具备能力者的偏好是两者的可选适配，核心只提供只读渴求查询。

普通侵蚀中的主人对象免疫是该入口的规则，不扩成所有 PNA 物品／枪械给主人免疫。后者的专属待遇尚未设计。

## 2 已确定的规则与后置范围

- 现有 PNA 影响重做为多阶段 Hediff，支持长期慢性存在和急性快速积累，末期参考旧负面效果。
- 低频普通接触主要维持慢性；更高频率、集中接触或药物等高剂量输入才能堆满。不能使用每天固定扣除、使任何正净增量都必然无限堆满的唯一衰减方案。
- 普通对象达到一次 PNA 满值后获得渴求／依赖，其长期作用为增强性欲；PNA 回落后不立即失去这项作用。
- 依赖可通过长期停止补给逐渐消退，不写成永久不可解除；重复满值不叠加多份依赖或性欲加成。
- 有锁链性奴视为微械已扎根，不形成这种成瘾，PNA 对其总体为正面。完整正面阶段及可选主动摄入维持效果，后置开发。P1 使用无普通能力惩罚的独立性奴负荷载体承接同严重度转换，暂共用基础负荷清除，不预先定义完整正面收益。
- 源于主体液的 PNA 输入、身体开发和少量恶堕仍由侵染规划规定；PNA 堆满不要求恶堕达到 30%，不突破无锁链 12% 恶堕上限。
- 是否偏好正在开启侵蚀或具备能力的角色仅为可考虑方向，不是首版验收要求。

## 3 采用已有记录、避免重复保存

建议继续使用 `Hediff_PNA_Debuff` 作为负荷记录，保留原始严重度上限 **2**，用 `L = Severity / 2` 表示 0～1 负荷。这样不为归一化界面增加另一条保存值，也减少旧档数值转换。以下阈值与剂量均先按 L 表达，实际写入再乘 2。

| 记录 | 职责与保存建议 |
| --- | --- |
| PNA 负荷严重度 | 当前实际身体状态，唯一阶段依据；不另存含量、活性或侵蚀经验 |
| `PNA_Addiction` | 沿用 DefName，游戏中名称后定；保存一份依赖及其恢复进度 |
| 原 `Need_PNA` | 沿用补充满足度和 `Need_Chemical`，缩短方案保持每日下降 0.333；具体生成准入／自动补给细则仍需确认 |
| 恶堕需求 | 使用原当前值／历史值，与 PNA 负荷和依赖严重度无互相替代 |

建议不增加永久“曾堆满”布尔：依赖存在时已足够防止重复建立。依赖自然消除后再次有效输入达满，可以重新建立；这项重建规则为建议，尚待确认。负荷和依赖不要求 `CompSexSlaveTraining` 作为保存载体，必要健康／需求准入仍按实际角色判断。

慢性性欲来自当下负荷，达满依赖另提供长期因子。满值与末期门槛分别为 1 和 0.97：进入末期不必已经获得依赖。提高末期门槛是为了让集中小剂量可以从仍能活动的阶段直接跳满，避免必须先长期倒地才能完成普通接触。

`SexFrequency` 使用 RJW 已有需求下降机制，仍受其睡眠冻结、无性和其他原条件影响。它改变通用性欲，不等于只对某位主人产生渴望。末期意识压制也只是健康能力效果，不据此虚构 RJW 高潮事件、恶堕奖励或动画。

首版建议不沿用旧普通感染自动 +5／+8 的统一持续心情；第 8 节依赖戒断思绪与侵染自己的四格记忆分别承担反馈。后续如加入 PNA 条件心情，需重核总量，不能让旧 +5 抵消低恶堕抗拒 -4 而未被发现。

## 5 慢性稳定与急性恢复

### 5.1 已确认的缩短周期测试方案

2026-10-13 维护者确认采用缩短方案：增加基础清除、加快比例清除，并把普通侵蚀输入从 0.06 调到 0.08；这是已选定的开发测试初值，尚未实机平衡。

- `L <= 0.97`：基础与比例两部分共同清除，`dL/dt = -(0.03 + 0.20 × L) / 天`。
- `L > 0.97`：保持固定快速清除，`dL/dt = -0.25 / 天`，跌到 0.97 后转回上式。
- `L <= 0.005`：移除负荷 Hediff，结束极低量条目；不再使用纯比例清除形成很长的微量拖尾。
- 新输入先结算已过去的时间，再加有限正剂量并钳制到 1；自然消退不授予新依赖。

可在既有健康更新节奏处理，不新增每 tick 全地图扫描。若使用原生逐 tick 更新，不能又在输入／读档补算同一段时间；若使用保存时钟的补算，需保留离图、商队和长期暂停的真实时间约定。两种实现不能混用导致重复清除。

跨越末期门槛的一段时间应分段处理，而不是按起始阶段对整段时间扣减。数学参考：

```text
慢性清除(L, dt) = max(0, (L + 0.15) × exp(-0.20 × dt) - 0.15)

若 L0 > 0.97：
    tHigh = (L0 - 0.97) / 0.25
    dt <= tHigh 时：L1 = L0 - 0.25 × dt
    否则：L1 = 慢性清除(0.97, dt - tHigh)
否则：
    L1 = 慢性清除(L0, dt)

L1 <= 0.005 时移除
```

dt 为游戏天；从满停输入整一天约剩 L=0.789252，不能整天按末期速率减到 0.75。等于 0.97 时后续按慢性一侧积分，不在门槛停住。原始严重度 S=2L 下，慢性清除等价于 `dS/dt = -(0.06 + 0.20 × S) / 天`，不能把归一化基础量 0.03 原样当成原始严重度扣除。

| 一份普通 PNA | +0.20 | +0.40 | +1.00，上限钳制 |
| 一份浓缩 PNA | +0.70 | +1.40 | +1.00，不因浓缩突破满足度上限 |

普通侵蚀 +0.08／原始 +0.16 已按维护者确认的缩短周期方案同步；Need_PNA +0.12 暂沿用独立补充测试值，它与负荷严重度不是同一尺度，不随本次负荷调整自动改成 +0.16。普通与浓缩液剂量仍是测试建议，未假称与旧 0.30／1.00 相同。普通枪暂保留其既有抗性算法，输出剂量后接共享工具；穿甲语义、快照抗性重做不扩入本批。实际摄入份数、身体大小与其他化学效果修正需在专用摄入适配明确只算一次，不能与原 Doer 重复输入。

忽略份间衰减时五份普通液合计正好满；实际连续摄入需按历时核算，可能要第六份。按新清除曲线，每天一份普通液稳态峰约 95.33%、谷约 75.33%，不满；每天两份、等间隔时第 8 份约 3.5 天可满。浓缩每天一份仍在第 2 份约 1 天满；短间隔两份也可满，间隔很久则不保证。

一份浓缩需对象原有 L 至少 0.30 才能直接满；每天一次普通侵蚀的稳态峰仅约 0.2913，加 0.70 后约 0.9913，不能继续宣称此情境一份浓缩必然满。

以上补充只作用已存在的实际需求，未依赖时不强行新建 Need_PNA。若有效满值建立依赖后由原版创建了需求，建议首次设为满值而不是留下随机初始量；缺少合法需求时不强行添加，长期 SexFrequency 仍按依赖记录生效。

## 7 共享输入与确定性依赖

建议一个 PNA 专用暴露工具按以下顺序处理：

1. 校验目标健康载体、当前锁链分流、输入来源及有限正剂量，补齐本体负荷已过去的清除。
2. 读取现有实例；缺失时旧负荷按零处理，新建后精确写实际输入值，不把 Def 初始严重度再当一份隐藏剂量。
3. 加实际 PNA 剂量并钳制，检查本次有限正剂量输入后是否处于满值；确认参与者仍有效且未因回调转入锁链保护。
4. 满值且无依赖时建立一份渴求；已有依赖不重建、不叠加因子，建议不重置已取得的恢复进度。
5. 按来源补充实际需求，返回实际输入、是否达满／建立依赖以及普通／锁链分流结果。输入的场景去重由调用者负责。

依赖首次建立由有效正剂量输入后的满值触发：输入前已满但尚无依赖，也可由这次真实输入建立；即使本次额外负荷因上限被钳掉，也不把真实暴露等同于零剂量。读取健康页、构建 ITab、自然消退、旧档钳制都不发新依赖。调试增加负荷应走同一工具；外部直接改严重度或绕过入口的第三方兼容需单独适配，不声称已全覆盖。

现有普通／浓缩 `CompDrug` 的 25%／50% 成瘾判定要被 PNA 专用分支替换，避免未满提前成瘾。仅设 `addictiveness=0` 会让原版摄入分支提前返回并丢补充，不能据此宣布完成接入。保留其他药物原逻辑，也不再无条件给已有 PNA 依赖 +0.1 严重度。

药物只输入 PNA 与补充，枪械另外保留各自伤害／治疗／强化；两者都不发主人性交记忆、部位经验或主人实践经验。普通侵蚀仍独立认领一次后调用，不把 PNA 核心做成性交补丁。

## 8 长期渴求与停止补给后的恢复

建议沿用 `PNA_Addiction` DefName 和原版 `Hediff_Addiction`／`Need_Chemical`。原版依赖必须有第 0 档未戒断、第 1 档戒断；两档都给 SexFrequency ×1.25 测试加成。多阶段负荷不使用这份依赖严重度来选阶段。

- 建立时建议依赖严重度 D=1，表示完整恢复进度仍未完成；已有记录不强行抬到 1。
- 缩短方案保持 Need_PNA 每日下降 0.333，满满足度约三天后进入戒断；恢复需要同时满足 **L <= 0.20 且已处于戒断**。
- 满足这两个条件时 D 每天减少 0.125；新记录 D=1 需要 8 个符合条件的恢复日。其他时间不减、不因补给自动反向增加；D 到零移除依赖，需求由原版相应撤销。
- 角色缺少合法 Need_PNA 时，建议低负荷即可开始恢复，避免需求未生成造成永远不能退出；暂停／冻结和缺人格的状态按实际健康载体单独校验。
- 恢复期间建议长期性欲因子保持 ×1.25，直到依赖消除；用 D 显示恢复进度，不为渐变因子增加新等级。若要求性欲也平滑下降，再单独适配动态数值。
- 普通戒断心情建议先用 -6 替代旧 -25，作为待测值；不重跑 RJW 性交记忆，不直接改变基础关系。

从满负荷、新依赖 D=1 开始完全断供的健康普通对象，约 5.94 天进入 20% 低负荷恢复区，再需 8 个有效恢复日，约 13.94 天解除依赖。化学需求约三天进入戒断，与负荷下降并行，不额外顺延三天。实际供给、冻结、身体状态和已有 D 会改变过程，不将它写成固定倒计时。

每天一次等间隔普通侵蚀时，稳态负荷谷约 21.13%，高于 20% 恢复门槛，因此可以维持慢性，也能维持已建立的依赖。重新补给通过负荷和需求自然打断恢复条件，但不抹去已完成的 D 恢复进度；不额外保存“最近补给后若干天”的重置计时。

长期性欲与负荷因子乘算：L 处于深度档时 ×1.40 ×1.25 = ×1.75，还会与 RJW 既有性格等来源叠加。需验证需求下降、日常任务与精神崩溃变化，不能只检查健康页。

## 9 自动补给与实际物品使用

保留化学需求时，原版会按药物政策实际寻找并消耗 PNA，包含地图与旅队；其筛选不比较普通／浓缩的安全性。两种同 Chemical 物品目前都可能被选择，所以不能期待原版自然优先普通液。

建议首版的化学需求自动补给：只选普通 PNA，沿用预约、禁用、社会合宜、可摄入与药物政策判断；预计摄入后 L 高于 0.90 时暂缓，不为赶补充把对象直接送进末期。手动使用可继续承担剂量风险，玩家能通过政策控制自动补给。

没有一个现成专用 Def 标签能同时覆盖地图和旅队的化学需求选择；候选过滤需只针对 PNA 适配。药物计划服用、娱乐摄入和狂欢是不同入口，是否也禁止浓缩自动摄入尚待明确，不能只修化学需求路径就声称覆盖所有自动使用。

补给受限时可能有戒断心情，但应能靠断供逐步恢复；不新增必须完成特殊事件才能解除的锁定。测试还要覆盖多来源接触令负荷持续偏高、因门槛长期暂缓普通药物的情况。

## 10 锁链基础保护与性奴后续

必须按实际锁链识别扎根对象，不能只看 Slave 身份、历史特质或 `HasEstablishedSexSlaveState`；后者会把恶堕大于零的未绑定者也算进去。残留或零阶段锁链的有效口径需在实现前核对，不由本设计偷换成新的绑定准入。

第一批建议先做以下保护，不等待完整性奴正面玩法：

- 各来源均不添加普通负荷负面和新依赖，原枪械已有治疗／战斗强化继续保留。
- 2026-10-14 维护者确认：绑定时直接清除 PNA 依赖／成瘾 Hediff，普通 PNA 状态转换为同原始严重度的性奴 PNA 状态；解绑时再转换回同严重度的普通 PNA 状态。负荷及未结算有效时间不重置，旧依赖不恢复，也不因转换补建新依赖。
- 视图隐藏不负责停用能力：需要实际移除／中性阶段并使健康缓存重算，不让残留的负面 CurStage 继续作用。
- 性奴完整正面剂量、阶段、持续收益与个人“主动摄入维持”开关另见[未来规划第 25 项](未来内容开发规划.md#25-新版-pna-的性奴正面效果与主动补给待设计)，后置开发；首批不提前显示它们已完成。

`makeImmuneTo/PNA_Addiction` 会被原版免疫查询读取，但药物成瘾与直接添加不据此拒绝，不能替代这里对这些入口的显式保护。新链状态、解绑、旧档／外部链变化均要重评估；PNA 工具自身不改绑关系。

## 11 身体归属、人格凝胶与克隆建议

用户尚未确定这部分。为使 PNA 可以独立实现，首版建议将负荷、身体依赖和 Need_PNA 都作为**身体状态**，不随人格凝胶搬运，不增加另一份凝胶字段；原恶堕与记忆仍按其人格机制处理。若希望长期渴求随人格保留，需另行确认并显式保存依赖及需求快照。

在身体状态方案中，采集人格不把原身体的 PNA 搬走；植入也不让来源依赖替换宿主身体的状态。空壳是否也显示／维持其物理负荷、需求和性欲需明确，不能靠主人开关的空壳清源顺带删除。人格恢复后的链分流仍优先。

克隆建议不复制当前负荷、依赖或满足度，初生与成熟复制都显式过滤，仅保留克隆后来自己暴露获得的记录。这是本轮建议，不能从此前“克隆不继承主人资格”自动推导已实现。

现有凝胶 `hediffTags` 只存 Def→严重度并取较大值合并，克隆又按 SSC 前缀／模组标识宽泛复制，必须分别检查和过滤；不把直接换 DefClass 当作完成保存兼容。

## 12 旧档与定义兼容建议

- 保留现有 PNA 负荷、依赖、化学与需求 DefName；普通负荷上限仍为 2，旧值按原始值保留并夹到合法范围，不因重做阶段额外翻倍／减半。
- 旧已有依赖作为已有记录保留，恢复 D 和实际需求值按合法范围清理；它不证明历史上曾 PNA 满值，不重放新成瘾提示。
- 旧负荷已经满但没有依赖，建议本次迁移不自动补建；仅之后新的有效正剂量输入后仍为满值才走新规则，不要求旧满先人为降下来再跨满。是否需要一次性补建列为维护者待确认项，不能把新阈值／钳制冒充输入。
- 如果出现重复实例，需保留一致单份的合法负荷／依赖，不简单相加制造满值；需求满足度也不强制灌满已有记录。
- 有锁链旧对象按最终保护转换，保留其他药物及 SSC 身份／成长，不回放旧摄入、枪击或性交。
- 迁移版本只服务必要的一次性规范化，不用作永久“曾满”标记；完成后再次读档幂等。

旧 PNA_Addiction 只有一档，而原版戒断返回 1；`Hediff.CurStage` 直接索引，现有戒断 Thought 又按最小阶段数被钳回隐藏档。因此必须修复阶段结构，不能只改概率。作者定义／DLL 证据尚未替代运行时合并 Def 和实机验证。
