## 1. 原调教标签直接开窗

继续注册 `ITab_SexSlaveTraining`，保留原「调教」标签的位置、排序、`labelKey`、`tutorTag` 和可见条件。点击时复查当前单选角色及其训练 Comp，沿用对原版殖民者、本殖民地囚犯、原版奴隶和符合自我调教例外角色的准入。首次打开进入概况，同一角色已有窗口时复用实例。 [原标签和可见条件](../../Sexslavecraft/ITab/ITab_SexSlaveTraining.cs) · [种族注入](../../Sexslavecraft/common/ITabAddForRace.cs)

目标 DLL 的原生点击顺序为 `DoTabs → InterfaceToggleTab → ToggleTab`。`InterfaceToggleTab` 先检查教程许可，`ToggleTab` 在 `OnOpen()` 返回后写入 `OpenTabType`。1.7 接入精确签名的 `InspectPaneUtility.ToggleTab(InspectTabBase, IInspectPane)` Harmony Prefix，仅处理地图原生检查面板上类型精确匹配的 SSC 调教标签。匹配后转交窗口打开逻辑并跳过原展开流程。旧 SSC 展开状态若存在则清理，其他标签继续走原方法。1.7 工程显式纳入新窗口与补丁，真实点击和教程许可列入实机验收。 [1.7 工程](../../Sexslavecraft/SexSlaveCraft_1.7.csproj)

## 2. 窗口布局与角色切换

使用单实例原生 `Verse.Window`，以约 1000 × 560 逻辑像素的横向布局居中打开。窗口允许原版界面接收窗外点击，按殖民者栏的实际行高避让重叠。顶部标题区显示当前角色肖像、姓名和身份，下面单列关系摘要条。主区用左侧六页导航与右侧独立滚动内容区，使用原版中号文字并加大头像和行高。可用宽度或高度不足时，导航移到内容区上方换行。页面分为概况、关系、日常调教、特化、身体与外观、行为规则。 [窗口实现](../../Sexslavecraft/UI/Dialog_SSCTrainingManagement.cs)

第一批即绘制完整窗口布局。概况使用左侧字段、右侧状态值和行分隔线，性奴显示日常调教和当前特化，主人显示当前阶段。摘要条按身份显示主人、指定调教员或所属性奴数量和缩略肖像。其余页面在导航中以禁用态显示，随对应功能批次开放。

- **选角。** 玩家从原版殖民者栏或地图单选，窗口读取 `Selector.SingleSelectedThing`，沿用原调教标签资格并核对角色所在地图。空选、多选和不可管理对象显示提示，下一次有效单选继续显示概况。切换地图时跟随有效的地图单选，进入世界视图或离开原游戏时关闭。标题肖像显示当前角色。点击关系摘要中的肖像可沿原主从概览导航定位，能选中的有效角色继续在同一窗口显示。
- **切换后状态。** 第一批切换角色或训练组件时将概况滚动归顶。可编辑页面接入后，当前页对新角色适用时保留页签，否则回概况。届时维护窗口编辑代次，清理旧视图与拖放状态。指派动作和能力行应复查原窗口代次与各自业务上下文，覆盖 A → B → A 后的迟到提交。

## 3. 关系页

复用第 29 项的直接关系事实与详情。主人按实际锁链读取，所属性奴按缰绳候选逐一核对实际锁链，指定调教员读取现有指派及工作状态。顶部预览与详情共用当前角色的关系视图和局部刷新。抽取原详情绘制内容，让新窗口跟随原版单选并管理滚动。原命令栏放大镜对可管理角色直达新窗口的关系页。仅满足旧概览资格的角色继续沿原详情入口，两个入口共用绘制器并明确详情视图的释放归属。地图上的原快捷定位和批选继续调用原入口。 [关系完成记录](../Development/Completed/主从关系概览完成核对.md) · [直接关系查询](../../Sexslavecraft/common/SSCBondOverviewUtility.cs) · [关系会话](../../Sexslavecraft/common/SSCBondOverviewSession.cs)

关系分组按当前 SSC `PawnIdentity` 显示。主人只显示所属性奴，零人时显示空状态。性奴只显示主人和调教员相关分区，保留「未绑定」和「未指派」状态。未设身份时只显示身份提示，历史锁链的显式身份恢复入口在概况。 [SSC 身份与历史恢复](../../Sexslavecraft/common/SSCIdentityUtility.cs)

### 性奴关系页三区

```text
┌──────────────┬────────────────────────────────┐
│ 1 主人       │ 2 已指派调教员                 │
│              │   头像和姓名按宽度换行         │
│   大头像     ├────────────────────────────────┤
│    姓名      │ 3 可指派调教员                 │
│              │   头像和姓名按宽度换行         │
└──────────────┴────────────────────────────────┘
```

- **1 区主人。** 左侧窄列跨右侧两区，内容为大头像和姓名。已绑定的正常状态用主人头像表达。
- **2 区已指派。** 右上按实际人数占高。2.4.10 显示零或一张头像卡，空区也可接收拖放。工作关闭或暂时离图的现任仍属于已指派区。
- **3 区可指派。** 右下常驻候选，排除已指派者。候选沿用原同图自由殖民者、调教员身份、工作条件及目标许可。可提交的候选包括工作已启用者和可随指派启用工作者，暂不可指派原因沿用现有判断。 [候选查询](../../Sexslavecraft/common/TrainerAssignmentUtility.cs) · [工作状态与指派事务](../../Sexslavecraft/common/SSCTrainerWorkUtility.cs)

2 区和 3 区按分区可用宽度排入头像卡，放满一行后自动换行。姓名常驻头像下方。悬停提示两行，第一行显示调教工作是否启用，第二行提示拖放操作。可指派头像提示拖入 2 区，符合同时启用条件时写明「指派并启用」。已指派头像提示拖回 3 区撤销。不可提交时用原受限原因替代操作提示。窄窗按 1、2、3 纵向排列，各区按剩余宽度减少列数。肖像复用原版缓存和现有可见区裁剪。 [肖像、提示及网格](../../Sexslavecraft/UI/SSCBondOverviewWidgets.cs)

### 拖放和提交

| 操作 | 结果 |
| --- | --- |
| 从 3 区拖到 2 区 | 松手时指派。已有调教员时，新人成功指派即自动替换前任。前任仍符合条件时回到 3 区 |
| 从 2 区拖回 3 区 | 松手时手动撤销当前指派。撤销后符合条件的角色进入候选区 |
| 拖回原区、拖到无效位置或取消 | 结束手势，保留原指派 |

点击肖像执行跳转。从独立把手按下时记录原受训者、拖动角色、来源区、原指派和窗口代次，达到移动阈值后开始拖动。有效内容区高亮，悬停预览操作结果，松手时用捕获的原业务请求提交。复用第 21.1 项的指派、启用和清除规则，并复查地图、Comp、人格、工作设置、实际主人及相关许可。替换由一次事务完成，新指派成功时前任才退出。失败时显示原原因并按实际保存值刷新，原事务只撤回仍由本次请求持有的新增工作值。成功后刷新 2、3 区和顶部摘要，地图单选与窗口编辑对象继续指向原受训者。 [共用菜单的现行规则](../../Sexslavecraft/UI/SSCTrainerAssignmentMenu.cs) · [第 21.1 项实现与验收](../Development/Completed/调教员指派与工作启用便捷操作实现与验证.md)

候选区在进入关系页、切角、提交后及受控刷新时生成，只读取得候选和工作状态。保留原菜单的同一套候选与事务，绘制使用轻量候选视图。当前保存只使用原 `selectedTrainer`，界面将其投影为零或一条。未来第 21 项可把真实多人列表接入 2 区，3 区承接新增，2 区拖出承接逐人撤销。人数上限、优先级、轮换、任务争用和旧档迁移由第 21 项单独定义。 [原保存字段](../../Sexslavecraft/Comps/Comp_Train.cs) · [第 21 项总体规划](未来内容开发规划.md#21-调教员指派系统重构与多调教员指派)

### 第二批实施顺序

1. **接通页签和关系视图。** 在 `Dialog_SSCTrainingManagement` 加入概况、关系的页状态及各自滚动位置。先保留原标签入口的概况默认页。当前角色的顶部摘要和关系页共用 `SSCBondOverviewSession.OpenDetails` 取得的本地快照，继续用 `SSCBondOverviewNavigation` 做点击定位。新窗口持有自己的关系视图，换人、换地图、组件替换或关闭时释放原视图，避免与旧详情争用全局会话的 `Details` 槽。把旧详情绘制中的头像、位置与状态展示提取成可复用部分。 [窗口入口](../../Sexslavecraft/UI/Dialog_SSCTrainingManagement.cs) · [原详情](../../Sexslavecraft/UI/Dialog_SSCBondOverview.cs)
2. **先跑通只读三区。** 主人页展示所属性奴，性奴页左侧大头像为主人，右上为已指派，右下为候选。已指派、候选和所属性奴统一按卡片最小宽度、间距及分区可用宽度计算列数。宽窗让已指派区保持可见，候选区独立滚动。窄窗三区纵排，后续拖放接入时处理视口边缘滚动，使两个落区都可达。现任取原始 `selectedTrainer`，候选用 `GetTrainerCandidates` 排除现任。候选成员按进入、换人、提交及受控刷新重取，工作状态独立于锁链刷新。悬浮第一行取 `SavedPriority` 表示工作开关，第二行结合 `GetState` 给出指派、指派并启用、撤销或受限原因。 [候选](../../Sexslavecraft/common/TrainerAssignmentUtility.cs) · [工作状态](../../Sexslavecraft/common/SSCTrainerWorkUtility.cs)
3. **接入窗口内拖放。** 在独立把手左键按下时捕获原角色、候选、来源区、原指派、窗口代次及 `SSCTrainerWorkUtility.Request`。只有实际拖动事件达到移动阈值才进入拖放，松手时按可见且经裁剪的落区提交一次。使用同一坐标空间计算滚动后的命中区。1.7.5005 的 `DragAndDropWidget` 在重绘时按控件索引跟踪拖动，候选数量变化会取消拖动，因此本页用窗口自己的手势状态承接滚动与动态列表。换人、换页、换图、关闭或取消时清理手势，在高亮内容区之外松手取消。
4. **复用事务并切换放大镜入口。** 3 → 2 调用原 `Request(source, candidate).TrySubmit`，2 → 3 用按下时构造的 `Request(source, null)`。原事务检查工作、人格、权限及指派，成功后从保存值刷新摘要与两区。清空前复用 `SSCRestrictionTrainerAssignment.CanAssign(source, null)`，被原规则锁定时显示限制原因。关系页可用后，把 `Gizmo_SSCBondOverview` 的放大镜动作按 `ITab_SexSlaveTraining.CanInspect` 分流到新窗口关系页或原详情窗口。原命令栏的定位、批选和现任启用入口继续使用既有逻辑。 [原放大镜](../../Sexslavecraft/UI/Gizmo_SSCBondOverview.cs) · [指派限制](../../Sexslavecraft/common/Restrictions/SSCRestrictionTrainerAssignment.cs)

第二批重点核对两个界面边界。其一是滚动、裁剪和窗外松手，确保只有可见落区接收拖放。其二是从 A 切到 B 再切回 A、指派变化或人格替换后，旧手势不能写入当前角色。机制复用 `TrainerIdentity` 和 `BondOverviewUI` 的现有覆盖，另做目标构建下的真实鼠标拖放及窄窗换行检查。
