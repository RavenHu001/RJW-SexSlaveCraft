## 3 数据与视图会话

### 3.1 会话的拥有者

将现有 SSCBondRelationGameComponent 改为 partial，由新分文件持有 SSCBondOverviewSession，并在 GameComponentUpdate 中调用其轻量更新。既有 FinalizeInit 的绑定维护保持独立，打开界面不调用该维护入口；新增字段不进入 ExposeData。构造会话时不扫描世界。

会话最多保留命令栏与详情窗口两个使用位置，不按每个见过的 Pawn 建立永久缓存。两者的 Game、Source、ViewedMap 相同时共享同一份快照和刷新时间；来源不同才保留两份。窗口关闭、命令栏停止访问和失效来源分别退订，最后一个使用者退出即清除该份快照及行、提示和待执行操作。

两侧 ViewedMap 统一取当前 Find.CurrentMap；地图切换只登记快照刷新以更新排序，窗口 Source 仍固定。来源、地图或快照代次变化时同步废弃旧命中动作；会话不能把 A 的上一份快照当成刚切换到的 B 来绘制。

Gizmo 是会话的展示对象，不负责拥有独立世界快照。不能把快照塞进每个角色的训练组件，导致所有曾被选中过的角色长期持有其他 Pawn；也不设置静态的当前 Game／Pawn／Dialog 字段。

以下为本批实现契约；当前源码和验证入口见第 7、8 节及第二批记录。

| 对象或入口 | 输入与输出 | 限制 |

文字按实际可见行、主人文字或悬停惰性生成，每份展示最多缓存 64 行；全文与截断结果分开，截断以文字／宽度／字体／UI 缩放区分、每视图最多 256 项。快照、语言、地图、来源或释放时失效，保留完整候选快照与全文提示。

每次 GUI 事件先取得一份展示状态局部引用；这次事件的计数、头像、行位置、提示和命中全部使用它。刷新在 Update 中替换整体快照，不在列表循环中重建或修改行集合。

### 3.3 刷新参数与空卡片探测

现行参数如下，第二批性能优化将原 0.25 秒全局门槛及可绕过自动退避的优先请求收紧为统一预算；后续仍须用真实存档测量调整。

| 触发 | 当前处理 |
| --- | --- |
| 新单选来源或新窗口 | 登记待刷新，下一个全局预算及本视图截止均允许的 Update 构建；卡片与窗口同源时合并 |
| 已有可显示概览 | 每 2 秒真实时间自动刷新一次 |
| 有训练组件，但上次查询无身份、无关系、无异常锁链 | 不显示空卡片；保持单选且命令栏仍在访问时，每 5 秒探测一次 |
| 手动刷新、发现旧行失效 | 合并为等待请求；遵守全局与本视图截止，在 Update 执行，不在当前 GUI 事件改布局 |
| 不同来源快速切换或连续手动刷新 | 全会话从上次查询完成后至少间隔 2 秒，关闭重开不重置预算；每帧最多一次 Build，丢弃过时来源请求 |
| 一次查询较慢 | 全局预算取 `min(30 秒, max(2 秒, 10 × 本次耗时))`，本视图再取基础间隔与预算的较大值；所有请求遵守退避，查询仍同步执行 |
| 无合格单选命令栏访问且无打开窗口 | 停止完整查询；短暂心跳宽限后清除卡片使用位置 |
| 加载中、非 Playing、跨 Game、销毁／丢弃来源 | 不 Build、不导航，清除失效视图或等待就绪 |

空卡片探测不能只看身份、缰绳数量或自身锁链：身份未选择且缰绳缺失的主人，仍可能被别人的锁链指向。要在玩家保持单选期间自动发现这种关系，就需要低频完整查询。上述 5 秒探测明确包含“选中普通训练组件角色但没有可见卡片”的成本；无选中／无窗口的后台不探测。不能同时承诺坏索引自动发现与这种单选状态下零扫描。

命令栏访问以组件枚举的轻量心跳为依据，连续两个完整帧没有访问便释放该使用位置；截图模式、离开地图命令栏、多选、切换来源均停止旧来源续期。是否显示卡片由查询结果决定，不能以卡片可见性反过来阻止首次探测。窗口使用位置持续到 PostClose；来源死亡仍展示并标注，销毁、丢弃或跨存档才停止操作。

时钟回退时重设截止时间；到期按当前时间安排下一次，不补跑错过的多轮。两个不同来源均到期时轮换，持续手动请求也不能长期饿死另一来源。查询异常转为可重试状态、清除可操作旧行并限频报告，不在每个 GUI 事件重复报错。

## 4 单选关系 Gizmo

### 4.1 接入和显示条件

在 CompGetGizmosExtra 的 Pawn 检查之后、Prefs.DevMode 门槛之前调用新分文件入口。要求当前游戏就绪、恰好单选来源本人、来源存活且在当前地图生成、已有 CompSexSlaveTraining。除此之外不增加研究、阵营、SSC 身份许可或原版囚犯／奴隶状态门槛。

来源有主人／性奴身份，或快照存在任一方向的有效关系时显示卡片；自身存在无效锁链时也显示异常状态。身份未选择但确有绑定必须可见。只有指定调教员、没有 SSC 身份与实际绑定时不据此显示主从卡片。首次查询未完成时，有明确 SSC 身份或锁链的来源可显示等待文案，其他来源等查询结论后决定。

`GroupsWith` 返回 false；不继承其他 Gizmo 的组操作，不做 Shift 多选、拖拽或批量命令。

### 4.2 初始布局

卡片建议宽 300、高 75，宽度上限遵守 maxWidth。上下内边距 6，标题约 18 高，预览区约 40 高；头像绘制与请求固定 40×40，最多五个位置，数量增加只显示更多计数，不压缩头像。

| 数据形态 | 标题和预览 |
| --- | --- |
| 有从属 | 存活／总绑定数，预览若干从属，保留“查看全部”入口 |
| 有实际主人 | 主人姓名、生命／位置提示与一个主人头像，详情入口始终可达 |
| 两个方向并存 | 同一卡片分别标明主人与从属，为主人保留一个头像位置，从属使用剩余位置 |
| 只有身份、无关系 | 按身份显示“未绑定主人”或“暂无绑定性奴”，仍可查看详情 |
| 坏锁链或查询未就绪 | 明确异常或等待状态，不伪造主人头像，不提供旧定位操作 |

不足以容纳预览时先减少从属头像数量，再改为文字摘要和详情入口；不得让固定头像越界或让按钮覆盖头像。头像死亡标记、方向和位置均取同一行；完整姓名、阶段、特化及位置放在提示中，卡片短文字可截断。

### 4.3 输入与绘制

卡片用不重叠的头像区和详情区命中。GizmoOnGUI 在左键 mouseDown、GUI.enabled 且操作未禁用时只记录待处理动作，并返回含该事件的 Interacted；ProcessInput 重新确认仍然单选来源本人、来源符合卡片条件，定位时再复查确切行，执行一次后 finally 清空动作。由原版网格消耗事件，不同时在头像里直接跳转再返回 Interacted。右键不冒充左键，悬停不改变选中。

每个可见行每事件只做一次 IsCurrent 并复用结果。失效时停止头像导航和提示操作，登记刷新；计数仍属于旧快照并显示等待刷新，避免临时重算一部分造成头像和计数不一致。IsCurrent 核对关系，不证明位置、存活状态或显示文字已经更新。

只在 repaint 获取肖像；卡片 40×40、窗口 48×48 两档均初用 Rot4.South、默认 cameraOffset 和 cameraZoom=1，其他参数保持固定，待实机确认取景后统一调整。恢复 GUI.color、GUI.enabled、Text.Font、Text.Anchor 和 Text.WordWrap。仅悬停时解析提示及当前地图的安全高亮目标，不为每个头像每事件遍历持有链或重建飞船索引。

## 5 完整窗口

窗口固定打开时的 Source，不随着选中目标偷偷改变；标题持续显示来源姓名。优先尺寸 880×640，并按 UI.screenWidth／Height 留出边距限制。保留关闭、手动刷新、状态提示和滚动区；forcePause=false，不改变玩家原有暂停选择。

内容依次为实际主人、指定调教员文字、存活从属、死亡从属。主人的独立行使用快照 Master，不放入 Slaves 计数；无主人、坏目标和未就绪分别显示。指定调教员使用原始引用及 None／Active／Inactive／InvalidTarget／Unavailable 状态，不套用绑定定位路径。

从属行建议固定 64 高：左侧 48×48 肖像，中部姓名、阶段 0～4、特化与位置，右侧定位按钮。阶段直接读 ChainStage，不复制阈值；特化复用 Strings 的既有名称，区分 null 与 None，不调用 ITab 的维护或选项初始化。死亡以文字和图形共同标注；长姓名提供完整提示。

宽度较小时将中间信息合为两行，仍保持固定行高；长位置内容截断并提供提示，基本操作不依赖横向滚动。显示文本、组标题及各组起始偏移在换快照／换语言时生成，绘制不对全列表反复排序或做 Where／ToList。

滚动区先由总行数计算完整高度，再用 scroll.y、viewport.height 和固定行高直接算出可见索引范围，只处理该范围及边缘一行。主人和分组标题占用高度也需计入偏移。不能先循环所有行再在 DrawRow 内判断是否可见；离屏行不请求肖像、不做 IsCurrent 或 CanJump。

刷新尽量保留滚动位置并按新内容高度钳制，不在每次自动刷新时回到顶部。窗口失效来源显示说明并停止旧操作；跨 Game 在 WindowUpdate 或下一次 GUI 入口关闭并退订。PostClose 清理快照使用位置、滚动／提示引用和待执行行。

窗口按钮沿用 SSCUIWidgets 的禁用表现与输入封锁；行内只记录一个待导航动作，在本次列表绘制结束后执行，避免关闭窗口或切图打断行遍历。刷新按钮也只登记请求，不在按钮命中的同一事件替换行列表。

## 6 导航和悬停

### 6.1 点击的完整过程

所有卡片头像与窗口定位按钮进入同一个 TryNavigate，不分别实现两套跳转规则：

1. 调用 IsCurrent，确认当前 Game、来源、两端有效性、行属于此快照及当前实际锁链；失败只登记刷新并给出原因。
2. 用已有 World 上下文重新解析这一行 Pawn 的当前位置：Rent → AddLocationRequest → IndexShipLocations → GetLocation → Dispose。这里不收集全世界候选，不重建整个来源名单，也不复用旧位置事实。
3. 将新位置转为最终 GlobalTargetInfo，拒绝 Unknown／环／失效目标；不把带循环的未生成 Pawn 直接交给原版持有链调整。
4. 原版 CanJump 再检查目标可达性；必要时在分派前再确认行仍有效。此时仍不写任何绑定数据。
5. 地图目标检查 def.selectable，世界对象检查 SelectableNow；可选时调用 TryJumpAndSelect，只能定位时调用 TryJump。记录“已分派”，不能将 void API 的调用包装成已观察到的选中成功。
6. 已分派后关闭详情窗口；若失败则保留窗口并显示原因。卡片跳转后由新的单选来源重新建立展示状态。

离图且需要飞船字典的点击最多为这一目标建立一次稀疏索引；地图／容器／世界持有链已能定位时不扫飞船。该成本只发生在实际点击，不能挪到每行绘制、按钮可用性检查或悬停中。

### 6.2 目标转换

| 新解析的位置事实 | 向原版传入的最终目标 | 行为与说明 |
| --- | --- | --- |
| Map | 当前有效且已生成的 Subject | 可选时定位并选中，异图交给原版切换 |
| MapContainer | 当前已生成的 Container | 定位容器；不承诺选中内部 Pawn |
| Caravan／Transport／WorldObject | 当前可用的 WorldObject | CanJump 通过才定位；没有原版可跳转目标的飞船仍禁用 |
| WorldTile | 当前有效的 Subject.Tile | 仅定位世界格，不显示“选中角色” |
| Unknown、持有环、尸体／容器失效 | 无 | 保留关系与失败原因，不跳到旧船或旧容器 |

死亡行重新取得有效 Corpse；复活后重新使用 Pawn。不能一直复用旧快照的 Subject。普通导航能力不因目标死亡而一概关闭。

按钮预览可依据快照位置和最终目标的轻量可用性检查显示预计操作，但不能把它当作点击授权。目标刚移动时允许等待下一次刷新恢复按钮；旧按钮仍可点击时也必须执行上述实时解析。失败原因至少区分关系变化、来源失效、位置未知、目标不可跳转和游戏未就绪。

悬停只高亮当前地图中的可确认 Subject／Container；先检查关系与当前已生成状态，必要时只做有防环的局部持有链检查。不给未知／离图对象传原始 Pawn 做原版自动调整，不在悬停时扫描飞船。旧快照的地图或容器关系已变化时跳过高亮并安排刷新。
