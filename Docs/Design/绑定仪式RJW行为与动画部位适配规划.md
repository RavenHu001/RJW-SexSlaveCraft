# 绑定仪式的 RJW 行为与动画部位适配规划

**状态：2026-11-22 完成 1.7 实现和相关自动回归，待实机验收。** 对应[总体规划第 23.1 项](未来内容开发规划.md#ssc-training-anatomy-compatibility)。首批适用于 RimWorld 1.7 双人绑定仪式。日常调教、自我调教及 1.6／Common 沿各自范围维护。

本机 RimWorld 1.7.5014、RJW 6.2.2 的女女组合实测完成了现有六阶段。第 3 阶段启动动画，其余五个阶段未找到匹配动画。第 6 阶段保留 `Sex_Vaginal` 进入 RJW 流程，RJW Menstruation 按交互类型处理体液，日志记录了 33 条 `0 fluid` 警告。这是现行实现的排查依据。 [阶段映射及空接触路径](../../Sexslavecraft/common/RitualTrainingUtility.cs)

## 六阶段筛选

**性奴的目标部位参与是自动筛选的硬条件，调教员的阴部参与是排序偏好。** SSC 保留调教员主持、性奴受训的仪式角色及原有准入检查。每阶段维护性奴侧的部位规则，候选动作由 RJW 提供。调教员以任何能通过 RJW 校验并参与本次交互的部位配合。自动筛选无结果时，强制采用该阶段原有的固定动作保底。

| 阶段 | 性奴侧目标部位 | 可用于确认参与的结果 | 原有保底动作 |
| --- | --- | --- | --- |
| 1 手部 | `Hand` | 候选明确选用了性奴的手。若有配对，从对应端点确认手的归属。 | `Sex_Handjob` |
| 2 足部 | `Foot` | 候选明确选用了性奴的脚。调教员侧按候选本身的要求匹配。 | `Sex_Footjob` |
| 3 口部 | `Mouth`、`Tongue` 或交互明确支持的 `Beak` | 性奴口部出现在其参与部位或明确的接触端点中。`Sixtynine` 有时只返回生殖器参与部位，阶段仍须取得口部参与证据。 | `Sex_Sixtynine` |
| 4 胸部 | `Breasts` | 候选明确选用了性奴的胸部，部位可用性及交互的严重度门槛由 RJW 判定。 | `Sex_Breastjob` |
| 5 肛部 | `Anus` | 确认候选用到性奴的肛部。若以插入配对证明参与，核对来源是调教员、接纳端是性奴的肛部。经 RJW 解析的手或舌配合也可入选。 | `Sex_Anal` |
| 6 阴部 | `Vagina` | 确认候选用到性奴的 `Vagina`。双方阴部接触、调教员用手或舌配合均可入选。若以插入配对证明参与，核对接纳端属于性奴。 | `Sex_Vaginal` |

### 选取与部位归属

1. 在阶段启动前用本场双方及交互情境调用 `SexInteractionFinder.FindInteractions`。每条 `SexInteractionResolved` 提供一个具体交互及双方的一组可用部位。同一 Def 可能有多个部位组合。先过滤每条结果，再进行排序和选取。
2. 用 `Initiator`、`Recipient`、部位的 `Owner` 和 `Family` 核对性奴侧是否参与了目标部位。有 `Penetrations` 时按各端点的实际归属和方向判断。没有插入的候选可由双方明确的参与部位支持。多部位候选的目标参与无法从解析结果确认时，继续检查下一项。
3. 在合格候选中，优先选择调教员的阴部也实际参与的组合。调教员侧使用其他部位的合格组合继续可选。阴部偏好按实际部位类别判断，RJW 的通用 `CouldBePenetrator()` 也接受手，因此仅这个判定不足以认定阴部参与。同优先级取 RJW 返回的首个候选。
4. 采用选中的具体 Def 和同一份 `resolved`，保留交互的 `Reverse` 标记及其 RJW 语义。SSC 的筛选依据是本场角色和部位归属。例如 `Sex_Fingering` 用到性奴的手，可用于手部阶段。其反向版本用到性奴的 `Vagina`，可用于阴部阶段。两者都继续遵守本场许可。 [现有交互字段校验](../../Sexslavecraft/common/RJWSexPropsUtility.cs) · [部位和接触归属](../../Sexslavecraft/common/SSCOrdinarySexPartsUtility.cs)
5. 没有通过阶段规则的候选时，复用 `RitualTrainingUtility.GetPhaseData` 的原有指定动作映射，以该 Def 强制启动保底。用本场双方解析这个固定动作。解析成功时使用实际结果，解析不到时沿用 `allowEmptyParts` 记录当前 Def、当前双方及空接触。保底仍须通过仪式原有许可和归属复查，缺少固定 Def 或初始化失败沿原失败清理流程处理。 [原有阶段保底映射](../../Sexslavecraft/common/RitualTrainingUtility.cs)

## 阶段执行与动画

**优先保证有效仪式完整跑完六阶段。** 动画由现有框架随 RJW 场景自行匹配和播放。1.7 绑定仪式移除 SSC 的手动动画回退调用。缺少匹配动画时，RJW 动作按原流程继续，SSC 按阶段时钟和仪式归属推进。动画状态不参与动作筛选、暂停、重新选取或完成判定。 [当前手动回退调用点](../../Sexslavecraft/JobDriver/JobDriver_RitualTraining.cs)

| 匹配结果 | 推进方式 |
| --- | --- |
| 解析出实际部位 | 执行自动选中或固定保底的 RJW 交互，沿场景时钟推进。阶段完成后按实际参与部位记录凭据。 |
| 固定保底动作没有解析出部位 | 保留原动作 Def，完成场景准备和清理，由 SSC 按阶段基本时长推进。空接触期间跳过双方依赖接触的 `SexTick` 和 `ProcessSex` 路径，防止仅凭 Def 触发体液或受孕处理。阶段结束记录无接触。 |

阶段切换后按当前身体重新筛选。已开始阶段沿用已选交互及阶段时钟，读档恢复本场角色、所选部位或保底空接触状态及相应进度。仍由同一仪式 `Lord` 及当前阶段 Job 认领阶段推进和完成资格。许可失效、角色变化、取消或中断沿原有清理流程处理。旧档正在执行的阶段缺部位凭据，或原身体引用失效时，保留阶段进度并按空接触完成，后续阶段照常重新筛选。 [阶段 Job 与恢复](../../Sexslavecraft/JobDriver/JobDriver_RitualTraining.cs) · [仪式生命周期](../../Sexslavecraft/common/BindingRitualStateUtility.cs)

## 开发与整场结算

- **普通部位开发。** 每个正常结束的阶段按实际接触记录性奴侧的目标部位及原身体引用。在整场一次性结算中，用已完成阶段凭据替代现有的六类固定发放。按阶段目标查对应部位经验，保持原有数值、研究门槛及上限。同一阶段的同一身体记录只领一次。固定保底也按同样的部位证据结算。空接触或目标部位未参与时不发该阶段经验，动画缺失不影响已确认的部位经验。 [现行整场发放](../../Sexslavecraft/common/ConditioningUtility.cs) · [精确部位经验入口](../../Sexslavecraft/common/TrainingExpUtility.cs)
- **专门部位开发。** 胃部继续按已有的严格口部接触凭据发放。子宫开发随合格的阴部阶段结算，要求性奴的目标阴部确实参与且满足原有成长资格。 [口部接触证据](../../Sexslavecraft/Comps/Comp_Train.StomachDevelopment.cs) · [现有子宫与胃部结算](../../Sexslavecraft/Ritual/RitualOutcomeEffectWorker_SSCBinding.cs)
- **整场奖励。** 完成六阶段后按现有规则领取一次整场结算资格，绑定、关系、观礼及记忆等继续走原有流程。部位奖励读取有效阶段凭据。 [整场资格与结算](../../Sexslavecraft/common/BindingRitualStateUtility.cs)

## 验收范围

- 对照双方均有、仅一方有及双方均无可用阴茎的组合。验证性奴目标部位缺失或被封锁时该候选被排除，调教员阴部参与时优先，只有手或舌等配合时仍能选中合格动作。覆盖同类型正反向动作的部位归属差异。
- 用六阶段各一个明确目标案例核对选中的部位与开发记录，重点检查 `Fingering` 在手部和阴部阶段的不同归属、`Sixtynine` 口部证据不足和双方阴部接触的情况。
- 验证自动筛选无结果时采用本阶段原有的固定 Def，并分别检验保底解析到部位和保底为空的行为。覆盖有动画与无动画的整场仪式，核对六阶段均能推进、接收任务正常清理、整场只结算一次及空接触零部位经验。用无法解析第 6 阶段部位的组合验证 `Sex_Vaginal` 保底仍可推进，空接触期间不触发 `0 fluid` 警告。
- 验证阶段中断、换阶段及读档恢复。核对已完成的凭据、本场角色和阶段进度，以及胃部、子宫和整场奖励各自的资格。
