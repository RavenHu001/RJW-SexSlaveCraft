## 3. 推荐接入方案，尚待采用

1. 为同一技能分派独立自指任务，不能让角色同时扮演现有双人场景的发起者和受方。首版直接完成建孕、不增加读条／自慰为前轮建议，尚未确认。
2. 自指使用现有RJW类人妊娠，比在原版Pregnant→Labor→LaborPushing之间传递新标识更贴合旧分娩入口；对他人分支保持原后端。
3. 只为这次原妊娠保存一个克隆路线标识，建议轻量Comp、缺省false、无Tick。也可在原子宫妊娠Comp追加独立字段，不能混用倍率枚举或RJW的is_hacked等字段。不新增SSC妊娠Hediff、遗传快照或孕中管理。
4. 直接复用原RJW妊娠Initialize和已有子宫倍率；建孕确认完整落地后才执行成功冷却。异常回收仅限本次新建实例和其待产幼体。
5. 将旧创建服务的兔资格与公共分身创建分开；沿用共享、成长、成熟及低产机制，不原样照搬失败回普通出生。
6. 来源列表建议使用不参与人格载荷的身体载体，来源链接仍指向原身体；避免随终极成果迁移、重复来源列表或重复计算数量。具体载体与旧兔并存方式待机制检查后确定。

## 4. 身份、印记及成熟衔接

新分身最终必须清来源印记→完成Slave身份→授予淫欲之奴，复用已有[印记服务](../../Sexslavecraft/common/SSCImprintUtility.cs)；永久锁直接从Hediff读取。旧流程只复制来源身份并把主人改成未选择，不能代替这项初始化。

旧ShouldKeepSscHediff宽泛保留SSC前缀，初生和成熟均会带入来源印记。成熟补复制必须排除全部来源印记，保护分身自己的方向；还需明确排除绑定、个人设置和冷却等独立数据，不靠Hediff互斥兜底。身体快速成长和成熟赋龄建议在写入前限至25岁，不先超龄再等日检查。

普通胎儿性别／物种设置建议不应用于克隆，沿旧Duplicate复制本体性别、物种与基因；固定性奴印记已确定，其余设置处理仍属建议。已有特化成果、技能、记忆和SSC健康状态以旧机制为调查基线，不能把“成熟补健康状态”误记为再次完整人格覆盖。

绑定与分身来源关系分别处理。前轮建议本体有有效主人时仅为新分身建立同一主人双向绑定，无主则保持无主性奴，不带入仪式奖励；成熟不再改绑。此方案尚未确认，不能原样依赖复制出的空链，也不能解绑／重绑本体或改动人格切换绑定规则。

## 6. 建议开发顺序与最小验收

建议先核对／整理旧创建服务，再实现新生身份与印记、来源保存及成熟过滤，然后接自指建孕／出生替换和共享冷却，最后补显示与联测。限制／浪漫新生默认、PNA身体排除和原能力默认必须沿用现行契约，不为克隆重做这些系统。

最小验收候选如下，待实现范围确认后采用现有宿主覆盖真实边界，不穷举全部旧参数：

- 自指成功建立原有妊娠并启动共享冷却；建孕失败不扣冷却，孕期／临产仍禁用。
- 普通妊娠及对他人技能不被替换；分娩没有额外普通婴儿、重复分身或残留预生成幼体。
- 新生唯一性奴态印记与身份锁，主人资格／成长清理；本体印记和绑定保持。
- 成熟与存读档不改变分身身份、个体设置和后来绑定，不重复成熟或复制来源冷却。
- 数量、禁止再分身、三天成长／25岁衔接、共享和低效PNA按已确认规则运行。
- 来源死亡、离图、失效与创建失败按届时确定的有限规则处理，不扩成通用生命周期框架。
- 分身仍禁止人格排泄；实际克隆放置如需接出生培养，仅成功后旁路Observe一次，不按进入GiveBirth就发放。终极施法者本身不继续获得普通培养进度。

以上为后续阶段准备材料，不计作已实现、已验收或新测试结果；主体完成状态不受这些待定建议影响。
