最新规则修订：限制只在实际绑定主人后生效，未绑定的性奴身份本身不激活；指定非主人调教员时同步保存调教授权，普通互动没有指派豁免。已实施的职责整理和验证见[绑定门槛与职责整理](../Development/新限制系统绑定门槛与职责整理.md)。科技赋予条件仅为未来方向，本轮未加入。

本文统一定义开发目标和行为约定；代码证据、接入注意事项及详细验证见[代码复盘与实施参考](新限制系统设计与代码复盘.md)。出厂初始值、配置生命周期及界面交互细节沿用委托分析形成的方案，不将这些分析结论表述为已经实现的功能。

目标是将所有性爱/调教行为的 SSC 许可判定统一到一个入口，让每个适用角色拥有一份独立配置，按主动、被动、调教三类管理。入口确认实际主人向自己的性奴发起行为后立即返回允许；其余行为再按条目解析特化、装备与个体配置。不保留绕过入口的放行路径或额外保护拦截。分批接管时停用对应旧判定，验证后清理旧代码；旧字段仅保留迁移用途。本轮保留 2.3.0 已实现的性奴调教员身份和同床功能；不扩展自我调教、无主性奴玩法、原版奴隶调教工作范围，或整体重做身份与绑定。未来将调教员资格关联新特化的方向另行开发。

## 1. 规则与默认值

下表初始值由现行默认保护推导，2.3.0 未改变相关旧设置。旧存档按自身旧值迁移，不直接套用出厂值。

| 分类 | 规则 | 可选值 | 普通初始值 | 公交车覆盖 |
| --- | --- | --- | --- | --- |
| 主动 | 单人自慰 | 允许 / 禁止 | 禁止 | 无 |
| 主动 | 发起双人自愿行为 | 禁止；允许时选仅限主人 / 不限对象 | 允许，仅限主人 | 无 |
| 主动 | 发起强制行为 | 允许 / 禁止 | 禁止 | 无 |
| 被动 | 接受非主人自愿行为 | 允许 / 禁止 | 禁止 | 默认允许；启用强制时强制允许 |
| 被动 | 接受非主人强制行为 | 允许 / 禁止 | 禁止 | 默认允许；启用强制时强制允许 |
| 调教 | 接受非主人调教 | 允许 / 禁止 | 禁止 | 无 |

- 单人、普通双人、日常调教、仪式调教及事件/兼容任务均调用同一许可入口。入口先确认实际发起方向和绑定关系，命中主人规则立即放行，其余行为再识别用途、适用角色并解析条目。各任务适配器负责提供上下文和执行结果，不自行增加许可放行或拒绝分支。
- 未命中主人直接放行规则的普通双人行为，在统一入口内分别检查发起方主动许可和接收方被动许可；“不限对象”仅解除发起方的对象限制。被动表示接收方身份，不等于强制。双人分类沿用 RJW，互相自慰已包括在内，无需单列处理。
- **实际绑定主人向自己的性奴发起的任何性爱/调教行为，统一入口都直接返回允许，不得被本限制系统拒绝。** 确认这对绑定关系后立即结束许可判定，不再检查双方主动、被动或调教条目，也不允许装备、特化、个体设置、空指派或另有指定调教员推翻结果。“最高许可”在这里就是整次行为直接通过，不是逐条竞争的覆盖值。反向行为、第三人和仅具主人身份者不获得该直接放行。能力、研究、可达性等原有任务执行条件继续保留。
- 玩家命令与自主 AI 调用同一入口、使用相同许可。即时下达、排班及预约机制仍按原有调度处理。
- 未命中主人直接放行规则的调教，由同一入口按独立的调教条目判断，不查询双方普通主动/被动条目；日常调教与仪式调教均如此。人格排泄专用任务本轮按普通双人非强制许可处理。
- 现有 SSC 防护装备转换为条目强制来源：穿戴时将“接受非主人强制行为”的有效值强制为“禁止”。装备只声明其影响的条目，不在许可结果之外再次拦截；本轮现有装备不影响自慰、普通非强制行为或调教条目。

## 2. 生效规则与关系边界

### 统一入口、覆盖来源与全局控制

| 设置 | 作用 |
| --- | --- |
| 是否启用性奴行为限制规则 | 原保护总开关改名，初始开启。关闭时由统一入口返回允许（限制停用），暂停行为限制及装备、特化的条目强制；保留并允许编辑个体配置。 |
| 是否启用特化强制规则 | Mod 总设置中的全局开关，初始开启；实时决定是否启用特化文件的条目强制值，不控制装备强制，不改写角色保存值。 |
| 行为规则默认配置 | 为之后首次激活的角色提供初始模板；单纯修改模板不影响已有配置。 |

每个角色只有一份配置。特化只在 Mod 文件中声明少量条目的默认值和强制值，未声明项不受影响；本轮只有公交车的两项被动许可。装备在文件中声明受影响条目的强制值，由同一解析机制收集；未声明项不受影响，也不写入角色保存值。不提供角色级或逐特化强制开关，也不为每个特化或装备建立一份角色配置表。

统一入口首先判断是否为实际主人向自己的性奴发起行为：是则直接返回允许，后续条目没有否决机会。该规则属于统一系统的最高判定，不进入下面的条目覆盖排序。

系统启用且未命中主人直接放行规则时，对本次行为所需条目按以下优先级解析；高优先级来源只覆盖其声明的条目，不连带放行其他条目或其他参与者：

| 优先级（高 → 低） | 来源与作用 |
| --- | --- |
| 1 | 当前穿戴装备的条目强制值：本轮现有防护装备强制禁止接受非主人强制行为。 |
| 2 | 当前适用特化的条目强制值：仅在特化强制开关开启时参与。 |
| 3 | 角色保存值：没有更高优先级覆盖时使用。 |

同层多个来源覆盖同一条目时取较严格值（禁止 > 仅限主人 > 允许），同值按 defName 稳定选择来源；该顺序只用于条目合成，不参与主人已经直接放行的请求。

异常数据按统一口径处理：角色保存配置中任一条目损坏，会拒绝本次需要读取该配置的请求；主人直接放行和总开关关闭仍优先。特化/装备文件覆盖只校验本次所需条目；某层出现非法值时保留具体错误来源并停止合成，不由后续正常来源覆盖诊断。未知版本及非法值不在查询中自动重置。

装备优先于特化，保持原规划中防护装备与公交车强制允许冲突时的保护结果，但通过条目合成完成。默认模板及特化默认只在规定事件写入保存值，不是运行时额外覆盖层。关闭特化强制后，仍有装备覆盖的条目继续使用装备值，其余使用保存值；脱下装备后重新解析剩余来源，均不重写保存值。两个全局开关均不属于角色默认模板。

主人直接放行只针对当前这对有向绑定关系，不把任一 Pawn 的所有配置永久改为允许。统一入口记录“实际主人直接放行”的原因，调用方必须接受该许可结果；不在入口外重复添加主人判定，不保留公交车整次放行、玩家命令豁免、兼容白名单或装备后置否决。

总开关不取消调教员身份、唯一工作指派、仪式关系资格或正常任务条件，也不控制同床许可。配置变化只影响尚未开始的请求；已经开始的当前场景或仪式阶段正常收尾，新加入者和下一阶段重新检查。

### 调教者与仪式

- 系统启用且已有有效绑定时，禁止非主人调教则指定者协调为实际主人；玩家可以直接选择符合资质的非主人，同时开启调教许可。候选检查不写入，实际指派才一起提交；装备或特化强制禁止时仍不能指派。首次绑定前保留候选主人指定和准备流程，由统一入口识别该用途；候选人不获得实际主人关系的最高许可。
- 沿用 **2.3.0 的有效调教员身份及候选过滤**：包含已开启调教员身份的 SSC 性奴，保留自由殖民者、非自身、工作及身体条件，不因新许可放宽资格。
- 自动日常工作只分配给唯一指定者；没有指定者不开放任意非主人接替。实际主人经合法入口发起时，不得因指定了别人而被许可检查拒绝。
- 指定者身份停用或临时不能工作时保留指派，禁止其他人自动补位；失效引用才清理。强制改回主人后再开放非主人，等待玩家改选，不恢复隐藏的历史人选。总开关关闭时解除限制带来的选择锁定，保留已有指派与资格筛选；重新开启后再按许可协调。
- **实际主人和当前有效指定调教者均有仪式主持关系资格。** 空指派或第三方调教员停用不能排除实际主人；非主人仍须满足统一入口中的调教条目许可。主持资格不授予主人身份、不替换已有绑定，也不代替首次建绑对合法主人的要求。
- 同床继续采用 2.3.0 的主人及有效指定调教员关系。新规则实际改变指定者时，由现有关系接口反映变化；不直接用普通行为或调教许可禁止同床，不强制删除已有床位或睡眠记忆。

## 3. 配置何时建立或改变

适用门槛为实际主人绑定，兼容已有旧锁链关系；仅有 SSC 性奴身份、指定调教员、恶堕值、组件、装备、特化或研究解锁均不激活限制。未绑定已有配置和旧迁移输入保留，实际绑定后再启用。首次绑定准备仍保留正常资格检查，不提前启用个人条目；科技门槛留待后续明确。

| 事件 | 配置处理 |
| --- | --- |
| 新角色首次实际绑定 | 立即复制当时的默认模板并保存；不等第一次行为、打开界面或总开关开启。 |
| 旧版本升级 | 按旧全局值、个体例外和特化状态一次性映射；之后不再从旧字段覆盖。旧档原本不适用、升级后才首次适用的角色采用新默认。 |
| 编辑全局默认 | 已激活角色保持原配置。 |
| 为所有性奴应用默认配置 | 重设当前存档内全部适用角色，包括其他地图及离图对象：普通默认 → 当前特化默认，再解析当前装备与特化强制值。不把强制结果写入保存值，不修改两个全局开关、身份、绑定或进度；无存档时不可执行。 |
| 穿上、脱下或更换保护装备 | 更新对应条目的强制来源并重新解析有效值；不修改保存值、不重新应用默认，不改变已经开始的当前场景或仪式阶段。 |
| 人格提取或植入 | 配置属于当前 Pawn，不随人格物品转移；接收者已有配置则保留，未初始化者在恢复完成且首次适用时初始化。 |
| 新克隆 / 已存在的旧克隆 | 新克隆独立初始化，不复制来源的配置及初始化状态；旧克隆从自身旧数据迁移。 |
| 解绑、换主或合法身份变化 | 保留配置，按实际关系和适用状态重新判断；继续遵守 2.3.0 已绑定角色身份锁定，不提供绕过锁定的入口。 |

批量操作应说明会覆盖个体选择，并报告处理结果。总开关关闭时只更新配置，不执行强制改回主人的指派副作用；重新开启时统一协调。

公交车默认与强制按以下事件处理；未命中主人直接放行规则时，其强制值与装备按条目优先级解析：

| 事件 | 两项被动许可的处理 |
| --- | --- |
| 当前方向为公交车，或拥有整理后的有效基础/终极公交车状态 | 适用公交车覆盖；仅有历史进度不算。保留终极状态切换方向，仍然适用。 |
| 首次初始化时已有公交车，或已有配置后首次真正取得公交车 | 写入两项特化默认一次；强制关闭时也应用这次默认。 |
| 重复选择、认领、升级终极、读档、离开后重新取得或切换全局开关 | 不再次写默认；强制按当前状态生效。 |
| 完全失去公交车适用条件 | 停止强制，保留保存值，不自动恢复普通默认或取得前的值。 |
| 显式批量应用默认 | 重新应用当前适用的特化默认。 |
| 旧角色迁移、人格植入到已有配置的接收者 | 保留迁移结果或接收者原值，当前适用公交车则记为默认已处理，避免状态恢复再覆盖一次。 |

## 4. 设置界面

以下界面已在阶段 2 实现，维护者已确认界面有效，随后按反馈改为右侧展开以保持主 ITab 位置；右侧位置调整也已获确认：Mod 设置支持默认模板、特化开关与全存档批量应用；调教页提供右侧展开规则栏。原独立窗口继续用于双方许可测试，编辑控件与侧栏共用。

- Mod 设置提供两个全局开关、三类默认配置，以及“为所有性奴应用默认配置”操作。
- 个体控制放在现有调教 ITab **右侧可展开子窗口**中，展开与收起均保持主 ITab 的位置和宽度，按三类排列；以左侧文字、右侧原生绿勾/红叉编辑个人保存值。自愿发起下属一对对象单选，关闭时置灰并保存偏好。装备/特化强制用短标记，当前有效值和具体来源放入悬停提示；仅总限制停用时额外提示，不新增角色级强制开关。单独明确说明“实际主人向其绑定对象发起任何行为均直接允许”，不能把对非主人的有效值也显示为允许；实际行为的结果显示主人直接放行原因或本次命中的条目来源。
- 首版会话初始收起，同一会话记住展开状态；左右内容独立滚动。适用角色在研究完成前也能编辑限制，但配置不解锁调教工作；不适用时说明原因，已有配置可只读查看。
- 非主人调教许可与原面板指定者选择同步；“是调教员”、接受调教和工作优先级仍各自独立。切换角色或收起窗口不修改配置。
- 尺寸、宿主绘制方式和窄屏布局在基本实现后通过游戏内测试调整，满足屏幕边缘可访问、输入不穿透、多语言不溢出即可，不把试验尺寸写成固定规格。
