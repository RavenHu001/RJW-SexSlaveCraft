## 3. 生产端设计建议

以下为实现建议，除第1节明确规则外仍待定。

### 3.1 资格与唯一保存源

- 以当前SSC性奴身份、当前有效肛门及其完整开发记录查询生产资格。现有肛门完成档严格为 `SSC_Exp_Anus.Severity >= 1.0`，不是角色当前恶堕率100%，也不能把其他模块的0.999门槛直接搬来。
- 保留下来的开发记录不证明器官仍存在；实施时核对记录所属Pawn、部位及其父部位是否缺失，并核实当前RJW器官识别。性交阻挡装备是否影响分泌另定，不自动把所有行为阻挡当作不能生产。
- 建议新增独立身体生产Hediff与Comp，保存生产选择、批次进度和必要计时余数；不向人格能力字典另存一份bool，不搬运PNA或泌乳的历史字段。
- 拟用稳定能力ID `SSC_CorruptionGelProduction` 接入通用框架；本ID仅为规划命名，尚未注册。优先在身体管理区复用共用开关行及只读详情。
- 按规范区分保存选择 `Enabled`、当前通用准入 `Active` 和切换资格 `CanChange`。自然生产、催熟及生产代价使用同一最终资格，不能以行是否可见代替消费者判断。
- UI由 `GetView` 捕获原Pawn、Comp、人格token和生产owner，再经 `TrySet` 提交；不在点击时重拍上下文。关闭入口如何处理暂时失格需单独定案，建议允许在原owner仍有效时安全关闭，不照搬子宫开关的特殊门槛。

空壳、人格替换期间是否暂停、是否要求当前恶堕大于零，以及是否需要实际绑定主人，仍是待定产品条件；不能仅因其他模块有这些检查就自动增加门槛。

### 3.2 积累、暂停与交付

建议以有效经过时间推进自然生产。关闭时保留进度，停止自然积累、行为催熟及生产代价，恢复后从原值继续，暂停期间不补算。身份退出、器官失效等失格场景建议暂停并保留选择；真正删除后重建属于新owner，默认与进度重新初始化。

若采用固定批量、阶段调速，阶段变化只影响之后的积累。自然推进和催熟都写同一份进度；是否保留超过整批的余量及单次交付批数上限，实施前确定。

地图交付和旅队库存可参考PNA，但应在物品成功放置或进入合法库存后才扣除一批进度。没有接收位置或交付失败时保留待交付批次，避免高价值产物丢失；等待交付期间是否继续积累、是否继续承受生产代价需明确。

不要直接追加到现有牛特化催熟分支。凝胶应有独立入口，只读取自己的生产选择与资格；若采用“每场首次高潮催熟”候选，可与消费端共享真实高潮事件及场次归属，生产催熟认领和消费恶堕额度分别保存。

### 3.3 生产代价与平衡

建议由生产组件实现 `ICorruptionModifierSource`：实际生产资格有效且开启时返回配置倍率，否则返回1；不新增恶堕底线。该接口已经进入自然衰减计算，可保留全局关闭、旧评分及保护规则。

**自然衰减倍率不是按份支付的固定资源成本。** 当前衰减还乘性需求、评分、主人好感、锁链阶段、部位开发和其他来源；维持底线可以抵消净损失。即使候选×2，也不能描述成每人每天固定扣若干个百分点，或承诺一定退阶。角色当前恶堕已低时是否暂停提取仍待定，不因本方案默默增加门槛。

工作负面建议由同一生产状态派生，避免开关已停却残留属性影响。采用动态效果还是派生marker，需要核实健康／属性缓存和生命周期通知；marker不是保存源。若使用marker，按能力规范接读档、身份、空壳和健康owner变化的必要协调，不新增全图每tick扫描。

生产者自服可能以库存回补恶堕，形成维持生产循环。建议首版允许自服，先用产出周期、劳作损失及售价平衡，不给每份商品增加生产者引用；是否限制生产与药效同时存在仍待定。

## 4. 使用品与持续药效设计建议

建议将堕落凝胶制作为普通可堆叠药品，第一版不保存来源Pawn、完整记忆或人格快照。体验碎片的设定由持续心情、轻微身体影响和行为恶堕增量表达；真实数据化的片段／品质变体与第16项衍生用途另行规划。

- 摄入沿原版服用流程，明确默认及单次最多1份；专用摄入入口处理凝胶效果和主人资格，不直接套用PNA负荷／成瘾算法。
- 建议只有一份有效药效状态，期限和强度分开。续药采用第2节候选，不叠加心情或负面层数，也不新增单场恶堕额度。
- 心情从当前有效药效派生，到期、移除或免疫后结束；每次服药／高潮不再另发一份同类记忆。
- 普通未选SSC身份角色不额外要求 `IsSexSlave` 才能获得恶堕增量；仍核对当前有效 `Need_Corruption`，缺少需求时不临时创建。其他身体效果和心情的目标范围需与现有需要／健康资格一起细化。
- 第一版建议先平衡固定期限和单层效果；耐受、成瘾、戒断、过量、配方、商人库存和专用美术均未定，不因使用“药品”分类就自动继承PNA规则。

## 5. 高潮事件、场次额度与恶堕写入建议

### 5.1 真实事件与结算时机

前置调查已核对RJW真实成功高潮分支会增加本人驱动 `orgasms`。建议在调用前后比较真实增量，使用 `__instance.pawn` 归属；不能把达到阈值当作成功事件，也不能用 `Partner` 或最终混合汇总代替本人次数。

建议补一个小的真实高潮事件适配层，无需等待第50项整体框架。当前 `BeginOrgasm/EndOrgasm` 只承担推进样本失效，不是可直接订阅的新奖励事件。前后采样还要验证原Pawn、Job、药效owner及必要人格／身体凭据；重入、异常或实例替换不能重复或迟到认领。

**实时发放是建议，尚未作为已确认玩法规则。** 若采用该方案，半途服用只计算之后真实发生的高潮，到期后停止后续加成；中断不追扣已发生的收益。若最终改为完整行为结束才给奖，需要重设中断、药效到期和快照语义，不能混用两套结算。

### 5.2 单场额度保存

已确认凝胶额外收益每场最多10个百分点。建议按本人及实际场次保存已经发放的累计额度，续药、药效移除后重服、换药效owner或临时失效都不重置同场额度；保存的是累计已发收益，不按之后的恶堕下降返还额度。

普通场景可评估以Pawn＋Job作为归属；同一参与者的多人场景共用额度，常驻家具接收者需核实是否需要独立轮次编号。存读档保留同场已发记录与催熟认领，真实新场次才建立新额度；本节是保存契约建议，具体载体尚未选择。

普通完成守卫明确排除部分训练、仪式和人格提取任务，不能只接普通完成入口便声称覆盖“每次性行为”。沿同一真实高潮入口的普通、训练、自慰、动画和UAP场景分别核实；这些场景是否全部纳入首批仍待定。原版 `Lovin` 没有本次已核实的高潮计数，建议首版不凭空折算一次高潮。未来第50项新增日常事件也不自动领取凝胶收益。

### 5.3 阶段刹车

建议遵守现有阶段上限，先计算：

`实际增加量 = max(0, min(本次高潮计划增量, 本场剩余额度, 当前阶段上限 - 当前恶堕))`

再通过现有 `SetCorruption`／恶堕写入入口维护当前值、历史最高和特质镜像。达到上限时不降低已有值、不延后补领；生产衰减也不主动清历史最高或部位开发进度。

**沿用阶段刹车尚待确认。** 现有新版无锁链上限为0.12，旧评分按对应现行规则处理；直接 `AddCorruption` 本身只钳0～1，不负责锁链刹车。普通角色可增长已确认，不等于已批准药物突破无链12%上限、自动绑定或推动锁链进阶。

现有高潮恶堕补丁另有0.003收益，且使用阈值预判与伴侣归属；它不是既有的“单场10%”规则。新凝胶的额外额度与原调教／其他收益独立，本项不顺带重写旧收益。

## 6. 主人免疫与身体生命周期建议

主人免疫已确认，具体建议是统一调用当前 `SSCIdentityUtility.IsMaster`，覆盖心情、负面属性与高潮恶堕全部效果。有主人资格但未选主人身份，不据此自动免疫。摄入、持续效果和收益消费者分别复查，避免只拦一次摄入却留下旧药效。

| 场景 | 建议处理；均未视为已确认细则 |
| --- | --- |
| 药效中转为主人 | 协调并清除现有药效，实际消费者先停止生效；退出主人后不恢复已经清除的药效。 |
| 人格提取／植入 | 建议生产选择与进度留在身体，不采集进人格凝胶；是否因空壳或替换暂停见第3节待定条件。消费药效也明确排除出人格采集范围。 |
| 新生克隆 | 可按原身体开发规则获得器官开发资格，但生产记录初始化为关闭、进度0；不复制本体药效或生产负面。 |
| 克隆成熟 | 缺载体才初始化，已有生产记录保留自己的选择与进度，不以来源严重度覆盖；不能用通用人格清字典代替身体处理。 |
| 同名健康记录重建 | 使用新owner，不恢复已删除载体的旧选择／进度；旧UI提交及旧事件请求拒绝。 |
| 旧档满级肛门 | 用完成阶段的幂等Refresh或完整初始化补授，避免只监听“刚达到100%”而漏掉旧角色；只读UI getter不创建Hediff。 |
| 死亡／复活、离图／旅队与读档 | 核实有效计时、药效期限及生产暂停恢复，不因更新间隔变化补算无资格期间；具体时间语义在实施前确定。 |

现有克隆流程对SSC前缀Hediff有宽泛继承，并在成熟复制时写入来源严重度；若新生产进度使用Severity，必须显式排除复制库存及覆盖自身进度。不能仅标注“身体保存”就假定这些边界已经解决。
