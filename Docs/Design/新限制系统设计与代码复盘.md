# 新限制系统：代码复盘与实施参考

复核日期：2026-09-16。正式版基线：**2.3.0 / `29fcfd9`**；复核工作树：`aba9ec8`，相对正式版没有运行代码变化。

开发目标与行为约定统一维护在[新限制系统开发规划](新限制系统开发规划.md)。本文件保留代码事实、接管位置和验证清单；不再重复一套需求编号。代码结构、标记名称和 UI 承载方式属于实施建议，可在满足主文约定的前提下调整。

后续规则修订：所有性爱/调教许可经单一入口，实际主人向自己的性奴发起任何行为均在入口内立即返回允许，不再进入条目否决；装备保护仅提供其余行为的条目强制值。下文对旧例外、白名单和装备独立拦截的描述仅为待迁移的代码事实，不代表新系统保留这些路径。

## 2. 代码接入参考

### 2.1 默认值、旧例外与统一判定

证据：[Settings](../../Sexslavecraft/common/Settings.cs)、[Comp_Train](../../Sexslavecraft/Comps/Comp_Train.cs)、[SSCSexInteractionPolicy](../../Sexslavecraft/common/SSCSexInteractionPolicy.cs)。

现行缺省值为：保护总开关、protectNonRapeOwnerOnly、protectChainedAggressorRape、protectBusAggressorRape 开启，allowSexSlaveRape 和旧个体例外 allowOthersForTrainingOrSex 关闭。由此推导主文的普通默认；特化强制总开关初始开启则是保持旧公交车强制开放特征的分析选择，旧代码没有同名字段。

旧策略存在整次行为提前返回：双方没有锁链时跳过；公交车接收方提前放行；公交车发起方及旧例外可能连带开放主动、被动或调教。这些不能机械映射为“某一条允许可以覆盖对方所有限制”。迁移应保留能明确对应的玩家选择，并说明主人关系最高许可、双向许可和装备条目覆盖带来的有意变化。

新系统只提供一个行为许可决策入口。内部可以拆分用途分类、来源收集和条目解析，但普通行为、调教、装备及兼容适配不能各自维护另一套许可判断。入口统一处理总开关、适用范围和关系上下文；界面与行为共用条目解析逻辑。主人关系也必须进入该流程并返回来源明确的结果，不能在 Harmony、JobDriver 或事件调度层提前放行。

- 例如旧 protectNonRapeOwnerOnly 关闭，普通角色原本可自慰、主动不限对象并接受非主人自愿行为；不能升级后用出厂表全部重置。旧例外还影响调教，但本身不单独解除强制行为限制。
- 特化默认只在主文规定事件写入；特化与装备强制共用条目覆盖机制，只计算有效值，未声明条目不按布尔缺省值覆盖。来源优先级以主文为准，不保留整次公交车放行或装备追加否决与新条目判断并存的路径。
- 适用判定集中处理 SSC 性奴身份及旧锁链数据。原策略仅看锁链与新身份配置范围不同；首次绑定准备属于已有流程，不能因尚无主人而被锁死，也不能用恶堕值或存在组件初始化所有普通角色。
- 初始化在首次适用的生命周期入口完成，行为查询负责读取；总开关关闭、主人关系最高许可或没有行为不应延迟首次配置。人格/克隆恢复应等完整操作结束。
- 入口还原行为方向和用途，规则模块不修改身份、基因、指派或特化。信息不足时先补上下文；已接管且涉及适用角色的任务若到开始前仍无法判定，则拒绝该未开始任务并记录原因，不以空目标放行，也不限制无关任务。

### 2.2 调教员身份、唯一指派与主持资格

证据：[TrainerAssignmentUtility](../../Sexslavecraft/common/TrainerAssignmentUtility.cs)、[SSCIdentityUtility.Trainer](../../Sexslavecraft/common/SSCIdentityUtility.Trainer.cs)、[SSCBondUtility](../../Sexslavecraft/common/SSCBondUtility.cs)、[JobDriver_Train](../../Sexslavecraft/JobDriver/JobDriver_Train.cs)。

2.3.0 已通过 IsTrainer 统一身份；CanAssignTrainerTo 组合身份、同图自由殖民者、非自身、工作及身体条件。GetTrainerCandidates 先复制候选集合，避免嵌套查询重建共享集合导致异常。此过滤及快照修复应保留。

IsAllowedTrainer 先检查身份，但旧例外/公交车仍能跳过 selectedTrainer，未强制主人且无指派时也可放行。这些关系分支需要改为主文的唯一指定语义；GetForcedMaster、Bind、TryAssignTrainer 与读档协调须同步，不能只替换 UI 布尔值。

- **已指定、有效指定、此刻能工作**是不同状态。GetActiveAssignedTrainer 只排除死亡/销毁和身份停用，不读取倒地、地图或工作开关；它供同床和归属使用，不应加入全部行为许可或工作可执行性条件。
- 自动扫描按指定者分配，行为许可统一调用新入口并携带用途及调度上下文；不能用“未指定”拒绝实际主人经合法入口发起，也不能因主人关系最高许可让其他人自动候补。
- 日常驱动已有两处 IsAllowedTrainer 检查，其行为许可部分应委托统一入口按调教用途判断，不保留并行的旧许可策略。TrainingJobUtility 的能力检查保留；不要重跑含自身 isBeingTrained、冷却和预约的完整工作筛选，把本任务占用误判为冲突。
- 首次绑定前仍能指定符合资格的对象；只有符合建绑主人条件的人才是候选主人。GetResolvedMaster 虽已改为实际主人优先、否则有效指定调教员，仍不能作为系统内最高关系许可的依据。

仪式证据：[RitualRole_BindingMaster](../../Sexslavecraft/Ritual/RitualRole_BindingMaster.cs)、[RitualRole_BindingSlave](../../Sexslavecraft/Ritual/RitualRole_BindingSlave.cs)、[CorruptionProgressionUtility](../../Sexslavecraft/common/CorruptionProgressionUtility.cs)。

当前两侧会要求有效指定者，主人角色还要求 IsMaster；这会排除另选调教员后的实际主人，以及具备有效指派的性奴调教员。实现主文主持规则时须同时改两侧配对，并覆盖先选主人/先选性奴两种顺序；实际主人先获关系资格，不能被空指派或第三方停用挡住。

主持关系资格与建立所有权必须分开。Bind 仍要求真正的新主人具备 Master 身份，且默认 replaceExisting=false；本轮不因允许性奴调教员主持而修改其身份或覆盖旧绑定。现有流程若把主持者直接用作新主人，首次建绑前须明确验证该条件，不能将“可主持”误当作“已绑定成功”。正常仪式能力、活动、场地和阶段条件继续适用。

### 2.3 任务用途、方向与开始时序

证据：[Harmony_ProtectSexSlave](../../Sexslavecraft/ThePatches/Harmony_ProtectSexSlave.cs)、[JobDriver_Train](../../Sexslavecraft/JobDriver/JobDriver_Train.cs)及以下驱动。

| 入口 | 接入要点 |
| --- | --- |
| 日常调教 | 通过统一入口解析调教条目，复用已存在的预约及开始前复查。 |
| [仪式调教](../../Sexslavecraft/JobDriver/JobDriver_RitualTraining.cs) | 通过同一入口解析调教条目及关系许可，保留主持资格检查；按仪式阶段还原是否已经开始。 |
| [人格排泄](../../Sexslavecraft/JobDriver/JobDriver_PE.cs) | 保留用途区分，查询普通非强制许可；不能因工作类型或接收驱动相同而加入日常调教身份门槛。 |
| 单人自慰 | 依据已知单人任务及可靠场景识别，不能将空目标当自慰，也不能因缺少第二人跳过自身限制。 |
| 普通双人 | 使用实际发起/接收信息；姿势反转不等于发起方向反转，双方均适用时分别检查。 |

日常调教、仪式与人格排泄复用 SSC_TrainingReceiver，单靠 JobDef 或 RJW 基类无法分用途；用途需在预约、步骤、发起、接收及读档恢复中一致。一般行为附带[人格排泄状态结算](../../Sexslavecraft/ThePatches/Harmony_PersonalityExcretion.cs)不改变原任务用途。

当前 DetermineRoles 的后备读取偏重 targetA，而本机 RJW 还支持 PartnerPawn 等目标布局。SexProps.isReceiver、实际 Partner 与关联任务应在适配中核对，不凭性别或主人身份猜方向。预约中的 playerForced 不能保留为新保护豁免；调度、排班和失败日志所用 forced 含义不一，不能一并删除。

已有内存开始标记与接收参与者推断不足以覆盖单人和仪式准备读档：仪式准备时已创建 SexProps/接收任务，真正 Start 在后续步骤，不能把已有场景对象当作开始证据。结合实际进度及仪式 phaseSceneStarted 恢复；这一旧时序风险来自静态分析，尚未实机复现。

开始状态应关联当前任务、参与者与用途，仪式还需关联阶段。新加入者、下一阶段和后续任务重新检查；拒绝时仅清理本次预约、等待及 isBeingTrained，占用残留修复不代替正常清理。晚到回调不终止新任务，已开始收尾不绕过死亡或离图等正常终止条件，不伪造成功结算。

### 2.4 系统内主人最高许可、装备条目覆盖、兼容与同床

统一入口在可靠识别双方及发起方向后，首先使用 SSCBondUtility.IsBoundTo(receiver, initiator) 判断实际绑定关系，不能用 IsMaster、指定者或 GetResolvedMaster 替代。命中时立即返回允许并记录“实际主人直接放行”；不再调用主动、被动、调教条目或装备/特化的否决逻辑，不改写双方配置。主人最高许可是整个行为的确定结果，不是逐条合成的最高允许值。只有未命中时才继续条目解析；旧共享策略中可能先拒绝主人的分支必须移除，各任务适配器不得追加许可否决。

[CompSSRapeCheck](../../Sexslavecraft/Comps/ThingsComp_PreventRapeJustForSexSlave.cs) 是旧装备标记，旧策略用它额外拦截非主人强制行为；Apparel_EFOutfit 使用此标记。新实现将对应装备定义映射为“接受非主人强制行为 = 禁止”的强制来源：可沿用标记识别来源，具体强制条目由装备文件声明，不能继续直接返回拒绝。未命中主人直接放行时，装备与特化共用条目解析器，装备优先于特化；装备收集器不负责判断最终行为许可。

穿脱只更新来源，不写保存值、不重新应用默认。关闭特化强制不关闭装备来源；关闭整个限制系统时两类强制均暂停。普通条目解析完成后不再追加装备否决。界面显示具体装备和被覆盖条目；旧公交车曾绕过装备的行为会改变，需同步物品与规则说明。

兼容范围与接入顺序：

- **LifeForce**：KnownDirectAllowJobs 的 rjw_genes_lifeforce_randomrape、rjw_genes_lifeforce_seduced 必须适配到统一入口并删除无条件白名单；未完成时记录为接管缺口，不能作为最终系统保留的例外。早期本机核对前者使用 RandomRape，后者使用 RJW_Genes.JobDriver_Seduced；后者内部方向和时序尚未验证，不能仅凭名称分类。未安装时不得产生硬类型依赖。
- [LifeForceConflictUtility](../../Sexslavecraft/common/LifeForceConflictUtility.cs) 会处理基因并产生副作用，不是纯权限接口；保留既有功能，不能在每次许可查询中调用或假定它已排除所有兼容任务。
- **原版 Lovin**：纳入普通非强制规则。早期本机 RJW 源码核对显示 override_lovin 关闭时原版驱动不经过 RJW 基类；2.3.0 没有补齐此覆盖。实施时复核实际依赖和双方任务结构，分别验证替换开/关，避免重复拦截、角色反转及 Cleanup 标记成功导致虚假结算。第三方独立驱动须另作适配记录。
- **同床**：[SSCSharedBedUtility](../../Sexslavecraft/common/SSCSharedBedUtility.cs) 经 GetAllowedPartners 读取实际主人与有效指定调教员；[同床补丁](../../Sexslavecraft/ThePatches/Harmony_SharedBedCompatibility.cs) 已不再修改 LovePartnerRelationUtility。保留床位、恶堕门槛和睡眠记忆规则；普通许可、调教许可及其总开关不直接接管同床。同床也不授予 Lovin 许可。
- 若新限制实际改了 selectedTrainer，现有同床/床位标签/归属接口据新关系更新；身份停用仍保留原引用。不要通过修改 GetActiveAssignedTrainer 的含义将日常行为限制扩散至这些系统。

### 2.5 公交车事件与交易副作用

状态证据：[Comp_Train.Specialization](../../Sexslavecraft/Comps/Comp_Train.Specialization.cs)、[Comp_Train](../../Sexslavecraft/Comps/Comp_Train.cs)、[BusSpecializationUtility](../../Sexslavecraft/common/BusSpecializationUtility.cs)。

SetSpecialization 会写旧例外；方向先改变、基础 Hediff 可能稍后补齐，ReconcileSpecialization 又会认领状态并保留终极状态。以主文事件表统一处理，避免在中间状态或每次查询重写默认。可保存一个“公交车默认已处理”的元数据标记，随本 Pawn 配置保存；它不构成特化配置表。写默认和写完成标记须一致；新克隆不继承，旧迁移和已配置的人格接收者按主文保留值。

交易证据：[Harmony_BusTrade](../../Sexslavecraft/ThePatches/Harmony_BusTrade.cs)。

2.3.0 当前行为应作为接管起点：

- 自愿分支用 xxx.quick_sex，由交易角色发起；强制分支用 xxx.RapeRandom，由商人发起。
- CanStartTradeInteraction 已检查身体、征召、同图距离、战斗/精神状态、工作可中断性以及预约寻路；随后检查 RJW 能力。不要回退到旧 Sex/Rape 定义或移除这些检查。
- TryStartTradeJob 用 StartJob 创建 600 ticks 等待及行为任务，核对 CurJob 是否接收，失败时只清理本事件任务和队列；不再使用旧 StopAll 流程。
- 当前消息在任务被接收后出现，这尚不等于真正进入行为阶段；新系统需把“已发生”的通知关联到实际开始事件。

新增许可预检应在第一次 partner.jobs.StartJob(waitJob, ...) **之前**完成，正式开始前再查；若预检拒绝，不打断当前工作。排队或走位后拒绝只清理相关任务，保留现有任务接受校验和去队列处理。

交易本身的成长仍按现有成功成交、分支及终极状态条件发放，不以行为发生为前提；后续拒绝不撤销已完成交易或交易成长，也不重掷分支。行为成长仍由真实行为结算，消息和各来源收益各发一次。飞船交易范围、概率和成长数值不借此改动。

[DogSpecializationUtility](../../Sexslavecraft/common/DogSpecializationUtility.cs) 的事件冷却按掷骰消耗；调度前接入同一预检，拒绝不返还该冷却、不撤回已满足条件的工作成长、不产生未发生行为的收益。AI 高频筛选不弹重复拒绝消息，手动失败应提供具体原因。

### 2.6 配置迁移、人格、克隆与绑定变化

证据：[Comp_Train](../../Sexslavecraft/Comps/Comp_Train.cs)、[SSCTrainerIdentityMigration](../../Sexslavecraft/common/SSCTrainerIdentityMigration.cs)、[人格存储组件](../../Sexslavecraft/Comps/ThingsComp_PE_PES.cs)、[ExcretionUtility](../../Sexslavecraft/common/ExcretionUtility.cs)、[RabbitCloneUtility](../../Sexslavecraft/common/RabbitCloneUtility.cs)、[SSCIdentityUtility](../../Sexslavecraft/common/SSCIdentityUtility.cs)。

- 捕获旧迁移输入须早于旧修复、SetSpecialization 或周期认领对字段的改写。固定本次存档可获得的旧全局值，避免地图与延迟载入角色用到不同时刻的设置；不可恢复的历史全局值不能声称已还原。
