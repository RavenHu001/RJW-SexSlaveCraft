## 1. 目标与实施边界

统一现有个人能力开关的注册、只读状态查询、ITab 展示和提交入口，并覆盖后台实际消费者。每个开关继续使用一个真实保存源，保持当前默认值、人格／身体／关系归属和业务规则。

本专项按以下五项实施。界面可以保留主人、身体管理、凝胶外观等原有区域；通用化不要求把所有内容集中到一个长列表。

| 开关 | 当前保存载体与默认值 | 本专项处理 |
| --- | --- | --- |
| 欢愉恩赐 | `CompSexSlaveTraining.abilityToggles` 内稳定 ID `SSC_MasterDesireInfestation`，默认关闭 | 保留已发布 ID、存档键、人格生命周期及实际收益规则，作为人格后端回归基线 |
| 主人伤害分担 | `Hediff_BridleOfSexSlave.shareDamageEnabled`，默认开启 | 通过适配器统一查询／提交，保留原缰绳载体和伤害业务检查 |
| 泌乳 | `CompSexSlaveTraining.milkProductionEnabled`，默认开启；凝胶有同名独立快照字段 | 适配旧字段及已有采集／复制／植入行为，保留原生产与营养规则 |
| 生育 | `Hediff_SSCUterusDevelopment` 内 `sscUterusFertilityEnabled`，默认关闭 | 保留当前身体记录及完成度、妊娠、配置检查，调用原工具入口 |
| 凝胶个人渲染 | `HediffComp_FullGelAppearance` 内 `sscGelRenderingEnabled`；新身体默认开启 | 保留身体归属、旧档迁移、快照发布和渲染刷新；调色窗口继续独立 |

本轮不迁移身份选择、调教员任职、训练启停、排程、姿势、指定调教员、行为许可、工作设置或全局 Mod 设置。它们分别具有职责、任务取消、时段、对象或模板语义，不因外观也是复选框就纳入能力存储。必要的共用控件可后续复用，但不重写其业务模块。

猫狗当前为主动 Ability，没有既有 ITab 能力开关，本轮不新增“禁用技能”玩法，也不改变终极成果不依赖当前 SSC 身份的资格。兔繁殖是枚举，精细调教是预留字段，不纳入五项接入。不重启兔重设计、第 17 项完整兼容排查、第 31 项关系重构、第 34 项性能专项或第 38 项整体重构。

## 2. 当前代码事实与保存契约

### 2.1 可复用的框架

- [能力定义与工具](../../Sexslavecraft/common/SSCAbilityToggleUtility.cs) 已有稳定 ID、Master／Slave 分组、默认值、可选激活／编辑规则和健康标记；分析基线只注册欢愉恩赐，后续第一批源码已增加伤害分担，Slave 组仍为空。
- [状态容器](../../Sexslavecraft/common/SSCAbilityToggleState.cs) 按 `sscAbilityToggles/enabledById` 保存，保留显式 `false` 和未知键；查询不补写缺省值。缺键采用定义默认值，修改已发布默认值会影响未明确保存该键的旧档。
- [Pawn／凝胶组件](../../Sexslavecraft/Comps/Comp_AbilityToggles.cs) 分别持有独立字典；提取、植入和克隆已有入口。植入精确替换，不能将来源关闭与宿主开启按“取 true”合并。
- [通用 ITab 行](../../Sexslavecraft/ITab/ITab_SexSlaveTraining.AbilityToggles.cs) 已共享测量／绘制快照、动态行高、GUI 状态恢复及人格 token 防迟到提交。主人面板已接 Master 行，主页面已为 Slave 行计算高度。
- [标记同步补丁](../../Sexslavecraft/ThePatches/Harmony_SSCAbilityToggles.cs) 监听能力标记、空壳、死亡与成功复活；[游戏组件](../../Sexslavecraft/common/SSCAbilityToggleGameComponent.cs) 在完整载入后协调一次，不新增每 Tick 全图扫描。

### 2.2 泌乳归属更正与已有例外

泌乳开关不是保存在身体 Hediff：原值由[训练组件](../../Sexslavecraft/Comps/Comp_Train.cs)保存，[凝胶组件](../../Sexslavecraft/Comps/ThingsComp_PE_PES.cs)采集、保存及加工复制，[人格植入](../../Sexslavecraft/common/ExcretionUtility.cs)将来源值覆盖到宿主。身体管理栏只决定展示位置。

但是，旧泌乳字段也不等同于现通用人格字典的全部生命周期：`ClearPersonalityState` 当前只清空字典，没有顺带重置泌乳字段；[克隆准备](../../Sexslavecraft/common/RabbitCloneUtility.cs)也没有显式将该旧字段按能力定义默认值重置。后续应保持现生产流程的结果，补对照验证，不因“随人格采集／植入”就额外增加提取清源或克隆重置。

生育开关属于子宫开发 Hediff 当前身体实例；凝胶渲染开关属于身体外观 HediffComp，两者不进入人格凝胶能力字典。身体状态的克隆复制与成熟恢复继续遵循各自已有过滤／复制规则，不能统一理解为“身体项从不复制”。

### 2.3 现有模型需要扩展的位置

分析基线中的 `GetEnabled`／`TrySetEnabled` 固定访问人格字典，`HasStablePersonality` 同时要求固定身份、人类、存活、非空壳且非人格替换中。此规则适合欢愉恩赐，不能直接成为五项共同准入；第一批已将该门槛保留在默认人格后端，缰绳采用独立资格。

分析时 `CanEdit` 只返回 bool，通用行只有保存值与编辑资格；第一批已补每项显示条件、动态原因和针对目标值的公共校验。生育已有“未完成不能开、妊娠时不能关”的方向性规则，第二批接入时仍须保留。

## 3. 共用接口与状态表达

以下为三批共用契约。第一批已实现 `SSCAbilityToggleBackend`、`GetView`、`CanSet`、`TrySet` 及人格／缰绳后端；身体项目仍未接入，不能将公共接口存在视为第二、三批完成。

| 职责 | 规划要求 |
| --- | --- |
| 注册描述 | 稳定 ID、标签／提示键、展示分组、排序、可见条件及后端适配；展示分组不推导保存归属或身份资格 |
| 只读状态 | 读取保存偏好、当前通用准入／暂停原因、是否可见，以及本次提交所需的载体凭据；查询不创建记录、不迁移、不刷新健康或图形 |
| 目标值校验 | `CanSet(pawn, id, nextValue, out reason)` 按下一次操作判断；区分开启、关闭和重复同值请求 |
| 权威提交 | `TrySet(..., nextValue, context, out reason)` 重新读取当前状态，核对玩家操作资格、载入阶段及原载体，再调用真实 setter |
| 后台入口 | 消费者通过共用入口取得开关选择／适用状态；伤害类型、目标、营养、任务等事件条件仍由所属模块判断 |
| 可选标记 | 仅对确有展示需要的能力保留；标记是派生状态，不从标记反推保存值，不给所有身体项另建标记 |

保留现有 `SSCAbilityToggleState` 作为人格偏好容器。旧字段、缰绳、身体 Hediff 和外观工具分别提供适配，不能把它们复制到人格字典后再双向同步。保留现有查询接口作为兼容入口或明确更新全部调用者，避免形成两套资格判断。

“保存开启”“当前具备作用资格”和“某次事件实际发生效果”分别表达。例如没有本次伤害或没有承伤候选，不应禁止保存伤害分担偏好；UI 不能将一项需要具体事件上下文的能力简单标成常驻失效。暂停／禁用原因仅显示已能确定的当前条件。

提交上下文按实际归属捕获：人格项核对原 Comp 与人格 token，身体项核对原 Hediff／HediffComp，关系项核对原缰绳；混合前提按需同时核对。泌乳涉及人格偏好和当前泌乳状态，须防止同一 Comp 换入新人格后旧点击写入新偏好。

### 6.2 生命周期验收矩阵

| 场景 | 必须保留／验证的结果 |
| --- | --- |
| 旧档缺节点／缺字段 | 恩赐按既有默认关闭；缰绳分担与旧泌乳字段按原默认开启；生育按原默认关闭；凝胶遵循旧全局设置迁移例外。读取不补写整个注册表 |
| 明确保存与未知键 | 每项 true／false 往返不丢失；人格字典未知键保留，不能将 false 当缺键；原字段名与节点不变 |
| 身份退出／恢复 | 欢愉恩赐保存偏好但按资格暂停／恢复；身体生育与外观不因退出 SSC 身份被清空；工作／身份模块未被框架接管 |
| 两条人格提取与凝胶加工 | 恩赐捕获独立字典，成功提取后按原规则清源；泌乳采集／复制旧字段，不额外加入字典清源；生育与外观不进入人格能力快照 |
| 人格植入 | 恩赐与泌乳分别覆盖来源开／关 × 宿主开／关四组合，来源关闭能覆盖宿主开启；身体项按宿主现有记录及既有恢复规则处理，不被人格值覆盖 |
| 人格替换进行中／结束 | 人格能力按原规则暂停；旧 UI token 失效；结束后按最终状态协调。身体 setter 仍检查自己的 owner，不因共享接口取得错误人格授权 |
| 新生克隆 | 恩赐字典清空后按定义默认值处理；用默认 true 的测试能力证明“回默认”不等于“一律关闭”。泌乳与改造前生产复制流程对照，不额外套用字典 reset |
| 克隆身体与成熟 | 生育沿用身体开发的复制过滤；凝胶外观遵循已有身体复制工具，不进入人格凝胶。成熟不覆盖克隆后来取得的能力偏好或既有身体选择；来源与副本无共享可变容器 |
| 解绑／换绑／替换缰绳 | 分担偏好仍归原载体；旧界面不能修改新缰绳，不自动向新关系搬运旧字段或创建替代缰绳 |
| 死亡／成功复活／空壳 | 恩赐资格及派生标记按原规则协调，原始偏好保留；身体／关系数据不被通用人格清理误删，实际业务仍走各自已有检查 |
| 外部删标记／换身体记录 | 标记不反推偏好；去重／重入有界；原身体 owner 离体后不能接受旧提交，新增 owner 不继承旧界面的值 |
| 保存／加载阶段 | 加载中拒绝编辑，完整加载后按最终状态协调；无重复健康标记、收益、图形刷新或开关写回 |

泌乳提取后原体残值、克隆复制等历史差异以改造前生产调用链建立对照，不能只用一个新建适配器的模型结果宣称等价。若要改变这些旧语义，应另列设计，不混入通用化。
