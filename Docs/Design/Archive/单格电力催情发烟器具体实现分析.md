## 2. 保存与配置

组件保存的真实用户状态只有 `enabled` 和 `radius`；半径缺省10，限制在5～20，耗电始终由 `100 + 4r²` 派生，不另存功率。初建开启状态建议默认true，正式实施时与最终产品规则一并落实。

建议入口为 `TrySetEnabled`、`TrySetRadius`、`RefreshPowerDemand`、`CanRunNow`、`ApplyExposurePulse`、`TryEmitSmoke`。UI只调用提交入口，入口检查组件仍属于当前已生成的玩家建筑，防止残留Gizmo修改已拆除／离图设备；半径须校验有限性并裁剪范围，重复提交相同值不重复发送信号。

配置类可持有XML注入的 `HediffDef hediff`（指向 `HumpShroomEffect`）、速率、120 tick采样间隔和特效参数；原药效只引用，不复制或改写。固定产品参数使用唯一配置源，校验层不得另藏一套不一致的默认值。

读档后校验半径并重算功率；缓存电力组件引用和Gizmo。临时目标缓冲、房间对象、烟点与视觉计时不作为持久累计量。搬运／重新放置、换图后重新取得地图上下文，离图时不执行暴露或生成烟朵。

## 3. 玩家直接开关与原版电网

已核实 `FlickUtility.WantsToBeOn` 会查询 `CompAutoPowered.WantsToBeOn`。设备组件可用这个抽象属性返回玩家保存的开关选择，从而让电网尊重人工关闭，而不需要添加普通 `CompFlickable`。

建议执行方式：

1. `Command_Toggle` 的回调立即调用设备setter，修改 `enabled`；不生成Flick指定、Job或任何寻路操作。
2. 关闭时发送原版 `AutoPoweredWantsOff` 信号，使 `CompPowerTrader.PowerOn` 关闭，并立即将需求输出设为0；药效与特效入口同样直接检查 `enabled`，不等待120 tick结算才停机。
3. 开启时写回公式对应的负 `PowerOutput`（负数表示负载），由原版电网决定是否获得实际供电；不无条件将 `PowerOn` 强设true。玩家选择立即生效，实际恢复发烟沿电网供电时序，不承诺缺电时也能运行。
4. 开启但暂未通电时，仍保留公式负载作为待分配需求；实际电量结算由电网按 `PowerOn` 决定。不能因暂时 `PowerOn=false` 就把待接通需求归零，造成电网按零负载接通设备。
5. `TrySetRadius` 同步刷新半径、平方距离阈值和耗电。滑动期间不逐次重连电网；修改本实例的 `PowerOutput` 即可，不改写全局共享的 `CompProperties_Power`／ThingDef。

原版电力初始化／重置可能重写输出值，建议在生成／读档、开关／半径提交和相关电力信号时同步，并在普通Tick以廉价差值检查兜底。检查栏及滑条显示实际公式需求；Def的静态500W只能解释为默认半径值，不能冒充所有实例的当前耗电。若信息卡需显示当前实例耗电，在本设备的电力配置显示层做局部适配，不全局修改Power显示。

`CompAutoPowered.UpdateOverlays()` 的当前实现会访问 `Flickable.SwitchIsOn`，不适合本设备没有Flickable的结构，不能直接调用。优先沿用PowerTrader自身的供电提示并提供设备状态文字；需要额外关机图标时再局部绘制。

## 4. 120 tick药效采样

本构建 `Thing.DoTick()` 对Normal类型既调用普通Tick，也可能调用间隔Tick；`ThingWithComps` 分别转发为 `CompTick` 和 `CompTickInterval`。首批建议只在 `CompTick` 中用 `parent.IsHashIntervalTick(120)` 触发剂量采样；不再从另一个Tick入口重复结算。

每次采样流程建议：

1. 确认建筑已生成、开关开启且实际有电；停机期间不累计待补算剂量。供电失效／禁电条件在本次提交前复查。
2. 获取当前Map、建筑位置、半径平方及房间。不存在有效房间时跳过，不能因为双方 `GetRoom()` 都为null就判为同房间。
3. 遍历 `map.mapPawns.AllPawnsSpawned` 的现有列表，仅检查有效健康对象、同图、距离和房间；不另加年龄、类人／动物／种族、身份或阵营过滤，不每轮构建类人筛选列表，也不使用仅殖民者集合。药效本身的阶段与生效规则仍沿最终Def。
4. 如果药效回调可能修改地图角色集合，先将候选收集到组件复用的短期 `List<Pawn>`，再逐个提交；缓冲仅服务本轮，不长期缓存目标。提交前复查来源仍有效及目标仍在同图、范围和房间。
5. 查找同一个 `HumpShroomEffect`：已有则增加0.01，尚无则创建原Def的实例并设置本轮输入；使用原生health添加与Severity setter，让最终定义决定阶段和上限，不手工硬编码0.3／0.6／0.9／1。

同一目标在同一设备一轮只处理一次。多设备各自增加剂量，保持原规划的加量语义；不建立来源Hediff，不在离场时删除共享药效。原生Def解析与health消费者仍有必要验证，不能仅用独立数学副本证明接通。

## 5. 半径滑条与覆盖显示

建议使用原版 `Gizmo_Slider`：`Target` 与 `ValuePercent` 在归一化坐标上工作，转换采用 `t=(r-5)/15`、`r=5+15t`；提交最终半径值给组件，显示值与耗电都从组件读取。关闭／缺电时仍可预设半径，不因供电状态丢失设置。

当前 `Widgets.DraggableBar` 会按 `Increments` 量化。维护者已确认先用1格步进：归一化区间显式设15段，对应5～20共16个整数半径，显示整数。提交入口及读档校验统一规范为范围内整数，公式直接使用该半径，不另外保留小数档位。

控件缓存以保持拖动状态；设备拆除或切换上下文后提交被拒绝。首批建议每台设备独立调节，不默认引入多选批量同步；`GroupsWith` 等合并行为需明确避免错误地共享拖动状态。

`PostDrawExtraSelectionOverlays` 可用于选中范围。圆形圈表达最大半径；若要显示同房间裁剪后的实际轮廓，仅在选中绘制期间计算相关格，不在每次药效扫描中维护全图覆盖矩阵。绘制与滑条GUI不推进药效或生成烟朵。

## 6. 雾气特效：先复用原版资源

当前Core有 `Smoke`／`SmokeGrowing` Fleck，仓库已有 `FleckMaker.GetDataStatic`＋`map.flecks.CreateFleck` 的接入示例，见[现有PNA特效](../../../Sexslavecraft/common/SSCPnaWeaponEffectsUtility.cs)。机制阶段可引用原版纹理，不需要制作建筑或烟雾新贴图。

首次60 tick一朵、后续每30 tick一朵以及尺寸7.5／12秒分片方案均保留为历史。对比图后当前方案保留5×5小片、6秒轮巡，每片收集最多25个当前合法格到复用临时缓冲；按有效格数÷6随机取整生成量，部分洗牌无放回抽取多个烟点。最大半径每次最多4片／100格检查、20朵范围烟，不为每朵重复扫描小片，不保存房间拓扑。相机不满足生成条件时跳过，不补发。

独立Fleck仍引用Core纹理，不改原版定义或增加文化／Ideology依赖。范围尺寸恢复为4，淡入0.5秒、持续20秒、淡出0.5秒、增长0.05；不额外旋转，RGBA(1,0.97,1,1)保留接近白烟的亮度。源头仍每15 tick一朵、尺寸0.8～1.2，寿命9.7秒及增长0.005参照Core Smoke，速度0.1～0.35、出口偏移0.5格，颜色保留少量紫调。单位面积稳态期望约0.583朵／格，参照文化无遮拦88格空间约0.573朵／格；整圆半径5／10／20期望约47／185／733朵范围烟、另加源头约39朵。此为几何期望，GPU与FPS／TPS未实测；`ShouldSpawnMotesAt`只检查地图／视野，不能充作粒子总量限制。

后续消散反馈已覆盖上述范围烟固定时长：当前通过 `solidTimeOverride` 为每朵设14.5～18.5秒停留，Def默认16.5秒、淡出4秒、淡入仍0.5秒；总寿命19～23秒，平均21秒，原烟量期望不变但透明度时间积分约降8.5%。随机仍在原视觉随机状态内，不增加队列或修改轮巡顺序；源头沿原9.7秒，不设置覆盖。实际浓淡与消散节奏待复测。

已生成烟朵按自身寿命消失；关闭停止新的生成。烟没有药效碰撞、毒气遮蔽或逐格扩散行为；目标被判断命中即可累计，和这一帧是否画出了烟无关。

关机标识使用原版 `OverlayDrawer.DrawOverlay(parent, OverlayTypes.PowerOff)`。建筑启用 `MapMeshAndRealTime`，由 `PostDraw` 根据保存的关闭选择逐帧提交，在迷雾／故障时不显示；不添加CompFlickable、第二份bool或持久图标句柄，暂停点击也能刷新，开启缺电仍沿PowerTrader原版提示。

## 7. 需收口的产品边界与建议

1格步进与不额外筛选药效目标已获维护者确认；下表其余建议仍需收口，不改变已经接受的数值：

| 边界 | 建议及实现影响 |
| --- | --- |
| 药效目标（已确认） | 不额外实现年龄、种族、类人／动物、身份或阵营过滤。遍历同图已生成Pawn，保留有效健康状态、半径与同房间等必要检查；不接入“可以进行性行为”的业务准入。玩家建筑控件的所有权／提交检查仍保留，与药效目标过滤分别处理。 |
| 室外与门口 | 直接使用当前 `GetRoom()` 的归属，双方Room相同且非null才成立，不额外要求封闭室内。门格按游戏自身房间归属处理，不主动选相邻房间；拆墙合房后下次采样读新归属，不永久缓存Room。 |
| `drugExposure` | 既有发烟器还更新娱乐用药时间与相关需求。建议保留同类暴露语义，并把需求补充值按120 tick换算为0.2；不照搬旧87 tick下的0.145，也不触发完整摄入或另加PNA负荷。是否保留这组配套行为开发前需明确。 |
| 初建开关与滑条精度 | 滑条1格步进已确认；初建默认开启仍为建议，搬运／读档保留已有选择。 |

## 8. 实施与验证范围

后续获准开发后，建议先完成XML、开关／半径保存和动态电力，再接周期药效、滑条／状态／范围，最后接低成本烟雾。正式贴图单列，不影响机制代码接入分析。

验证遵循[测试准则](../../Development/Reference/测试编写与执行准则.md)，优先小型原生宿主执行生产组件、真实电网与health路径，参考现有[原生宿主工程](../../../Tests/CosmeticNative/CosmeticNative.csproj)的隔离引用方式。代表性范围包括：

- 直接关闭后无Flick指定／任务，电网不会自行重开；开启缺电、断电／禁电及恢复供电保持选择，滑条改负载后电网按新需求处理。
- 半径默认／端点／一个中间值的公式与保存，越界或非有限输入不污染存档；关闭时改半径及移动／重放置后重新计算实例需求，不影响其他同Def建筑。
- 实际120 tick路径累计量、没有双Tick重复、空间边界、多个来源合并、最终Def替换及停机不补算；使用当前环境Def，不把已知文化四档表复制为固定预期。
- 开关／半径Scribe往返、移除与换图不继续结算、药效回调移走目标时不修改错误对象；具体用例依真实故障选择，不展开全部数值组合。

四语与资源复用现有轻量检查；Def可解析及引用核对不等于实机。实际范围显示、滑条输入、电网接通时序和药效分档在游戏内验收，性能以设备／角色数量和半径的代表场景测量；不承诺固定测试项数或TPS提升百分比。

**原分析整理时点仅为文档。** 后续授权开发已实施并完成相关自动验证；未生成新贴图，已提交实现并同步游戏，当前状态见[实现记录](../../Development/Completed/催情发烟器/单格电力催情发烟器实现与验证.md)。
