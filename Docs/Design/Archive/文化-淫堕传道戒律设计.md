# 淫堕传道戒律设计

[第 53 项入口](../未来内容开发规划.md#ssc-culture-partner-corruption) · [实现与实机验收](../../Development/Completed/文化淫堕传道戒律实现与验收.md) · [简中文案定稿](../../Development/Reference/文化-淫堕传道中文定稿-v1.md)

机制、图标与文案已通过实机验收。归档记载的 +0.5 个百分点是当前源码值；实机安装仍为已验收的 +0.25 个百分点，调值版已通过自动验证、尚未部署。

仅 1.7。新增独立议题，四档互斥，挂入「主奴秩序」可替换组。关闭是唯一有生成权重的档位；三个启用档由玩家手选。旧档缺少此戒律、未启用文化 DLC 或未能读到有效档位时，按关闭处理。现有「性奴性别」戒律继续独立判定，两组互不限制。见[实现与验证](../../Development/Completed/文化淫堕传道戒律实现与验收.md)。

| 档位 | 可受影响的对象 |
| --- | --- |
| 不传（默认关闭） | 无 |
| 传男子 | `Pawn.gender == Gender.Male` |
| 传女子 | `Pawn.gender == Gender.Female` |
| 传众生 | 不筛性别，包含 `Gender.None` |

- **施加者与对象。** 在非 SSC 性交场景中（包含多人），已有恶堕需求的参与者**本人实际高潮**时，只要同场至少有一名**其他实际参与者**持有 SSC 锁链，且其自己的文化戒律匹配对象性别，就满足施加条件。无需两者直接配对，也无需对象是性奴或信仰同一文化。仅预选性奴身份、旁观、仍在集合或已离场的人不算；已进入互动阶段的 UAP 被动参与者可以作为施加者。多名施加者符合条件时，同一个对象的同一次高潮仍只结算一次。不额外按自愿与否分类；SSC 自有性交任务（如调教、仪式）及单人行为不走这条戒律。
- **主人免疫。** 对象当前是 SSC 主人时，这条戒律不增加其恶堕率，也不启动或延长冷却。复用现有主人身份查询，不要求对象是施加者实际绑定的主人；仅拥有主人资格不算免疫。免疫只针对这条戒律，不改变其他恶堕来源。
- **单次收益与冷却。** 符合条件的对象本人高潮增加 **0.5 个百分点**恶堕率（需求值 `+0.005`，不超过满值），仅在实际加值后进入 **600 tick** 冷却。冷却按受影响对象记录，换施加者或换场次不刷新，存读档保留截止时间。冷却内的高潮照常发生，但不加值、不续期、不补发；到期也不自动结算，等下一次真实高潮。首版不另设单场次数上限。
- **现有结算与叠加。** 复用 [RJW 本人高潮观察](../../../Sexslavecraft/common/SSCCorruptionGelSceneRuntime.cs)的原调用前后计数、场次身份与重入边界，作为独立消费者；不借用旧伴侣恶堕补丁的阈值预判，也不占凝胶额度。与现有来源独立叠加，共用 100% 上限及 [Need_Corruption](../../../Sexslavecraft/common/Need_Corruption.cs) 的历史、特性和满值分化规则；不直接升锁链、扣意志或发调教经验。
- **实现与验证范围。** UAP 优先读取已进入互动阶段的有效会话参与者；普通 RJW 用接收方与已登记伴侣作为候选，按当前任务复查是否仍在原场。无法确认场次时跳过，不按附近人物或同床名单推断。结算前复查对象和至少一名符合条件的其他参与者仍在原非 SSC 场次，以及施加者锁链与文化档位、对象性别、当前主人身份及原需求归属；确认有正增量后先认领冷却，再写入需求。冷却以独立游戏组件稀疏存储并按需清理，不做逐 tick 扫描，也不在读档时重放事件。验证重点是默认关闭、性别筛选、SSC 场次排除、多人同场无直接配对仍可触发、集合／离场者不计入、多人符合只结算一次、主人免疫且不占冷却、无对象本人真实高潮不发放、冷却边界与换场／存读档、凝胶叠加和满值裁剪。四语与源码镜像已落实，图标与文案获实机认可。
