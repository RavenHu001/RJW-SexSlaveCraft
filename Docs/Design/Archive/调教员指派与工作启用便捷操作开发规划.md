## 1. 问题与交付范围

部分玩家已经把角色设为主人，却因没有在原版工作面板中启用“调教”，无法在性奴的指定调教员名单里找到该角色。现有候选过滤没有解释这一原因，玩家还需要跨面板完成设置。

本批让具备资格、仅缺工作启用的角色进入指派菜单，点击一次完成指派与启用；对已有指派但工作关闭的情况，提供原位置启用入口。训练页与关系概览采用一致的规则和提交服务。

本批保留单个 `selectedTrainer` 引用。第21项整体重构与多人指派仍暂缓；不增加轮换、批量工作模板、独立自动调教系统或全局默认开启设置。新开发仅面向1.7，1.6／Common保留冻结基线。

## 2. 已确认的操作规则

### 2.1 指派菜单

| 角色状态 | 菜单表现 | 点击行为 |
| --- | --- | --- |
| 调教员身份有效，其他指派条件满足，调教工作已启用 | 沿用角色名及主人／授权后缀 | 指派；不改原工作优先级 |
| 同上，仅调教工作未启用 | 角色名附“指定并启用调教工作”说明 | 启用调教工作并指派 |
| 身份及关系条件满足，但原版禁止从事该工作 | 灰色条目，提供具体原因 | 不可启用或指派 |
| 不具备调教员身份或训导官任职资格 | 沿用原资格限制 | 不通过指派自动取得身份、资格或开启任职 |

候选范围继续使用当前地图自由殖民者，排除自身，保留原存活、倒地、目标身份、绑定与限制规则。本批仅放宽“工作优先级必须大于0”的前置条件，并为工作禁止提供原因；不借此扩大原版奴隶、囚犯或离图角色的候选范围。

主人固定具备调教员身份；性奴仍须有训导官资格且手动开启任职。取得资格、开启任职、选择主人身份和打开菜单本身，都不自动启用工作。

### 2.2 工作启用与后续管理

- 仅工作关闭时设置原版默认优先级3；已启用时保留玩家设置的数值。普通勾选模式和数字优先级模式都使用原版工作系统。
- 玩家之后关闭调教工作，保留已有指派，不在查询、Tick或生命周期通知中重新开启。
- 已指派但工作关闭时，显示“调教工作未启用”，并提供“启用”操作。只调整当前指定者的工作，不重新指派、不重复授予非主人调教许可。
- 身份失效、原版工作禁止、倒地、离图等原因分别显示；仅在确实是工作未启用且当前允许启用时提供可用按钮，不以“启用”承诺解决其他不可用原因。
- 清空、更换指派或关闭性奴调教员任职时，不自动关闭原角色的调教工作；同一角色可能还承担其他任务。
- 启用只改变工作安排，不强制打断当前Job、立即生成调教任务或绕过研究、排程、冷却、身体、预约与目标许可。

### 2.3 同一工作类别的影响

当前 `TrainSexSlave` 同时包含日常调教、人格排泄和人格植入WorkGiver。人格排泄目前仅提供手动入口；人格植入会自动扫描已有有效凝胶分配的空壳。

菜单与就地启用入口的悬停说明须明确“启用调教工作类别，同时允许其中符合原条件的其他工作”。本批保留这套分类与各任务原判定，不拆分工作类型。玩家主动设置的凝胶分配仍是原任务条件，启用操作本身不新增分配。

实现补充：过期检查与失败撤回只读原版`priorities`字段取得实际保存值，避免勾选模式将不同正数统一显示为3；字段不匹配则拒绝提交，写入仍走原版setter。

目标DLL中，`Pawn_WorkSettings.WorkIsActive`只判断`GetPriority(w)>0`；非数字模式下，已启用工作的`GetPriority`返回3。`DefaultPriority`为3；`SetPriority`会拒绝原版禁用的工作类型，并将WorkGiver缓存标记为待刷新，返回类型是`void`。实现不能把调用完成当作启用成功，也不能靠`WorkIsActive`替代`WorkTypeIsDisabled`及工作设置初始化检查。

## 4. 提交与保存契约

### 4.1 共享查询与提交

优先在现有指派服务附近提取小范围工作状态与提交辅助，训练页和关系概览复用；具体命名在实施时确定。区分“有身份／资格”“允许指派给此对象”“工作能够启用”“当前工作已启用”，避免继续用单个bool承担所有显示和拒绝原因。

工作安排属于原版工作设置，不注册到个人能力开关框架、不新增人格字典bool、健康标记、Scribe字段或旧档迁移。`selectedTrainer`、调教许可、性奴任职开关分别留在原保存源；本次启用后的优先级沿原版保存／加载和既有人格流程，不新增迁移或重置规则。

显式菜单操作提交“指定”或“指定并启用”的意图；后台自动协调、读取指派及普通资格查询不能顺带启用工作。已指派者的“启用”也必须是显式提交，不能为了复用而重放整个指派授权事务。

### 4.2 一次提交的检查顺序

1. 捕获来源角色、Comp、当前指定者、实际绑定主人、游戏及所属界面上下文；对候选角色捕获Comp、人格token和工作设置实例。保留现有过期保护，并覆盖同Comp人格替换。
2. 点击时复查原上下文及当前候选资格、地图、工作设置初始化与原版工作禁止；预检目标的指派及非主人授权，确认强制限制不会拒绝。只读查询不修复数据或初始化工作列表。
3. 对照菜单原操作意图和观察到的工作状态。若玩家在菜单打开后关闭了原先启用的工作，旧“指定”选项不得擅自打开；工作状态或相关上下文变化时拒绝旧请求并刷新。不得在点击时重新捕获凭据，使旧请求获得新人格或新载体的权限。
4. 明确需要启用时，按原版接口设置默认优先级，并核实结果；再完成指派与必要授权的提交。实施时把可能拒绝的检查集中到写入前，减少多次写入之间的外部回调。
5. 如启用后指派提交失败，本次新增工作启用不得残留，指派和调教授权也不得留下部分修改。仅在仍是原载体且值仍属本次写入时撤回；不覆盖回调或其他操作写入的新状态。若实际路径存在重入或异常，须用对应故障用例验证收尾，不能无条件声称具备完整事务回滚。
6. 成功后刷新原训练页／关系概览显示。失败返回具体原因，不用泛化提示掩盖工作禁止与身份失效。

已指派者就地启用使用相同的上下文与工作检查，另复查原指定引用未变；不更改绑定、授权或指派。原工作面板继续是同一保存值的另一入口，不新增“已同意自动开启”等永久状态。

## 5. 界面与文案范围

新增状态与操作包括“指定并启用调教工作”“调教工作未启用”“启用”、工作禁止／状态变化失败原因及整类工作的影响说明。现有主人、非主人授权后缀继续保留，避免多个后缀挤在同一行；布局以实际测量处理，详细原因优先放悬停。

工作关闭只说明工作状态，不能显示为调教员身份已关闭；同床、归属及自我调教等读取有效指定者的功能，继续沿既有身份与关系语义，不因工作关闭清空指派。

实施时补齐简中、繁中、英文和俄文Keyed资源及已有镜像，复用轻量键／参数检查。此次规划不回填运行文案，不新建缺失的Def镜像，也不抽象整个ITab布局。

## 6. 实施顺序与最小验收

先拆清状态查询与显式提交，再接共用菜单、已指派者就地启用及四语显示，最后选择相关回归和实机范围。按[测试准则](../../Development/Reference/测试编写与执行准则.md)复用[调教员测试](../../../Tests/TrainerIdentity/README.md)、[整合测试](../../../Tests/TrainerIntegration/README.md)与[概览UI测试](../../../Tests/BondOverviewUI/README.md)，不按下表逐行新增永久测试或穷举组合。

| 验收重点 | 必须成立的行为 |
| --- | --- |
| 基础操作 | 未启用工作的合格主人可见，一次点击完成启用与指派；已启用者保持原优先级；两种工作显示模式语义一致 |
| 资格与许可 | 训导官资格／任职、原版工作禁止及目标强制限制仍有效；失败不改变工作、授权或指定者 |
| 已有指派 | 手动关工作仍保留指派，就地启用不重新授权；换人或清空不关闭原调教员工作，也不影响其其他对象 |
| 旧请求与异常 | 换绑、改指定者、Comp／人格／工作设置替换及工作状态变化拒绝旧操作；选取实际写入后的失败或重入边界，检查不会遗留本次半成品或覆盖新状态 |
| 两个界面 | 训练页与关系概览都经过相同提交；禁止条目、工作暂停与身份失效能区分，按钮和悬停只读 |
| 既有消费与保存 | 自动工作仍遵守原排程及任务条件；工作关闭不改变同床等关系；保存加载保留原指派、任职与工作设置，不新增迁移 |
| 共享工作类别 | 有有效凝胶分配时，启用后人格植入仍按原条件工作；无分配不凭启用新建任务，提示与实际影响一致 |

自动化优先验证公共提交及真实入口接入，UI入口不重复整套机制组合；原版工作接口和存档路径按最终改动选择代表性验证。完整场景、菜单可读性及与原版工作面板互相操作留给实机，结果单独登记，不能用当前DLL取证代替。
