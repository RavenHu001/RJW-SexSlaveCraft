同一受训者可以指派多名调教员。只要受训者可接单，任一符合现有工作条件的名单成员都能通过原版工作系统领单。同一目标从实际领单、走位到结算结束只由一个日常任务占用。关系页沿用现有头像网格和拖放把手管理名单。

## 玩家规则

| 情形 | 首版行为 |
| --- | --- |
| 已指派多人 | 名单按添加顺序展示。各角色按自己的原版工作优先级接单，实际领单顺序决定执行者。主／备、名单优先级与轮换留给后续方案。 |
| 成员暂不可用 | 停工、倒地、离图或任职停用时保留名单记录，界面显示对应状态。其他符合条件的成员仍可接单。训练开关、排班、普通冷却和短失败冷却按受训者共享。 |
| 空名单 | 自动工作没有执行者。已绑定主人仍可按原有准入手动发起或主持仪式，非主人继续核对有效指派及许可。 |
| 尚未绑定 | 新增只接受具备首次建绑资格的 SSC 主人。可指派多名符合条件的候选，任何一位都可能经实际执行和现有成长结算成为唯一绑定主人。旧档或解绑后保留的其他成员仍可查看和移除，首次建绑时按实际资格拒绝。 |
| 指派非主人 | 已绑定目标沿用显式指派附带 `ReceiveTraining` 授权的流程，预览同时显示授权。装备或特化的强制禁止仍优先。 |
| 只准主人 | 有效规则生效后，名单仅登记在世且仍可引用的绑定主人。主人死亡或销毁时名单为空，原许可继续生效。实际任务照常核对主人的任职和执行资格。解除限制后，由玩家重新添加第三方。 |
| 移除一人 | 只移除选中的关系，保留其他成员、原版工作优先级、已保存的调教许可与实际绑定。离图、失格和停工的成员也可移除。 |
| 指派影响当前任务 | 重新检查被移除者的实际准入。已失权的排队任务在确认原 Job 后撤销并释放预占，在途任务最迟在下一个守卫检查时退出。已实际开始的同一任务沿用现有收尾和一次结算，受训身份等持续条件仍适用。实际主人仍满足手动准入时，其任务继续执行。 |

首次建绑候选扩展会改变玩家对谁可能成为主人的预期。关系页应随候选操作说明这一后果，新增预检和提交均核对 `IsMaster`。首次建绑成功后，沿用绑定通知按生效许可协调其余成员。工作状态与任职资格继续沿用第 21.1 项。启用工作仅在优先级为零时设原版默认值 3，已有优先级按原值保留。 [调教准入](../../../Sexslavecraft/common/Restrictions/SSCRestrictionTrainingUtility.cs) · [限制策略](../../../Sexslavecraft/common/Restrictions/SSCRestrictionPolicy.cs) · [建绑与成长结算](../../../Sexslavecraft/common/CorruptionProgressionUtility.cs)

## 名单保存与变更

1. 在 1.7 的 `CompSexSlaveTraining` 保存私有、有序的 Pawn 引用列表。使用 `Scribe_Collections.Look` 的 `LookMode.Reference`。旧 `selectedTrainer` 仅用于加载旧格式，引用解析后在 `PostLoadInit` 迁成零或一条。以明确的格式版本区分旧档和新档，写入显式空列表，保证清空后读档仍为空。迁移保留离图、停工和暂时失格引用，按原顺序去除空引用、重复、自身和永久失效项。先完成名单迁移，再执行旧任职迁移及许可协调，任职迁移枚举名单中的所有间接引用。 [原存档入口](../../../Sexslavecraft/Comps/Comp_Train.cs) · [旧任职迁移](../../../Sexslavecraft/common/SSCTrainerIdentityMigration.cs) · [读档协调](../../../Sexslavecraft/common/Restrictions/SSCRestrictionGameComponent.cs)
2. 提供只读名单和成员查询。区分保存的成员、当前具备任职资格的成员，以及某一任务此时可用的执行者。地图扫描直接查询成员，关系页使用独立快照。将 `SSCRestrictionTrainerAssignment` 与 `SSCTrainerWorkUtility.Request` 扩展为新增、逐人移除和就地启用工作。保留原角色、组件、人格、地图、绑定与工作载体复查，用名单版本识别迟到请求。第三方授权和新增在同一提交内完成。工作优先级写入触发外部回调时重新核验，失败时按现有规则精确撤回本次写入。 [指派提交](../../../Sexslavecraft/common/Restrictions/SSCRestrictionTrainerAssignment.cs) · [工作事务](../../../Sexslavecraft/common/SSCTrainerWorkUtility.cs)
3. 生命周期写入统一维护名单。受训者退出 SSC 性奴身份时清理整份名单。常规解绑按旧规则移除原主人并保留明确指派的第三方，沿用原主人缺失时的旧数据清理分支。兔克隆按现有继承入口取得独立副本，再按自身规则协调。人格排泄和植入继续按现有的身份清理、实际绑定恢复流程处理，名单随原角色的调教组件管理。 [身份变更](../../../Sexslavecraft/common/SSCIdentityUtility.cs) · [绑定与解绑](../../../Sexslavecraft/common/SSCBondUtility.cs) · [兔克隆](../../../Sexslavecraft/common/RabbitCloneUtility.cs) · [人格流转](../../../Sexslavecraft/common/ExcretionUtility.cs) · [限制协调](../../../Sexslavecraft/common/Restrictions/SSCRestrictionLifecycle.cs)

## 日常工作预约与结算

`WorkGiver_Training` 继续作为工作入口。将 `TrainerAssignmentUtility.IsPotentialTrainingTarget`、统一调教准入和 `SSCRestrictionPolicy` 的首次建绑分支改为成员检查。粗筛保持只读，沿用现有研究、身份、工作、地图、排班、冷却和兼容检查。原版强制命令保留既有的排班例外。名单变更只使实际失权的任务退出。 [工作入口](../../../Sexslavecraft/WorkGiver/WorkGiver_Training.cs) · [目标筛选与准备](../../../Sexslavecraft/common/TrainerAssignmentUtility.cs) · [预约与开始守卫](../../../Sexslavecraft/common/Restrictions/SSCRestrictionJobGuard.cs)

现行日常任务用单槽预约，并在启动接收任务时主动释放发起者预约。走位期间受训者可能尚无接收 Job，现有恢复路径会将这种占用误作残留。场景收尾还早于训练收益及冷却记账。1.7 原版任务清理先释放预约，再调用驱动清理，因此接收交接和任务结束都要核对目标的占用归属。 [日常驱动](../../../Sexslavecraft/JobDriver/JobDriver_Train.cs) · [接收交接与清理](../../../Sexslavecraft/common/TrainingJobUtility.cs)

1. **预约和领单。** 保留原版单槽预检及预约。原版玩家点名可能在排队前预占，进入实际执行后才登记目标的日常占用。以受训者、发起者、当前驱动、`Job` 引用与 `loadID` 核对领取和归属。在登记接收任务或触发可重入通知前复查。竞争失败沿正常拒绝路径退出，短失败冷却仍只由现行业务失败路径写入。
2. **接收与收尾。** 让占用跨过接收任务交接，持续到收益、排班和冷却记账完成，或当前任务中断收尾。接收器只复用同一发起者的配对，调用原生收尾、清理接收任务或释放占用前核对归属。兼容设备上的常驻接收器沿原有交接约束处理。`isBeingTrained` 的旧状态和启停写入只用于原有状态展示及兼容，释放日常占用以实际 Job 归属为准。仪式继续以有效 Lord 管理占用，检查入口同时识别实际日常占用。
3. **读档恢复。** 在工作扫描开始前从实际发起任务、保存的准备目标、原版预约或精确的发起／接收配对恢复占用。覆盖旧档中发起者已走位、受训者尚无接收 Job 的情况。失效凭据按原归属清理，另一名调教员的新任务和有效仪式可继续。保持现有一次性结算标记与旧档恢复边界。

## 实施顺序与验收

| 阶段 | 交付与关键用例 |
| --- | --- |
| 1. 名单、许可与迁移 | 旧单人档迁为一条。新版多人、显式空名单和离图成员能存读档。覆盖重复添加、逐人撤销、强制禁止、只准主人、解绑保留第三方，以及工作启用失败撤回和迟到请求。优先扩展 `TrainerIdentity` 和 `RestrictionCore`。 |
| 2. 工作选择与占用 | A 停工时 B 可接单。A、B 同时领单时只有一名执行者及一次结算。验证移除发生在排队、走位和实际开始后的不同结果。覆盖原任务中断、旧回调与第二人接管、兼容接收器，以及旧档在途恢复。优先扩展 `RitualLifecycle` 的交接用例及 `InteractionProtection` 的守卫用例。 |
| 3. 关系页及其他入口 | 多人网格可逐卡添加、撤销、启用工作和导航。覆盖窄窗、滚动、切角后迟到拖放、仪式首人失败而第二人有效、同床第二张候选床及自我调教快照。复用 `BondOverviewUI`、`RitualSelection`、`SharedBed`、`SelfTrainingManual`，四语键和镜像走现有轻量检查。 |
