## 1. 设定与首批范围

首批是低技术阶段将现成纳米催情液用于压制敌人与奴隶的初步尝试。角色改造熟悉的武器，将其工作部分或投射物涂满、浸泡在紫色药液中，尝试让药液随伤口进入目标体内。技术仍然粗糙，投送依赖实际命中，附带创伤也难以精确控制。

共同原则是：**在中世纪工艺能够实现的范围内，保证武器能够造成伤口、送入药液，并尽量减少其他伤害。** 保留与载体相符的物理威力和误杀风险，不把伤害统一压为 1～2 点，也不承诺绝对非致命。“原始”指相对于专用 PNA 发射器而言的粗糙应用方式，三件成品均设为 `Medieval`。

| 武器 | 载体与外观方向 | 职责与局限 |
| --- | --- | --- |
| 纳米催情液短矛 | 绳带固定金属矛头的手工短矛经过少量改造，工作部分覆盖明显的紫色药液；保留手工武器的木材与金属质感 | 稳定贴身施加。直接接触允许较高药量，但使用者承担近战风险；实际刺伤保留。 |
| 纳米催情液吹箭筒 | 手工吹箭筒及浸液轻箭，外观体现普通器械与紫色药液结合 | 低精度、较高射速的中近距离投送。主要在 5～10 格工作，射程末端效率下降，难以应对护甲。 |
| 纳米催情液轻弩 | 轻型弩具配合携液弩矢，保留中世纪弩的辨识度 | 高精度、较远射程，主要在 15～30 格工作。较慢预热与较高单次创伤是代价，仍不擅长重甲目标。 |

首批只使用普通紫色纳米催情液。药量差异解释为不同载体能够送入身体的药液量不同，不表示已经掌握浓缩工艺或精密注射技术。新补液系统、浓缩武器与高阶原型枪不并入本批范围；涂层续航的具体规则见第 7 节。

研究描述方向：

> 尝试将纳米催情液用于压制敌人与奴隶。通过改造熟悉的武器，让附着的药液随伤口进入目标体内。手段仍然粗糙，效果依赖实际命中，也难以避免投送过程中造成的伤害。

“简易应用”提供操作现成药液的初步经验，武器研究将其用于战斗投送；“浓缩技术”继续负责提高药液浓度的加工方法。既有简易发射器保持 `SSC_RES_PNASimpleApp` 与 `PrecisionRifling` 前置，不要求先研究这条新武器支线；浓缩、人格排泄等既有发展线也保持原顺序。

研究本身可用不等于原液已经充足。制作仍消耗真实材料，首批不新增普通 PNA 的合成生产线，也不解除既有基础调教的蓝图条件。

## 5. PNA 结算规则

### 5.1 伤口成立后输入一次

1. 先执行正常物理命中、闪避、护甲与伤口结算。
2. 未命中、完全被护甲挡住、未实际形成伤口时，不输入 PNA。锐器伤害被护甲转为钝伤、只形成挫伤时也不输入。
3. 确认本次产生有效开放伤口后，输入一次本武器经意识修正后的剂量。药量不按伤害数值同比缩放，也不按同次传播的伤口数量累加。
4. 同一游戏 tick 的两个独立有效命中分别结算；嵌套伤害与传播不能重复认领同一次投送，也不能吞掉其他独立命中。
5. 药效结算继续检查真实身体和当前身份／锁链，避免健康回调改变状态后沿用过期判定。

不以投射物接触、扣血或开始执行伤害函数代替“有效伤口成立”。新武器不沿用现有发射器的固定创伤替换、无伤保护或治疗分支。

### 5.2 剂量与意识修正

| 武器 | 归一化基础负荷 | 原始严重度尺度的等值 |
| --- | --- | --- |
| 纳米催情液短矛 | `0.15` | `0.30` |
| 纳米催情液吹箭筒 | `0.06` | `0.12` |
| 纳米催情液轻弩 | `0.10` | `0.20` |
| 现有简易发射器参照 | `0.075` | `0.15` |

共享系统的满严重度为 2，配置与输入时必须区分两种尺度。新武器沿用现有发射器的意识抗性、高意识快照和单次输入上限规则；实现时核对取值时点，避免本次活化等回调反过来改变同次剂量。剂量作为独立参数配置，不直接用物理伤害推导。

### 5.3 身份与负荷分流

| 目标 | 物理部分 | PNA 部分 |
| --- | --- | --- |
| 普通有效肉体 | 保留实际伤口 | 输入普通负荷，沿用现有阶段、清除与成瘾规则 |
| 主人 | 保留实际伤口 | 药效免疫，不建立受药负荷 |
| 有效锁链目标 | 保留实际伤口，不治疗 | 输入活化负荷，沿用现有正面作用与普通成瘾豁免 |
| 不满足共享入口准入的目标 | 按正常物理流程处理 | 不输入 PNA |

沿用 `SSCPnaExposureUtility.ApplyExposure` 的 `Weapon` 来源，不直接添加负荷 Hediff。现行武器来源对已有成瘾每次有效输入基础增加 0.01，末期再增加 0.20；首次成瘾仍按满负荷规则处理。本批不改这些共享规则，但须观察快速吹箭对已有成瘾的加深速度。

代码参照：[共享输入](../../../Sexslavecraft/common/SSCPnaExposureUtility.cs)、[负荷数学与阈值](../../../Sexslavecraft/common/SSCPnaMath.cs)。

## 6. 开发步骤

按实际工作类型划分，避免为三件武器拆分过多批次。**当前源码需要一次结算适配，不能直接视为纯 XML 扩展。** 现有 `DamageWorker_SSCPna.FinishHit` 会让有效锁链目标跳过伤口，普通分支则替换为固定创伤；`healAmount` 设为零也不会取消该无伤分流。XML 数值配置无法同时保留本方案要求的伤口与活化效果。

| 步骤 | 工作内容 | 完成依据 |

### 6.2 已实现的处理器结构

三件武器共用一个继承 `DamageWorker_AddInjury` 的通用涂覆伤害处理器，独立于现有 PNA 发射器。涂覆类型位于 [DamageWorker_SSCPnaCoated.cs](../../../Sexslavecraft/DamageWorker/DamageWorker_SSCPnaCoated.cs)，共用抗性与剂量工具位于 [SSCPnaWeaponDoseUtility.cs](../../../Sexslavecraft/common/SSCPnaWeaponDoseUtility.cs)，均使用仓库 `SexSlaveCraft` 命名空间与 SSC 前缀；武器 XML 尚未接入。

| 组件 | 职责 |
| --- | --- |
| `SSCPnaCoatingExtension` | 新伤害定义的配置，使用明确的归一化 `baseLoad` 与既有 `recordHediff` 引用，不混用旧扩展的原始严重度字段；非法／缺失药量只禁用 PNA，正常物理伤害继续。 |
| `DamageWorker_SSCPnaCoated : DamageWorker_AddInjury` | 三件武器共用。三个 DamageDef 分别配置药量与物理字段，短矛／吹箭产生 `Stab`，弩矢沿用 Arrow 的 `Cut`；只在 `Apply` 外层接入药效结算。 |

处理器调用一次 `base.Apply`，随后执行药效结算。每次调用的样本与结果均保存在局部变量中；不增加工人实例上的认领字段，不按 Pawn 或 tick 缓存命中。部位传播只得到一次药效，同 tick 与嵌套的独立命中也各有自己的结算。

简化后仍由 XML 保留三件武器各自的伤害、穿甲、射程、射速、精度、伤势类型和剂量，护甲与共享身份分流规则不变。舍弃的是 `DamageWorker_Stab` 特有的主动内部部位选择，以及命中内部时按外层 0.75／内层 0.4 分配创伤的流程；改用 `DamageWorker_AddInjury` 及各 DamageDef 配置的普通传播。常规外部部位命中的基础创伤可以保持一致，但两种流程在内部命中或特殊指定部位时并不等价，不能宣称完全复刻原版刺伤，也不能保证绝不伤及内部部位。

单处理器主要减少类与调用组织；伤口确认、意识快照、一次输入和回调检查仍需实现。首批不拆分刺伤／箭伤处理器，也不给旧发射器增加涂覆模式开关；保留现有发射器的固定创伤、有效链无伤／治疗与药效行为。

首版不需要新增全局伤害 Harmony 补丁、自定义射击 Verb、投射物 C#、持久化命中组件或存档迁移。`DamageWorker_PNA.cs` 的低阶入口已改为调用[共用工具](../../../Sexslavecraft/common/SSCPnaWeaponDoseUtility.cs)，物理分流、输入认领及原时序保留；`SSCPnaExposureUtility` 未修改。提取前后的处理器使用同组回归对照，详见[实现记录](../../Development/Completed/PNA武器共用抗性与剂量工具实现与测试.md)。

### 6.3 一次命中的执行顺序与剂量

1. **物理处理前只读捕获。** 读取已有高意识抗性快照；没有快照时读取此刻意识，保存局部候选值及识别人工部位所需信息。这里不添加 Hediff、不刷新或改变药效，避免被挡住的攻击也建立抗性记录。
2. **完整执行通用父类的物理流程。** 正常处理伤害量、穿甲、护甲变换、命中部位、传播、失血、断肢、死亡及战斗日志，不设置忽略护甲，不补写固定伤害；与原版刺伤的传播区别见 6.2。
3. **确认本次有效开放伤口。** 采用 6.4 的结果检查；没有合格伤口立即返回原结果。物理伤害已经致死的目标也不再输入 PNA。
4. **协调并重查身体。** 调用现有 `RefreshBodyState`，检查存读档状态、目标有效性与当前主人身份。主人只保留物理结果，不建立抗性快照；当前锁链状态交给共享入口分流。
5. **确定剂量并按需保存快照。** 无既有快照且命中前意识大于 2 时，只有到此时才允许建立旧类型的抗性快照。添加过程中重查身体，不能覆盖期间独立命中已建立的快照，或强行继续写入被回调移除的对象。
6. **调用一次共享输入。** 使用 `ApplyExposure(pawn, dose, SSCPnaExposureSource.Weapon)`，由其继续复核身份、链与负荷载体；不治疗，不因药效失败重跑物理伤害。返回原 `DamageResult`。

实现采用**本次物理伤害之前的意识**作为无快照时的取样时点，防止本击造成的意识下降立即放大同一击药量；同次传播各部位也使用同一候选值。已有抗性快照优先，非法旧快照沿用除数 1 的回退；无快照时意识除数至少为 0.2。候选值在本次调用内固定，期间嵌套命中建立的快照留给其自身及后续命中使用，不覆盖，也不反算外层剂量。

归一化剂量计算为 `dose = min(baseLoad / divisor, 0.5)`，等价于旧算法“原始严重度单次上限 1，再除以满值 2”。三件武器的 `baseLoad` 分别为 `0.15 / 0.06 / 0.10`。例如意识 100% 时输入 15／6／10 个百分点；意识 20% 且无旧快照时分别为 50／30／50 个百分点，**单次上限不是满负荷 100%**。非有限或非正药量不输入；新读取的意识若为非有限值，使用除数 1，且不建立非法快照。

药量不因本次伤害减半、部位数量或材质伤害倍率同比变化。完全阻挡与转钝伤仍先由伤口条件排除；只有合格的开放伤口才按上述独立剂量处理。已有成瘾、需求补充、97% 阶段与满负荷首次成瘾全部留在共享入口。

### 6.4 有效伤口的具体判定

以**当前 Apply 返回的 `result.hediffs`** 为候选，结合当前健康列表确认实际写入；不扫描旧伤寻找施药机会，也不只用整次的 `wounded`、`deflected` 或总伤害判定。一次传播可能同时包含被挡住与成功伤口，存在合格伤口即可输入一次。

- 首批认可原版 `Stab` 与 `Cut` 的正严重度肉体伤口；必须由本次携液伤害产生，排除 `Bruise`、`Crush`、`Crack`、附加非伤口 Hediff，以及只有结果对象却没有实际写入的情况。
- 不用实时 `BleedRate > 0` 作为必要条件。原版该值还受种族、基因、止血和人工部位等因素影响，不能将“不流血”一律当成“没破皮”；机械／非肉体仍由共享准入排除，非有机人工部位另行排除。
- 同击摧毁自然部位时，若原伤口已被清理，可由本次结果中的新鲜缺失记录及匹配的 `lastInjury` 确认；人工部位摧毁不算肉体开放伤口。命中前保留的部位信息用于防止人工部位移除后被误认。
- 原版 `Stab`／`Cut` 均显式 `canMerge=false`，首批可用本次记录与健康列表中的真实实例核对。第三方若将它们改为可合并或替换整个伤害结果，需要另验证合并接收语义，不能仅靠全身严重度差值推断，以免把嵌套的其他命中误算给外层；本批不因此增加全局补丁。
- 健康回调中切换主人、绑定／解绑、移除伤口或使目标失效，都要在药效写入前重查。物理已完成后不因这些变化补伤、治疗或回滚正常创伤。

### 6.5 与第二步 XML 及构建的衔接

三个独立 DamageDef 分别配置短矛、吹箭和弩矢的剂量，并明确 `armorCategory=Sharp`、肉体／实体伤势和对应物理参数。短矛新增专用 ToolCapacityDef 与 ManeuverDef，由动作的 `verb.meleeDamageDef` 指向携液刺伤；不向原版 `Stab` 能力增加新动作，避免影响其他武器。未涂覆的柄击仍用普通钝伤，不能通过其旧伤口触发 PNA。吹箭与弩矢直接从投射物配置指定新 DamageDef，当前视觉弹丸使用继承原版 Bullet 的 `Projectile_SSCPnaTrail`；物理命中继续由原版流程执行。

三份 DamageDef 是同一处理器的三份数据配置，不对应三个 C# 处理器，也不要求按武器名称写判断分支。当前入口从本次 `DamageInfo.Def` 的 `SSCPnaCoatingExtension` 读取剂量；短矛与吹箭的剂量不同，且近战／远程标记不同，弩矢还使用不同的肉体伤势。独立定义便于分别调整这些参数。攻击伤害与穿甲仍主要由近战 Tool／远程 Projectile 配置；以后多件武器若携液剂量及伤害语义相同，可以共用一份 DamageDef，不要求每件武器永久绑定唯一伤害定义。

不使用 `extraMeleeDamages`、投射物 `extraDamages` 或零伤害的第二次 PNA 命中：它们是独立 `TakeDamage` 调用，不能自动证明前一份物理伤害成功开口，也会引入额外命中、护甲与重复剂量问题。
