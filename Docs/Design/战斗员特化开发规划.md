# 战斗员特化开发规划

记录日期：2026-09-26。

状态：**规划整理完成，功能尚未实现。** 本文区分维护者已确认的玩法规则、建议实施方案及待定数值，不代表战斗员已经可以在游戏中使用。

开发分支：`codex/combatant-specialization`，从本地 `main` 的 `3e45a52` 创建。源码检查基线为该提交，仓库版本为 `2.3.3`；本轮尚未指定目标发布版本。

关联：[未来内容开发规划](未来内容开发规划.md)第 18 项。普通／终极状态参考公交车；人格迁移、配方保护和能力管理可参考现有实现，但不照搬训导官的持续资格及终极禁用机制。

## 1. 已确认的方向与规则

| 项目 | 当前约定 |
| --- | --- |
| 定位 | 通用战斗强化，覆盖近战、远程及战场稳定性。 |
| 特殊能力 | 只有完成终极化后才授予；普通培养达到 100% 不授予能力。具体能力效果仍为草案。 |
| 终极状态 | 与公交车一样，终极化后永久保留效果，不因解绑、退阶或切换培养方向而失效。 |
| 成长来源 | 仅保留被实际主人调教、击杀生物两项。 |
| 调教动态收益 | 按本次调教评分变化。 |
| 击杀动态收益 | 按目标实际体型变化，取代此前讨论的目标战斗力方案。 |
| 经验与培养进度 | 动态依据是事件质量，不增加随当前特化进度变化的加速或衰减倍率。 |
| 熟练收益 | 熟练阶段增加常态承伤乘数，提供持续减伤；具体倍率待平衡。 |

普通完成后沿用现有人格凝胶加工、植入的终极化路线。首版优先复用进度、存档、界面和人格搬运结构；不将本任务扩大为整个特化框架重构。

## 2. 首版范围及尚未确定的入口条件

首版开发范围：

- 增加可选择的战斗员方向及普通阶段属性。
- 接入两项成长事件和统一进度结算。
- 完成普通／终极互斥、方向切换及人格凝胶终极化流程。
- 终极化后授予特殊能力，处理使用条件、冷却、存档及人格迁移。
- 补齐研究说明、阶段说明、能力提示、四语文本及验证。

选择门槛尚未最终确定。已有 `SSC_RES_Combatant` 研究可复用，当前成本 1200、前置为人格编辑。此前提出的“有效绑定、锁链第 2 阶段”等属于候选入口条件，不是已确认规则；原版奴隶与自由殖民者的适用范围也需要在实施前明确。

入口条件不能被实现为终极状态的持续生效条件。战斗员不增加因解绑、退阶自动退出方向或禁用终极成果的维护机制，也不新增调教员资格或行为许可强制条目。

本轮不需要助攻分配、逐次命中经验、连续射击限频、伤害贡献统计或新的军事训练工作。其他特化、身份体系重构及现有身体培养的数值修复分别处理。

## 3. 培养阶段和被动收益草案

### 3.1 阶段安排

| 阶段 | 拟定行为 |
| --- | --- |
| 0～20% | 培养中，开始通过两类事件增长。 |
| 20%～50% | 基础战斗员，提供基础被动收益。 |
| 50%～100% | 熟练战斗员，增强被动收益，并获得常态减伤。 |
| 普通 100% | 普通培养完成，取得凝胶终极化加工资格，仍不获得特殊能力。 |
| 完成终极化并植入 | 终极被动收益及特殊能力生效；之后可培养其他方向。 |

20% 沿用现有特化基础阶段的常用门槛作为实施草案；熟练阶段按本次讨论使用 50%。界面和终极化配方应沿用公共完成容差 `SpecializationCompletionProgress = 0.999f`，实际保存进度仍限制在 0～1，避免显示完成但配方拒绝。

### 3.2 首轮平衡候选值

以下全部为数值草案，未经实战平衡验证：

| 属性 | 基础：20% | 熟练：50% | 终极化 |
| --- | ---: | ---: | ---: |
| 射击精度原始评分 `ShootingAccuracyPawn` | +2 | +4 | +6 |
| 近战命中原始评分 `MeleeHitChance` | +2 | +4 | +6 |
| 瞄准时间 `AimingDelayFactor` | ×0.95 | ×0.90 | ×0.85 |
| 角色近战冷却 `MeleeCooldownFactor` | ×0.95 | ×0.90 | ×0.85 |
| 精神崩溃临界值 `MentalBreakThreshold` | −0.02 | −0.04 | −0.06 |
| 承伤乘数 `IncomingDamageFactor` | ×1.00 | ×0.90 | ×0.80 |
| 特殊能力 | 无 | 无 | 授予 |

每个阶段写入完整效果，阶段之间不累加。普通完成保持熟练收益；终极化用终极状态替换普通状态，不能把普通 ×0.90 与终极 ×0.80 同时叠加。

精神崩溃临界值是日常也生效的属性，不能描述为仅在战场生效。是否保留这项稳定性收益仍属于被动效果定稿范围。

### 3.3 已核对的属性计算规则

本次讨论期间检查了本机 RimWorld 1.6 原版 XML 与程序集，得到以下接入依据：

- `MeleeHitChance`、`MeleeDodgeChance`、`ShootingAccuracyPawn` 会将原始评分通过曲线转换为概率；Hediff 中的 `+0.10` 不能直接理解为最终概率增加 10 个百分点。
- 脚部培养的闪避 `5 / 12 / 20` 不能仅凭数值大小判定为百分比填错。此前把它视为明显量级错误的疑问已由曲线核对修正。
- 角色近战攻击冷却读取 `MeleeCooldownFactor`；现有手部培养写入的 `MeleeWeapon_CooldownMultiplier` 属于武器侧属性，不能据此认定角色已经获得相应加速。
- `AimingDelayFactor` 是瞄准时间，`RangedCooldownFactor` 是远程射击轮次之间的冷却，不等同于整套射击周期或连射内部间隔。

新特化直接使用正确的角色属性。现有身体培养、装备及其他特化的实际收益需要作为叠加验证基线；发现的问题另记修复范围，不能未经核对整体改写。

## 4. 成长结算

### 4.1 共用约定

两项来源共用一个战斗员进度提交入口：

- 当前培养方向必须是战斗员，不能向其他方向发放经验。
- 已终极化者不再获得普通培养经验；普通完成后停止累计。
- 输入增量必须是正的有限值；异常评分、体型或进度不能写入 NaN、无穷值等损坏数据。
- 最终进度限制在完成范围内，并同步普通 Hediff；不得只增加 Hediff 严重度而遗漏组件进度。
- 每次完整事件只领取一次，保存读档、重复通知或回调重入不能重复发奖。
- 切换方向保留本方向历史；切回时恢复，不把其他方向进度带入。
- 不增加按当前进度变化的收益倍率。

初始显示用的 Hediff 严重度下限不应凭空产生经验；实际培养进度以组件为准。

### 4.2 被实际主人调教

确认“主人”使用 `SSCBondUtility.GetBoundMaster(receiver)`，与实际施教者比较。不能使用会回退到指定调教员的 `GetResolvedMaster`，也不能只检查施教者拥有主人身份。

现有日常调教在完整结算时已取得本次 `score`。建议直接复用该次评分，不新增战斗员评分系统，也不在结算后再按已经变化的状态重新计算。

建议初始公式，`delta` 为 0～1 范围的进度增量：

```text
delta = clamp(score / 2000, 0, 0.04)
```

| 本次评分 | 进度增量 |
| ---: | ---: |
| 0 或负值 | 0 |
| 20 | 1% |
| 40 | 2% |
| 60 | 3% |
| 80 及以上 | 4% |

除数 2000、单次上限 4% 及非正评分处理均为数值草案。完成正常结算才发放，中断不发放，不扣已有进度。

**待定：是否同时包含绑定仪式。** 若包含，按整场成功结算一次，不能按每个阶段重复发放。仪式质量与日常调教 `score` 不是相同量纲，需要定义明确映射后再接入，不能直接套用同一个除数。

### 4.3 击杀生物

已确认以目标实际体型作为动态依据，不使用 `combatPower`，不追加按装备、伤势、技能或双方实力差距计算的强度模型。

拟在死亡处理前读取游戏当时返回的 `Pawn.BodySize` 并保留快照，死亡真正完成后结算。不得用物种的 `RaceProps.baseBodySize` 替代实际体型，也不在目标死亡转换或销毁之后重新推算。

建议初始公式：

```text
有效体型：有限且大于 0
delta = min(0.01 × bodySize, 0.03)
```

| 目标实际体型 | 进度增量 |
| ---: | ---: |
| 0.25 | 0.25% |
| 0.5 | 0.5% |
| 1.0 | 1% |
| 2.0 | 2% |
| 3.0 及以上 | 3% |

基础倍率 1%、单次上限 3% 及不设最低奖励均为草案。小体型目标自然提供较少经验，异常或无效体型不发奖。此前的战斗力平方根公式和最低 0.25% 奖励不再属于当前方案。

技术接入候选为 `Pawn.Kill(DamageInfo?, Hediff)` 的死亡前后边界：死亡前保留目标体型、原存活状态、攻击者及本次结算所需信息，死亡后确认真实发生死亡，再提交奖励。仅进入死亡方法不能算击杀成功。

建议首版只处理能直接确定击杀者的死亡，不引入助攻比例或长期伤害来源追踪。同一次死亡的重复调用、嵌套调用及主从伤害转移不得重复产生奖励。

下列范围尚未确认，实施前应选定简单且一致的规则：

| 边界 | 当前建议／待定事项 |
| --- | --- |
| 生物种类 | 建议覆盖人类、动物、昆虫等血肉角色；机械体和特殊模组种族是否计入待定。 |
| 狩猎与敌对 | 建议狩猎可以成长，不把敌对状态设为所有击杀的必要条件。 |
| 屠宰、处决 | 建议首版排除，尚未确定。 |
| 已倒地目标的补刀 | 是否奖励待定；先前逐次伤害方案的倒地排除不能自动沿用为已确认规则。 |
| 失血、火焰、陷阱等间接死亡 | 建议只接受能明确归属的情况；缺少击杀者时不额外追溯。具体入口覆盖待核对。 |

## 5. 普通、终极与人格状态

### 5.1 状态安排

拟增加普通战斗员与终极战斗员两个 Hediff 定义，不增加终极禁用定义。

| 情境 | 处理约定 |
| --- | --- |
| 当前培养普通战斗员 | 普通状态反映本方向进度，按阶段提供收益。 |
| 切到其他方向或明确选择“未选择” | 归档进度、移除普通状态；保留所有已完成的终极成果。 |
| 普通达到完成门槛 | 仅标为普通完成，不能自动添加终极状态或能力。 |
| 终极化后切换方向、解绑、退阶 | 终极被动和已授予能力保留，不进行资格停用。 |
| SSC 身份或原版身份变化 | 不因此撤销战斗员终极成果；具体行为仍遵守游戏正常使用条件。 |
| 抽取或替换人格 | 终极成果随人格保存和恢复，原身体对应效果、能力及临时强化按人格流程清理。 |

永久生效是指终极成果不依赖后续绑定和阶段资格，不代表旧身体在失去该人格后仍保留一份成果。普通、终极状态不能共存；已有终极记录不能再次加工为同一终极成果。

### 5.2 凝胶加工与恢复

- 保存当前方向、各方向历史和本方向唯一状态标签。
- 凝胶终极化配方拟要求当前方向为战斗员、达到公共完成门槛、持有普通标签且无终极记录；具体工作量和材料成本仍待定。
- 筛料和消耗原料前的最终检查使用同一判定，防止制作过程中条件变化导致材料被吞。
- 加工时深拷贝人格数据，只替换战斗员标签，保留其他方向历史及终极成果。
- 植入前清理接收身体原有的战斗员进度派生状态、能力和临时强化，避免宿主成果污染源人格。
- 完成人格恢复后统一对账；明确选择“未选择”时，不从终极标签重新认领培养方向。

## 6. 终极特殊能力草案

**只在终极化后授予是已确认规则；下列名称、效果、时长及施放条件仍为候选。**

首版建议一项手动自身强化能力，暂名“战斗超频”：

| 项目 | 建议初值 |
| --- | --- |
| 授予依据 | 终极战斗员记录；与当前培养方向、主人及锁链阶段无关。 |
| 发动方式 | 玩家手动对自身发动。 |
| 持续时间 | 1800 ticks，正常速度下约 30 秒。 |
| 冷却 | 10000 ticks，约 4 游戏小时，从发动成功开始计算。 |
| 近战效果 | `MeleeCooldownFactor` 额外 ×0.80。 |
| 远程效果 | `RangedCooldownFactor` ×0.80。 |
| 防御效果 | `IncomingDamageFactor` 额外 ×0.85。 |
| 普通使用条件 | 建议要求征召、未倒地、未处于精神状态及正常施放条件；最终条件待定。 |

若采用终极常态承伤 ×0.80 和能力额外 ×0.85，发动期间本特化合计承伤为 ×0.68，即减伤 32%。这不是包含护甲、其他模组和伤害分摊后的最终承伤承诺。近战冷却同样与常态及其他来源相乘，需要实战验证。

首版建议以持续时间和冷却限制使用；不同时引入资源消耗、疲劳、多模式或自动施放。特殊能力不得成为普通阶段的经验来源。

### 6.1 能力与冷却管理建议

- 原版 `Ability` 已保存冷却到期时间和持续长度，正常存读档应复用这套机制。
- 切换培养方向、解绑和退阶不删除终极能力，不刷新冷却。
- 临时无法施放时显示不可用原因，发动时复查正常使用条件，不改变终极完成记录。
- 现有 `HediffComp_GiveAbility` 在 Hediff 移除时直接删除技能。战斗员需要检查其与人格恢复、重复添加及冷却的配合，不能仅挂上组件就视为闭环完成。
- 人格凝胶目前没有能力冷却字段。建议只保存本特化能力的冷却快照，不搬运整个原版能力列表。
- 建议以同一存档内的游戏 tick 到期时间保存冷却，使离图、凝胶储存和加工期间时间继续经过，植入不刷新冷却。
- 正在运行的临时强化不随人格迁移；新身体恢复能力和原有冷却即可。
- 冷却采集、`CopyFrom`、Scribe、加工复制及植入恢复都要覆盖；恢复顺序应保证授予能力后再写入正确冷却，不被重新创建覆盖。

## 8. 开发拆分与验收

| 阶段 | 开发内容 | 完成依据 |
| --- | --- | --- |
| 1：普通方向 | 枚举、研究与菜单、普通 Hediff、阶段属性、进度切换和读档 | 能选择、切换、恢复本方向；属性计算使用正确角色 Stat；50% 起常态减伤。 |
| 2：两类经验 | 主人身份核对、调教评分公式、击杀体型公式、事件去重 | 两来源独立有效，其他来源不发奖；中断、重复死亡和异常输入不污染进度。 |
| 3：终极与人格 | 完成判定、凝胶配方、消耗前检查、标签保存恢复及终极永久性 | 普通完成不自动终极化；成功加工植入后永久保留，普通／终极互斥。 |
| 4：终极能力 | 能力授予、施放、临时强化、冷却和人格迁移 | 普通阶段无能力；终极阶段跨方向保留；读档、加工及换身体不刷新冷却。 |
| 5：整体验证与说明 | 四语、研究说明、玩家说明、相关回归和真实游戏测试 | 规则与界面一致，实际培养速度、承伤和武器表现经过核验。 |

重点自动回归场景：

- 各阶段边界、公共完成容差、进度上限与异常浮点值。
- 实际主人、其他主人、指定调教员的区别；正常完成与中断、重复结算的区别。
- 不同体型、单次上限、无最低奖励、真实死亡与未死亡、同一死亡重复通知。
- 切换方向保留历史，明确留空不被终极状态自动改写。
- 普通与终极互斥；解绑、退阶、身份变化及切换方向不移除终极效果。
- 凝胶加工资格变化时在消耗前阻止，复制和恢复不混入宿主数据。
- 普通 100% 无技能；终极技能只授予一份；存读档和人格恢复保留冷却。

实机验收需要覆盖近战、单发远程、连射、狩猎及已选定的击杀边界，检查身体培养、装备、多个终极特化和伤害分摊叠加后的表现。原版接口核对和模型回归不能替代这些测试；战斗改动模组的兼容性也不能仅凭通用事件入口宣称成立。

可扩展现有 `PersonalitySpecializations`、`PersonalityTraits` 和人格植入相关套件，并按需要增加战斗员规则／事件测试。新增套件须加入 [统一验证脚本](../../Scripts/Test-All.ps1)；具体测试数量以实际运行结果为准。

## 9. 开始实现前仍需定稿的内容

1. 选择入口的研究、身份、绑定和锁链门槛，以及原版奴隶是否适用。
2. 被动属性是否采用第 3 节全部项目；常态减伤倍率及其他具体数值。
3. 日常调教奖励公式与上限，是否把完整绑定仪式纳入同一来源。
4. 击杀奖励基础倍率与上限；生物类型、狩猎、屠宰、处决、补刀及间接死亡的范围。
5. 终极能力最终效果、名称、持续时间、冷却和普通施放条件。
6. 终极化配方成本及能力冷却迁移的具体保存方案。

以上待定项不改变第 1 节已确认的方向：特殊能力仅终极化授予、终极化永久生效、仅两项成长来源、动态依据为调教评分和目标体型、熟练阶段获得常态减伤。
