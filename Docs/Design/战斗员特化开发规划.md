# 战斗员特化开发规划

记录日期：2026-09-26。

状态：**阶段一普通方向已实现并获维护者实机可用确认；阶段二至五尚未完成。** 入口、普通阶段属性、进度历史及四语资源已接入；两类经验、终极化和特殊能力尚未接入。终极能力名称、强化幅度与冷却时长仍待确定。实施记录见[战斗员特化阶段一](../Development/战斗员特化阶段一.md)。

开发分支：`codex/combatant-specialization`，从本地 `main` 的 `3e45a52` 创建。源码检查基线为该提交，仓库版本为 `2.3.3`；本轮尚未指定目标发布版本。

关联：[未来内容开发规划](未来内容开发规划.md)第 18 项。普通／终极状态参考公交车；人格迁移、配方保护和能力管理可参考现有实现，但不照搬训导官的持续资格及终极禁用机制。

## 1. 已确认的方向与规则

| 项目 | 当前约定 |
| --- | --- |
| 定位 | 通用战斗强化，覆盖近战、远程及战场稳定性。 |
| 选择入口 | 直接使用已有 `SSC_RES_Combatant` 研究；不要求 SSC 身份、主人绑定或锁链阶段，原版奴隶可用。 |
| 被动属性 | 采用第 3 节全部项目、阶段和数值，作为首版实现基准。 |
| 特殊能力 | 只有完成终极化后才授予；普通培养达到 100% 不授予能力。提高近战伤害与移动速度，降低近战／远程冷却、承伤和疼痛，持续 1 游戏小时。 |
| 能力使用 | 正常技能释放条件，并且只在征召时可见、可用；名称、各项强化幅度及冷却时长待定。 |
| 终极状态 | 与公交车一样，终极化后永久保留效果，不因解绑、退阶或切换培养方向而失效。 |
| 成长来源 | 仅保留正常完成日常调教、直接击杀目标两项；日常调教不限施教者是否为实际绑定主人，绑定仪式和屠宰不计入。 |
| 调教动态收益 | 基础收益为 `clamp(score / 2000, 0, 0.04)`；实际绑定主人施教时，基础收益再乘以 1.5，单次上限 6%；其他施教者上限 4%。 |
| 击杀动态收益 | 仅按目标实际体型变化，采用 `min(0.01 × bodySize, 0.03)`；不设最低奖励，不附加目标种族、敌对或倒地等属性筛选。 |
| 经验与培养进度 | 动态依据是事件质量，不增加随当前特化进度变化的加速或衰减倍率。 |
| 熟练收益 | 50% 起常态承伤 ×0.90；终极化后替换为 ×0.80。 |
| 终极化流程 | 与其他特化一致：普通培养完成后，经已有雕刻台人格凝胶加工、植入流程获得终极成果。 |
| 代码复用 | 优先复用现有特化数据、事件评分、人格配方、能力授予及原版技能组件，只补充必要的战斗员接入。 |

普通完成后沿用现有人格凝胶加工、植入的终极化路线。首版优先复用进度、存档、界面和人格搬运结构；不将本任务扩大为整个特化框架重构。

## 2. 首版范围及选择入口

首版开发范围：

- 增加可选择的战斗员方向及普通阶段属性。
- 接入两项成长事件和统一进度结算。
- 完成普通／终极互斥、方向切换及人格凝胶终极化流程。
- 终极化后授予特殊能力，处理征召限制、正常冷却和存档；人格迁移沿用共用流程。
- 补齐研究说明、阶段说明、能力提示、四语文本及验证。

选择入口直接复用已有 `SSC_RES_Combatant` 研究，保留当前成本 1200 及前置 `SSC_RES_SlaveSpecialization`。不新增身份、绑定、锁链阶段或其他培养资格门槛；已有界面支持的自由殖民者与原版奴隶均可选择，不要求先设置为 SSC 性奴。已终极化者沿用已完成展示，不重复培养同一方向。

需要同步处理两处既有的隐含门槛：训练页目前在 SSC 主人、未设定身份时隐藏特化区，`ReconcileSpecialization` 会提前跳过主人。战斗员入口、布局高度计算和普通状态同步必须覆盖这些情况；只在下拉菜单中新增一项不能满足本次规则。调整限定在战斗员及其所需的共用展示，不放开其他特化自己的资格要求。

普通培养及终极成果均不增加身份、解绑或退阶失格维护；也不新增调教员资格或行为许可强制条目。日常调教正常完成即可提供经验，实际绑定主人只影响额外加成，不作为经验资格、选择或维持战斗员的门槛；未绑定者也可通过符合现有任务规则的日常调教及直接击杀成长。

本轮不需要助攻分配、逐次命中经验、连续射击限频、伤害贡献统计或新的军事训练工作。其他特化、身份体系重构及现有身体培养的数值修复分别处理。

## 3. 培养阶段和被动收益（已确认）

### 3.1 阶段安排

| 阶段 | 行为 |
| --- | --- |
| 0～20% | 培养中，开始通过两类事件增长。 |
| 20%～50% | 基础战斗员，提供基础被动收益。 |
| 50%～100% | 熟练战斗员，增强被动收益，并获得常态减伤。 |
| 普通 100% | 普通培养完成，取得凝胶终极化加工资格，仍不获得特殊能力。 |
| 完成终极化并植入 | 终极被动收益及特殊能力生效；之后可培养其他方向。 |

基础阶段使用 20%，熟练阶段使用 50%。界面和终极化配方沿用公共完成容差 `SpecializationCompletionProgress = 0.999f`，实际保存进度仍限制在 0～1，避免显示完成但配方拒绝。

### 3.2 首版属性数值

维护者已确认按下表实现全部属性；数值仍需在实现后进行实战平衡验证：

| 属性 | 基础：20% | 熟练：50% | 终极化 |
| --- | ---: | ---: | ---: |
| 射击精度原始评分 `ShootingAccuracyPawn` | +2 | +4 | +6 |
| 近战命中原始评分 `MeleeHitChance` | +2 | +4 | +6 |
| 瞄准时间 `AimingDelayFactor` | ×0.95 | ×0.90 | ×0.85 |
| 角色近战冷却 `MeleeCooldownFactor` | ×0.95 | ×0.90 | ×0.85 |
| 精神崩溃临界值 `MentalBreakThreshold` | −0.02 | −0.04 | −0.06 |
| 承伤乘数 `IncomingDamageFactor` | ×1.00 | ×0.90 | ×0.80 |
| 特殊能力 | 无 | 无 | 授予 |

每个阶段写入完整效果，阶段之间不累加。普通完成保持熟练收益；终极化用终极状态替换普通状态，不能把普通 ×0.90 与终极 ×0.80 同时叠加。

精神崩溃临界值按表保留；它是日常也生效的属性，不能描述为仅在战场生效。

### 3.3 已核对的属性计算规则

本次讨论期间检查了本机 RimWorld 1.6 原版 XML 与程序集，得到以下接入依据：

- `MeleeHitChance`、`MeleeDodgeChance`、`ShootingAccuracyPawn` 会将原始评分通过曲线转换为概率；Hediff 中的 `+0.10` 不能直接理解为最终概率增加 10 个百分点。
- 脚部培养的闪避 `5 / 12 / 20` 不能仅凭数值大小判定为百分比填错。此前把它视为明显量级错误的疑问已由曲线核对修正。
- 角色近战攻击冷却读取 `MeleeCooldownFactor`；现有手部培养写入的 `MeleeWeapon_CooldownMultiplier` 属于武器侧属性，不能据此认定角色已经获得相应加速。
- `AimingDelayFactor` 是瞄准时间，`RangedCooldownFactor` 是远程射击轮次之间的冷却，不等同于整套射击周期或连射内部间隔。

新特化直接使用正确的角色属性。现有身体培养、装备及其他特化的实际收益需要作为叠加验证基线；发现的问题另记修复范围，不能未经核对整体改写。

## 4. 成长结算

### 4.1 共用约定

两项来源共用一个战斗员进度提交入口：

- 当前培养方向必须是战斗员，不能向其他方向发放经验。
- 已终极化者不再获得普通培养经验；普通完成后停止累计。
- 输入增量必须是正的有限值；异常评分、体型或进度不能写入 NaN、无穷值等损坏数据。
- 最终进度限制在完成范围内，并同步普通 Hediff；不得只增加 Hediff 严重度而遗漏组件进度。
- 每次完整事件只领取一次，保存读档、重复通知或回调重入不能重复发奖。
- 切换方向保留本方向历史；切回时恢复，不把其他方向进度带入。
- 不增加按当前进度变化的收益倍率。

初始显示用的 Hediff 严重度下限不应凭空产生经验；实际培养进度以组件为准。

### 4.2 正常完成日常调教与主人加成

正常完成日常调教即可获得基础经验，不要求施教者为实际绑定主人。其他主人、指定调教员及其他符合现有任务规则的施教者均按基础公式结算；经验规则不额外放开调教任务自身的资格或行为许可。

仅在判定额外加成时核对“主人”：使用 `SSCBondUtility.GetBoundMaster(receiver)`，与实际施教者比较。不能使用会回退到指定调教员的 `GetResolvedMaster`，也不能只检查施教者拥有主人身份。

现有日常调教在完整结算时已取得本次 `score`。直接复用该次评分，不新增战斗员评分系统，也不在结算后再按已经变化的状态重新计算。

已确认公式，`delta` 为 0～1 范围的进度增量：

```text
baseDelta = clamp(score / 2000, 0, 0.04)
isBoundMaster = trainer != null && SSCBondUtility.GetBoundMaster(receiver) == trainer
delta = baseDelta * (isBoundMaster ? 1.5 : 1.0)
```

| 本次评分 | 其他施教者 | 实际绑定主人 |
| ---: | ---: | ---: |
| 0 或负值 | 0 | 0 |
| 20 | 1% | 1.5% |
| 40 | 2% | 3% |
| 60 | 3% | 4.5% |
| 80 及以上 | 4% | 6% |

除数 2000、普通单次上限 4%、实际绑定主人倍率 1.5 及主人单次上限 6% 均已确认。先将基础收益封顶，再应用主人倍率；不能在加成后重新限制为 4%。非正或非有限评分不给经验；加成不改变这一规则。完成正常结算才发放，中断不发放，不扣已有进度，实际到账仍受剩余培养进度限制。

**绑定仪式明确排除。** 不接入绑定仪式任一阶段或完整结束的奖励回调，不建立仪式质量到调教评分的换算。

### 4.3 直接击杀

已确认只接受直接击杀，并排除屠宰。对符合这两个事件条件的目标，仅以实际体型计算经验；不使用 `combatPower`，不检查种族是否血肉、阵营、敌对状态、是否倒地、装备、技能或双方实力差距。

拟在死亡处理前读取游戏当时返回的 `Pawn.BodySize` 并保留快照，死亡真正完成后结算。不得用物种的 `RaceProps.baseBodySize` 替代实际体型，也不在目标死亡转换或销毁之后重新推算。

已确认公式：

```text
有效体型：有限且大于 0
delta = min(0.01 × bodySize, 0.03)
```

| 目标实际体型 | 进度增量 |
| ---: | ---: |
| 0.25 | 0.25% |
| 0.5 | 0.5% |
| 1.0 | 1% |
| 2.0 | 2% |
| 3.0 及以上 | 3% |

基础倍率 1%、单次上限 3% 及不设最低奖励均按此实现。小体型目标自然提供较少经验，异常或无效体型不发奖。此前的战斗力平方根公式和最低 0.25% 奖励不再属于当前方案。

技术接入候选为 `Pawn.Kill(DamageInfo?, Hediff)` 的死亡前后边界：死亡前保留目标体型、原存活状态、攻击者及本次结算所需信息，死亡后确认真实发生死亡，再提交奖励。仅进入死亡方法不能算击杀成功。

只在本次致死事件能够直接归属到击杀者时结算，不引入助攻比例或长期伤害来源追踪。有 `DamageInfo.Instigator` 不足以单独证明属于直接击杀，还需要识别屠宰及间接死亡路径；射弹命中的直接致死仍归属发射者。每次死亡只结算一次，重复或嵌套调用不得再次发奖。

按“直接击杀、只看体型、屠宰除外”落实边界：

| 边界 | 处理规则 |
| --- | --- |
| 目标种类 | 人类、动物、昆虫、机械体及模组种族等 `Pawn` 均不因种类排除；建筑、物品不属于该击杀入口。 |
| 狩猎与敌对 | 直接致死的狩猎计入；友方、中立或敌对不影响奖励资格和倍率。 |
| 屠宰 | 明确排除，即使能取得操作者和目标体型也不发奖。 |
| 处决、已倒地目标的补刀 | 不另行排除；满足直接击杀且不是屠宰时计入。 |
| 失血、持续燃烧、陷阱等间接死亡 | 不计入，不追溯最后攻击者、点火者或陷阱建造者。 |
| 主从伤害转移导致死亡 | 属于间接死亡，不产生战斗员击杀经验。 |

这些是对已确认规则的实施解释，接口覆盖仍需验证；不能因某条原版死亡路径没有通常的伤害参数，就默默增加新的目标属性限制。

## 5. 普通、终极与人格状态

### 5.1 状态安排

拟增加普通战斗员与终极战斗员两个 Hediff 定义，不增加终极禁用定义。

| 情境 | 处理约定 |
| --- | --- |
| 当前培养普通战斗员 | 普通状态反映本方向进度，按阶段提供收益。 |
| 切到其他方向或明确选择“未选择” | 归档进度、移除普通状态；保留所有已完成的终极成果。 |
| 普通达到完成门槛 | 仅标为普通完成，不能自动添加终极状态或能力。 |
| 终极化后切换方向、解绑、退阶 | 终极被动和已授予能力保留，不进行资格停用。 |
| SSC 身份或原版身份变化 | 不因此撤销战斗员终极成果；具体行为仍遵守游戏正常使用条件。 |
| 抽取或替换人格 | 终极成果随人格保存和恢复，原身体对应效果、能力及临时强化按人格流程清理。 |

永久生效是指终极成果不依赖后续绑定和阶段资格，不代表旧身体在失去该人格后仍保留一份成果。普通、终极状态不能共存；已有终极记录不能再次加工为同一终极成果。

### 5.2 凝胶加工与恢复

- 保存当前方向、各方向历史和本方向唯一状态标签。
- 凝胶终极化配方要求当前方向为战斗员、达到公共完成门槛、持有普通标签且无终极记录。
- 成本和设施沿用现有其他特化：雕刻台 `TableSculpting`、工作量 `3500`、工作速度 `GeneralLaborSpeed`、1 份合格人格凝胶，不增加其他材料。兼容现有八种凝胶基底，研究条件使用 `SSC_RES_Combatant`。
- 复用 `RecipeDef_PSTag` 的 `requireSpecializationType`、`requireSpecializationComplete`、`hediffToAdd` 和 `exclusiveTags`，以及 `Recipe_PSTagWorker`、`PersonalityGelUtility` 的加工复制流程。
- 筛料和消耗原料前的最终检查使用同一判定，防止制作过程中条件变化导致材料被吞。
- 加工时深拷贝人格数据，只替换战斗员标签，保留其他方向历史及终极成果。
- 植入前清理接收身体原有的战斗员进度派生状态、能力和临时强化，避免宿主成果污染源人格。
- 完成人格恢复后统一对账；明确选择“未选择”时，不从终极标签重新认领培养方向。
- 能力随终极标签通过现有机制授予；冷却和临时强化按第 6.1 节沿用共用处理，不另建人格或终极化系统。

## 6. 终极特殊能力

**已确认六项效果、持续 1 游戏小时、正常技能释放条件及仅征召时可见可用。名称、六项效果的具体幅度和技能自身的冷却时长仍待确定。** 第 3 节确认的是被动属性，不等于确认此前主动能力的候选倍率。

首版按一项手动自身强化能力接入；文档使用“终极战斗员能力”作为描述性占位名，不把此前的“战斗超频”定为正式名称。

| 项目 | 实现约定 |
| --- | --- |
| 授予依据 | 终极战斗员记录；与当前培养方向、主人及锁链阶段无关。 |
| 发动方式 | 玩家手动对自身发动。 |
| 持续时间 | 1 游戏小时，即 `GenDate.TicksPerHour = 2500 ticks`，替代原 1800 ticks 草案。 |
| 技能自身冷却 | 时长待定；原 10000 ticks（4 游戏小时）仅是旧候选值，不视为本次已确认。 |
| 增加近战伤害 | 临时 Hediff 的 `MeleeDamageFactor`，倍率待定。 |
| 减少近战冷却 | 临时 Hediff 的 `MeleeCooldownFactor`，倍率待定。 |
| 减少远程冷却 | 临时 Hediff 的 `RangedCooldownFactor`，倍率待定；不额外修改连射内部间隔。 |
| 减少承伤 | 临时 Hediff 的 `IncomingDamageFactor`，倍率待定。 |
| 加速 | 按提高移动速度接入 `MoveSpeed`，幅度待定；不扩展为所有工作或身体能力加速。 |
| 减少疼痛 | 临时 Hediff 阶段的 `painFactor`，倍率待定；不使用提高疼痛休克阈值代替减疼痛。 |
| 可见及可用 | 只有征召时显示按钮并允许施放，其他条件复用正常技能流程；不附加 SSC 身份、绑定、锁链阶段或特殊资源门槛。 |

主动效果与终极被动相乘。例如本特化发动期间承伤为 `0.80 × 主动承伤倍率`，近战冷却为 `0.85 × 主动近战冷却倍率`；在主动数值确定前不固定总减伤或总攻速结论。移动速度、疼痛和近战伤害也要核对与身体培养、装备及其他来源的叠加。

征召限制针对按钮和技能发动，按成功施放后临时强化持续满 2500 ticks 处理，不额外设计解除征召即清除强化。技能授予本身仍永久保留，不能通过征召／解除征召反复添加删除技能。首版不引入资源消耗、疲劳、多模式或自动施放；特殊能力不得成为普通阶段的经验来源。

### 6.1 能力、冷却与代码复用

- 原版 `Ability` 已保存冷却到期时间和持续长度，正常存读档应复用这套机制。
- 切换培养方向、解绑、退阶以及征召变化不删除终极能力，不刷新冷却。
- 优先使用原版 `AbilityDef` 的 `displayGizmoWhileUndrafted = false`、`disableGizmoWhileUndrafted = true` 和征召显示配置。按钮隐藏不等于执行校验；还需覆盖排队施放后解除征召的情况，必要时仅增加一个轻量的征召判定组件，复用其余正常技能检查。
- 能力授予优先复用 `HediffComp_GiveAbility`；效果优先复用原版 `CompAbilityEffect_GiveHediff`、临时 Hediff 属性和 `HediffComp_Disappears`，避免自建增益计时器和整套施法逻辑。原版效果组件可能写入消失时间，配置和验证必须保证最终恰为 2500 ticks。
- `HediffComp_GiveAbility` 在 Hediff 移除时删除技能。仅人格抽取／替换等实际移除成果的流程清理对应技能，普通状态对账不应反复移除重加终极 Hediff。
- **人格迁移按“与其他特化一致”的共用流程落实。** 当前 `CompPersonalityStore` 保存特化标签和进度，没有通用能力冷却存储；首版不增加战斗员专属冷却快照、凝胶中的到期时间字段或整个能力列表搬运。
- 因此正常存读档保留原版冷却；人格迁移后通过终极标签重新授予能力，冷却按原版新实例初始化。此前“凝胶加工和换身体保留原冷却”的专门方案不再作为首版要求。这是沿用现有流程的实现结果，而非现有共用代码已支持跨人格冷却保存。
- 正在运行的临时强化不随人格迁移；人格抽取／替换时清理旧身体对应强化，避免与新身体重复保留。若将来增加通用能力冷却迁移，应由共用人格机制统一提供。

## 8. 开发拆分与验收

| 阶段 | 开发内容 | 完成依据 |
| --- | --- | --- |
| 1：普通方向 | 枚举、研究与菜单、身份无关的入口和对账、普通 Hediff、阶段属性、进度切换和读档 | 原版奴隶及其他已有界面支持者均无需 SSC 身份或绑定即可选择；第 3 节属性生效，50% 起常态减伤。 |
| 2：两类经验 | 日常评分公式、实际绑定主人 1.5 倍加成、直接击杀体型公式、屠宰排除及事件去重 | 两来源独立有效；正常日常调教不限实际主人，普通上限 4%、主人上限 6%；绑定仪式、间接死亡和屠宰不发奖，目标种族、敌对和倒地属性不造成额外过滤。 |
| 3：终极与人格 | 完成判定、凝胶配方、消耗前检查、标签保存恢复及终极永久性 | 普通完成不自动终极化；成功加工植入后永久保留，普通／终极互斥。 |
| 4：终极能力 | 复用能力授予、六项临时强化、2500 ticks 时长、征召条件和正常冷却 | 普通阶段无能力；终极跨方向保留，只有征召时可见可用；正常读档保留冷却，换人格沿用共用重新授予流程。 |
| 5：整体验证与说明 | 四语、研究说明、玩家说明、相关回归和真实游戏测试 | 规则与界面一致，实际培养速度、承伤和武器表现经过核验。 |

重点自动回归场景：

- 各阶段边界、公共完成容差、进度上限与异常浮点值。
- 研究前后、SSC 主人／未设定身份、原版奴隶、无绑定和低锁链阶段的入口及状态同步。
- 正常日常调教均有基础经验；实际绑定主人为 1.5 倍，其他主人及指定调教员无额外加成；未绑定者不因缺少主人而被经验入口拒绝。覆盖普通 4% 与主人 6% 上限、非正及非有限评分不发奖、接近完成时截断，以及日常中断、重复结算与绑定仪式不发奖。
- 不同体型、单次上限、无最低奖励、真实死亡与未死亡、同一死亡重复通知。
- 相同体型的不同种族、阵营及倒地状态直接击杀奖励相同；屠宰和间接死亡不给经验。
- 切换方向保留历史，明确留空不被终极状态自动改写。
- 普通与终极互斥；解绑、退阶、身份变化及切换方向不移除终极效果。
- 凝胶加工资格变化时在消耗前阻止，复制和恢复不混入宿主数据。
- 普通 100% 无技能；终极技能只授予一份；征召显示、解除征召隐藏及排队后的执行复查。
- 技能六项效果与被动叠加正确，持续恰为 2500 ticks；正常存读档保留冷却，征召切换不重建技能。
- 人格恢复按共用流程重新授予能力；旧身体技能及临时强化清理，无专属冷却迁移字段。

实机验收需要覆盖近战、单发远程、连射、狩猎及已选定的击杀边界，检查身体培养、装备、多个终极特化和伤害分摊叠加后的表现。原版接口核对和模型回归不能替代这些测试；战斗改动模组的兼容性也不能仅凭通用事件入口宣称成立。

可扩展现有 `PersonalitySpecializations`、`PersonalityTraits` 和人格植入相关套件，并按需要增加战斗员规则／事件测试。新增套件须加入 [统一验证脚本](../../Scripts/Test-All.ps1)；具体测试数量以实际运行结果为准。
