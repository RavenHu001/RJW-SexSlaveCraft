首版采用“单选角色时的关系概览 Gizmo＋完整列表窗口”，让玩家直接辨认实际主人和绑定性奴，并定位关联角色。归属以性奴侧锁链为准；界面读取既有数据，不建立新的存档归属表。当前实施契约见下文及本轮验证记录。

## 1 目标与开发边界

- 选中主人时显示绑定数量和从属头像；选中性奴时显示实际主人。
- 明确区分实际绑定、指定调教员与 SSC 身份。指定第三方调教员不计入主人或从属名单。
- 展示同图、异图、旅队、容器内、死亡和位置不可用等状态，并提供与状态相符的定位操作。
- 查询、查看、翻页和定位保持只读；明确更换／清空调教员复用现有事务及授权校验。解绑、改绑、互动模式和批量命令仍沿用原入口。
- 新功能仅面向 RimWorld 1.7。1.6 和 Common 保持 2.4.1 冻结内容；当前正式版本仍为 2.4.2，本规划不预设下一发行版本。
- 本功能不接入 RJW 行为结算，不增加 Biotech 等 DLC 依赖，不修改角色成长、共振场、承伤或仪式奖励。

## 3 归属数据与只读查询

### 3.1 数据职责

| 数据 | 当前职责 | 概览规则 |
| --- | --- | --- |
| 性奴侧 `Hediff_ChainOfSexSlave.target` | 保存实际主人引用 | 作为有向归属的最终依据 |
| 主人侧 `Hediff_BridleOfSexSlave.targets` | 保存反向索引 | 用作候选来源，逐项复查锁链并去重 |
| `CompSexSlaveTraining.selectedTrainer` | 保存指定调教员 | 仅作为明确标注的次级信息，不推断主人 |
| `pawnIdentity` | 保存 SSC 主人／性奴身份 | 决定空状态文案，不代替真实归属 |
| `SSC_FlawedLovers` 等社会关系 | 保存具有额外条件的仪式奖励关系 | 不用于构建绑定名单 |

[GetBoundMaster](../../Sexslavecraft/common/SSCBondUtility.cs)直接读取锁链；同文件的 `GetResolvedMaster` 会回退到指定调教员，不用于本功能。社会奖励要求完整仪式、实际绑定及至少 80 好感，见[奖励入口](../../Sexslavecraft/common/SSCBondRelationUtility.cs)，因此已绑定但没有奖励关系是合法状态。

### 3.2 从属枚举

新增独立的概览查询，不修改 [GetBoundSlaves](../../Sexslavecraft/common/SSCMasterBondUtility.cs)。该方法用于玩法结算，排除死亡对象；概览需要保留仍有有效绑定的死亡角色。

第一批已实现独立候选收集，后续[性能优化](../Development/Verification/主从关系概览第一批性能优化与对比.md)改为流式读取缰绳、世界存活／死亡、原版 Temporary、旅队／运输成员；地图分别读取已生成 Pawn／Corpse，并一次遍历持有树收集两者，保留世界容器与飞船成员／货物来源。按实际锁链和 Pawn 引用去重，过滤空引用、自指、销毁和丢弃，不将死亡视为解绑。为避免重复地图递归，概览不再调用现有 AllPawns，但保持原候选来源及尸体补充；该原方法与玩法调用者不变。

查询与模型分别见 [Utility](../../Sexslavecraft/common/SSCBondOverviewUtility.cs)、[Model](../../Sexslavecraft/common/SSCBondOverviewModel.cs) 和 [World](../../Sexslavecraft/common/SSCBondOverviewWorld.cs)。位置事实与生命状态分离，指定调教员及其有效性单列，查询未就绪与没有关系分开表示。覆盖限于可枚举或仍有有效索引引用的对象，不恢复不可达角色。

数量、排序、头像和窗口行共用一次查询结果。默认顺序为当前地图存活对象、其他位置存活对象、死亡对象；组内按姓名排列，并以稳定角色标识处理同名。显示存活数量和总绑定数量，避免死亡对象混入可用人数。

### 3.3 反向索引的完整性

正常 [Bind](../../Sexslavecraft/common/SSCBondUtility.cs) 同时建立锁链和缰绳。以下兼容入口说明仅凭缰绳不能保证完整：

- 外部直接改写公开 `chain.target` 后，[锁链 Tick](../../Sexslavecraft/Hediff/Hediff_ChainOfSexSlave.cs) 才会整理双方索引；游戏暂停时可能尚未执行。
- 直接调用 `Hediff_ChainOfSexSlave.AddToPawn` 换主，会更新 target 和 observedMaster、清旧缰绳，但该入口自身不补新缰绳。后续 Tick 也可能因引用一致而提前返回；正常 Bind 会另外补齐。此为静态发现的兼容边界，后续应加入针对性夹具核验。
- [ValidTargets](../../Sexslavecraft/Hediff/Hediff_BridleOfSexSlave.cs) 可以过滤旧归属，不能发现遗漏对象，也不负责去重。

概览通过锁链反查补齐显示。若后续确认兼容入口需要修复，单独定义修复范围与回归，不在界面查询中调用 `RepairReciprocalLink`、`PruneInvalidTargets`、绑定、解绑或奖励维护。

### 3.4 状态语义

无锁链显示“未绑定主人”；有链但目标无效显示“绑定目标无效”。有主人身份而没有从属显示“暂无绑定性奴”。旧档身份未选择但仍有有效锁链时，照常显示真实绑定，不通过打开界面恢复身份。

[现有关系规则](../../Sexslavecraft/common/SSCBondRelationRules.cs)允许保留死亡主人的绑定。死亡、复活、是否生成到地图与绑定有效性分别处理；`!Spawned` 不能直接解释为失踪。阶段读取复用 [SSCIdentityUtility](../../Sexslavecraft/common/SSCIdentityUtility.cs) 的现行判定，不新增阈值。

## 4 界面与交互

### 4.1 单选关系卡片

入口为当前地图中单选的存活 Pawn，要求有现有训练组件，且有主人／性奴身份、有效绑定或需要说明的异常锁链。查询不要求可征召、允许调教或取得某项研究；无 SSC 身份且没有关系的普通角色不占用命令栏。多选时首版隐藏卡片。为保留反向漏项的发现能力，单选训练组件角色先登记受控探测，显示条件不能只看本地缰绳；空结果探测成本见第二批细化。

性奴、调教员卡片均为 130×75，复用原版机械师命令背景和边框；性奴顶部完整显示“拥有性奴：n”，下方自动缩放全部头像，无分页。相邻的独立“选择所有性奴”按钮在点击时核对当前地图现时锁链并沿原生 200 上限批选。主人为 75×75 方形、大头像与底部“选择主人”文字叠放，整块可安全定位并按实际目标选中。主人和调教员卡片不常驻姓名，详情移入悬停；即使同一人也分别标注，不存在的方向不占位置。主人卡片无总览或改主入口；其他面板的总览和调教员更换使用有底框的放大镜／铅笔图标，说明放入悬停。调教员面板提供更换入口，指派不进入绑定计数，异常双向数据保留各自事实。

头像悬停显示完整姓名、阶段、特化及位置；同图目标可高亮，头像直接承担定位，不再常驻逐行定位按钮。头像显示矩形随人数压缩，但原版肖像请求维持 40／56 两档，避免按人数产生新纹理尺寸；顶部数量使用与原版机械师一致的 Small 字号。正常同图不重复文字，死亡、容器和异地等特殊情况再提示。

### 4.2 完整列表窗口

总览为最大宽 680、按内容计算高度的紧凑头像网格。仅显示实际相关的主人／指定调教员／从属分区，采用 56 头像和短姓名，详情放入悬停；完整计数、既有排序及死亡成员仍保留，末项可达。调教员分区提供更换入口。

窗口支持滚动和可见网格裁剪，按屏幕限制尺寸，不强制暂停。更换选中来源、多选、来源死亡或失效时关闭，成功定位后关闭；普通使用不再维持异源固定浏览器。没有常驻手动刷新按钮，全局补漏仍服从共享预算，本地直接读取不等待该期限。

现有 [ITab](../../Sexslavecraft/ITab/ITab_SexSlaveTraining.cs)已经包含多个功能区，且可见性受原版法律身份或自我调教资格约束，因此不是首版唯一入口。后续如需 ITab 入口，应复用同一模型与窗口，不复制绑定逻辑。

### 4.3 定位规则

| 关联角色状态 | 显示与操作 |
| --- | --- |
| 当前地图已生成 | 高亮，点击定位并选中 |
| 另一张已加载地图 | 提示地图名称，点击切图并定位 |
| 冬眠舱等地图容器中 | 标注容器，定位可用的持有物；不承诺选中内部 Pawn |
| 旅队／运输途中 | 标注位置类别，定位原版支持的世界对象或位置 |
| 死亡且有可定位尸体 | 显示死亡，定位尸体或其可用容器 |
| 有有效绑定但位置不可用 | 保留关系，禁用定位并说明原因 |
| 销毁、丢弃或无效引用 | 排除无效名单项；若来源锁链仍存在，显示目标无效 |

点击时重新核对来源、实际锁链和目标有效性，再用原版定位能力判断操作。头像绘制、高亮和按钮命中使用同一行快照；旧行不应在改绑后继续以原关系执行操作。首版不扩展旅队成员面板或尸体作为来源时的独立入口。

## 5 刷新与性能

主人和调教员在登记来源时直接读取；从属优先读取缰绳并校验锁链，再合入本视图已知引用。本地刷新独立于全局预算，直接字段变化立即重读，等长原地换项与显示元数据每两秒兜底；首轮全局补漏前标注已知数量，不将已知零误报为没有绑定。完整扫描仍覆盖原有全部来源，仅由 Update 按预算补漏。

快照仅存在于当前游戏的运行时视图中，不保存到人格凝胶或 Scribe。复用既有关系游戏组件承载会话，打开窗口、切换来源和显式刷新时登记查询请求，在 Update 合并执行。第二批初值为显示中的概览每 2 秒、单选无卡片候选每 5 秒探测，所有请求共用完成后至少 2 秒的查询预算，慢查询按十倍耗时退避、封顶 30 秒；手动、换来源与重新打开也不能绕过；使用暂停时仍推进的真实时间，实际大存档测量后调整。无合格命令栏访问且无窗口时停止查询。

每次 GUI 事件直接使用现有快照，数量、布局和绘制不得各自扫描世界。绘制和点击前复查已有行的关系；发现失效行时跳过并安排快照更新。缰绳中新增的直接候选可先出现，漏索引关系在下一次受控补漏出现，不为显示注册全局逐 Tick 世界扫描。

第一批性能优化已落地：按本次关联角色的位置请求建立稀疏飞船索引，不逐人扫描货物；地图／世界／飞船持有者共用去重和遍历缓冲，普通货物不进入中间候选列表。临时容器有界复用，成功或异常退出均清空游戏对象引用，快照本身仍由视图持有。专项当前 110/110，稳态模型对比与实机边界见[优化记录](../Development/Verification/主从关系概览第一批性能优化与对比.md)；首次分配和真实大存档耗时未按模型数字承诺。

肖像复用原版缓存，尺寸保持稳定；窗口只绘制可见行，不为所有关系预生成纹理。关闭窗口或切换存档时释放视图缓存，避免静态缓存长期持有旧存档 Pawn。

## 8 验收矩阵

| 类别 | 必须覆盖的场景 | 核对重点 |
| --- | --- | --- |
| 归属 | 一主多从、无仪式社会关系、指定第三方调教员、只有身份、旧档身份未选择但有链 | 名单与方向来自实际锁链；空状态与指定者不混淆 |
| 索引 | 重复／陈旧／缺失缰绳条目、直接写 target、直接调用 AddToPawn 换主 | 概览去重并补齐显示，不在查询中修复关系 |
| 生命周期 | 正常绑定、解绑、改绑、CE 删除、同主新链替换、读档、人格流转 | 打开窗口期间及时更新，旧行点击复查，历史关系不残留 |
| 存活状态 | 死亡主人、死亡从属、复活、尸体有无、销毁和丢弃 | 死亡不自动解绑；无效引用不绘制或执行旧操作 |
| 位置 | 同图、异图、容器、旅队、运输、世界角色和位置不可用 | 操作与实际可定位目标一致，未生成不误称失踪 |
| 显示 | 0／1／多名、大量从属、同名、长姓名、四语、窄屏和 UI 缩放 | 计数一致、姓名可辨、列表可达最后一项 |
| 交互 | 单选／多选切换、头像悬停、点击切选、窗口关闭、游戏暂停中外部改绑 | 来源清楚，输入只处理一次，命令栏其他操作正常 |
| 性能与只读 | 大存档分页／重复绘制、隐藏界面、跨存档、普通查看前后对照 | 世界查询受控、缓存释放、分页不查询，不写绑定数据 |
| 显式指派 | 菜单打开后资格／规则／来源变化、非主人授权、清空限制 | 调用原子后台、拒绝迟到状态，不改变锁链主人 |
