# SSC 性刺激与高潮独立框架规划

**整理日期：** 2026-10-31。**状态：** 整体框架规划，整合与新增部分尚未开发。维护者明确将 **现有敏感度系统、既有 RJW 高潮加速及其独立化方向、本次日常刺激与高潮累积方案整合为同一个独立框架**，先作为 SSC 内部的独立部分开发。本轮只修订规划，不启动实现或确定发布版本。

## 3. 建议的状态模型

本节描述整体框架新增的日常子系统。每个参与角色持有一份日常状态，普通 Job 切换不清空。来源、机制、效果和显示分开处理，不让绘制推进机制；现有场景执行状态仍沿原载体保存。

| 数据 | 职责 |
| --- | --- |
| 有效输入强度 `I` | 表示当前来源合计提供多少刺激，决定变化速度；来源改变不直接跳改已有进度 |
| 唤起程度 `A` | 统一归一化程度，界面以0～100%展示；所有日常显示读取同一份数据 |
| 实际阶段 | 区分积累、高潮和高潮后回落；自然消退、接近阈值属于需要明确展示的状态／趋势 |
| 选定模式与有效控制者 | 保存希望自然循环还是维持某区间；“选定”不代表来源与资格始终有效 |
| 累积影响 `B` | 跨高潮周期保留，承担长时间／多次高潮的累积加重，不与当前唤起混为一个量 |
| 事件及阶段记录 | 区分一次高潮开始、持续与结束，记录必要序号、阶段剩余时间和最近显示事件，防止重复确认 |
| 暂停状态 | 覆盖原阶段，保留程度与阶段时间；不把暂停显示成来源消退 |

建议将新增日常身体状态保存在唯一载体中，显示标记与效果等级由其派生。具体采用 Hediff、Comp 或其他保存载体尚未确定；人格提取／植入、克隆、空壳等规则不能仅凭“属于身体”直接套用现有模块。控制偏好的归属另行确定。现有敏感度身体记录、原字段和任务执行保存节点保持各自归属，框架分层本身不授权迁移或重置旧数据。

若增加同类个人布尔启停，先按[个人能力开关规范](../Development/Reference/个人能力开关接入规范.md)复用注册、唯一后端及原上下文提交。维持模式枚举、强度及目标区间保留各自语义，不塞入 bool 存储。

## 4. 刺激来源与输入汇总建议

| 来源类别 | 候选例子 | 接入规则建议 |
| --- | --- | --- |
| 身体持续效果 | 明确赋予持续刺激的身体状态 | 效果有效时持续输入；现有高敏感属性本身不等于具备这一来源 |
| 装备效果 | 开启中的佩戴装置 | 读取实际装备、开关、有效部位及强度；移除后停止未来输入 |
| 临时效果 | 药效、能力或短期状态 | 在其真实有效期间提供输入，到期停止 |
| 活动条件 | 某身体／装备效果在移动时增强 | 活动改变所属来源的输入；同一效果不能又作为来源、又作为独立加值重复计算 |
| 短时事件 | 一次短促刺激 | 在短时间内提供输入，同样经过积累判定，不直接宣告高潮 |

普通行走、制作、搬运是否提供刺激，由具体来源规定，不因属于日常 Job 就默认产生输入。来源类型只是框架入口，首批具体接入哪些装备、药效或身体效果仍待选择。

建议不同真实来源的强度相加，同一来源实例重复通知只计算一次；是否设置总强度上限、采用何种叠加曲线另定。倍率经框架统一的最终属性入口查询，日常输入的单位换算与响应规则另定，不另建竞争的倍率执行源。倍率不凭空生成刺激，也不将身体档位与已包含它的最终 Stat 再乘一次。

来源增加或消失，只改变之后的变化率；已有程度从现值继续。切换普通工作、打开界面或重复回调不构成新刺激。短时输入应按其有效时段处理，不能因低频更新而无条件遗漏，也不能在暂停期间排队供恢复后补入。

## 5. 自然积累到高潮及回落建议

自然循环暂按“有输入时积累，无输入时消退”细化；最终公式、是否有宽限及变化曲线在参数确定时统一。

| 状态 | 机制建议 | 可见信息 |
| --- | --- | --- |
| 平静 | `A=0`、无来源、无未结束阶段 | 选中后可查；无其他残余信息时地图提示可隐藏 |
| 积累 | 输入使程度随时间上升 | 真实程度、上升趋势和来源提示，低位就显示 |
| 接近阈值 | 达到提示区间，仍未发生高潮 | 保留同一条，加阶段文字／形状，不仅改变颜色 |
| 自然消退 | 普通积累中输入停止，程度下降 | 保留残余条，标明刺激停止／消退，与高潮后回落区分 |
| 高潮 | 跨过阈值并确认一次事件，进入高潮阶段 | 明确峰值阶段和事件提示，不能因每次更新仍满格就重发 |
| 高潮后回落 | 真实程度下降至残余值 | 显示真实下降量，主条不改成恢复倒计时 |
| 下一轮 | 回落结束，有来源则继续积累，无来源则消退 | 不清空整个系统，也不隐藏仍存在的输入 |

建议自然循环在高潮及回落期间仍识别、显示来源，但暂不将输入转成新积累，也不保存隐藏输入等待释放。回落结束再按当前来源继续，避免持续输入使其永远停在阈值附近。维持模式可有明确的阶段控制例外，见下一节。

来源停止不会取消已确认的高潮；未达阈值的残余也不会因来源移除或普通任务结束而自动补成高潮。一次高潮可以结束而 `B` 仍较高，两者独立恢复。

## 6. 长期维持阶段建议

强度决定推进能力，维持模式决定目标区间及阶段转换。以下模式是对维护者提出的挑逗、寸止和长期高潮需求的候选拆分，首批范围与控制入口待定。

| 模式 | 建议含义 | 边界 |
| --- | --- | --- |
| 自然循环 | 按上一节反复积累、高潮和回落 | 不锁定阶段 |
| 挑逗维持 | 逐渐靠近中低位区间并维持 | 输入不足／失效后退出维持，不把选择模式等同于实际生效 |
| 寸止维持 | 维持在高潮阈值以下 | 如需保证不越界，控制者须约束本模块的全部日常输入；仅控制一个来源不能保证其他来源不突破 |
| 高潮维持 | 正常达到阈值后延长一次高潮阶段 | 一次开始、持续及结束；维持过程中不反复增加高潮次数 |
| 反复高潮 | 多个独立高潮周期连续发生 | 每次均有真实触发和独立事件，不能按更新回调次数刷计数 |

建议每个角色只有一个有效维持控制者，其余来源提供输入；多个控制请求如何选择或排优先级需明确，不默认由强度最大者夺取。超出维持能力而不计入的输入直接丢弃，不累存在隐藏池中。

进入或切换模式时从当前真实程度逐渐接近目标，不瞬间跳到某百分比。从低位开启高潮维持仍须到达阈值；已经发生的高潮不因切换模式撤销，也不重新确认一次。退出峰值维持后的回落顺序与新模式接续需在实现前定案。

稳定区间可以使用上下沿形成迟滞，减少频繁启停。稳定条本身可以不动，通过“维持中”、控制来源及持续时间说明仍在生效；若需要区间浮动，应由真实状态变化产生，不能只让 UI 假装推进。

## 7. 长时间与连续高潮的累积影响

维护者提出的方向是：长时间高潮／连续多次高潮能够累计出越来越严重的效果。建议使用跨周期的 `B` 承载，先采用真实高潮期间按有效持续时间增加、离开高潮后缓慢恢复的方式。

- 长时间维持一次高潮，`B` 持续上升；不需要不停制造新高潮事件。
- 连续多次高潮，每次增加；间隔不足以恢复时，下一次从较高值开始。
- 普通回落、切换模式或来源移除不直接清零 `B`；其恢复沿独立规则处理。
- 挑逗及寸止暂不计入这项高潮累积，是否另有影响不在本轮展开。

候选关系为“高潮有效时长 × 增长率 − 非高潮有效时长 × 恢复率”，按真实阶段分段计算，最低为0。该模型衡量总高潮时间和恢复间隔；若还需要相同总时间下次数更多也额外严重，再增加每次真实开始的增量。两项贡献须分别定义，不无意重复计入；额外次数加值尚未采用。

效果等级建议由 `B` 派生，达到阈值升档，恢复到较低阈值退档，避免边界反复切换。最高档、数值上限、恢复速度及各档效果仍待定，不预设永久或不可逆结果，也不把持续时长直接等同于已有恶堕、培养或 PNA 进度。

## 8. 各阶段持续可见的显示建议

首要原则是低位和未选中时也能看见过程。属于 SSC 内部模块不要求复用现有训练窗口；现有 ITab／健康页可以承载补充详情，但不能独自承担持续可见。

| 位置 | 建议职责 | 边界 |
| --- | --- | --- |
| 地图姓名附近细条 | 显示真实程度、趋势、阶段及简化来源；有输入时即使为0也保留空条或输入标记 | 独立偏移，避开姓名健康底色、征召线、选中圈；自行检查当前地图、生成、迷雾、屏外与缩放 |
| 选中后的状态 Gizmo | 显示精确程度、模式与实际阶段、来源、阶段时间，以及 `B` 和效果等级 | 所有信息读取统一状态，不在绘制中扫描全部来源或触发事件 |
| 顶部殖民者栏 | 补充离屏殖民者的简化程度及最近事件 | 属于候选扩展，须评估栏位模组兼容；不能覆盖所有非殖民者 |

程度、趋势、来源与阶段分别表达不同含义。积累使用上升标记，稳定维持使用保持标记，暂停使用暂停标记；自然消退与高潮后回落即使都下降，也要有不同阶段提示。峰值维持可显示本次持续时间，累积影响显示独立数值／等级及变化趋势。

快进时可能在两帧之间发生高潮并进入回落。最近事件标记应短暂保留，让玩家知道发生过什么；主条继续显示真实现值，不能用动画假装仍在100%。展示保持时间可独立于机制时长，具体规则待定；短时间多次事件可合并提示而不丢失真实记录。

来源停止后，残余程度继续可见；`A` 归零但 `B` 尚未恢复时，仍保留累积影响提示。只有无来源、无残余、无未结束阶段及必要显示记录后，才完全隐藏。模式选择、来源失效、RJW 暂停均应可区分。所有示意文字只是功能说明，不是运行文案定稿。

## 9. RJW 暂停及保存生命周期

本节的暂停只作用于新增日常子系统。整体框架的既有 RJW 加速、任务恢复及动画／UAP 适配继续按原流程运行；当前新增工作仅需识别相关行为以暂停日常状态，不扩展为日常与场景共用计时或新增动画阶段同步。

1. 暂停期间，`A`、`B`、高潮／回落剩余时间及维持有效时长均冻结，不产生新的日常推进或高潮事件。
2. 退出时以恢复时点重新接续，不补算暂停时段，也不重放期间的短时输入。
3. 外部装备、药效等仍由各自系统决定是否有效。恢复时重新检查来源，不能恢复已经移除或到期的来源；失去维持来源后按当前阶段退出维持。
4. 界面保留原状态并标注暂停；同一持续高潮恢复时不重新派发开始事件。
5. 具体从任务准备阶段还是实际行为开始暂停、覆盖哪些普通／单人／SSC 派生及多人路径，实施前列清识别范围；识别闸门不等于完成日常与场景的共用进度适配。

建议保存唯一真实状态、必要阶段时间和已确认事件记录；读取后继续原阶段，不补离线时间，任务重建不视为新刺激。来源缓存和显示对象由当前环境重建。

死亡、离图／世界角色、冷冻、睡眠、昏迷、倒地、身份失效、外部直接改健康列表，以及人格／身体替换、克隆、空壳的处理尚须逐项确定。不得让这些边界继承某个旧模块的默认清理而改变新状态归属。资格失效或明确停用须由机制层处理，不能仅隐藏界面；普通离屏只减少绘制，不据此停用。

## 10. 性能设计建议

长期维持一个数值或阶段，与高频执行真实高潮事件的成本不同。优先减少无效扫描、重复 Stat 计算、UI 分配及事件派发，不承诺任意人数、频率与模组组合的固定开销。

| 层面 | 初步方向 |
| --- | --- |
| 参与对象 | 只维护有有效来源、残余程度、未结束阶段或累积影响的活跃角色；彻底平静后退出活跃集合 |
| 来源缓存 | 来源／模式变化时更新该角色缓存，并保留错峰低频核对，处理遗漏的外部直接修改 |
| 数值计算 | 稳定输入按经过的游戏 Tick 积分，来源变化处分段；稳定维持区间减少重复写入，等待变化或边界 |
| 阶段边界 | 正确处理跨阈值、峰值结束、回落结束及效果升降档；散列间隔及按边界提前处理的具体调度待定 |
| 绘制 | 只处理必要可见角色／选中／顶部栏，读取缓存或在已知变化段内投影；绘制不提交机制事件 |
| 提示与特效 | 复用对象、限制表现派发、合并近期提示，避免每帧重建来源文本或堆积过期动画 |

机制低频更新仍须按真实经过时间处理完整阶段。不能用“每次更新最多一次高潮”改变快进或更新间隔下的实际频率。离屏只减少绘制，不能擅自暂停仍在机制范围内的角色。

极高频周期只有在语义等价时才能数学汇总事件数量；具有逐次、非线性消费者的事件不能随意合并。延长单次峰值可以按时间积分，但真实多次高潮的事件成本仍随次数增长。显示平滑不能越过尚未确认的阶段边界来创造事件。

初版建议先采用活跃集合、来源缓存及错峰更新，再按测量决定是否需要更复杂的边界调度。后续分别测量来源更新、稳定维持、集中跨阶段、连续事件和多角色显示；当前只有设计推导，没有新框架 FPS／TPS 或宿主实测结果。此处仅设计本模块，不恢复第34项暂缓的整仓性能工作。
