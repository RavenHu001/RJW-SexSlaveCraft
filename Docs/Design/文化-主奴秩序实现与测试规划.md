## 1 已确认范围与待定边界

当前内容为 1 个「主奴秩序」模因、5 个 Issue、22 条普通戒律：性奴 6、训导官 5、主人 5、主人数量 3、性奴数量 3。label、impact 和语义以内容设计表格为准。

维护者已明确：

- description 必须填写可检索的占位句，正式描述交给其他智能体处理。本轮不创作描述正文；已有名称与英文字段保留，四语资源使用对应 label 和占位标记。
- 文化系统以实际性奴锁链判断「已是性奴」。ITab 里的性奴身份更接近途径预选，用于允许参加相关活动，不能据此判定已经成为性奴。
- 艳羡不检查个人主人资格。持有资格但尚未担任主人者，不因资格而失去艳羡条件。
- 不增加意愿、身份或绑定拦截；按照当前文化与实际状态做心情和关系反馈。
- 首席性奴暂缓。功能与用途尚未确定，维护者不希望作为专家职位占用原版有限的专家类型名额；本轮不创建职位资源或授职逻辑。
- 不预先把首批限制为 XML 骨架；按具体分析分解步骤，并以可玩的反馈闭环验收。
- 各档数值以原版同类戒律为参照，使用[内容设计第 3～6 节](文化-主奴秩序戒律与职位设计.md#3-戒律性奴)已确认表；不因 SSC 既有加成而刻意压低，不把既有仪式奖励联动纳入本轮分析或专项测试。
- 训导官与性奴项全额相加，每组一份，不覆盖、折半或设跨戒律总上限。艳羡心情为无链非主人 -6、有链 +10、无链主人 0。
- 主人戒律另有领袖环境项，按正式领袖是否为 SSC 主人分别结算，无有效领袖为 0；无额外领袖社交好感。
- 主人总数只纳入有效人物栏成员中的当前 SSC 主人，不以“玩家阵营”扩大名册；名下性奴按实际链统计，不附加人物栏条件。两组每超额一人 -3，达标和无上限为 0，不新增硬限制或社交惩罚。

- 五组均为模因必选组，但范围分别为性奴 3 档、训导官 5 档、主人 2 档、数量各 3 档；仅 4 条专属最高档要求模因，性奴／主人低档共 6 条与模因冲突。
- 完整生成主奴秩序文化使用“神圣＋圣职＋圣主＋三主以内＋三奴以内”；普通文化态度按 1／2／7 补全低档，数量默认不限。权重 0 不妨碍合法手选，改革保留已有合法档位。
- 首批不新增与原版模因的硬互斥，不自动改写原版奴隶制，不限制既有契约仪式；完整名单与两类权重见第 3.4 节及[内容设计第 9 节](文化-主奴秩序戒律与职位设计.md#9-挂载与默认值)。

仍待确定的是美术与文化命名资源，以及在不改变已定语义前提下的代码拆分、名册查询和刷新实现方式。各档位数值、叠加、反馈承担者、统计口径与本次挂载规则不再列为待定。进一步的模因冲突或跨模因戒律联动只作后续讨论，不自动加入已确认范围。

### 2.3 首席职位的保留取证

首席职位不属于当前实施或验收范围，以下只防止未来重复误判：

- 文化职位由 PreceptDef 表达；`Precept_RoleSingle` 的单人存储以文化中的职位实例为范围。原版“两类专家”上限检查针对 `Precept_RoleMulti`，不是同一类型检查。
- 原版 `Precept_Role.ValidatePawn`、社交页授职入口和授职仪式角色均有限制原版奴隶的路径；仅增加一个 SSC 任职要求不足以适配。
- 原版 Assign 对非法对象可能只记录错误而继续赋值；授职结果还存在先卸旧职再赋新职的顺序。若未来恢复开发，要在卸职前复核条件。
- 原版职位基类包含信徒人数、性别、着装 thought、确信度等配置，不能直接把道德导师当作中性职位模板。
- 不将候选首席直接放入普通戒律的 `requireOne`；原版同 Issue 的替换处理可能影响既有 `IdeoRole` 内容。

恢复首席设计时另行确定功能、用途和载体，不把这些接口记录转为当前开发任务。

### 2.4 人物栏与领袖补充取证

以下成员已在第 2.1 节的 4984 构建及 MVID 中续查，仍属于历史静态证据；不将本轮 4985 挂载续查扩写为这些接口均已重新验证：

先建立存活、玩家势力、非囚犯／临时成员的有效人物栏成员名册，再筛当前主人得出总数。正式领袖查询复用身份过滤前的成员名册，不能用主人列表查领袖，否则无法区分“有效非主人领袖”与“无有效领袖”。

### 3.2 态度、自身状态与艳羡

建议共享条件 worker，通过明确的 Def 配置区分评价对象；档位数值保存在 ThoughtDef 中，不将“第几档”或 impact 换算成固定分数。

- 本人反馈：持有者的戒律与本人实际链状态决定持续心情。
- 社交反馈：观察者的戒律与另一角色的实际状态决定条件性评价；无需另建持久 PawnRelationDef。
- 漠视各项为 0；性奴敌视档对另一名持链者为 0，尊重档本人持链心情为 0，保留制度、人格和身份认同的区别。
- 训导官与性奴项**全额相加**。每个 Issue 一份，不覆盖、折半或施加跨戒律总上限；社交按观察者自己的文化，不要求目标同文化，不对自身增加好感。
- 既有主人赏识、任职信任和锁链阶段反馈保持独立，不为了新文化数值重调既有逻辑；不展开既有仪式奖励联动。
- 本人持链时使用本人心情，未持链者才使用性奴环境项；两者互斥。环境项按管理范围内活体持链人数计算，包含持链囚犯与原版奴隶，排除访客／临时借住／尸体及销毁／丢弃对象，按 Pawn 去重，不额外封顶。
- 环境项接收者为未持链的玩家殖民地长期成员；自身状态和双人社交仍依据个人文化及实际状态。环境对象不套用主人总数的人物栏条件。

数值落地契约如下，顺序与内容设计的档位表一致；生产 Def 配置和测试预期都要逐格对照，不从 impact 自动计算：

艳羡为以下互斥心情分支：持有戒律时，有链为 +10；无链且非主人为 -6；无链且为主人为 0。未预选性奴、预选但无链、仅解锁主人资格、直接选择主人设置切换均不改变这套判定；取得锁链将 -6 替换为 +10，不叠加、不产生事件记忆。

对另一名持链者的 +20 艳羡社交只由未持链、非主人观察者产生；观察者取得锁链后停止该社交项，但开始 +10 本人心情。-6 愿望心情不要求殖民地已有其他性奴。改宗、改革或丢失链后按当前分支刷新，不保留旧值。

有效主人是实际锁链指向的另一名存活、未销毁／丢弃且当前为 SSC 主人的角色；正常离图仍有效，不使用回退到指定调教员的 `GetResolvedMaster`。正式领袖另按 2.4 的职位及有效名册判断：无授职、无有效任职者为“无有效领袖”，不得按非主人领袖扣分；不新增领袖社交项，不要求领袖与观察者同文化。此项可与本人／从属、性奴、训导官心情相加。

### 3.3 数量反馈

两组数量阈值为 1／3／无上限，已确认采用 `-3 × max(0, count - limit)` 的线性超额心情，无上限固定为 0。达标不发奖，零个不产生不足，不封顶，不新增身份／绑定硬限制或超额社交惩罚。

| 规则 | 已确认查询口径 | 反馈承担者 |
| --- | --- | --- |
| 主人数量 | 原版应入人物栏名册中的玩家势力活体当前主人，排除囚犯／临时借住／销毁／丢弃者；跨据点、跨文化同一个总数 | 持有该戒律的玩家殖民地长期成员各按自身上限结算 |
| 性奴数量 | 每主人名下实际锁链绑定活体，排除死亡／销毁／丢弃／自指并去重，不附加途径预选、人物栏、文化或同势力条件 | 仅持有该戒律的玩家长期成员中的当前主人本人，不让名下每个性奴重复承担 |
| 无上限 | 任意数量均为 0 | 同各自对应范围 |

主人总数不能按玩家 Faction 或全部 WorldPawn 兜底扩充；其他地图、商队、运输、休眠均服从人物栏资格，不再无条件计入。仅持有主人资格不计，原版奴隶法律身份不单独排除当前 SSC 主人。UI 关闭、切地图和分辨率不改变应入栏资格。

名下性奴的实际关系不受离图、运输、休眠、成为囚犯或转入其他势力影响；只要活着且仍实际绑定就计入。缰绳只提供候选，逐项核链并去重；不把旧条目、指派或其他主人名下对象计入，也不在常规刷新中用世界扫描补漏或修复外部破坏的索引。

一人上限下数量 `0 / 1 / 2 / 3 / 4` 对应 `0 / 0 / -3 / -6 / -9`；三人上限下 `0 / 1 / 2 / 3 / 4 / 5 / 6` 对应 `0 / 0 / 0 / 0 / -3 / -6 / -9`。只读 thought 不增加全局逐 tick 轮询，不趁本批恢复暂缓的性能优化计划。
