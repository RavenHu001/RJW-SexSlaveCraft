## 1 已确认范围与待定边界

当前内容为 1 个「主奴秩序」模因、5 个 Issue、22 条普通戒律：性奴 6、训导官 5、主人 5、主人数量 3、性奴数量 3。label、impact 和语义以内容设计表格为准。

维护者已明确：

- description 必须填写可检索的占位句，正式描述交给其他智能体处理。本轮不创作描述正文；已有名称与英文字段保留，四语资源使用对应 label 和占位标记。
- 文化系统以实际性奴锁链判断「已是性奴」。ITab 里的性奴身份更接近途径预选，用于允许参加相关活动，不能据此判定已经成为性奴。
- 艳羡不检查个人主人资格。持有资格但尚未担任主人者，不因资格而失去艳羡条件。
- 不增加意愿、身份或绑定拦截；按照当前文化与实际状态做心情和关系反馈。
- 首席性奴暂缓。功能与用途尚未确定，维护者不希望作为专家职位占用原版有限的专家类型名额；本轮不创建职位资源或授职逻辑。
- 不预先把首批限制为 XML 骨架；按具体分析分解步骤，并以可玩的反馈闭环验收。

以下仍为实现建议，不能因保存规划就视为规则已定：各档位的数值、态度叠加方式、主人身份与成员名册口径、数量反馈承担者，以及五组戒律的必选／手选范围和生成权重。

### 2.2 定义、挂载与 thought 接口

| 原版成员 | 已核对行为 | 本方案的约束 |
| --- | --- | --- |
| `MemeDef.impact` | `int`，普通模因为 1～3 | Medium 在 XML 中写 `2` |
| `PreceptDef.impact` | `PreceptImpact` | 按内容表保留 Low／Medium／High；不是效果数值 |
| `IssueDef.allowMultiplePrecepts` | 普通新 Issue 默认不允许多条 | 同组互斥，不用 impact 实现互斥；神圣和艳羡不能并存 |
| `PreceptDef.displayOrderInIssue` | 同 Issue 选项的排序字段 | 保留内容表的顺序值并验证界面顺序 |
| `Def.ConfigErrors()` | 检查非 null 的空 description 字符串 | 使用非空占位句，不写空元素 |
| `IdeoFoundation.CanAdd()` | 检查 required／conflicting memes、重复 Issue 和必选替代范围等 | 不能只检查 XML 引用；必须用实际资格检查验证切换 |
| `IdeoFoundation.AddRequiredPreceptsForMemes()` | 对每个 `requireOne` 内层列表按 `selectionWeight` 选择 | 不同 Issue 分组，候选集合同时影响必选与替换规则 |
| `IdeoFoundation.RandomizePrecepts()` | 模因关联阶段使用 `selectionWeight`，补全阶段使用 `defaultSelectionWeight` | 两种权重分开设计，不把关联等同于默认或解锁 |
| `IdeoFoundation.EnsurePreceptsCompatibleWithMemes()` | 添加／移除模因会调整不兼容戒律与必选内容 | 新建、随机化和改革分别验证 |
| `ThoughtWorker_Precept` | 基类检查文化、挂载及适用条件，子类提供 `ShouldHaveThought(Pawn)` | 本人状态 worker 实现该方法，保留基类入口 |
| `ThoughtWorker_Precept_Social` | 基类检查观察者文化与挂载，子类提供双人 `ShouldHaveThought` | 社交评价从观察者文化读取，不要求对象同文化 |
| `PreceptComp_SituationalThought` | 将固定 ThoughtDef 挂到戒律 | 复杂条件写在 worker／查询工具，不为每个档位复制 C# 逻辑 |
| `PreceptComp_SelfTookMemoryThought`／`KnowsMemoryThought` | 本人行为记忆与知晓者反馈不同 | 本轮用持续状态反馈，不新增历史事件或行为记忆 |
| `PreceptComp_UnwillingToDo`／`IdeoUtility.DoerWillingToDo` | 意愿组件需要实际调用方查询 | 本轮没有意愿拦截，不向 SSC 写入入口添加查询 |

原版普通模因界面允许空分组。本方案仍计划新建 MemeGroup 便于组织，具体排布通过实机验证。`symbolPacks`／`generalRules` 可由其他文化来源补足；不能未经组合验证就断言省略必然产生缺词或一定正常。

### 2.3 首席职位的保留取证

首席职位不属于当前实施或验收范围，以下只防止未来重复误判：

- 文化职位由 PreceptDef 表达；`Precept_RoleSingle` 的单人存储以文化中的职位实例为范围。原版“两类专家”上限检查针对 `Precept_RoleMulti`，不是同一类型检查。
- 原版 `Precept_Role.ValidatePawn`、社交页授职入口和授职仪式角色均有限制原版奴隶的路径；仅增加一个 SSC 任职要求不足以适配。
- 原版 Assign 对非法对象可能只记录错误而继续赋值；授职结果还存在先卸旧职再赋新职的顺序。若未来恢复开发，要在卸职前复核条件。
- 原版职位基类包含信徒人数、性别、着装 thought、确信度等配置，不能直接把道德导师当作中性职位模板。
- 不将候选首席直接放入普通戒律的 `requireOne`；原版同 Issue 的替换处理可能影响既有 `IdeoRole` 内容。

恢复首席设计时另行确定功能、用途和载体，不把这些接口记录转为当前开发任务。

## 3 当前代码接入与建议实现

### 3.1 文化状态查询

| 查询 | 当前代码基础 | 接入原则 |
| --- | --- | --- |
| 是否已经是文化性奴 | [SSCBondUtility.GetChain](../../Sexslavecraft/common/SSCBondUtility.cs) | `GetChain(pawn) != null`；不附加 ITab 预选条件，也不在只读查询中补链或修复身份 |
| 原有途径身份 | [SSCIdentityUtility](../../Sexslavecraft/common/SSCIdentityUtility.cs) | 保留现有 setter、准入和绑定保护，不全局替换 `IsSexSlave` 语义 |
| 有效训导官 | [TrainerOfficerFeedback.IsActiveOfficer](../../Sexslavecraft/common/TrainerOfficerFeedback.cs) | 复用资格和个人开关；它目前依赖原有 SSC 途径身份，不为文化反馈改写任职制度 |
| 调教员 | [SSCIdentityUtility.Trainer](../../Sexslavecraft/common/SSCIdentityUtility.Trainer.cs) | 主人也能返回 true，不能据此把主人归为训导官 |
| 当前主人 | `SSCIdentityUtility.IsMaster` | 建议用于主人态度；与主人数量的最终口径一起确认 |
| 个人主人资格 | [SSCMasterQualificationUtility](../../Sexslavecraft/common/SSCMasterQualificationUtility.cs) | 艳羡不读取；不将 `HasQualification` 或 `CanSelectMaster` 当作艳羡条件 |
| 实际绑定对象 | [SSCMasterBondUtility.GetBoundSlaves](../../Sexslavecraft/common/SSCMasterBondUtility.cs) | 基于实际有向锁链；按最终数量范围过滤，不再加 ITab 性奴身份条件 |

文化“已有锁链”与数量“名下有效绑定”分别查询：无有效主人引用的残留链仍可能满足前者，但不能凭链的存在虚构名下关系。过渡状态的读取不得触发修复或改写。

新增小型文化查询工具集中保存这些区别，不新增长期保存的文化身份，不复制全局身份体系。已有锁链、原版法律身份、途径预选和主人资格保持各自含义。

### 3.2 态度、自身状态与艳羡

建议共享条件 worker，通过明确的 Def 配置区分评价对象；档位数值保存在 ThoughtDef 中，不将“第几档”或 impact 换算成固定分数。

- 本人反馈：持有者的戒律与本人实际链状态决定持续心情。
- 社交反馈：观察者的戒律与另一角色的实际状态决定条件性评价；无需另建持久 PawnRelationDef。
- 漠视原则上不增加反馈；敌视制度、尊重人格、推崇身份的具体效果仍需区分，不能全部映射为同一条线性好感曲线。
- 训导官也可能是持链性奴。“训导官评价覆盖普通性奴评价”是可选方案，尚未确认；必须先决定叠加规则再编写相应用例。
- 已有主人赏识、任职信任和锁链阶段反馈保持独立；是否与新文化项叠加及强度需要检查，不更改其现有数值来补偿未定效果。

艳羡的已定状态式：

```text
持有艳羡戒律 && 没有性奴锁链 && 当前不是主人
```

其行为必须包括：未预选性奴可触发；预选性奴但无链仍可触发；已解锁主人资格但未任主人仍可触发；有链或当前为主人时不触发。获得／失去链、改宗和改革后通过原版 thought 刷新重新判断，不发送历史记忆。

### 3.3 数量反馈

两组数量阈值已在内容设计中确定为 1／3／无上限，实施方案建议采用超额心情反馈，不增加身份或绑定硬限制。

| 规则 | 建议查询与行为 | 尚待确定 |
| --- | --- | --- |
| 主人数量 | 统计当前主人，区分上限 1／3；仅持有资格不自动等同主人 | 主人资格口径最终确认、单据点或全殖民地、地图／商队／运输中成员、访客与死亡过滤 |
| 性奴数量 | 对每个实际主人分别读取其实际锁链绑定对象，排除只预选、只指派和其他主人名下对象 | 反馈只落在主人本人还是也影响其他信徒、跨地图对象、死亡与去重范围 |
| 无上限 | 不因数量超额产生惩罚 | 是否还存在其他效果及数值 |

一人上限只在 `count > 1` 时超额，三人上限只在 `count > 3` 时超额；零个不等同于“数量不足”。只读 thought 不增加全局逐 tick 轮询，不为了统计修复绑定，也不趁本批恢复暂缓的性能优化计划。

## 5 建议实施步骤

实现顺序用于组织工作，不代表已经开始编码；前两步与后续验证应共同形成可玩的戒律版本，不把只有名称的 XML 骨架作为完成结果。

| 步骤 | 工作与退出条件 |
| --- | --- |
| 1. 固定未定规则与挂载 | 确定各档位效果、数值、叠加、数量名册和反馈承担者；区分默认与手选范围。建立完整 Def 配置及相应自动检查，确认五组选择不会互相覆盖 |
| 2. 态度、自身状态与艳羡 | 实现共享查询与 workers，使用实际链状态；完成预选／持链／主人／资格差异、改宗和改革用例，并接入四语标记 |
| 3. 数量反馈 | 按确定的成员范围实现两个独立统计，覆盖阈值、绑定方向、换绑、死亡、跨地图与重复对象 |
| 4. 综合验证与实机交付 | 通过匹配 1.7 构建、专项、关联回归与统一门禁后，记录实际结果；按维护者后续授权再同步游戏。实机确认界面、状态刷新、改革与保存重载 |

正式描述替换由其他智能体后续完成，替换时单独检查四语键与占位遗漏，不借文案替换修改机制。首席职位不是上述任一步的前置条件。

## 6 测试方法与覆盖边界

自动测试承担主要机制验证，手工只确认难以在离线夹具中完整验证的界面和加载行为。尚未决定的效果与数量口径必须先确定期望值，不写“镜像实现”的测试来掩盖规则缺失。

| 层次 | 必须覆盖的内容 |
| --- | --- |
| Def 与语言检查 | 1 个模因、5 个 Issue、22 条戒律，6／5／5／3／3 分布；同组互斥、神圣／艳羡互斥、排序、所有引用、四语键与非空占位描述、DLC 加载条件 |
| 链状态矩阵 | 无途径身份无链、预选性奴无链、有链且预选性奴、有链但途径身份不匹配；文化判断只按链，既有活动准入不被改写；仅特质不等同持链 |
| 艳羡矩阵 | 有／无对应戒律、无文化、无链、有链、当前主人、仅解锁主人资格、直接选择主人设置切换、预选但无链；取得／移除锁链及改宗后按当前条件刷新 |
| 态度与任职 | 观察者与对象方向、不同文化对象、各档位条件、漠视无新增反馈、有效／失格／关闭开关训导官、主人不误认训导官、确定后的叠加规则 |
| 数量边界 | 每档 `0 / 1 / 2 / 3 / 4`，只预选不计、只指派不计、实际名下与其他主人名下、重复／死亡／失效对象；外出、访客和跨地图按最终口径分别断言 |
| 真实原版接口 | 引用本机 net10.0 游戏程序集，检查必选组与权重、CanAdd 的可替换范围、新建／随机化／添加和移除模因；不能用自制替身代替这些接口后宣称原生通过 |
| 关联回归 | 身份与绑定、训导官反馈、现有锁链 thought、人格恢复／旧档显式恢复、契约仪式与演化点开关；文化反馈不产生额外行为拒绝或旧状态奖励 |
| 实机专项 | 有／无 Ideology 加载、模因分组与图标、戒律选择与顺序、thought 及社交显示、取得／移除锁链、改革、保存重载；不测本轮未做的授职流程 |

新专项可参考 `Tests/RitualDevelopmentNative` 的真实 1.7 引用方式，但 fixture 使用了哪些替身、初始化前提和不能模拟的界面必须单独记录。XML 能解析不等于游戏已完成继承与交叉引用；离线 API 调用也不等于实机全部通过。

实施后执行与改动相适应的专项和统一门禁，分别记录构建、机制、资源镜像、编排及实机结果。新增运行 Def 不一定已有 `Sexslavecraft/Defs` 镜像，当前 Def 镜像脚本仅覆盖既有镜像集合，因此不能仅凭该检查声称新增定义已完整验证；新增语言文件则需维护语言镜像。
