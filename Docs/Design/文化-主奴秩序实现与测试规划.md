## 1 已确认范围与待定边界

当前内容为 1 个「主奴秩序」模因、5 个 Issue、22 条普通戒律：性奴 6、训导官 5、主人 5、主人数量 3、性奴数量 3。label、impact 和语义以内容设计表格为准。

维护者已明确：

- description 必须填写可检索的占位句，正式描述交给其他智能体处理。本轮不创作描述正文；已有名称与英文字段保留，四语资源使用对应 label 和占位标记。
- 文化系统以实际性奴锁链判断「已是性奴」。ITab 里的性奴身份更接近途径预选，用于允许参加相关活动，不能据此判定已经成为性奴。
- 艳羡不检查个人主人资格。持有资格但尚未担任主人者，不因资格而失去艳羡条件。
- 不增加意愿、身份或绑定拦截；按照当前文化与实际状态做心情和关系反馈。
- 首席性奴暂缓。功能与用途尚未确定，维护者不希望作为专家职位占用原版有限的专家类型名额；本轮不创建职位资源或授职逻辑。
- 不预先把首批限制为 XML 骨架；按具体分析分解步骤，并以可玩的反馈闭环验收。
- 各档数值以原版同类戒律为参照，使用[内容设计第 3～6 节](文化-主奴秩序戒律与职位设计.md#3-戒律性奴)已确认表；不因 SSC 既有加成而刻意压低，不把既有仪式奖励联动纳入本轮分析或专项测试。
- 训导官与性奴项全额相加，每组一份，不覆盖、折半或设跨戒律总上限。艳羡心情为无链非主人 -6、有链 +10、无链主人 0。
- 主人戒律另有领袖环境项，按正式领袖是否为 SSC 主人分别结算，无有效领袖为 0；无额外领袖社交好感。
- 主人总数只纳入有效人物栏成员中的当前 SSC 主人，不以“玩家阵营”扩大名册；名下性奴按实际链统计，不附加人物栏条件。两组每超额一人 -3，达标和无上限为 0，不新增硬限制或社交惩罚。

- 五组均为模因必选组，但范围分别为性奴 3 档、训导官 5 档、主人 2 档、数量各 3 档；仅 4 条专属最高档要求模因，性奴／主人低档共 6 条与模因冲突。
- 完整生成主奴秩序文化使用“神圣＋圣职＋圣主＋三主以内＋三奴以内”；普通文化态度按 1／2／7 补全低档，数量默认不限。权重 0 不妨碍合法手选，改革保留已有合法档位。
- 首批不新增与原版模因的硬互斥，不自动改写原版奴隶制，不限制既有契约仪式；完整名单与两类权重见第 3.4 节及[内容设计第 9 节](文化-主奴秩序戒律与职位设计.md#9-挂载与默认值)。
- 全面禁欲 Lovin_Prohibited 暂允许并存，不新增其与主奴秩序的冲突；非人化保留原版好感系数与 thought 生效规则，不为文化表中数值额外绕过或补偿。模因间暂不新增硬冲突不改变原版既有互斥或 SSC 已确认的戒律资格限制。
- 后续改动必须检查每个待填必选组存在合法候选且 selectionWeight 总和大于 0；已有合法旧项满足的组走保留路径，不用零权重空候选误报。
- 人物栏名册按原版地图／商队来源独立建立，领袖查询覆盖玩家主、次文化正式职位；三类人口集合分离，不从世界全量扫描兜底。
- 共享查询采用 Game 实例隔离、不序列化的 100 tick 懒更新快照；个人条件直接读现状，反馈沿用原版心情 150 tick 散列周期和双人社交 100 tick 重算间隔，不加全体观察者广播或逐 Tick 扫描。

仍待确定的是美术与文化命名资源，以及查询层具体类名、内部配置和 Def／worker 最终拆分等实施细节。效果、统计、挂载、原版并存边界、生成可行性及第 3.6～3.8 节名册／领袖／刷新方案不再待定。未来其他跨模因联动或暂停即时刷新需求仍须另行确认。

### 2.3 首席职位的保留取证

首席职位不属于当前实施或验收范围，以下只防止未来重复误判：

- 文化职位由 PreceptDef 表达；`Precept_RoleSingle` 的单人存储以文化中的职位实例为范围。原版“两类专家”上限检查针对 `Precept_RoleMulti`，不是同一类型检查。
- 原版 `Precept_Role.ValidatePawn`、社交页授职入口和授职仪式角色均有限制原版奴隶的路径；仅增加一个 SSC 任职要求不足以适配。
- 原版 Assign 对非法对象可能只记录错误而继续赋值；授职结果还存在先卸旧职再赋新职的顺序。若未来恢复开发，要在卸职前复核条件。
- 原版职位基类包含信徒人数、性别、着装 thought、确信度等配置，不能直接把道德导师当作中性职位模板。
- 不将候选首席直接放入普通戒律的 `requireOne`；原版同 Issue 的替换处理可能影响既有 `IdeoRole` 内容。

恢复首席设计时另行确定功能、用途和载体，不把这些接口记录转为当前开发任务。

### 2.4 人物栏与领袖补充取证

以下成员已在第 2.1 节的 4984 构建及 MVID 中续查，仍属于历史静态证据；不将本轮 4985 挂载续查扩写为这些接口均已重新验证：

| 原版成员 | 已核对行为 | 当前机制约束 |
| --- | --- | --- |
| `ColonistBar.CheckRecacheEntries()` | 收集各地图的 FreeColonists／可控成员、部分尸体和玩家商队成员，并有空分组条目；收集受 `showColonistBar` 控制 | 人物栏集合并不等于活体主人集合，不能直接取长度，也不能用显示开关决定人数 |
| `ColonistBar.Entries` | 会触发界面条目的重新缓存 | 不把 UI 缓存作为唯一机制来源；数量查询不得借此改变显示设置 |
| `ColonistBar.GetColonistsInOrder()` | 只排除 null，返回复用的临时列表 | 仍需存活、身份等过滤，不长期保存该列表或在嵌套查询中依赖其内容稳定 |
| `ColonistBar.Visible` | 受分辨率、界面状态影响 | 实际是否绘制头像不是成员资格，改变分辨率不能改变人数 |
| `Precept_RoleSingle.Assign()` | 正式领袖授职可更新玩家 faction 的 leader 指针并清除其他领袖任职 | 从 `leaderRole` 正式职位及实际任职者确认领袖，而非只信任指针 |
| `Faction.TryGenerateNewLeader()` | 阵营也存在独立生成 leader 的路径 | 阵营字段不能保证指向已正式授职、位于有效殖民地名册的领袖 |

需要原创的独立“人物栏资格名册”查询，对齐原版会列入的人物规则，忽略单纯的显示开关／布局，不复制原版 C# 实现。其他地图、商队、运输和休眠都通过同一资格规则判断，不能再把所有同阵营 WorldPawn 加回来。

先建立存活、玩家势力、非囚犯／临时成员的有效人物栏成员名册，再筛当前主人得出总数。正式领袖查询复用身份过滤前的成员名册，不能用主人列表查领袖，否则无法区分“有效非主人领袖”与“无有效领袖”。

### 3.2 态度、自身状态与艳羡

建议共享条件 worker，通过明确的 Def 配置区分评价对象；档位数值保存在 ThoughtDef 中，不将“第几档”或 impact 换算成固定分数。

- 本人反馈：持有者的戒律与本人实际链状态决定持续心情。
- 社交反馈：观察者的戒律与另一角色的实际状态决定条件性评价；无需另建持久 PawnRelationDef。
- 漠视各项为 0；性奴敌视档对另一名持链者为 0，尊重档本人持链心情为 0，保留制度、人格和身份认同的区别。
- 训导官与性奴项**全额相加**。每个 Issue 一份，不覆盖、折半或施加跨戒律总上限；社交按观察者自己的文化，不要求目标同文化，不对自身增加好感。
- 既有主人赏识、任职信任和锁链阶段反馈保持独立，不为了新文化数值重调既有逻辑；不展开既有仪式奖励联动。
- 本人持链时使用本人心情，未持链者才使用性奴环境项；两者互斥。环境项按管理范围内活体持链人数计算，包含持链囚犯与原版奴隶，排除访客／临时借住／尸体及销毁／丢弃对象，按 Pawn 去重，不额外封顶。

### 3.3 数量反馈

两组数量阈值为 1／3／无上限，已确认采用 `-3 × max(0, count - limit)` 的线性超额心情，无上限固定为 0。达标不发奖，零个不产生不足，不封顶，不新增身份／绑定硬限制或超额社交惩罚。

| 规则 | 已确认查询口径 | 反馈承担者 |
| --- | --- | --- |
| 主人数量 | 原版应入人物栏名册中的玩家势力活体当前主人，排除囚犯／临时借住／销毁／丢弃者；跨据点、跨文化同一个总数 | 持有该戒律的玩家殖民地长期成员各按自身上限结算 |

主人总数不能按玩家 Faction 或全部 WorldPawn 兜底扩充；其他地图、商队、运输、休眠均服从人物栏资格，不再无条件计入。仅持有主人资格不计，原版奴隶法律身份不单独排除当前 SSC 主人。UI 关闭、切地图和分辨率不改变应入栏资格。

名下性奴的实际关系不受离图、运输、休眠、成为囚犯或转入其他势力影响；只要活着且仍实际绑定就计入。缰绳只提供候选，逐项核链并去重；不把旧条目、指派或其他主人名下对象计入，也不在常规刷新中用世界扫描补漏或修复外部破坏的索引。

一人上限下数量 `0 / 1 / 2 / 3 / 4` 对应 `0 / 0 / -3 / -6 / -9`；三人上限下 `0 / 1 / 2 / 3 / 4 / 5 / 6` 对应 `0 / 0 / 0 / 0 / -3 / -6 / -9`。只读 thought 不增加全局逐 tick 轮询，不趁本批恢复暂缓的性能优化计划。

### 3.5 原版并存边界与生成可行性

维护者确认的并存规则以[内容设计第 9.4 节](文化-主奴秩序戒律与职位设计.md#94-模因生成与跨组冲突)为准：

- 模因间暂不新增硬冲突，保留原版模因彼此已有互斥；个人主义、罪责、苦痛美德、性别至上等不因名称或观念张力自动增加 SSC 限制。
- 全面禁欲 Lovin_Prohibited 暂允许并存，不补丁其 conflictingMemes、不强制更换性生活戒律；性生活、婚姻与数量、法律奴役、穿着、身体改造和药物各自保留原有对象／行为评价，SSC 锁链不自动提供豁免。
- 非人化遵循原版最终效果与 thought 资格；不移除好感系数、修改原版 Hediff 或强制保留最终 +20／+15 等文化增量，不以追加补偿系数抵消原版效果。原文化表是配置与条件反馈契约，最终值还要经过原版结算。
- 本次不新增事件桥接、文化组合奖励或跨议题自动改档；“允许并存”的测试不能冒充所有 SSC／RJW 行为事件均已接入。

可行性检查逐组区分已满足和待填两类状态：已有合法戒律满足 requireOne 则保留；待填组才按真实参数调用 CanAddForFaction 过滤候选，并断言候选非空且 `sum(selectionWeight of eligible candidates) > 0`。资格过滤包括前置／冲突、派系／参数禁止项和已有内容／重复限制；defaultSelectionWeight 或零权重手选资格不能代替必选抽取权重。

当前无额外禁止项的完整生成基线，每组合法正权重和为 1。用“禁止圣主、保留零权重尊奉”的待填场景验证检查能识别权重和 0；再用已有合法尊奉的改革场景验证保留路径不会误报。识别不可行是设计与测试门槛，不在运行时静默放宽资格、调整权重、覆盖手选或新增拦截来消除失败，也不依赖普通补全偶然填满。

新建、完整随机化、不同先后顺序添加模因、移除模因和保存重载分别验证；比较最终合法性、五组完整性及应保留项，不要求含随机普通戒律的两个流程产生逐项相同的整个文化。后续每次修改候选／冲突／前置／权重都要重跑相关原生组合矩阵，具体见第 6 节。

### 3.7 正式领袖查询

从 Faction.OfPlayer.ideos.AllIdeos 遍历主、次文化实际职位，筛 def.leaderRole，调用 ChosenPawnSingle 读取任职者。先验证存活、有效玩家成员与身份过滤前的人物栏名册，再遵循原版自由非奴隶殖民者等职位资格及公开 RequirementsMet；最后按 IsMaster 返回主人／非主人／无有效领袖三态。

观察者不要求同文化；不要求当前地图或 Spawned，也不增加三名信徒门槛。道德导师、未授职者、只有 Faction.leader 指针或不在名册的隐藏角色不算有效领袖。不调用 Assign／Unassign／RecacheActivity 修复任职，不从已筛选主人的列表中找领袖。

多个不同有效任职者属异常：内部标记资料冲突，反馈暂按无有效领袖处理，不任取第一人，不自动清理职位。正常原版授职的唯一领袖路径与异常分支分别测试，不改第 5.2 节的反馈数值。

### 3.8 100 tick 懒更新与人数倍率

独立文化 GameComponent 仅持有本 Game 的临时查询快照，职责如下：

| 数据／阶段 | 实现契约 |
| --- | --- |
| 共享数据 | 人物名册、主人总数、管理持链人数、正式领袖结果；每主人数仅对实际查询者懒计算，同周期复用 |
| 更新条件 | 首次使用或距上次建立已满 100 tick 时，读取中重建；其他时间复用，不增加 GameComponentTick 或逐角色轮询 |
| 生命周期 | 不序列化、不跨 Game 实例共享；加载中不建立有效快照，完整加载后首次查询重建，实例切换／tick 回退失效；更换快照清空每主人数缓存 |
| 个人状态 | GetChain、IsMaster、IsActiveOfficer 及实际主人等直接读既有查询，不以共享快照保存第二套文化身份 |

快照到期只意味着下次使用需重建，不会主动广播清空所有 thought。正常参与需求调度的人物，个人心情按原版 150 tick 散列周期、双人社交按同一对象 100 tick 重算间隔更新；共享快照心情保守按最多约 250 tick 验证收敛。暂停不按墙钟刷新；休眠、离图及暂停需求的状态遵循原版调度，不作无条件现实时间保证。

需要离图仍可查询的新 thought 显式配置 validWhileDespawned，并保留原版其他资格检查；被统计者仍计数不代表观察者正在更新 thought，不额外推动休眠需求。无 Ideology 或定义未加载时不查询缺失 Def、不建立错误文化缓存，原有无 Anomaly 路径保持。

数量 thought 基础效果 -3，MoodMultiplier 返回 max(0, count - limit)，无上限／达标／不适用时不产生数量惩罚；环境 thought 保留已定每人系数，倍率为管理持链人数。通过原版 Thought.MoodOffset 保留失效检查与后续结算，不按人数无限创建阶段、不覆盖全局心情或最终好感，不补偿非人化。互斥、全额叠加和独立领袖项仍按前文契约。
