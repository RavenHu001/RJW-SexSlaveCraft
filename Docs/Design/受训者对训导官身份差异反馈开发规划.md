## 1. 设计决定与交接摘要

主人保留现有调教心情和社交记忆的文案、Def、数值与叠加规则。训导官使用独立的一套记忆，表达对训导官的反感、动摇、适应或依赖；单次效果较主人基准弱。受训者先后接受两者调教时，两套记忆可以同时存在，按各自规则生效、刷新和到期。

| 问题 | 本方案的决定 |
| --- | --- |
| 本轮入口 | 日常调教，自动／手动共用，新旧评分均覆盖 |
| 主人原内容 | 原文案、原 Def 与实例类、数值、时长、上限、启动修正均保留 |
| 训导官内容 | 新增独立的心情与定向社交记忆 Def，不覆盖主人记忆 |
| 单次发放 | 有效训导官执行时只发训导官套；主人执行时走原套，不把一次训导官调教重复算成主人调教 |
| 共存 | 不同已完成事件产生的两套记忆可以同时保留；不互相替换、清除或刷新 |
| 弱化初稿 | 心情、实际社交偏移均按对应主人基准 ×0.5；正负效果绝对值都减小 |
| 感受档位 | 先沿用未弱化的原评分／等级判断，再弱化效果；不因乘系数而把沉沦改成适应 |
| 时长与容量 | 训导官对应项暂沿用主人对应项，不新增第三套额外认可奖励 |
| 历史类别 | 新 Def 直接表达发生过的训导官事件；之后失格／解绑不改写为主人事件 |
| 社交方向 | 受训者对实际训导官；`otherPawn` 为真实执行者，不把好感转给其主人 |
| 老记忆 | 原样保留，不按当前身份重新分类、不迁移到较弱 Def |
| 仪式 | 本轮维持原仪式反馈；独立训导官记忆仅接入日常，仪式扩展另行设计 |
| 首版职责反馈 | 训导官自身 +3 心情和主人对所属训导官 +5 条件评价保持原规则 |

本方案取代此前文档中“只换文案、主人与训导官共用同一 Def、为全部记忆增加身份快照”的设计。已废止的方案不作为本轮实施要求。

## 3. 共存、分流与历史规则

### 3.1 完成时只决定一套记忆

日常任务正常完成且认领本次结算后，在 `ExecuteOutcome` 开头、正式成长／绑定相关效果应用之前，记录一次只读发放类别：

- 实际执行者通过 `TrainerOfficerFeedback.IsActiveOfficer`：`Officer`，本次改发独立训导官套。
- 执行者仍为 SSC 性奴但完成时已不满足有效任职：`None`，不发本次受训者调教心情／社交，不能通过失格回退到较强原套。这一边界只处理记忆发放，不自行回滚已发生的正式效果或重试结算。
- 其他原本合法的执行者：`Existing`，继续现有路径；主人必走此路径。本轮不改变其他合法执行者的准入或原反馈，也不将所有非训导官角色宣称为受训者的实际主人。
- 空对象、自身施教、失效上下文等继续受原准入和结算资格检查约束；分流工具不能给无效任务发新奖励。

这一类别用于选择本次 Def。进入效果应用后不再查询当前任职来改变类别，避免同一次结算前后选择两套。原任务归属与受训者身份复查仍须保留；记录类别本身不构成发奖或重试授权。

有效训导官复用已有资格：SSC 性奴、任职开关开启及持续资格有效，普通当前方向至少 20%，普通满进度和有效终极跨方向均适用。不能仅凭特化名、单个 Hediff、历史任职或被他人指派判断。

### 3.2 共存的明确含义

| 场景 | 预期 |
| --- | --- |
| 主人 A 调教受训者 B，之后训导官 C 调教 B | B 同时保留原主人套和较弱训导官套；两者各自计时 |
| C 单独完成一次调教 | B 只获得本次训导官心情／社交；不额外生成指向 A 的主人记忆 |
| C、D 两名有效训导官分别调教 B | 社交记忆分别指向 C、D；心情采用同一训导官 Def 家族，按原生分组和上限处理 |
| 对 A 的原记忆为正，对 C 的记忆为负 | 正负心情可以共同参与总值；社交效果属于不同对象，不能把对 C 的反感转给 A |
| C 以后关闭任职、切方向、解绑或禁用终极 | 已生成的训导官记忆仍为历史事件，自然到期 |
| 同一 Pawn 以后合法变成主人再执行调教 | 原训导官记忆与新的原套记忆也可共存，这是不同事件 |
| 更新前已有指向 C 的原套强记忆 | 保留旧 Def、数值和年龄；更新后的新事件才走弱套，两者可以临时共存 |
| 接收人格记忆的身体有不同主人 | 保留历史 Def、阶段、偏移和原对象，不按新身体重新分类 |

两套 Def 独立分组，不能互相调用删除、替换或年龄刷新。各套内部沿用对应记忆的阶段／对象分组原则，重复训导官工作按新套自身上限处理。

“共存”允许总心情贡献增加。例如对应适应档，原主人 +8 与训导官 +4 同时存在，合计 +12；不能用降低主人值、覆盖原记忆或两套取最大值抵消这个需求。多次事件与多个对象的总量需实测，不把“单次较弱”写成“任何累计场景都必然比主人小”。

## 4. 弱化数值初稿

### 4.1 统一 50% 系数与整数口径

弱化系数 **K=0.5**，已由维护者确认。它作用于受训者本次心情效果和本次定向社交效果的绝对强度；负面也按同样系数趋近零。本版不延长持续时间、不增加单套容量来补偿弱化。

弱值一律换算为整数，规则为**四舍五入到整数，并对非零基准保底绝对值至少为 1**：`弱值 = RoundAwayFromZero(主人运行基准 × K)`，当 `主人运行基准 ≠ 0` 且该结果被舍入为 0 时取 ±1。这样既避免界面出现半值，也避免小幅效果被截断成零效果。D 本身的 `Mathf.Round` 由原算法负责，`D=0` 仍不发记忆，不受保底规则影响。

| 模式／感受 | 主人运行基准 | 训导官值 |
| --- | --- | --- |
| 新模式心情：反感 | -10 | -5 |
| 新模式心情：动摇 | +2 | +1 |
| 新模式心情：适应 | +8 | +4 |
| 新模式心情：沉沦 | +15 | +8 |
| 新模式社交 | 原计算 D | WeakValue(D) |
| 旧模式心情：厌恶／迷茫／极乐 | -10／+2／+15 | -5／+1／+8 |
| 旧模式社交：反感／适应／沉沦 | 运行值 -20／+5／+15 | -10／+3／+8 |

上表的旧模式一列刻意使用**运行基准**：`SSC_Training_Social_Lvl2/3` 的 XML 写的是 +10／+40，由 `SSCThoughtBootstrap` 在启动时改写为 +5／+15，所以弱值是 +3／+8 而不是 +5／+20。弱套旧社交的 XML 直接写入运行后的值，且不受启动修正二次改写。

K 只保留一个代码常量来源；XML 的整数心情值由回归断言按 `K` 与主人值互相校核。如调整 K，须同步数值表、说明、XML 与验收断言。

### 4.2 感受档位由未弱化结果决定

新模式先按原算法得到 D，再用原 `GetDisplayStage(D)` 选择 0～3 档，最后设置训导官社交实际值 `WeakValue(D)`。心情同样沿用这个档位，使用弱心情 Def 的对应阶段。

例如 D=12，主人对应沉沦、+12 好感；训导官仍为沉沦，但实际好感 +6。若直接让原动态社交类按 +6 判断，会误显示为适应。因此新训导官动态社交类应按**保存的阶段**显示／分组，不按弱化后的偏移重判档位。

D=0 仍不发心情／社交记忆；D=-1 则为反感、训导官社交 -1（`WeakValue(-1)` 保底绝对值 1，而不是被舍入为 0）。D=1 同理为动摇、训导官社交 +1。旧模式沿用本次已经确定的等级，不用较弱数值重新决定等级。

### 4.3 持续时间、容量与间接影响

训导官动态心情 1 天、容量 3；动态社交 15 天、容量 40、同对象容量 40。旧模式弱心情各 1 天、容量 3；弱社交 15／15／30 天、容量 3／10／10。原项未显式设置的容量字段，新项保持对应的相同默认语义。

本次将这些相同值作为初稿，先通过效果减半实现强弱差异。由于 Def 家族拆开，整体能够同时保留两套贡献，这是有意的玩法改变；不新增共同总上限，也不把主人原上限改小。

受训者对实际施教者的好感参与后续调教评分，所以弱社交会改变未来评分的累积速度；本次已计算的评分和成长收益不乘 K。对训导官的好感不能当作对实际主人的好感，不能额外改变恶堕衰减的主人关系项。原生总好感上下限、其他记忆抵消和长期饱和仍需纳入平衡评估；单次偏移减半不保证最终总好感恰好减半。

## 5. 新 Def、实例类与本地化

### 5.1 独立 Def 清单

建议新增 `Defs/ThoughtDefs/SSC_TrainerTrainingMemories.xml` 及 `Sexslavecraft/Defs/ThoughtDefs` 镜像，共 8 个 Def：

| 建议 defName | 用途 |
| --- | --- |
| `SSC_TrainerTraining_MoodDynamic` | 四阶段弱心情，对应新评分 |
| `SSC_TrainerTraining_OpinionDynamic` | 四阶段动态社交；保存阶段并设置实际 D×K |
| `SSC_TrainerTraining_Mood_Lvl1/2/3` | 三个旧模式弱心情 Def |
| `SSC_TrainerTraining_Social_Lvl1/2/3` | 三个旧模式弱社交 Def |

名称可以在开发前统一调整，但不得覆盖现有主人 Def。补齐 `SSCDefOf` 字段／加载及工程引用。旧模式新 Def 直接写入弱化后的运行基准，不能把 +10／+40 折半，也不能被原启动修正意外改回 +5／+15。

普通弱心情优先使用原生 `Thought_Memory`，固定弱社交优先使用 `Thought_MemorySocial`。新动态社交可以增加独立 `Thought_MemoryTrainerTraining`，按 `CurStageIndex` 选择标签／描述，显示实际 `opinionOffset`；原 `Thought_MemoryDynamicTraining` 保持不变。

新动态社交保留原套“同感受档位才同组”的语义，但以保存阶段实现。核验本机 `Assembly-CSharp.dll` 的原生分组、同对象上限和合并行为，并据此补充最小实现。不能未经核验便声称普通职责记忆的单份 `Renew` 行为也覆盖多档动态社交。

### 5.2 不再要求身份快照字段

新 Def 已经记录“这是一条训导官施教记忆”，保存阶段记录当次感受，`otherPawn` 记录实际施教者。显示不需要读取当前任职、绑定或身份，也无需修改主人实例类或给原记忆增加枚举快照。

采用该结构时，不新增 `trainingActorSnapshotVersion`、`TrainingActorRole` 等历史方案字段，也不提升通用人格快照版本。若实际实现确需额外字段，应说明必要性并贯通人格采集／复制／存读档／恢复，不能仅实现记忆类自身的 `ExposeData`。

### 5.3 文案初稿

主人原文案保持。下面只描述新训导官套；标签明确“训导官调教余韵”或“训导官调教记忆”，社交描述明确实际执行者。

| 新模式感受 | 训导官描述方向 |
| --- | --- |
| 反感 | “同样受人支配的{0}却来训导我，让我难以接受。” |
| 动摇 | “明明身份相近，我却开始接受训导官{0}的指导。” |
| 适应 | “我逐渐习惯了训导官{0}的指导。” |
| 沉沦 | “那次经历让我越来越依赖训导官{0}的调教。” |

旧模式分别保留厌恶／迷茫／极乐以及反感／适应／沉沦的感受方向，不用正面文案覆盖差结果。训导官弱套的依赖描述应比主人原套克制，不能宣称训导官成为主人、取代主人或获得新所有权。

不默认两名性奴同主，也不宣称某位主人明确命令本次工作。本版不新增同主人／跨主人、特质、嫉妒或敬重分支。

四语新增 `DefInjected/ThoughtDef/SSC_TrainerTrainingMemories.xml`。动态社交描述需运行时格式化，另增 `Keyed/SSC_TrainerTrainingMemory.xml`，`{0}` 显示实际施教者名字、`{1}` 显示实际弱化偏移的整数形式；静态阶段与运行时描述共用清晰的键清单。心情不误报社交数值。根语言目录和源码语言镜像保持一致。

人物显示名沿用实际引用的当前名字；不保存历史名字。改名不改变训导官 Def 与阶段；无可用名字时使用本地化兜底称呼，不查询其主人代替。既有社交对象丢失处理沿用原规则。

## 6. 旧档、人格与共享路径兼容

1. 更新前所有旧记忆保留原 Def、数值、阶段、年龄和人物引用。即便对象现在是训导官，也不自动降级或改写；新完成事件才分流。
2. 主人原 Def 与实例类不修改，从而避免原类深度保存与新类混合升级问题。新 Def 在普通存读档后保持身份和阶段，不重查当前身体关系。

### 10.1 简单条件性任职加成

| 想法 | 获得者／方向 | 建议初值 | 生效方式 |
| --- | --- | --- | --- |
| 受到主人信任（社交） | 训导官对实际绑定主人 | +5 好感 | 当前有效任职且主人有效时生效 |
| 受到主人信任（心情） | 训导官本人 | +3 心情 | 使用与社交想法相同的当前条件 |

维护者明确的是简化为反向好感与心情；+5／+3 是本次提出的建议初值，尚非实机平衡或数值确认结果。它们是固定任职加成，不乘受训者弱反馈的 K，也不根据最近工作、成绩、受训对象数量或累计次数分档。

共同条件直接复用首版只读资格：训导官通过 `TrainerOfficerFeedback.IsActiveOfficer`，并有存活、未销毁、未被丢弃且具 SSC 主人身份的实际绑定主人。可复用 `HasOwnerAppraisal(owner, officer)` 验证这一对角色；调用参数顺序保持该方法定义，不因为本次好感反向而把参数交换。

- 普通有效任职、普通满进度和有效终极跨方向均适用。
- 关闭个人任职、普通切走方向、解绑、锁链退阶或终极禁用后，两项在原生想法刷新后失效；资格恢复后重新生效。
- 临时停工、倒地或旅行本身不撤销任职加成，沿用首版语义。
- 只评价训导官自己的实际主人。跨主人施教或受训者指派不改变本项对象，不能奖励受训者的主人或指定调教员。
- 不以开启开关或工作完成发历史记忆，不设持续天数，不叠加实例；反复开关不能累积 +5 或 +3。

与已有首版反馈的关系：主人对训导官的 +5 评价继续保留；本节新增训导官对主人的 +5，形成两个方向。训导官的任职信任心情 +3 可与完成工作的一天职责心情 +3 共存，两者同时有效时合计 +6；职责心情仍可在失格后自然到期，信任心情则随当前条件失效。两种心情不得互相替换或混为同一个事件。

### 10.2 已核查：受训者好感参与日常评分

2026-10-10 检查当前生产代码，确认已有这一机制，无需新增训导官专属评分加成：

| 模式 | 原有关系项 | 代码依据 |
| --- | --- | --- |
| 新评分 | `受训者.relations.OpinionOf(实际执行者) / 40f` | [TrainingOutcomeUtility.GetScore](../../Sexslavecraft/common/TrainingOutcomeUtility.cs) |
| 旧评分 | `受训者.relations.OpinionOf(实际执行者) / 5f`，之后与其他分数一起乘尺寸系数，再加原有随机项 | [LegacyTrainingUtility.GetScore_Legacy](../../Sexslavecraft/common/LegacyTrainingUtility.cs) |

[日常驱动](../../Sexslavecraft/JobDriver/JobDriver_Train.cs)使用 `ConditioningUtility.GetScore(pawn, target)`，其中 `pawn` 是实际施教者、`target` 是受训者。因此训导官执行时，读取的是受训者对该训导官的总好感，而非受训者对实际主人的好感。相同其他输入下，好感增加 40 对新评分关系项贡献 +1，对旧评分在尺寸倍率前贡献 +8；负好感同样参与。

前述训导官弱社交记忆通过原生总好感自然影响后续调教评分。日常驱动先取得本次分数，再发本次结算记忆，所以不应为新记忆回算本次分数，也不能重复叠加一次“训导官好感加分”。训导官自己的信任心情不直接进入该评分公式。

此项核查针对日常调教。仪式经 `GetQuality` 和整场质量结算，本节不新增仪式好感评分项。

训导官对实际主人的反向 +5 会进入训导官自身的现有恶堕衰减关系项：[Need_Corruption.cs](../../Sexslavecraft/common/Need_Corruption.cs)读取锁链关联主人的好感，并计算 `Clamp(1 - opinion / 200, 0.3, 1.0)`。本节接受既有机制产生的间接影响，不增加专属衰减公式，也不把对受训者或其他主人的好感代入。
