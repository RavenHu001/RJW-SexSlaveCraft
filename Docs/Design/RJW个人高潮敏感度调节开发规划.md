## 3. SSC 设定、身体载体与操作流程

### 3.1 锁链提供控制，身体状态保存选择

[性奴之锁链](../../1.7/Defs/HediffDefs/HediffOfSexSlave.xml)现有设定已包含向神经系统传达主人意志、强制调节身体机能。维护者补充的设定为：随着紫色微械侵蚀身体与神经，性敏感度可以受主人控制；调高后，较轻的刺激也能引起明显反应。当前只落实已有 RJW 行为中的敏感度调节及随 Hediff 的属性／心情，日常刺激事件及其独立框架暂不开发。

拟新增全身 Hediff，暂定 `SSC_OrgasmSensitivity`／“微械感度调节”，实现类暂定 `Hediff_SSCOrgasmSensitivity`。名称用于定位规划，正式文案另行落实。

- `Part = null`，不依赖子宫或某一类生殖器；不自动补建解剖部位。
- 缺记录表示关闭，开启时通过正常健康入口创建唯一记录，关闭时正常移除。
- `Severity` 使用稳定的 1／2／3／4 表示所选档位；其含义是枚举档位，不是自然成长进度、药物负荷或倍率数值。
- 不安装自然衰减／成长组件。读档及自有写入须规范化重复记录、非法档位，具体异常修复方式在载体实现时记录，不由 getter 静默重写。
- 枚举值与 Hediff 合并规则必须独立处理：当前原版 `Hediff.TryMergeWith` 会相加严重度，不能直接沿用，也不能照搬经验型状态“取最大进度”的策略。重复加入时保留原有效 owner 与原档位，不相加、不自动升档；明确的调档请求只经原上下文 setter 修改。显式规范化时保留首个合法原记录并清理重复，不从重复记录推导更高档位。
- 完整运行 Def 必须声明可容纳 1～4 的严重度范围，合法状态为有限的整数档位；非整数、越界或非有限值不参与效果，不以取整自动升档。异常修复只在明确写入／读档规范化入口进行，普通查询不能补建或改档。
- 锁链的 `Severity` 继续表示关系阶段，不能挪作本功能档位；锁链、Comp 和人格能力字典不保存第二份选择。
- 性奴身份失效、解绑、性奴自身死亡或人格替换期间保留身体档位，但暂停实际效果；重新满足原资格时可恢复。这里的死亡指性奴自身，主人死亡不使仍有效的锁链指令失效。不能把“有保存记录”等同于“当前有效”。

普通身体开发及 PNA 仍保留原有语义；它们现有的 `SexFrequency`、`SexSatisfaction` 不作为本项档位保存源。效果作用于驱动所属的角色自身，双方分别查询；不要求行为对象恰好是绑定主人。

### 3.2 ITab 专用分档行

在 [身体管理 partial](../../Sexslavecraft/ITab/ITab_SexSlaveTraining.BodyManagement.cs)中增加关闭／一至四档的下拉行，显示当前档位、配置倍率及暂停／不可编辑原因。默认关闭，不新增自动开启或追溯赋值。

这是枚举配置，按[个人能力规范](../Development/Reference/个人能力开关接入规范.md)保留独立业务语义，不注册成几个互斥 bool，也不为了本项扩建整个通用能力框架。复用现有布局风格与上下文提交原则。

视图构建必须覆盖“没有其他 bool 行，但当前可显示敏感度行”的情况，并统一计算行高、换行、滚动区域和无资格时保留档位的显示。当前 `toggles.Count == 0` 的提前返回不能遮掉新入口。

菜单创建时捕获原 Pawn、Comp、人格 token、原锁链和原身体 Hediff owner；无记录时也捕获“原记录不存在”的事实。提交时复查原上下文，不重新捕获新凭据；解绑重绑、人格替换、同 Def 新实例或外部增删记录，均不能让旧菜单获得新载体权限。查询和绘制不得创建状态。

区分实际准入与修改资格：开启／改到非零档位需当前身份、有效锁链、阶段和配置允许；关闭只需当前身体可编辑、原角色／人格／记录上下文仍有效，不因效果已失格或配置损坏而阻止清除自己的选择。若旧锁链凭据已经失效，旧菜单仍应拒绝，必须由刷新后的当前视图发起关闭。重复选择当前值保持幂等，不重建 Hediff 或重置执行状态。

### 3.3 已确认的阶段解锁与有效档位

| 当前锁链阶段 | 可选档位 | 默认最高高潮敏感系数 |
| --- | --- | --- |
| 见习性奴 | 关闭、一档 | ×2 |
| 性奴 | 关闭、一至二档 | ×4 |
| 屈服性奴 | 关闭、一至三档 | ×8 |
| 肉便器化 | 关闭、一至四档 | ×16 |

按现行权威查询取得当前锁链阶段，不用历史最高恶堕、Trait 或当前恶堕百分比替代。默认门槛下：

```text
当前最高可用档位 = 当前锁链阶段（1～4）
实际生效档位 = min(保存档位，当前最高可用档位)
```

无有效身份／锁链或其他准入失败时，实际档位为关闭；已有身体记录保留。降阶不改保存选择，例如保存四档、当前二阶段则实际二档；恢复四阶段后恢复四档。菜单提交不能新选超阶段档位，旧请求须重新校验阶段；当前选择超限时，界面同时展示保存档位、实际档位和限制原因。

身份与阶段须分别检查：[现有身份工具](../../Sexslavecraft/common/SSCIdentityUtility.cs)的 `GetSexSlaveStage` 不等于“已选择性奴身份”，[关系工具](../../Sexslavecraft/common/SSCBondUtility.cs)的 `GetChain` 也只是读取记录，不自动验证全部引用。统一有效状态查询须同时检查当前性奴身份、当前身体记录归属、当前链及主人引用／当前阶段。依照现有锁链语义，主人引用为空、Destroyed／Discarded 等失效时暂停；主人仅死亡、离图或暂时不能行动，不额外新增暂停条件。不得使用可能转而返回指定调教员的查询充当实际锁链主人。

脆弱度、高潮敏感系数、持续心情及界面说明均从同一份有效状态查询取得实际档位。不能直接用保存 `Severity` 决定属性或心情，否则降阶后仍可能获得四档效果。有效阶段派生或专用消费者适配的具体实现须在开发时核对，保存源仍只有身体档位。

缓存刷新不能只依赖敏感度 `Severity` setter：锁链降阶、解绑重绑、直接改主人引用、人格／Comp 替换都可能使保存档位不变但有效状态变化。自有变更入口统一刷新属性与思想缓存，运行消费者复查当前 owner／链／阶段；未通知的外部修改不能依靠旧缓存持续生效。不得针对单个 Pawn 修改共享 HediffDef、HediffStage 或 ThoughtDef 数值。

### 3.4 已确认的两项属性

| 属性 | 含义与来源 | 当前参数状态 |
| --- | --- | --- |
| RJW 脆弱度 `Vulnerability` | 使用 RJW 原 StatDef 及原消费者，按实际档位提供加法偏移；不是伤害易损倍率或概率直接加成 | 已确认 **+0.30／+0.75／+1.50／+3.00**，以四档 +3 为基准，保留上一候选方案比例放大三倍 |
| 高潮敏感系数（暂称） | 本功能对实际原始推进量的倍率，唯一参数来源为四档 XML 配置 | 已确认 **2／4／8／16**；关闭或失格不增加推进 |

| 实际生效档位 | 高潮敏感系数 | RJW 脆弱度加法偏移 |
| --- | --- | --- |
| 关闭／无资格 | 正常推进，不补充 | 0，不应用本项修正 |
| 一档 | ×2 | +0.30 |
| 二档 | ×4 | +0.75 |
| 三档 | ×8 | +1.50 |
| 四档 | ×16 | +3.00 |

脆弱度仅按实际档位加一次，不再按锁链阶段额外乘算；阶段负责解锁。+3.00 是属性计算中的偏移，不是强制把最终读值设为 3，也不是把最终属性乘以 3。结果继续受 RJW 原抵抗能力、身体状态、其他属性修正及原统计边界影响，不为本项绕过原计算或追加效果保证。上述数值是已确认的首版配置，不代表已经实机平衡验收。

本机 RJW 作者资源 `1.6/Defs/StatDefs/Stats.xml` 声明了 `Vulnerability`，`xxx.get_vulnerability` 通过 `RJWStatDefOf.Vulnerability` 查询。实施时继续核对实际运行 Def、最终属性边界与其他修正，不绕过原统计流程。无资格／关闭时停止本项脆弱度修正；保留配置记录不能让属性继续生效。

高潮敏感系数不等于 `SexFrequency` 或 `SexSatisfaction`，也不同时作为另一份效果重复乘算。当前不新增移动、操控、意识、工作效率、恢复或需求频率等其他 Buff／Debuff。

当前“高潮敏感系数”要求在 ITab／Hediff 说明中显示实际倍率，并由业务查询供推进消费者读取；不隐含再增加一个会重复参与运算的 StatDef。若以后需要把它扩展为可受其他模组修改的独立 StatDef，另行定义组合顺序及接口，不能本次顺带引入。

### 3.5 随 Hediff 的持续心情

维护者确认当前只做跟随 Hediff 的心情，采用持续情境思想；**不要求已经发生高潮，不等行为结束，不生成本项事后体验记忆，也不按高潮次数堆叠或刷新独立记忆。**

## 4. 独立的原始推进量公共接口

### 4.1 公共职责

第一批已实现 `SSCOrgasmProgressUtility`，供本项及未来依赖原始高潮推进量的功能复用。它是 RJW 计时观察工具，**不依赖敏感度档位、SSC 身份、锁链资格或本项倍率**。

第一批公共入口如下；类型、失败原因及最近有效结果查询以[当前源码](../../Sexslavecraft/common/Orgasm/SSCOrgasmProgressUtility.cs)为准：

```text
CaptureBeforeAdvance(driver, observationContext) -> 只读推进前快照
TryGetOriginalAdvance(snapshot, driver, currentContext, out advance) -> 是否取得有效原始推进结果
```

`observationContext` 由计时适配层提供，包括来源标识、允许变化的字段、原驱动／Job／SexProps、周期凭据及本次操作编号；`currentContext` 用于完成时复核。普通来源只允许倒计时推进，可选移动阈值来源必须显式声明，不能由公共函数看到差值后自行猜测。周期与操作编号在适配层产生，嵌套调用各自持有；不按全局 tick 去重，不由公共 getter 创建状态，也不依赖 SSC 身份、锁链或敏感度保存节点。这样即使本项关闭，其他消费者仍可复用公共采样契约。

公共结果至少提供：原驱动／角色、本轮与本次推进的识别信息、推进来源、推进前后计数与阈值、`CounterAdvance`、`ThresholdAdvance`，以及合成的 `RawAdvance`。差值运算使用足够宽的整数中间量，避免两个计数字段相减溢出。这里的单位是距触发阈值的计数距离，不是百分比、每秒速度或推算的高潮次数。

该工具只观察、验证并计算，不修改倒计时，不调用高潮，不应用增益，不写存档／Hediff／日志，不在查询中创建组件。结果不可变，同一次原始推进只生成一份结果，各消费者读取同一份；不能让后调用的消费者采到 SSC 已经补充过的进度。

公共接口不自行调度消费者或维护全局事件队列。本项当前只有敏感度一个推进修改者；未来其他功能可读取同一原始样本，但多个修改者之间的加法／乘法组合不由这个只读工具擅自规定。应用前若计数已被其他写入改变，须重新验证实际当前状态，不能把旧样本的推进后计数写回覆盖外部结果。

### 4.2 有效采样边界

约定时序：

```text
在已确认的真实推进入口捕获快照
→ 原有流程完成本次推进，包括该边界内已有的推进修正
→ 在 SSC 加速和实际高潮判定之前完成公共采样
→ 各消费者读取同一份原始结果
→ 敏感度消费者补充进度
→ 原高潮判定及所有既有处理继续运行
```

统一按“距阈值的距离缩短了多少”计算：

```text
CounterAdvance = before.sex_ticks - after.sex_ticks
ThresholdAdvance = after.orgasmstick - before.orgasmstick
RawAdvance = CounterAdvance + ThresholdAdvance
           = (before.sex_ticks - before.orgasmstick)
             - (after.sex_ticks - after.orgasmstick)
```

当前普通／动画／UAP 推进不改阈值，故退化为原计数差；可选 Onahole 的专用推进操作会同时上移阈值、下移计数，不能漏掉阈值项。**只有逐项核实的推进入口才允许将阈值变化解释为推进**；普通适配若发现阈值变化仍判样本无效，初始化与重设一律不套此公式。调用方须提供可信的推进范围；不能把跨任意代码的差值当作通用速度接口。

实施时须同时校验驱动仍属于原角色和原任务，SexProps／周期等必要上下文未更换，且未跨过初始化、高潮计数变化、动画重设、仪式阶段切换或 SSC 自身补充。单靠差值正负不能识别所有重置：初始化也可能把计数写小，因此真实边界和周期凭据必须共同成立。

- 有效 `RawAdvance = 0` 是“本次未推进”，不是采样失败。
- 计数回增、上下文失效、重置或边界不明返回无效结果，并给出可诊断原因；不能回退为假定推进 1。
- 不从相邻两次 `Orgasm()` 的计数直接相减，不在整个 `SexTick()` 结束后才测量，避免高潮后重置污染结果。
- 不将初始化到当前的累计差值、全局 tick 时间差、暂停时间或离场时间当成本次推进量。
- 同一次推进的多个消费者可以重复读取结果，修改型消费者各自保证只提交一次。去重按真实推进操作，不能仅按 `TicksGame` 粗暴合并，否则可能吞掉同 tick 内合法的多次推进。

### 4.3 挂接策略与实施前提

优先复用真实接口；本轮确认没有直接读取原始推进量的接口，采用字段采样。已对当前 DLL 的完整方法 IL 逐条核对，确定在真实推进的 `sex_ticks` 写回点接入，具体五处主路径及可选 Onahole 边界见 [14.2 节](#142-原始推进量的确定采样位置)。

仅给 `Orgasm` 随意加一个 Prefix，不能自动保证捕获了推进前状态，也不能保证早于 SSC／第三方的阈值观察。基础 `SexTick` 的原生代码还可能被动画 Prefix 替代；UAP 多人又有独立推进入口，必须分别观察，再交给同一公共函数。

可以在本项目的 Harmony 适配层对这些计时边界增加观察和 SSC 补充，但不修改第三方源文件／DLL，不重写其高潮处理结果，不增删原生事件调用。无法可靠识别的路径保持原行为、暂不施加 SSC 加速，并记录有限诊断；不停止原任务，不伪造兼容成功。

主路径采用窄范围 Transpiler，将已确认的计时写回交给适配桥：保留原表达式求出的新计数，捕获旧值，执行原写回，调用只读公共函数形成原始样本，再由敏感度消费者补充进度，最后回到原调用链。公共函数自身仍不写计时；写回桥与消费者另负修改职责。原有 `Orgasm()` 调用以及其中所有 Prefix／原方法／Postfix 继续运行；高潮入口及阈值预判 Prefix 可读取已补充的计时，Postfix 则仍看到原高潮处理后的状态，不能假定它还能读到高潮前计时。不再增加一个负责加速的 `Orgasm` Prefix。

动画实际推进位于第三方 Prefix 内，须对该 Prefix 方法本身接入计时观察，而非只补基础方法。安装先后、有效排序、重建入口包装和 IL 校验约束见 [14.3 节](#143-补丁顺序与安装约束)。第一批已在独立宿主验证新采样补丁的实际排序、五处写回及 Prefix detour，完整游戏的启用组合尚待实机。未知或锚点不符的路径仅停用相关 SSC 采样／后续效果，原流程继续；不能改回固定减 1 或把当前进度比例当速度。

## 5. 四档统一倍率算法

### 5.1 倍率与余数

设本次有效原始推进量为 `Δ`，按当前阶段限制取得实际生效档位及其“高潮敏感系数” `r`。原流程已经执行 `Δ`，SSC 补充：

```text
本次额外推进理论量 = Δ × (r - 1)
```

四档默认 `r = 2 / 4 / 8 / 16`，关闭或当前不具备资格时不补充。原始推进为 3、档位为四档时，原流程推进 3，SSC 再补 45，合计 48；不假设原始推进固定为 1。

虽然默认倍率为整数，XML 允许有效的小数配置，使用每驱动／周期的余数保留小数部分：

```text
x = carry + Δ × (r - 1)
extra = floor(x)
carry = x - extra

remaining = max(0, 原始推进后的 sex_ticks - 当前 orgasmstick)
实际补充 = min(remaining, extra)
sex_ticks -= 实际补充
```

这是算法说明，不是本次写入运行文件的实现。执行前仍须复查原样本、驱动和周期未失效。乘法使用有限数值并先做饱和比较，不能让极大有效配置先溢出再截断。

`extra`、新余数及目标计数先在局部量中计算并验证，再提交一次；不能先更新余数再发现样本过期。无效样本不提交额外进度，适配层使相关旧执行凭据失效；原始零推进正常保留同周期余数，不触发任何额外写入或事件。原计时写回的执行与本项是否成功分开，具体失败边界见 14.2 节。

### 5.2 阈值与真实事件

- 使用当前实例阈值，不硬编码 180；不新增固定最短等待，不把 60 tick 或其他常数写成保护下限。
- 原流程已经达到／越过阈值时，不把计数抬回去或延后高潮，交给原判定处理。
- SSC 额外推进到达阈值即停止，超过本轮需求的整数进度不补发、不跨轮积存。真实高潮后清理本周期余数。
- 不循环调用 `Orgasm`，不递归补发，不增加虚拟计数，不直接代替原结算。倍率很高时，可在原有每次有效判定时达到阈值；这是离散执行时机的结果，不是新增时间下限。
- `orgasmStartTick` 保持原周期起点，原进度条随倒计数加快；不为了实现倍率重设场景时长或反复初始化周期。
- 四档使用相同流程；第四档不自动进入无限 Job，不改变 `neverendingsex` 或原任务结束条件。是否能几乎每次推进都高潮，取决于原周期及推进量，不保证固定次数。

### 5.3 启停、周期及保存

最终采用实际推进时应用倍率，替代早期“下一轮初始化时缩短周期”的方案。改档、关闭或资格变化从下一次有效推进开始影响新增进度；已经完成的进度保留，不重置进度条或倒推恢复。

档位／资格／当前锁链阶段变化后刷新实际档位、倍率及属性／心情缓存；关闭／失格清理本功能余数，不欠账、不在恢复后补发。驱动、人格上下文、周期、仪式阶段或计时初始化变化时，丢弃旧采样并重新建立边界，不能把重设当作推进。

旧档缺新记录即关闭。身体档位仍只存在 Hediff；执行余数通过对 `rjw.JobDriver_Sex.ExposeData` 的附加序列化补丁，深存于当前驱动的独立 `sscOrgasmAdvanceState` 节点。运行时弱引用表只作实例索引，不能代替该存档节点。节点包含版本、余数和周期／归属校验凭据；倍率指纹只用于识别 XML 改动，不成为配置来源。字段及阶段流程见 [14.4 节](#144-执行余数的存档载体与字段)。

推进快照和“待应用一次”的瞬时凭据不跨读档复用，不在加载时重新补乘。读档先将余数标为待恢复，等 Toil 构建及自我调教计时恢复完成，在首次真实推进前校验；原驱动读档后若确实开始新周期则清零，不为保留余数而改写其原计时。新 Job、出生复制和人格替换均不继承旧执行余数。默认整数倍率不能替代对 XML 小数倍率读档行为的验证。详细恢复屏障及失败处理见 [14.5 节](#145-加载顺序与延迟恢复)。


**原写入必须独立完成。** 桥接方法保持原 `stfld` 的目标实例与原表达式结果；即使本项关闭、适配门槛未通过、快照无效或本模块可恢复检查失败，仍执行这一次原写入并返回原控制流。采样失败不能提前 return 而吞掉原推进，也不能在失败回退时再次写入原值、覆盖已经提交的补充。只处理 SSC 自己的可恢复错误；原表达式、原字段访问、后续 `Orgasm` 及其他模组的异常语义保持，不用一个包住整个行为的 catch 隐藏它们。补充的目标计数与余数先算好，再作无回调的提交；结果分发发生在补充之前且同一结果只由该操作持有，后调用者不重新差分。

5. **周期观察包含 override 与直接重设。** 观察基础 `SetupOrgasmTicks`，以及不调用基础实现的自慰 override；可选 Onahole override 同样需单独检查。嵌套 override／base 用重设深度合并为一次周期失效，清理本模块样本／余数，不调用 Setup、不重算第三方周期。另覆盖动画 Start、UAP `SynchronizeRJWClock`、SSC 仪式直接写入／回退动画和自我调教恢复屏障。这些初始化写入均不接推进桥。需要成对开闭的观察范围应包住相关改写 Prefix／原方法／Postfix，并核对其有效排序；每次调用记录本范围是否真正打开，在 Finalizer 中至多关闭一次，不能因原方法被跳过或前置错误造成深度泄漏。加载中的重设只记录事实，不删除 14.5 节的待恢复载荷。
6. **事件观察只清理执行状态。** 在原 `Orgasm` 及已支持自定义事件的完成边界观察实际计数前后变化／周期重设。存在真实事件或真正新周期时清除旧余数；异常时使当前样本失效，保留原异常语义。该观察不改第三方返回值，不增减原计数，也不把一个被跳过的调用当成真实事件。

本机 Harmony DLL 已核实公开接口 `Harmony.GetPatchInfo(MethodBase)`、`PatchProcessor.GetSortedPatchMethods(MethodBase, Patch[])` 和两个 `GetCurrentInstructions` 重载。前两者用于检查 Prefix／Postfix／Transpiler／Finalizer 的有效排序；**不能把 `GetPatchInfo` 中的列表枚举顺序当作执行顺序**。本机 `PatchSorter` 会处理 before／after 依赖，存在冲突时还会打破依赖，因此必须检查排序结果与诊断，而非只查属性是否写过。

**`GetCurrentInstructions` 不是被动读取已安装包装。** 本次继续核实它调用 `MethodCopier.GetInstructions`（token `0x060001BE`），后者读取原 IL、按当前顺序重新加入 Transpiler 并执行转换；结果不包含完整 Prefix／Postfix 包装，也不能证明 JIT／detour 实际经过某桥。主要证据应是实际安装期间本适配收到的输入／生成的输出、排序信息，以及启用后对真实调用的有限诊断。仅在确认相关 Transpiler 可安全重放时，才可用此 API 作辅助重建检查；第三方不可安全重放则不调用，不为诊断额外执行它的副作用。

本适配的 Transpiler 转换本身须可重复执行：只转换输入，返回本次匹配报告；不读取游戏 Pawn、不注册更多补丁、不清余数、不直接改变正在使用的适配开关。安装协调层在该轮安装／检查全部完成后提交门槛状态，诊断重放不提交。写回桥默认只保留原写入，直到所属路径明确通过门槛才启用 SSC 补充；门槛失败不停止原方法。不能从 Transpiler 内递归调用 `GetCurrentInstructions` 检查自身，或因一次重放误启用／误停用正在执行的路径。

对“补第三方 Prefix 本身”的静态可行性，另外核对了本机 Harmony 的 `MethodCreator.EmitPrefixes` 与 `MethodCreatorTools.EmitPatchCall`（token `0x060001E1`／`0x06000238`）：普通 Prefix 经其 MethodInfo 生成 `call`，不是直接把原 Prefix 方法体复制进入口。该证据支持对被调用方法单独适配；仍须按第 3 条检查当前运行时的包装更新与实际调用，不能拿这段磁盘源码替代 JIT／detour 验收。

上述排序检查与可选重建诊断用于适配安装过程；前期 DecompilerServer 读取的是磁盘程序集，第一批现已补充独立宿主的实际安装／排序证据，完整游戏进程的全组合仍未验收。安装后或检测到相关方法补丁集合改变时，先使旧门槛失效再重查，包括原方法、动画 Prefix 本身、周期重设／恢复观察点；不每 tick 反射／扫描全表。不支持未经重新检查的任意运行中重打补丁。若支持某条路径所必需的周期或恢复观察点失配，相关推进桥也不能单独继续加速；缺失事件清理不能被“写回锚点仍匹配”掩盖。检查失效仅关闭相应 SSC 采样／效果，原 Job 与模组逻辑继续。

### 14.4 执行余数的存档载体与字段

**采用每个 `JobDriver_Sex` 的附加深存节点，不使用 Hediff／人格／全局 GameComponent 保存余数。** 原版 `Pawn_JobTracker.ExposeData` 对 `curJob`、`curDriver` 使用 `Scribe_Deep.Look`；RJW `JobDriver_Sex.ExposeData` 保存 `sex_ticks`、`orgasmstick`、`orgasmStartTick`、`duration`、`orgasms` 等已有字段。本机核对的 receiver、SSC 日常／自我／仪式调教及 Onahole ExposeData override 均沿继承链调用此基类；UAP 该发起驱动没有另起独立存档入口。

拟在 `rjw.JobDriver_Sex.ExposeData` Postfix 中，经 `Scribe_Deep.Look` 保存实现 `IExposable` 的 `SSCOrgasmAdvanceSaveState`，节点暂定 `sscOrgasmAdvanceState`。每个驱动沿基类调用只写一份，不能再给所有子类各写一份同名节点。运行时用 `ConditionalWeakTable<JobDriver_Sex, …>` 索引执行记录；真正跨读档的数据在深存节点。保存入口与快照 getter 分开，读取原始推进不会触发存档。

执行记录中分开保存“加载得到的待恢复载荷”和“当前周期已经提交的运行余数”，状态至少区分无载荷、待恢复、已接续与已失效。载荷类只负责自身字段的 Scribe，不从自己的 ExposeData 回调修改 Pawn／驱动、建立样本或宣布恢复成功；运行时周期 token 不写入载荷。这个区分防止构建期的清零逻辑同时删掉尚待校验的保存数据。

同一驱动在 LoadingVars 建立的执行记录必须供后续各加载阶段复用；不能在每次 ExposeData Postfix 中重新建记录、清空载荷，或因该阶段 `Scribe_Deep.Look` 不执行构造而用空局部量替换既有记录。附加节点保存的是类对象，由标准 Scribe 注册一次；运行时字典的索引关系不取代这些回调。

| 节点字段（暂定） | 保存用途与规则 |
| --- | --- |
| `schemaVersion` | 本格式初版为 1，保存时明确写出；加载缺字段默认 0，未知／缺失版本不冒充当前格式，缺节点按余数 0 |
| `carry` | `double`，有限且 `0 ≤ carry < 1`；仅保存已经提交的小数余数，不保存整数超额 |
| `jobLoadId`／驱动类型 | 使用已有 `Job.loadID` 与驱动类型确认原任务，不能只比较 JobDef 或 Pawn |
| 身体 Hediff、锁链与主人引用 | 按正常 `Scribe_References` 记录既有对象，读档重绑原记录；不深拷贝、不创建新链／身体记录，不因主人仅死亡而拒绝 |
| 实际档位／倍率配置凭据 | 记录保存时实际档位及当前倍率的稳定数值／位表示，逐项比较；不使用进程相关 GetHashCode、对象地址或整个 Def 哈希。仅校验余数，恢复仍从当前 XML 查询倍率；单改思想、偏移或显示文案不导致数学上无关的失配 |
| 周期字段指纹 | 保存当时 `sex_ticks`、`orgasmstick`、`orgasmStartTick`、`duration`、驱动 `orgasms`，用最终恢复值检验仍为原周期；还须结合加载期真实重设标记，不能只凭数值恰好相同 |

`Scribe_Values.Look<T>` 已核实可存取基础数值类型，余数用 double 存读；引用依正常交叉引用阶段解析。保存时只写已经提交且仍属于该驱动／周期的余数，过期状态保存为零或不写有效载荷。不能把原始快照、推进操作 ID、待消费标志、运行时人格 token、旧 SexProps 对象或静态缓存作为可恢复命令序列化。

保存前先用执行记录已知的周期／字段终态复查当前原生计时，再生成保存指纹；不能先把未知改写后的字段盖进指纹，借此使旧余数重新合法。保存校验不推进计时、不重建周期。**读档后未发生首次推进就再次保存**时，须在该安全保存边界对待恢复载荷执行同一套无推进校验：合法则接续并保存原余数，无效则只保存零；不能因为它还不是“已接续”就无条件丢掉，也不能不验证直接转存。Scribe 仍处于加载的任何阶段时，不执行这种保存／恢复提交。

身体选择仍只保存在新 Hediff 的 Severity。新旧主人／锁链／档位或有效资格发生变化会清理执行余数；保存节点中的引用／档位只用于校验，不能反向覆盖身体选择、恢复旧链或绕过当前准入。仅思想配置错误不影响有效倍率的余数，遵守 6.2 节失败隔离。

### 14.5 加载顺序与延迟恢复

实际调用链已核对：`Pawn_JobTracker.ExposeData` 在 `LoadingVars` 阶段**先**深读 `curDriver`，返回后才给它赋 `pawn` 和 `job`。不能在驱动读节点时就用“owner 为 null”清掉合法余数。到 `PostLoadInit`，RJW 基类 ExposeData 首先进入原版 `JobDriver.ExposeData`，后者调用 `SetupToils()`；因此 Toil 重建发生在 RJW ExposeData Postfix 之前。

**父子对象的加载回调不是逐层递归保证的。** 本机 `Scribe_Deep.Look` 在 Saving／LoadingVars 做深存／构造，ResolvingCrossRefs／PostLoadInit 时直接返回；`ScribeExtractor.SaveableFromNode` 将每个新建的引用型 IExposable 分别注册到加载器，由 `CrossRefHandler` 与 `PostLoadIniter` 调度其后续 ExposeData。后者保存的是 HashSet，不能依赖附加节点、驱动、Hediff 之间的 PostLoadInit 先后。附加节点的 `Scribe_References.Look` 必须写在该节点自己的 ExposeData 内，由标准注册流程完成，不在驱动 Postfix 手动再调用子节点 ExposeData，也不重复注册／解析引用。恢复只在所有加载阶段结束后判定。

SSC 自我调教的 `MakeNewToils` 是迭代器：枚举时先 `base.MakeNewToils().ToList()`，再依据既有快照恢复 `sex_ticks`／阈值／起点／时长等。给 `MakeNewToils` 本身加普通 Postfix 只得到尚未执行的 IEnumerable，不能作为恢复完成屏障。流程固定为：

1. **LoadingVars：** 附加节点只反序列化数据，置 `PendingRestore`；不检查尚未绑定的 Pawn／Job，不修复 Hediff、不计算进度、不应用倍率。缺节点时执行余数为零，已有身体选择按自身存档正常读取。
2. **交叉引用阶段：** 按标准 Scribe 流程解析身体／链／主人引用，仍不提交余数。进程内人格凭据和 SexProps 以后从最终驱动重新绑定，不保存对象地址跨读档比较。
3. **PostLoadInit／Toil 构建：** 在原版 `JobDriver.SetupToils` 外围建立构建屏障，记录期间发生的周期初始化，但待恢复载荷先保留；退出时记录最终计时与是否有真实重建。成功与失败须按下段的正常路径标记判断，不能只看异常参数。SSC 自我调教在现有恢复分支完成、必要 Toil 完整性检查通过之后，补一个仅通知执行状态的“原周期已恢复”候选标记；只有外围构建也成功且驱动仍为原当前任务时才接受。不得改既有恢复值或认领逻辑，不能把恢复赋值刚结束就视为整个迭代器已经成功。
4. **首次真实推进前：** 明确要求 `Scribe.mode == Inactive`、加载期构建屏障已结束且成功；校验当前驱动／Job、当前身体与链、当前身份／人格上下文、有效档位／倍率凭据及最终周期字段。仅在未真实换周期，或已被明确标记为原周期恢复且字段匹配时，接续原小数余数并重新绑定当前运行时上下文。随后捕获的是本次新推进的快照，绝不重放存档前样本。在加载中意外进入推进桥时，仍执行原写入但不应用 SSC 加速，标记待恢复凭据受污染，后续不再接续旧余数。
5. **不匹配：** 只将本模块余数清零，以当前有效周期开始新的采样；不写回旧原生计时、不追回进度、不补发高潮。坏格式、非有限／越界余数、断引用、改档／改倍率、换 Job／人格或链均走此规则。

**SetupToils 的异常会被原版内部处理。** 本次核对完整 IL：枚举结束、Dispose 正常完成后到 `IL_0065` 的成功离开路径；catch 在 `IL_0067` 开始，`IL_0085` 调用 `JobUtility.TryStartErrorRecoverJob`，两条路径最终都到 `IL_008C ret`。因此普通 Postfix 或 `Finalizer(__exception == null)` 无法证明成功。后续采用窄 Transpiler，在正常离开 try、进入 catch 之前的语义锚点插入只设置本模块标记的成功通知；不把标记插到两条路径共有的 ret，不改 catch 或原恢复 Job。外围 Prefix／Finalizer 负责范围开闭与异常失效，成功还须复核当前驱动／任务、Toil 有效范围以及自我调教候选标记；内部捕获、提前 yield break 或被跳过的构建不能伪装成功。该成功标记的锚点失配时，禁用依赖它的跨读档接续及相应 SSC 加速，不能仅凭计时数字吻合恢复。

加载期间周期观察可使正在使用的运行余数失效，但只能给待恢复载荷记“发生过重设／构建失败／引用待定”等状态，不用普通 clear 把两者一起删除。节点对象保持由 Scribe 正常完成自己的引用／初始化回调，加载结束后的验证才决定接续或舍弃；旧的采样快照与待应用操作始终不保留。Toil 构建成功标记只是必要条件，其他对象之后的 PostLoadInit 仍可能改变身体或链，最终资格必须到首次推进或安全保存时再查。

**原生读档行为优先。** 普通 RJW、UAP 或其他驱动若在 Toil 重建时真正初始化了新周期且未恢复旧计时，执行余数随之清零；不能为了“读档保留”擅自把其计数恢复成存档前值。即使重设后数字碰巧与指纹相同，发生过真实重设且没有明确恢复证明也不接续。自我调教则可凭现有恢复分支与新通知保留同周期余数，这两种情况均符合“不把旧周期余数带入新周期”。

正常运行时，真正新周期／真实高潮、关闭、实际档位／资格失效、任务结束或人格上下文替换会清理对应执行状态。任务 Cleanup 后移除本模块索引，出生／克隆不复制任务节点；没有新的有效推进就不创建高潮、不补算离线时间。默认四档整数倍率通常没有非零余数，但 XML 小数配置必须完整执行上述方案。

余数失效关注数学和归属变化：当前实际档位、倍率、身体／链／主人、任务／人格或周期变化必须清理；单纯刷新界面、重复选择同档，或锁链升降但实际档位／倍率及归属均未改变时，不额外重置余数。阶段导致的脆弱度／心情刷新仍正常进行，不和周期重设混为一件事。
