## 1 已确定的功能边界

- 主人面板增加个人开关；开启后，主人参与一次完整的普通双人性交，对性交对象施加侵染收益。主人位于发起方或接受方都适用。
- 排除 SSC 日常调教、绑定仪式及其阶段、自我调教、人格排泄；单人自慰也不触发。普通性交仍经过已有行为许可，不改变许可规则。
- 普通 RJW 行为和原版 Lovin 纳入入口。普通行为是否带有强迫属性不改变侵染反馈公式；RJW 自行处理相应影响。
- 对象当前 SSC 身份为主人时，整套侵染效果豁免，包含恶堕、身体开发、心情和社交好感。判断依据是 `PawnIdentity.Master`，不是永久资格或主人 Hediff 的存在。
- 对象可以是未选择身份、未绑定的角色，也可以是属于其他主人的性奴；侵染不创建、转移或抢占主从绑定。
- 开启后，主人分泌体液携带少量活化的紫色纳米机械；性交使对象摄入少量 PNA，并产生弱身体开发、少量恶堕和本次反馈。
- 侵染包含恶堕、弱部位开发、心情／好感与 PNA 输入四个独立分量。PNA 自身按独立重置规划处理慢性／急性阶段及达满后的渴求；某一分量达上限不阻止其余分量。
- 有锁链性奴不走普通对象的 PNA 负面和依赖分支，完整正面增益及主动补给属于后续开发；既有恶堕、弱开发和本次反馈不因这项分流自动取消。
- 主人身上的可见 Hediff 表达侵染已开启，帮助尚未专门适配的 RimTalk 读取状态。Hediff 不承担绑定、成长经验或持续感染职责。

## 2 开关准入与目标资格

首版采用以下准入规则；不从 UI 是否可见推断实际生效。

| 项目 | 首版方案 |
| --- | --- |
| 操作入口 | SSC ITab 主人面板中的独立复选框 |
| 操作权限 | 玩家阵营、当前主人、有效角色组件、非空壳；点击时复查当前选中角色与组件实例 |
| 默认值 | 关闭；新角色、旧档缺字段及旧凝胶缺字段均为关闭 |
| 主人实际生效 | 开关开启、当前主人、存活且未销毁／丢弃、有效人格与健康状态；效果本身不额外要求玩家阵营 |
| 额外开放门槛 | 不要求永久资格、主人阶段记录／等级、绑定人数或缰绳；部位开发单独保留原研究门槛 |
| 对象资格 | 不同于主人本人、存活且未销毁／丢弃、人形、有实际恶堕需求、非空壳、当前身份不是主人 |
| 不支持的对象 | 没有恶堕需求或必要人格／健康载体的对象不领取侵染；不强行创建需求 |

只读面板构建不创建成长记录、缰绳或开关默认配置。关闭状态必须仍能重新开启，不能把“当前效果已经开启”作为复选框的可编辑条件。开关位于现有主人功能区域，沿用动态文字测量与左栏滚动；具体排序、名称及悬停在开发时确定。

## 3 保存、人格流转与克隆

### 3.1 唯一保存依据

建议在 `CompSexSlaveTraining` 保存 `masterDesireInfestationEnabled`，布尔默认值为 `false`。凝胶快照保存同名布尔值；字段缺失表示关闭，无需推断历史开启状态或补发历史收益。

Hediff 是开关有效状态的可见结果，不保存另一份可独立编辑的开关。退出主人身份后保留布尔偏好、移除可见标记；重新成为主人时按原偏好重建标记。成长记录的存在、严重度和可见性不决定本功能开关。

### 3.2 人格处理顺序

| 流程 | 处理方式 |
| --- | --- |
| 保存／读档 | 保存布尔值；完整角色引用恢复后根据当前身份、空壳和开关状态同步标记 |
| 成功采集人格 | 先保存开关快照并成功生成凝胶，再将原身体开关清为关闭并移除标记；覆盖两条现有采集路径 |
| 凝胶复制／加工 | 复制布尔值；不存完整标记 Hediff 实例或 Pawn 引用 |
| 植入人格 | 在现有人格清理／恢复流程内清宿主旧开关与标记，再按来源布尔值精确恢复；来源关闭必须覆盖宿主开启 |
| 恢复未选择／性奴人格 | 可以保存来源偏好，但当前不是主人时不显示标记、不产生效果 |
| 恢复主人人格 | 现有身份恢复成功后同步标记；不授予缺失的永久资格、不建立缺失的成长记录 |
| 新生克隆 | 初始关闭，清除可能复制的标记；继续遵守主人身份、资格和成长不继承规则 |
| 克隆成熟复制 | 过滤来源标记，不复制来源开关；不重置克隆后来独立取得身份并自行开启的设置 |

通用 `hediffTags` 导出／恢复与克隆健康复制显式过滤侵染标记，避免绕过布尔来源重建错误状态。现有记忆及身体开发记录继续使用各自原有的人格／身体处理路径，本项不改变它们的保存归属。

## 4 可见 Hediff 与 RimTalk

建议定义独立标记 `SSC_Hediff_MasterDesireInfestation`，不附带属性加成、疼痛、治疗需求、持续侵染计时或绑定关系。仅在第 2 节主人实际生效条件满足时保留一个实例；重复同步去除重复实例，关闭、退出身份或人格清理时移除。

标记使用非负面的不可治疗状态，建议 `isBad=false`、`tendable=false`、`everCurableByItem=false`。可见性也读取同一有效条件，避免死亡、身份更换或空壳状态下的残留实例被健康页／RimTalk 当成开启；不是通过隐藏标记来停用实际效果。

同步入口包括开关写入、统一身份切换、读档初始化、两条成功采集路径、人格恢复完成及新克隆初始化。不为本功能新增每 tick 全地图扫描。游戏机制查询以布尔值与当前资格为准，不以标记暂时存在与否作为开关真值。

已核对本机 RimTalk 1.4.1 的 `ContextBuilder.GetHealthContext`：开启健康上下文时，通过原版可见健康列表提取 `Hediff.Label`，不提取其完整描述；简短上下文排序后最多取三项。`GetThoughtsContext` 使用心情条目的 `LabelCap`，同样不读取完整描述，且简短上下文最多取三项。

因此开发时应让标记名称表达主人正在开启这项能力，心情名称表达对象的本次反应；关键信息不能只写在 description 或 extraTooltip。是否最终被模型读取仍受 RimTalk 配置、上下文截取和其他扩展影响。此设计不宣称完成专用 RimTalk 适配，也不提高虚假的 Hediff 严重度来抢占上下文排序。

对象侧以重做的现有 PNA 多阶段 Hediff 和达满后的渴求／依赖表达持续影响，见[独立 PNA 规划](PNA机制重置开发规划.md)；它们承担实际作用，不再额外加一份同义感染标记。主人开关标记的职责与对象 PNA 状态分别维护。

## 5 普通性交完成与一次性结算

### 5.1 RJW 普通任务

主要接入 `SexUtility.ProcessSex`。复用现有普通场景的用途识别、开始凭据、驱动／Job 实例及 loadID 校验、参与者方向与倒计时结束检查；排除准备、拒绝、取消、中断以及专用 SSC 任务。

目前 `TryClaimOrdinarySexOutcome` 的 `TrainerProgressClaimed` 已被训导官主动性交经验使用，不能由第二个补丁抢先消费，造成原奖励失效。首版建议提取共用的完成验证，并新增本功能自己的 `sscDesireInfestationOutcomeClaimed` 持久化认领字段；两项奖励共享真实完成条件，各自最多领取一次，原训导官键和行为保持原语义。

双方角色均检查一次；主人／主人组合整套豁免，所以一组双人参与者最多形成一个有效的主人到对象方向。双方都是非主人或主人开关关闭时也记录本次完成已处理，不能以后开启或切换身份再重放旧场景。

单双人以已核实参与者和用途判断，不仅看性交类型名称：有真实双人凭据的相互自慰可以纳入，单人自慰和自我调教始终排除。普通 Forced 与 Consensual 用途都可领取；该用途区分用于已有许可和场景识别，不进入第 8 节反馈公式。

### 5.2 原版 Lovin

复用 `SSCRestrictionLovinGuard` 的实际开始、唯一发起方向及双方任务编号。只在实际发起端倒计时结束且本次成功完成时结算；接收端结束、失败条件和未开始的伪成功都不能领取。

扩展原版任务保存本功能的认领状态。完成时在现有 Cleanup 顺序中捕获参与者和输入，并核实本次成功完成；RJW 的 Lovin 结算可能也调用 `ProcessSex`，必须明确由原版适配器统一认领该场景，防止通用入口再发一次。

本机 RJW 在 Lovin 成功 Cleanup 才生成交互，不能把该收尾交互直接当作全过程真实部位凭据。首版建议原版 Lovin 跳过部位开发，真实完成事件仍结算恶堕、PNA 输入与反馈；若后续采用代理部位需明确新规则。RJW 将 Lovin 替换为普通 RJW 驱动时，按当前实际任务走普通入口，迟到的原版回调无收益。

### 5.3 输入与应用顺序

1. 在同一次结算增加侵染收益前，捕获目标当前恶堕 `C`、目标对主人的原始好感 `O`、评分模式、开发评分／倍率及真实参与部位。建议在 RJW 原结算前捕获，避免其新记忆改变本次分档；此时不发收益。
2. RJW 普通入口只在原 `ProcessSex` 正常返回且未被其他补丁跳过时领取；Lovin 由对应完成适配器确认。不把提前调用或只有 `SexProps` 当作完成证明。
3. 先消费本场持久化认领，再应用侵染。重复、重入及结算异常不重放已经消费的收益。
4. 再次确认原参与者、当前身份、开关和人格仍有效。用快照计算计划分量，分别应用 PNA 输入、恶堕、身体开发和反馈；PNA 达满后的渴求按独立规则处理。恶堕与 PNA 实际写入前复查当前值和当前适用上限，避免其他原结算／补丁已改值时越界。
5. 每次可能引发健康／身份回调的写入后，核对参与者仍有效且没有人格替换、身份变更等情况；失效则停止剩余分量，不重放或补发本场。

快照仅服务本场结算，不另存累计腐化、身体等级或关系评分。单场收益不依赖高潮次数、时长或动画次数；本功能不发主人实践经验或特化经验。

快照同时记录原角色组件、恶堕需求实例与人格归属。组件可能在原地承接另一份人格，因此建议在本项人格清理／恢复入口维护仅运行时的人格修订号，并在各分量写入前核对；即使新旧人格都是主人且开关同为开启，也不能沿用旧场景收益。该修订号不存档，不用作资格、阶段或迁移版本；旧格式开关仍按缺字段关闭处理。

## 6 恶堕增量与上限

测试初值：每次额外增加 `0.01`，即 **1 个百分点**。这是侵染自身的额外收益，与现有性奴高潮恶堕收益共同生效。

新评分模式使用当前阶段上限：无锁链为 `0.12`，有锁链从 `TrainingOutcomeUtility.GetChainCap` 读取。旧评分模式原恶堕需求不使用该阶段刹车，首版沿用其 `MaxLevel` 上限，不能给旧模式新增统一 12% 限制。

```text
cap = 新评分模式 ? 当前锁链阶段允许上限 : 恶堕需求 MaxLevel
gain = max(0, min(0.01, cap - 当前恶堕))
```

分档与开发采用快照，恶堕实际增量按写入时的当前值、当前上限再次限制。仅写入正的有限增量，已有值高于本次允许上限时不在这个入口倒扣恶堕。通过 `CorruptionUtility.AddCorruption`／`Need_Corruption.SetCorruption` 维护当前值、历史最高值及既有派生特性；不直接改 `CurLevel` 或独立保存历史值。

恶堕写入沿用历史最高派生特性：未绑定对象达到历史 10% 也可能获得“初被调教”，当前恶堕下降不自动抹去历史；这不等于建立主从绑定。

不调用 `ProcessCorruptionProgression`：该入口达到阈值后可能建立绑定，超出侵染职责。也不施加调教专有意志削减、转奴、锁链升阶或特化培养。恶堕达到上限后，仍结算符合条件的身体开发和反馈。

## 7 较弱的身体部位开发

### 7.1 开发额度

测试初值：同条件日常部位开发基础额度的 **20%**。保留 `SSC_BodyPartTraining` 研究判定、既有评分模式、恶堕倍率、锁链倍率及 `SSC_Exp_*` 的最高进度。采用侵染前评分与倍率；本次侵染加值不立即提高本次开发倍率。

建议从 `TrainingExpUtility` 提取共用的额度计算和指定部位写入方法，让原日常／仪式入口保持原行为，新入口按真实部位发放。额度按现有公式换算：

```text
budget = max(0, score / 1000) × 0.20 × 侵染前恶堕倍率 × 侵染前锁链倍率
单个有效候选的计划增量 = budget / 去重后的有效候选数量
```

不满足研究、评分无正额度、无可靠参与部位或全部候选已满时，部位开发为零，不影响恶堕与反馈。各记录分别限制在自身最大严重度；已满部分不把额度转给其他部位。

### 7.2 部位识别

使用本机 RJW `SexInteractionResolved` 的参与者、`InitiatorParts`、`RecipientParts` 及 `Penetrations`，其中 `ILewdablePart` 提供 `Owner`、`BodyPart` 和 `Family`。仅选取归属对象本人的实际参与部位，验证仍属于其身体且未缺失。

`SexProps` 存档不保存完整 `_resolved`，缺失后会按当前身体重新解析，因此需要在真实场景建立时记录最小部位凭据及其存档恢复规则；完成时新解析出的最高分组合不自动视为原场实际参与部位。缺乏可靠凭据时跳过该分量。单次 20% 也不等于每日只有日常开发的 20%，实机按一天多次接触的总收益验证，是否递减仍待平衡。

| 对象参与部位类别 | 对应现有开发记录 |
| --- | --- |
| Hand | `SSC_Exp_Hand` |
| Foot | `SSC_Exp_Foot` |
| Mouth／Tongue／Beak | `SSC_Exp_Oral`，必须有可靠的实际部位记录 |
| Breasts | `SSC_Exp_Breast` |
| Penis／Vagina | `SSC_Exp_Genitals` |
| Anus | `SSC_Exp_Anus` |
| Undefined、Tail 等未映射类别 | 首版不猜测对应开发记录 |

按“对象＋实际 BodyPartRecord＋开发 HediffDef”去重。不根据主人的性别、谁发起性交或单独的 `sexType` 推断对象使用了口部／生殖器；反向姿势、多个性器官及多部位行为使用同一识别规则。

增加既有开发记录后，其阶段与属性自然按原 Def 生效；不增加另一套侵染部位等级。行为开发可能让未绑定角色获得现有部位加成，这是本功能的预期培养来源。

## 8 简化的心情与社交反馈

### 8.1 两项输入与测试分档

只使用目标侵染前的当前恶堕 `C` 和目标对主人的原始好感 `O`。“原始”指保留正负的当前 `OpinionOf`，不是剔除此前侵染记忆后的关系基准；旧反馈可以影响下一次分档，需要覆盖记忆过期与正负边界。不使用历史最高恶堕、是否强迫、发起／接受角色、额外性格或本次高潮次数作为反馈输入。目标没有心情载体时跳过相应记忆，不创建新的需求。

首版采用 `C = 0.30` 区分低／高恶堕，`O = 0` 区分负面／非负好感，等于边界时进入高恶堕／非负档。2026-10-13 维护者明确确认保留 30% 分界，以现有锁链第二阶段的恶堕下限为参考，但反馈只检查当前恶堕，不要求实际锁链阶段。在新评分模式下，无锁链对象受 12% 上限约束，通常处于低档；旧评分模式仍按其实际恶堕值分档。

| 档位 | 侵染前状态 | 心情偏移初值 | 对该主人的好感偏移初值 |
| --- | --- | ---: | ---: |
| 0 | `C < 0.30`，`O >= 0` | +4 | +5 |
| 1 | `C < 0.30`，`O < 0` | -4 | -5 |
| 2 | `C >= 0.30`，`O >= 0` | +8 | +10 |
| 3 | `C >= 0.30`，`O < 0` | +4 | 0 |
