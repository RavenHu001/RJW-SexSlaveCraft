## 3. 所有特化共用的基础培养经验

### 3.1 结算原则

当前实现采用以下共用规则：

- 接收者须符合当前特化本身的培养资格；统一经验不绕过训导官等方向的既有门槛。
- 仅向当前正在培养的方向发放，不同时增加所有历史方向的进度。
- 普通培养完成或已有本方向终极成果后，不继续累计普通经验。
- 日常调教按一次成功完成事件结算；仪式按完整成功事件结算，不按阶段、循环或动画回调发放。
- 发放后同步进度与普通状态，保证界面、配方完成判定及存档使用相同结果。
- 同一次事件重复回调、存读档恢复或重入不得重复领取。

“所有特化统一基础来源”不意味着本轮开放兔，也不意味着自我调教自动获得特化经验。自我调教是否加入仍未确定。

### 3.2 已采用的动态公式

统一基础经验复用[战斗员经验公式](../../Sexslavecraft/common/CombatantSpecializationProgressUtility.cs)，通过[公共发放入口](../../Sexslavecraft/common/SpecializationTrainingProgressUtility.cs)应用于当前培养方向：

```text
baseDelta = min(score / 2000, 0.04)  // 无效或非正评分不发奖
delta = baseDelta * (实际绑定主人施教 ? 1.5 : 1.0)
```

所有受训方向当前均沿用这一倍率；普通单次上限为 4 个百分点，实际绑定主人施教时为 6 个百分点。研究条件只约束方向选择入口；受训发奖仍检查 SSC 性奴身份、当前方向、该方向持续资格以及普通／终极完成状态。

- 日常调教复用完整结算时取得的一次评分，不因先后发放其他奖励而重算。
- 完整仪式成功后使用 `quality × 75` 作为特化评分，再套用上述公式；部位经验的 `quality × 1000` 属于另一量纲，不用于特化进度。
- 自我调教暂不接入基础特化经验。猫普通选择入口已开放，兔仍禁用；合法当前方向持续培养不重查玩家选择的研究门槛。

这些数值是当前实现，后续可结合实机培养节奏调整；调整前须重新核对各方向总收益。

部位经验有独立研究、身体部位和阶段倍率，继续使用原有职责；本轮统一的是特化培养经验，避免把部位经验条件顺带变成所有特化的门槛。

### 3.3 旧奖励与特色来源

- 训导官原有固定受训 5% 奖励已由统一基础奖励替换；合格施教的特色经验仍独立发放。
- 战斗员原有日常受训入口已改为公共入口，整场仪式也已接入；直接击杀经验继续独立处理。
- 当前普通猫可通过成功亲昵获得 1 个百分点特色经验，沿用共用一天完成冷却；这是第 4.3 节的当前测试基线，培养节奏仍待实机评估。
- 狗保留动物工作特色经验；奶牛、公交车等保留其既有特色来源，统一基础经验不直接删除这些机制。
- 同一完整调教事件仅发一份受训基础经验；符合条件的施教等特色来源仍按各自入口发放。公交车旧有的日常堕落率受训增量已移除，避免与公共基础经验重复。

日常任务先调用外部行为结算，再执行 SSC 调教结果；当前基础经验在完整结果认领后按同一评分发放。仍应分别测量各方向总成长速度；训导官低评分受训可能变慢，原先主要依赖专属工作的方向则可能变快。

## 4. 猫特化的设计

### 4.1 普通方向：陪伴与灵巧

当前建议定位为“陪伴、情绪支持与轻机动”。普通移动、闪避属性提供日常收益；特色互动和终极技能体现角色用途。

| 阶段 | 建议内容 |
| --- | --- |
| 培养中 | 可经统一受训经验成长，并开放基础亲昵及其特色成长。 |
| 基础阶段 | 获得初步灵巧收益，亲昵体现猫专属反馈。 |
| 熟练阶段 | 提高被动收益，增强陪伴记忆或双方反馈。 |
| 普通培养完成 | 保持熟练收益，取得凝胶终极化资格。 |
| 终极化 | 保留终极成果，并授予第 4.2 节的单一技能。 |

20%／50% 等阶段阈值及现有移动、闪避数值可作为测试基线，最终表格待确认。原始属性偏移量不直接等同于最终概率百分点，数值调整须核对实际游戏计算与其他培养收益的叠加。

普通选择入口现已复用 SSC 性奴身份、基础研究、猫研究和宠物终极互斥，不增加绑定或阶段门槛。实际绑定主人只限制亲昵；没有绑定主人时仍可经合法受训成长并保留当前阶段被动。猫终极主动技能见第 4.4 节；猫狗共用的可见亲昵表现见第 7.3 节；猫专属表现差异及熟练阶段记忆增强仍待开发。

### 4.2 终极技能：按目标状态分支

技能本轮名称“安抚共鸣”。**只有一个技能，效果实际生效时检查目标状态：**

| 目标状态 | 已确认效果 |
| --- | --- |
| 存在当前 `MentalState` | 直接压制当前精神状态，覆盖全部状态类型及原因。 |
| 没有当前 `MentalState`，且满足基础目标条件 | 给予激励 buff。 |

不拆成两个按钮或手动选择模式。施放过程中目标状态变化时，按生效时状态选取一个分支；两种效果使用同一个技能冷却。

实现时，仅对当前 `MentalState` 调用 `RecoverFromState()`，沿用其恢复通知与结束处理，本次压制不再额外给予激励。紧张性昏迷使用 `CatatonicBreakdown` Hediff，本轮不查询、不删除，也不增加针对它的激励分支或目标筛选特例；没有 `MentalState` 时，是否可进入激励分支由通用基础目标条件决定。压制当前精神状态与治疗疾病等诱因属于不同机制。

### 4.5 第三步实现：地图选取与同格施放交互（2026-10-05）

维护者确认本轮功能有效，同时希望之后调整目标选择与释放方式，偏好流程为：

1. 在地图范围选择玩家阵营的其他人形角色，选择阶段不受当前 6 格施放距离约束。维护者补充确认仅包含玩家阵营目标，不扩展至其他阵营；无意识对象排除可选目标。
2. 施放者走至目标所在的同一格；到达前不开始读条或结算技能。
3. 同格后开始读条，同时播放动画／特效。施放者停止行走，目标采用原版施放期间暂停机制停止移动；不在接近阶段提前暂停目标。
4. 读条完成时重新检查目标状态，按恢复或激励分支结算一次。

原版接口核验：本机 RimWorld 1.6 的 `AbilityDef.stunTargetWhileCasting` 在 `Verb_CastAbility.TryStartCastOn` 成功进入预热后，通过 `target.stances.stunner.StunFor` 对目标施加与预热时长相同的限时眩晕，未醒目标另调用原版 `WakeUp`。实现中在同格到达后才进入这段原版预热，沿用当前 2 秒准备时间；不另加一段 2 秒等待，不用替换目标精神状态来停止其移动。原版暂停机制属于真正的短暂眩晕，效果分支仍在读条完成时判定。

无意识筛选采用原版 `target.health.capacities.CanBeAwake`。本机人形角色的该判定要求意识不低于 `0.3`；普通睡眠不等于失去意识，能醒来的睡眠目标仍可选择，进入原版预热时沿用唤醒行为。不以 `Downed` 或当前 `Awake()` 代替意识筛选，意识仍合格的倒地目标不额外排除。选择、进入预热和实际生效时均需复查，防止途中或读条期间失去意识后仍结算。紧张性昏迷继续不做专项 Hediff 查找、删除或筛选，其是否符合目标条件仅由上述通用资格决定。

该流程已实现，规则确认先提交为 `bbbe69c`，再进行实现。新增 [Verb](../../Sexslavecraft/Comps/Verb_PetCatComfort.cs)区分地图选取与同格开始，新增 [JobDriver](../../Sexslavecraft/JobDriver/JobDriver_PetCatComfort.cs)以 Pawn 引用追踪当前目标位置，不固定选择时的格子。目标选择要求可达同格，取消旧 6 格及直线视线限制；原版零射程在预热中仍可能接受相邻 `Touch`，因此 `CanHitTarget` 与 `CanHitTargetFrom` 均明确检查同格。

接近阶段 `abilityCasting=false`，不提前出现气泡、爱心、暂停目标或结算效果；不与目标碰撞，允许走入同格。到达后复用一次 `Toils_Combat.CastVerb` 的原版预热、进度条与 `Mote_Speech` 社交气泡。当前视觉修复将气泡符号改为 Core `Things/Mote/Heart`，按钮仍保留既有 `UI/Icons/Ritual`，无额外 DLC 或动画依赖。玩家可取消，普通工作调度不随意抢占。

行走阶段检查意识、技能归属及冷却；预热阶段检查同格与基本资格；实际 `Activate` 在原版预扣冷却前复查当前 Ability 实例、意识及同格。成功恢复后目标可能不再满足原恢复分支的心情资格，且技能已进入冷却，因此任务完成收尾不再按这些已变化的条件误报失败。效果、全部精神状态分支与人格绝对冷却迁移衔接现有实现。

正常寻路、目标引用和原版预热剩余 tick 由原版 Job／PathFollower／Stance 保存；自定义驱动只保存行走停滞重试次数，行走阶段每 60 tick 有限补寻路，不因读档重启 2 秒预热或再次暂停目标。中断时按本任务原始 Verb 清理本人预热 stance 与完成回调，不扣额外冷却。目标暂停沿用原版限时自然结束，不继续刷新，也不主动清除其他来源的眩晕。

## 7. 亲昵的表现与后续互动

### 7.1 明显且完整的亲昵

已确认需要提高亲昵的可见程度。当前建议采用“接近—停留互动—结束反馈”的完整短流程：显示双方朝向、适量互动图标和任务文字，完成后给予明确记忆或简短反馈。

当前实现已避让双方重要工作、战斗、睡眠、精神状态及其他准备等待，并沿用附近 2.9 格自动发现范围与两秒互动，详见第 7.3 节。手动安排入口、扩大范围及自动触发时段仍待定；猫狗共用调度和表现，普通猫保留既有特色经验。

### 7.2 限制允许时的概率分支

已确认：普通亲昵完成后，在限制允许时有概率触发后续性行为。当前讨论按成年猫／狗特化人形角色与成年主人之间的自愿互动设计；这里的“宠物”指角色特化，狗的动物管理技能单独处理。

建议流程：

1. 成功完成亲昵，结算其本身的心情、记忆及已确定的特色经验。
2. 检查双方当前意愿、可用状态、实际发起方向及对应行为许可。
3. 满足条件后，对本次亲昵进行一次概率判定。
4. 命中后提交正常后续任务，实际开始前重新检查当前资格与许可。
5. 确认任务实际开始后再显示事件发生提示；失败时清理本次准备状态。

由亲昵发起者申请后续互动时，许可按该实际方向检查。当前主人主动发起有特殊放行规则，接入时不能交换发起者来改变判定，也不能以“亲昵成功”代替行为许可。

同一次亲昵只判定一次；未命中、许可拒绝或后续启动失败，保留已完成的亲昵结果。冷却、存档与一次性记录须防止重复回调或读档重掷。许可拒绝不改走另一类行为作为替代。

本轮实现采用第 7.4 节固定20%、宠物向实际主人发起的测试基线，保留亲昵一天完成冷却及 RJW 双方准备条件，不增加配对专属冷却或后续独立经验。阶段概率、额外冷却、手动入口及其他陪伴对象仍待定。普通亲昵、猫终极技能和狗动物管理技能保持各自事件归属。

### 7.3 第一步实现：可见普通亲昵（2026-10-06）

- 自动发现继续使用实际绑定主人与 2.9 格附近范围；宠物和主人必须均清醒、可行动、无精神状态或战斗。只接替空闲漫步／等待，不抢玩家命令、已有队列、带到期时间的等待或 `Wait_MaintainPosture` 准备任务。走近期间及到达时主人变忙均取消。

- 保存本次等待主人、等待 Job 编号及互动已启动事实。取消、完成、重入和异常恢复只清理本次创建且仍在执行的确切等待；主人接手的新任务不受影响。原版恢复当前 toil 与剩余时间，字段加载不再次 `ForceWait` 或发奖。

### 7.4 第二步实现：成功亲昵后的自愿后续（2026-10-06）

- 成功亲昵先结算原有记忆、普通猫经验和一天完成冷却，再保存本次后续已判定事实。生效普通／终极猫狗使用固定 `20%` 测试基线，兔不参与；失格、拒绝、未命中或安装失败均保留亲昵结果，不重抽。
- 固定由亲昵宠物向真实绑定主人发起 RJW 自愿 Quickie，不找其他对象、不交换方向；SSC 权限按这一方向查询。双方须为至少18岁的成年人形角色，清醒、可行动、无战斗或精神状态，并通过 RJW 身体、双向配对设置、欲求、忠诚、吸引力与互动／工作时段冷却检查。
- 移交确切主人等待，准备窗口从当前时刻再延长 `600 tick`。派生驱动复用原版 Quickie，保存准备与接收归属；原版 `StopAll` 执行时暂存恢复原空闲队列，主人新工作／排队命令取消准备。每步及实际 Start 前复查，读档不中途重抽；未真正开始时只清本次准备／接收，已开始由原版正常收尾。
- 真实 Start 后显示一次四语事件提示，保存去重；命中概率或准备成功时不提前提示。不增加额外配对冷却或后续特化奖励，正常后续沿用 RJW 和模组既有普通互动结算。
- 代码块级说明、游戏影响及专项测试步骤见[后续事件实现记录](../Development/宠物亲昵后续事件实现与测试记录.md)。本轮自动验证完成后供维护者实机测试，尚未收到新功能实机确认；此前可见亲昵的确认不扩展为此后续已验收。
