# 主人身份拓展初步规划

记录日期：2026-10-01。
最近更新：2026-10-11。

状态：**道具入口第一、二批已实现；第二批已获维护者实机确认，获取任务继续规划。** 2026-10-11 第一批实现个人资格保存、身份选择准入、人格凝胶流转和一次性旧档迁移，手动赋予默认开启，克隆不继承资格；维护者确认资格限制有效。第二批实现主人资格模块、原版研究蓝图接入和设置调试生成按钮，原版蓝图暂时保留为单独研究来源。反馈未逐项列举的存档及人格流转专项验证边界见开发记录。初次任务、手动任务入口和长期投放尚未开发。本文保留主人本体、成长和技能候选，不将其视为已确定需求；本批记录见[开发更新记录](../Development/开发更新记录.md)。

主人被理解为自身具备 PNA 母机功能的角色，可以通过 PNA 侵蚀他人，并在性奴身上衍生更多功能。现有调教和绑定仪式已经承担侵蚀与加深侵蚀的作用；现有围绕性奴的培养、改造和特化均属于性奴功能。后续拓展集中于主人自身的功能、数值与强化。

关联：[未来内容开发规划](未来内容开发规划.md)第 8、22 项；第 6 项的身份与绑定拆分继续独立讨论。

## 1 已确定的方向与范围

- 主人身份需要拓展功能、相关数值和自身强化，使其具有更完整的角色内容。
- 主人自身具备 PNA 母机功能，现有调教与绑定仪式可按这一定位理解。
- 调教和绑定仪式本身就是侵蚀与加深侵蚀的行为，无需另设一条必经的侵蚀流程。
- 现有围绕性奴的功能，包括各项特化，均可以视为性奴功能。本规划不以新增或重做性奴侧功能为前提。
- 技能式的对他人能力可以考虑，具体技能尚未确定。
- 身份切换的限制与锁定继续沿用当前版本设计。

下文中的本体适配、个人成长、恢复、临时强化和绑定反馈调整属于候选方向。是否采用独立成长进度、哪些能力进入首版、具体收益和代价均未确定。

## 3 主人功能拓展的候选方向

### 3.1 主人本体

可以讨论主人自身对 PNA 的适配、利用以及由此产生的身体强化。候选包括主人专属的 PNA 使用效果、恢复、操控与实际培养效率加成。

部分本体功能可以考虑在没有绑定对象时生效，使主人刚取得身份时就有可感知的特点。感染、成瘾、弹药作用是否调整，以及与现有共振叠加多少，仍须分别确定。

### 3.2 主人自身成长

可以讨论主人长期执行调教与绑定仪式时如何获得自身成长。现有行为能够承载成长来源，无需先增加另一套侵蚀任务。

若采用独立成长进度，可考虑通过成功完成培养或完整仪式积累，并影响主人本体或主动能力。是否使用进度、阶段、研究解锁或其他方式，以及退出主人身份后的记录处理，均未确定。

### 3.3 主动能力

技能式能力属于可选拓展。候选包括自身修复、短时强化、对他人施加 PNA 效果，以及临时调节自己绑定对象的状态。

每项技能需要分别确定作用对象、效果、持续时间、冷却和资源代价。主动侵蚀能力可以作为额外操作，但不替代现有调教与绑定仪式的功能。

### 3.4 现有绑定反馈

可以结合主人本体和成长方案，复盘共振、伤害分担及其他绑定收益，讨论绑定数量、培养程度和主人自身成长分别如何影响强化。

主人能力作用于性奴时，可以复用性奴已有状态和特化效果。需要设计的是主人如何发动、如何增强和承担什么代价，而不是为性奴追加一套功能体系。

## 4 道具入口的已确定功能

该道具作为 SSC 功能的统一入口，核心功能是解锁个人主人身份选项；原版研究蓝图生效时，同时补充当前存档的研究蓝图。个人资格功能独立于 Royalty，道具名称、表现形式和设定细节未确定。

### 4.1 使用与解锁

| 项目 | 已确定规则 |
| --- | --- |
| 首版使用者 | 非 SSC 性奴可以使用；SSC 性奴使用无效。性奴专属使用效果暂缓。 |
| 重复使用 | 已解锁主人身份选项的角色再次使用无效。 |
| 消耗 | 成功使用消耗一个道具，无效使用不消耗。 |
| 当前身份 | 使用不直接改变 SSC 身份，由玩家自行选择。 |
| 研究蓝图 | 原版 Royalty 蓝图功能生效时，基础调教科技受蓝图门槛约束，成功使用道具后开放正常研究；无 Royalty 时沿用原版研究规则，不额外添加 SSC 蓝图门槛。 |
| DLC 条件 | 道具和个人主人资格解锁在无 Royalty 环境仍可用；蓝图相关 Def 配置按原版 DLC 条件加载，保持现有必需依赖。 |
| 研究进度 | 开放研究不等于完成研究，仍需正常研发；后续使用不改变已有研究状态。 |
| 个人解锁 | 每个小人分别使用，解锁自身的主人身份选项。解锁长期保留，退出主人身份后再次选择无需重复使用。 |
| 解锁记录归属 | 个人解锁属于人格记录，随人格转移；人格凝胶保存该记录，采集、存读档、复制、加工和植入均需保留。 |
| 克隆继承 | 克隆不继承来源人格的个人主人选项解锁记录。克隆的独立记录初始化为未解锁，不因复制来源身份或成长数据而获得解锁。 |
| 身份锁定 | 实际切换继续沿用当前版本的限制与锁定，不因使用道具而解除绑定或绕过检查。 |

当前身份锁定通过[统一身份入口](../../Sexslavecraft/common/SSCIdentityUtility.cs)处理：持有锁链的角色，以及缰绳仍有有效绑定对象的主人，不能切换 SSC 身份。道具规则尚待开发，不改变当前实现。

### 4.2 手动赋予与旧档

- 保留允许直接手动赋予主人身份的设置，**默认开启**。
- 开启时绕过个人道具解锁门槛，实际身份切换仍遵守现有限制。原版蓝图功能生效时，此设置不代替道具的全局研究蓝图解锁。
- 不重置或减少已保存的研究进度。沿用原版新增研究蓝图要求的兼容口径：已完成或已有任何研究进度的科技认可新增蓝图条件，只有研究进度为零且未完成的科技继续受蓝图门槛限制。原版核查依据见第 4.4 节。
- 旧档主人依据保存的 SSC 主人身份识别，补上个人主人身份选项的解锁记录。
- 个人解锁与当前身份分别保存：已经解锁但退出主人身份的人格仍保留解锁。人格凝胶恢复个人记录，不迁移当前存档的全局研究蓝图状态。
- 克隆不继承来源的个人解锁，相关复制入口需显式保持未解锁；普通人格凝胶转移继续保留该记录。旧档主人补解锁属于旧字段迁移，不能在每次加载时仅凭主人身份重新赋值，否则会绕过克隆不继承规则。

### 4.3 获取与调试

- 开局通过免费任务给予一个道具。
- 每次读档完成后检测一次基础调教科技是否已完成，以及是否已有 SSC 主人；只有科技未完成且没有 SSC 主人时，才自动触发初次获取事件。主人按保存的 SSC 身份识别，不以原版身份或调教员任职代替。
- 自动初次获取使用存档记录去重，避免重复读档重复投放；应在研究兼容及 Pawn 引用恢复完成后检查。事件判定使用“科技是否已完成”，有研究进度但未完成并不等于已完成，与第 4.4 节的蓝图兼容判定分别处理。
- 道具作为稀有品在商队、遗迹和任务奖励中生成，投放概率参考魔鬼素；具体参数待实现时核对。
- 制作功能暂缓，不将后期制作科技列为当前交付内容。
- Mod 设置界面增加调试栏，提供生成一个该道具的按钮。生成后仍走正常使用流程。
- 设置界面另提供手动触发初次获取事件的按钮，调用与自动触发相同的事件流程。手动触发不要求重新满足“科技未完成且没有主人”的自动条件；已有待处理的同类初次事件时不重复创建。

道具解锁、人格归属及初次获取条件已确认；任务形式、投放参数、主人检测的具体角色范围、界面和生成位置等实现细节仍待确定。

**实现方针：** 研究的全局蓝图状态、资格、提示及旧档兼容交给原版；SSC 补充自身的个人永久解锁、资格验证、有效消耗、人格凝胶记录、克隆不继承及初次获取事件。原版蓝图功能生效且数量不足时，道具补充原版蓝图记录；其他情况下成功使用仅增加个人解锁，不附带额外研究收益。

**已确定的 Royalty 处理：** 未安装 Royalty 时，原版 `ResearchProjectDef.PostLoad` 将 `techprintCount` 清零，`TechprintCount` 返回 0，自动蓝图道具生成器退出，`CompTechprint` 和 `ApplyTechprint` 也有明确检查。维护者确认这不影响 SSC 道具的核心用途：道具仍可使用并解锁个人主人资格，研究沿用无 Royalty 时的原版规则。保留 `About/About.xml` 当前必需依赖，不新增独立 SSC 全局蓝图字段，不为无 Royalty 环境另写研究蓝图系统；道具自身及个人资格功能不随蓝图 DLC 条件禁用。研究蓝图字段与持有派系等相关配置需按 DLC 条件成组加载，避免无蓝图需求时残留蓝图配置造成 XML 定义错误。

## 5 道具入口的具体实现分析（2026-10-11）

本节基于 2.3.9 基线和 RimSage 原版源码给出实现拆分。第一批已按下述资格、人格和迁移方案实现；第二批已实现独立道具、研究接入和调试生成。任务与长期投放段落仍是方案。道具入口独立开发，不依赖主人成长、主动能力或调教员指派重构。

### 5.1 数据与职责

| 数据 | 建议保存位置 | 职责 |
| --- | --- | --- |
| `pawnIdentity` | 现有 `CompSexSlaveTraining` | 当前身份；继续使用 `Unset / Slave / Master`，不扩展枚举。 |
| `masterQualificationUnlocked` | `CompSexSlaveTraining` 的新 partial 文件 | 该人格是否实际取得永久主人资格；默认 `false`，身份切换不清除。 |
| `masterQualificationVersion` | 同一 Pawn 组件 | 新角色初始化为当前版本，Scribe 缺字段默认读为 0；区分旧档缺字段与新记录明确未解锁。 |
| 资格值与格式版本 | `CompPersonalityStore` | 人格凝胶独立保存资格及格式，参与采集、序列化、`CopyFrom`、加工和植入。 |
| 基础研究蓝图 | 原版 `ResearchManager.techprints` | 继续由原版保存、检查和兼容，不增加 SSC 全局蓝图标记。 |
| 初次获取是否已发放及待处理任务 | 新 `GameComponent` | 每个存档独立去重，记录已成功创建的任务及待处理状态。 |
| `allowDirectMasterSelection` | `SSCSettings` | 建议设置名，默认 `true`；只放行手动选择，不等于写入永久资格。 |

第一批已新增直接赋予主人身份的独立设置，默认开启。不能根据“当前是 Master”在查询、切换设置或每次读档时反复推导永久资格。默认手动设置开启时，新角色可以选择 Master，但其道具资格仍为 `false`，后续道具接入后仍可正常使用一次；之后关闭设置不主动撤销已有身份，退出后重新选择才检查个人资格。

### 5.2 道具使用与有效消耗

第二批新增始终加载的 `SSC_MasterQualificationItem` ThingDef，名称为“主人资格模块”，配置原版 `CompProperties_Usable`、`useJob=UseItem` 和 SSC 自定义 `CompUseEffect_MasterQualification`。菜单、预约、接触、使用等待、任务保存和中断复用原版。当前使用时间 600 tick，价格 1000，堆叠上限 10，复用原版核心轨道定位器图像并加紫色；这些为首版配置，独立美术和数值平衡可后续调整。

`SSCMasterQualificationUtility.Item.cs` 集中提供道具使用判定与最终授予，普通身份准入及人格恢复沿用第一批入口。已实现流程如下：

1. 菜单通过 `CompUseEffect.CanBeUsedBy` 检查存活、未销毁、人形且非人格空壳，具有 SSC 组件、有效身份、当前不是 SSC Slave、个人资格尚未解锁，返回本地化拒绝原因。原版 `CompUsable` 继续处理身体、路径、预约等物理条件。原版奴隶身份不代替 SSC Slave 判定。
2. 原版 `JobDriver_UseItem` 在执行期间调用 `CompUsable.CanBeUsedBy`；途中变为 Slave、其他来源已授予资格、道具被禁止或失去接触时，不结算。
3. `DoEffect` 最终再次检查同一规则，并检查道具仍存在、数量至少为 1；直接调用效果也不能跳过 SSC 条件。
4. 基础研究 Def 和研究管理器有效时，计算 `missing = TechprintCount - TechprintsApplied`。只在 `missing > 0` 时调用原版 `AddTechprints`；无 Royalty 时数量为 0，跳过此步。缺失必要 Def 属于接入错误，应在写资格或消耗前拒绝并记录。
5. 写个人资格及当前格式版本，再消耗 `parent.SplitOff(1).Destroy()`；当前身份不变。成功提示、音效等表现放在成功结算之后。

**不要另挂无条件 `CompUseEffect_DestroySelf`。** 原版 `CompUsable.UsedBy` 逐一调用效果，并捕获单个效果的异常后继续执行；独立销毁效果不能获知 SSC 授予是否成功。授予和消耗应由同一 SSC 效果控制，失败返回时消耗为零。使用 `AddTechprints` 而非 `ApplyTechprint`，避免智识经验、重复应用研究加速和研究台前置改变道具规则。

### 5.3 身份入口与人格完整流转

身份面板的 Master 选项需要显示资格不足的禁用原因，并在点击时重新判定；只修改菜单不足以封住其他调用。普通选择应在 `SSCIdentityUtility.TrySetIdentity` 的统一入口检查 Master 资格，并在取消旧仪式后的最终写入前复查设置及资格，保留现有绑定锁定、清理和生命周期通知。

道具使用与身份切换采用不同判定：使用道具拒绝 SSC Slave；选择 Master 则检查实际个人资格或手动设置，再沿用身份锁定。曾经解锁的人格后来选择了 Slave，只要当前允许正常退出该身份，其保留的资格仍可支持再次选择 Master，不套用“Slave 不得使用道具”的限制。

人格恢复与玩家新选择分别处理：新增定向的人格恢复入口，先整体替换个人资格，再恢复凝胶保存的身份，复用原有身份修改核心及通知。它允许恢复已保存的身份，包括新格式凝胶中明确保存的 `Master + 未解锁`，不能因此把未解锁改为已解锁；不暴露通用“忽略一切检查”开关。原因是默认手动设置允许未使用道具就选择 Master，保存这个人格时两项记录本来就可能不同。

| 当前入口 | 必需改动 |
| --- | --- |
| `CompPersonalityStore.StorePawnData` | 采集资格及当前格式版本；采集前完成来源角色的旧字段归一化。 |
| `CompPersonalityStore.PostExposeData` | 保存资格和独立版本，旧凝胶缺字段保留可识别的版本 0。 |
| `CompPersonalityStore.CopyFrom`、`Recipe_PEMake` | 连同值和版本复制，不凭当前身份重算；现有加工调用 `CopyFrom`，通常无需每个配方重复写新字段。 |
| `ExcretionUtility.DoExcretion` | 建议在快照有效且凝胶成功生成后清除原身体的个人资格，版本仍保持当前，避免一次人格转移留下两份身体资格。该建议只处理新资格，不顺带重构既有空壳身份或绑定。 |
| `ExcretionUtility.CleanConsumerData`、`InheritEverything` | 清除宿主残留资格，按来源人格整体替换，再走定向身份恢复；不能用“宿主或来源任一有资格就保留”的合并方式。 |
| `RabbitCloneUtility` | 显式设资格 `false`、版本为当前，不复制来源资格。 |

当前兔克隆代码仍复制 `pawnIdentity`；“不继承主人资格”不自动等于“把复制的当前身份重置为 Unset”。首版建议只落实已确认的资格不继承。若来源当前是 Master，复制后可能出现 `Master + 未解锁`，退出后受重新选择门槛约束；若要连当前身份一起重置，应单独列为身份继承规则变更。兔入口继续保持当前禁用状态。

### 5.4 一次性旧档迁移

可以沿用现有训导官迁移的模式：新组件字段初始化为当前版本，序列化缺字段默认版本 0，在所有 Pawn 引用恢复后的 `FinalizeInit` 归一化旧数据。采用各 Pawn 的版本标记，不能只用一个全局“旧档已迁移”标记代替，避免遗漏世界、商队或容器中的角色。

- 旧 Pawn 版本 0：保存身份为 Master 时补个人资格，其余保持未解锁，然后写当前版本。建议排除可识别克隆和已成为人格空壳的身体，避免违背资格归属；这是迁移建议，需纳入边界验收。
- 新 Pawn、明确未解锁的 Pawn、抽取后的原身体和新克隆：版本已为当前，读档不根据 Master 身份重新授予。
- 旧凝胶版本 0：建议仅保存身份为 Master 的凝胶补资格，其他凝胶按未解锁处理；旧字段无法还原“曾经解锁但已退出主人”的历史，不猜测这类记录。
- 新凝胶：尊重明确保存的 `false`，即使身份为 Master 也不补资格。

加载遍历可复用 `SSCRestrictionGameComponent.AllPawns()` 的地图、世界、临时、商队和运输角色快照，但资格迁移不依赖限制开关。新获取事件在研究兼容与资格迁移结束后判定，不依赖多个 `GameComponent.FinalizeInit` 的偶然先后顺序。必要的晚出现旧记录在明确的采集、恢复或加载入口归一化，不在每帧 UI 查询中迁移。

### 5.5 原版自动蓝图与长期获取

原版 `techprintCount` 配置会自动生成 `Techprint_SSC_RES_BasicTraining`。独立 SSC 道具成功使用后也能应用同一研究蓝图，但原版自动生成道具默认只研究、不授予个人资格。这会形成两个研究入口，不能把它描述为已完成的统一道具方案。

2026-10-11 已确认并实现：独立 SSC 道具承载跨 DLC 的个人入口，原版自动蓝图暂时保留为单独研究来源。SSC 不拦截生成器、不替换原版蓝图菜单或效果。基础研究通过 `MayRequire="Ludeon.RimWorld.Royalty"` 添加 1 份蓝图要求、1000 价格及 Empire／Outlander 持有类别。原版 `BackCompatibility.ResearchManagerPostLoadInit` 为已完成或已有进度的研究补齐新增蓝图，SSC 不另写研究迁移。

以后若统一两种入口，对生成蓝图的定向适配须保留原版识别所需的 `CompProperties_Techprint.project`，并停用它原来的应用菜单，避免同时提供原版加速／经验路径。若要求最终只有一个 ThingDef，还需要定向处理原版自动生成器，开发量更高。

不能用普通 XML Patch 直接修改尚未生成的 `Techprint_SSC_RES_BasicTraining`。原版 `PlayDataLoader` 在 implied Def 生成之后才调用启动静态构造；当前 SSC `ThePatches/HarmonyStartUp.cs` 使用启动静态构造安装补丁，因此在那里新增生成器补丁不能拦截首次生成。优先采用生成后定向适配；确需拦截生成时，只提前安装这一项补丁并核对初始化与热重载，不移动整批现有补丁。

**长期投放必须独立配置。** 原版 `TechprintUtility.GetResearchProjectsNeedingTechprintsNow` 会排除 `IsFinished` 或 `TechprintRequirementMet` 的科技；仅依赖原版蓝图商队／奖励池，会在首个道具解锁研究后失去后续个人资格来源。SSC 道具应使用独立稀有品交易和任务／遗迹投放配置，即使研究已完成或无 Royalty 也仍有获取机会。添加交易或掉落标签本身不保证所有来源会生成该物品，需要核对相应 stock generator、奖励和遗迹物品池；概率再参照原版魔鬼素的实际来源配置。

### 5.6 初次任务和设置按钮

新增存档级 `SSCMasterEntryGameComponent`，初始化和加载时只做一次自动条件检查：`!SSC_BasicTraining.IsFinished && !HasExistingMaster`，再叠加本存档未曾成功发放、没有待处理同类任务的去重条件。研究已有进度但未完成仍按未完成处理；已有个人资格但未选择 Master 也不代替身份判定。

主人检测范围建议为存活、未销毁、非空壳的己方 SSC Master，覆盖所有地图、商队和运输状态；敌方、访客或已死亡主人不阻断己方初次获取。范围尚待确认，代码应集中在一个查询中，避免事件和界面各自推导。

免费任务建议首版采用无战斗、无付费条件的接收物资任务，固定奖励 1 个道具，复用原版 Quest、信号和空投部分。原版 `QuestNode_DropPods`、延迟奖励任务已有投放及目标地图处理，无需实现新投送系统。自动和手动入口共用 `TryCreateInitialAcquisitionQuest`；生成失败不能先写“已发放”。只有生成并登记成功才持久化标记和任务引用。加载暂时没有可投放地图时保留待创建请求，在地图可用时执行，不在 tick 中反复扫描整个世界或重做初次条件判定。

设置调试栏中的“生成 1 个道具”已在第二批实现：优先放在当前地图选中对象附近，否则放在地图中央；无游戏、地图或道具 Def 时禁用并说明原因，放置失败不提示成功。按钮不授予资格，也不依赖调试 Gizmo 开关。

手动创建初次获取任务按钮留待第三批，届时与生成按钮分开。手动任务入口跳过研究／主人自动条件和已发放标记，但仍防止创建同类待处理任务。任务完成、拒绝、过期及目标地图变化需要核对：自动不因再次读档反复补发，手动入口仍可恢复获取途径。

## 6 功能边界与后续待定事项

主人身份、主人选项解锁、实际绑定关系、恶堕与锁链成长、原版奴隶身份分别承担不同功能。后续能力需要明确自己改变哪些状态，并沿用相应系统的关系与结算规则。

本规划保留以下待定事项：

1. 主人本体的具体效果，哪些在无绑定状态下生效，以及与现有共振的叠加方式。
2. 是否增加主人成长机制；若采用，确定来源、速度、阶段及身份切换后的记录处理。
3. 是否开发主动能力，以及具体技能、作用对象、持续时间、冷却、资源和界面。
4. 共振和伤害分担是否调整，如何体现绑定数量、培养程度和主人本体成长。
5. PNA 感染、成瘾及弹药对主人的适配方式。
6. 任务投放与主人检测范围；调试生成按钮已在第二批实现，个人与人格流转实现及专项验证边界见开发记录。
7. 后续统一入口道具与原版自动生成蓝图的衔接，以及独立美术、数值平衡；第二批已按独立来源落地，个人资格始终可用，研究体系直接复用原版。
8. 开发顺序、目标版本、具体数值及后续验证范围。

本文件同时保留规划及第一、二批完成范围。主人本体的历史静态核对和资格的自动回归均不能代替真实存档往返与实机验收；第二批已获维护者实机确认，尚未实现的任务与长期获取入口继续按后续批次推进。
