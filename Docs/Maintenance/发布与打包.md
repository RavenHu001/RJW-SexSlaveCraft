## 编译 1.7

主开发工程为 `Sexslavecraft/SexSlaveCraft_1.7.csproj`，目标 `net10.0`，从旧项目读取唯一的显式 Compile 清单。输出仅写入 `1.7/Assemblies`，中间文件位于 `.builds/build/1.7`；依赖引用不复制到输出。旧项目保留源清单和历史结构，但本工作区不允许它覆盖冻结 DLL。

需要匹配的 .NET 10 SDK、实际 RimWorld 1.7 安装及目标环境选用的依赖 DLL。不要将 1.6 旧 Managed 路径回退到当前 1.7 游戏程序集。以下路径均为需要替换的示例：

```powershell
pwsh -File Scripts/Build-Mod.ps1 `
  -GameRoot 'D:/Games/RimWorld' `
  -RjwAssemblyPath 'D:/Mods/RJW/1.6/Assemblies/RJW.dll' `
  -AnimationsAssemblyPath 'D:/Mods/Animations/1.6/Assemblies/Rimworld-Animations.dll' `
  -GameHarmonyAssemblyPath 'D:/Workshop/Harmony/1.7/Assemblies/0Harmony.dll'
```

依赖目录叫 `1.6` 不自动证明它不适用于 1.7；引用必须来自目标游戏实际选用并待验证的依赖集合。上述 RJW/动画路径是示意，不能据此宣称它们已兼容。

可用 `SSC_GAME_ROOT`、`SSC_RJW_ASSEMBLY_PATH`、`SSC_ANIMATIONS_ASSEMBLY_PATH`、`SSC_GAME_HARMONY_PATH` 设置本机默认值。构建脚本按顺序选择 SDK 入口：显式 `-DotnetPath`、`SSC_DOTNET_PATH`、本工作区已有的 `.builds/version-layout/sdk/dotnet/dotnet.exe`，最后才使用 PATH 中的 `dotnet`。可传 `-DotnetPath '<本机 SDK>/dotnet.exe'` 指定其他 SDK，无须修改系统 PATH。缺省 `DOTNET_CLI_HOME` 放在工作区内；脚本结束或失败后恢复原有进程环境。

构建成功后，脚本检查产品版本、文件版本和原有程序集身份，并更新 `BUILD-INFO.json` 的 DLL 哈希、游戏构建、游戏及依赖程序集哈希、SDK 和源码工作区状态。`gameRuntimeVerified` 始终重置为 false。失败不得被当作已验证构建；重新打包仍会检查实际 DLL 与构建记录是否匹配。

## 自动检查与回归

需要 PowerShell 7、Git、.NET SDK 9 或更新版本、.NET 9 运行时，以及本地 **net9.0** 的 `0Harmony.dll`。游戏使用的 Harmony 与测试宿主引用不同，不混用。

```powershell
pwsh -File Scripts/Test-ModLayout.ps1
pwsh -File Scripts/Test-All.ps1 -GameVersion 1.7 `
  -HarmonyAssemblyPath 'C:/Dependencies/Harmony/net9.0/0Harmony.dll'
pwsh -File Scripts/Test-All.ps1 -GameVersion 1.6
```

冻结目录通过 `.gitattributes` 的 `/1.6/** -text` 保留原始字节，避免跨平台检出时换行自动转换导致哈希失效。

布局检查验证显式加载列表、缺失/重复程序集、1.6 的完整运行基线、共享旧贴图哈希和 1.7 二进制来源记录。

`Test-All` 默认选择 1.7，检查该版 Def/语言镜像并执行登记的 **43 套当前源码回归**，包括凝胶化单次结算、1.7 染色、Harmony `__state`、文化及医美原生专项。报告记录 GameVersion、RuntimeRoot、实际用例数和源码验证范围。资源路径与源码路径分开，直接运行单套时也默认读取 1.7。报告位于 `.builds/validation/`，可用 `-ReportDirectory` 指定目录。

`-GameVersion 1.6` 只检查冻结基线及该版 XML 资源，不用当前 1.7 源码冒充旧版源码回归。这些自动检查保留，不要求恢复旧版游戏引用、重编或实机回归环境。两种模式均不启动游戏。

镜像检查仍分别由 `Test-DefMirrors.ps1`、`Sync-LanguagesMirror.ps1` 执行；限制文本参数检查由 `Test-RestrictionLocalization.ps1` 执行。需针对实际游戏 DLL 的静态检查脚本使用明确的游戏程序集路径，不能把 .NET 9 模型回归当作 1.7 游戏加载证据。

发布编排的隔离夹具可运行：

```powershell
pwsh -File Tests/ValidationRunner/Run.ps1 `
  -HarmonyAssemblyPath 'C:/Dependencies/Harmony/net9.0/0Harmony.dll' `
  -FrameworkHarmonyAssemblyPath 'C:/Dependencies/Harmony/net472/0Harmony.dll'
```

此夹具模拟 dotnet 进程，验证失败传播、双版本文件选择、冻结保护、清单、文档白名单和链接转换，不计入机制回归用例。

## 发布包内容与检查

```powershell
pwsh -File Scripts/New-Release.ps1 `
  -HarmonyAssemblyPath 'C:/Dependencies/Harmony/net9.0/0Harmony.dll' `
  -OutputDirectory '.builds/local-dual-version-package'
```

默认复用两版预编译 DLL；修改源码后使用 `-Build`，并传入上述 1.7 构建参数。此开关仅重编 1.7，绝不重编或覆盖 1.6 基线。旧版 MSBuild 引用覆盖参数不适用于新的发布构建入口。

ZIP 顶层只有 `RJW-SexSlaveCraft-TieJin-Modify/`。运行文件按目录白名单收集：`About`、`Common/Textures`、两个版本的 Defs/Languages/Patches/Resources/Textures/Sounds/Shaders，以及各自唯一的 `Assemblies/Sexslavecraft.dll`；不存在的可选目录忽略。必须包含 `LoadFolders.xml`、`1.6/BASELINE.json` 和 `1.7/BUILD-INFO.json`。

文档仍按文件白名单收集：根目录 `README.md`、`QUICK_START_EN.md`、`读我，玩法介绍.md`、`机制详解.md`、`PLAYER_GUIDE_EN.md`、`VERSION`、`CHANGELOG.md`，以及 `Docs/模组介绍.md`、`Docs/Players/README.md`、`Docs/Releases/<当前版本>/<当前版本>发布说明.md`；另生成 `INSTALL.txt`。

不递归复制整个版本目录或 `Docs`。源码、测试、PSD、PDB、开发资料、美术备份、历史验证记录和第三方 DLL 不进入 ZIP。已有 PNG、DDS/ZSTD 运行纹理保留。

打包只改写随包 Markdown 副本：随包文件保留相对链接，未随包资料改为仓库链接，默认 `-RepositoryRef main`，避免当前 1.7 开发包错误指向已发布的旧 v2.4.1 标签。正式发布可显式传 `-RepositoryRef v<新版本>` 固定资料版本；目录使用 tree，保留锚点、标题及 URL 编码。改写不检查远端可用性，也不改写仓库原文档。

`RELEASE-MANIFEST.json` 记录每个载荷文件的路径、大小和 SHA-256、发布版本、文档仓库引用、基础提交、工作区状态、当前回归结果，以及各游戏版本独立的 DLL/来源/验证信息。冻结的 1.6 DLL 保持 **2.4.1**，以后发行包版本变化不要求它同步升级。1.6 保留原成品的历史验证信息，1.7 游戏内验证单独标记，不能由编译或模型回归推断通过。

任一布局、来源、版本、翻译或回归检查失败均在创建 ZIP 前停止。同版本产物默认不覆盖；明确替换本地输出时传 `-Force`。ZIP 旁生成 `.sha256`，可用 `Get-FileHash -Algorithm SHA256` 核对。默认 `Releases/` 和 `.builds/` 均为本地产物目录；新包不覆盖 `Releases/Published/` 中各版本的历史正式附件。
