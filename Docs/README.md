## 文档维护约定

- 玩家指南保留在根目录；玩家可见变化写入 `CHANGELOG.md`，未发布内容与正式版本分开。
- 实现、修复和技术验证放入 `Docs/Development/`；日期日志集中在 `开发更新记录.md`。
- 设计、未来需求与机制复盘放入 `Docs/Design/`，正文注明状态、日期和基线；完成后保留方案与实施历史。
- 发布说明、验证与公告放入 `Docs/Releases/<版本号>/`；根目录 `Releases/` 留给本地发布产物。
- 构建和维护流程放入 `Docs/Maintenance/`；命令默认从仓库根目录执行。
- 图标说明、提示词和美术备份放入 `Docs/Art/`；游戏运行纹理放入 `Textures/`。
- 测试与工具 README 保留在所属目录；新增文档同步对应分类索引，使用相对链接，移动文件时核对所有入站链接与脚本引用。
- 历史记录中的“未发布”“待确认”按当时语境阅读；当前交付以版本记录为准，最新开发状态以日志为准。提示词与交接文档用于追溯，不作为新的待执行任务。

打包脚本递归复制整个 `Docs`；分类索引会随安装包保留，其中指向测试、归档或源码的链接需要完整源码仓库。
