## 中文

### 独立配置与统一许可

新限制系统替代原先分散的保护开关、个体例外和装备独立拦截。每名实际绑定主人的角色拥有独立配置，玩家命令与自主行为使用同一个许可入口。

| 分类 | 可配置条目 |
| --- | --- |
| 主动 | 单人自慰；发起自愿性行为；发起强制行为 |
| 被动 | 接受非主人自愿行为；接受非主人强制行为 |
| 调教 | 接受非主人调教 |

- 自愿发起开启后，可以选择“仅限主人”或“不限对象”。普通双人行为分别检查发起方和接收方；主动“不限对象”不会替对方放开接收许可。
- 限制只在实际绑定主人后生效。仅有性奴身份、指定调教员、特化或装备不会单独激活；解绑后暂停，重绑后保留已有个人选择。
- 实际主人向自己的绑定对象发起任何纳入系统的行为，统一入口直接允许，双方个人条目、装备和特化均不能否决。反向发起或仅有主人身份的第三人不获得这项许可。
- 许可不替代正常工作条件：身体、身份、研究、冷却、排班、寻路、预约等仍按各自规则处理。既有同床规则保持独立。

### 装备、特化与调教员

- 装备和特化改为通过 XML 声明条目，不再使用系统外的装备保护检查。有效值优先级为“装备强制 > 已启用特化强制 > 个人保存值”；同层冲突取较严格值。
- 现有防护服强制禁止“接受非主人强制行为”。公交车的两项被动许可有默认允许，并可由全局特化强制开关持续强制允许；装备仍可覆盖对应条目。
- 穿脱装备、切换强制开关只改变当前有效值，不将覆盖结果写回个人配置。关闭特化强制不关闭装备保护；限制总开关关闭时两类强制均暂停，配置保留。
- 指定合格非主人调教员时，可同步开启“接受非主人调教”；若装备或特化强制禁止，则指派失败并保留原配置和指定者。普通互动继续检查普通条目。
- 自动日常工作仍由当前有效指定者承担；主人手动发起或主持不因指定了他人而被排除。非主人主持不会改变绑定归属，首次建绑仍要求合法主人。

### 已接入的任务与行为边界

- 统一接入 RJW 普通双人、单人自慰、人格排泄专用任务、日常调教及仪式；人格专用任务按普通非强制互动处理，不套用调教许可。
- 公交车交易、宠物事件在打断原工作前检查真实任务；保留原交易/工作成长、概率和冷却，实际开始后才发送发生提示，避免准备失败却提前宣布成功。
- 独立原版 Lovin、已支持的 LifeForce 随机强制与 Seduce 能力/准备/场景、现有家具双人和调教桥接使用同一许可。家具的普通占用、睡眠不会被虚构为互动请求。
- 玩家命令在修改原任务与队列前预检。走位和准备期间规则变化会重新检查；拒绝时精确清理本次等待、接收和占用，保留无关任务及其他参与者。
- 已经开始的场景或仪式当前阶段正常收尾；新参与者、下一任务和下一阶段重新检查。完善存读档的参与方向和开始状态恢复，取消时不领取成功结算。

### 默认配置、旧档与界面

- 首次实际绑定时建立配置，旧档原有选择一次性迁移；已有新配置优先，不因读档、重复通知或全局模板变化被重置。人格恢复保留接收角色已有选择，新克隆使用独立配置。
- 默认模板只影响后续需要初始化的角色。显式“应用默认配置”可覆盖当前存档全部适用角色，包括其他地图、商队及离图角色；按当前模板和特化默认重设，不保存装备强制结果。
- 行为限制入口位于调教设置紧邻上方，规则栏向 ITab 右侧展开，保持主栏位置，并避开关闭按钮。未绑定或总限制关闭时，展开入口置灰不可用。
- 条目采用原生绿勾/红叉；自愿发起下属一对对象单选，关闭后记住选择。装备或特化强制的条目显示当前生效值并锁定，原个人选择保留，悬停可查看原因和来源。
- 全局默认模板收纳到独立子窗口。批量应用按钮位于子页底部，使用橙色、感叹号及覆盖提示，并保留确认弹窗。
- 设置主页的行为限制测试入口位于限制区块最下方，可选参与者、用途和方向，查看实时许可结果；测试不启动实际任务。
- 删除旧四项全局保护控件与个人开放例外，日常面板减少常驻说明，以短标记和悬停呈现。新增限制界面的简中、英文文本同步。

## English

### Per-pawn rules and shared permission checks

- Replaces separate protection switches, pawn exceptions and independent equipment blocking with six saved permissions: solo activity, consensual/forced initiation, consensual/forced reception from non-owners, and non-owner Training. Consensual initiation offers Owner only or Anyone; ordinary pair interactions check both sides.
- Restrictions activate only after an actual owner bond. Identity, assignment, specialization and apparel alone do not activate them. Unbinding pauses restrictions; rebinding retains existing choices.
- The actual owner initiating with their own bound pawn receives immediate permission before either participant's rules or overrides are consulted. Reverse initiation and third parties with Master identity receive no such allowance. Normal job requirements and shared-bed rules remain separate.

### Equipment, specializations and trainers

- XML defines equipment overrides and specialization defaults/overrides. Equipment takes priority over enabled specialization overrides, then saved choices; conflicting entries within one layer use the stricter value.
- Existing protective apparel denies forced reception from non-owners. Public Use retains its two reception defaults and optional forced allowances. Changing apparel or override switches does not overwrite personal choices. Disabling specialization overrides retains equipment protection; disabling the restriction system pauses both.
- Selecting an eligible non-owner trainer also enables receiving non-owner Training, unless a forced denial prevents assignment. Ordinary interactions retain their own checks. Automatic work remains with the assigned trainer; the owner retains manual and ritual access, and third-party Training does not change ownership.

### Jobs, saves and cancellation

- Covers ordinary RJW pair and solo jobs, personality-excretion jobs, daily Training, rituals, trade/pet events, native Lovin, supported LifeForce ability/preparation/scene paths, and existing furniture interaction/Training bridges.
- Player orders are checked before replacing work or queues. Events are checked before interrupting participants, and occurrence messages wait until the scene actually starts. Trade/work growth, probabilities and cooldowns retain their existing rules.
- Preparation is checked again when rules change. Rejection removes only this request's waiting and participation state. Started scenes and ritual phases finish normally; later jobs, phases and participants are checked anew. Saved direction/start-state recovery and cancellation prevent false completion rewards.
- Initializes configurations on actual binding and migrates legacy choices once. Existing configurations survive reloads and template edits; personality restoration preserves the recipient's choices, while new clones receive independent configurations. Explicit save-wide default application includes eligible off-map pawns.

### Interface

- Adds a right-side rule panel without moving the main Training ITab. The entry sits directly above Training settings and is disabled for unbound pawns or when restrictions are globally off.
- Uses native checks/crosses, with remembered Owner only/Anyone radio options beneath consensual initiation. Forced entries show effective values and cannot be edited; saved choices remain available when overrides end, with details on hover.
- Moves the default editor into its own window. The batch overwrite button uses an orange warning, an exclamation mark and a confirmation dialog. The restriction test entry sits at the bottom of its settings block and previews permissions without starting jobs.
- Removes legacy protection controls and exception options; adds Simplified Chinese and English restriction text.

### Fixes and validation

- Fixes identity-only activation, dead/destroyed owner reassignment and unbinding cleanup during personality restoration. Preserves configuration errors and their actual sources without partially initializing data or silently resetting unsupported versions.
- Separates configuration building, assignment authorization, preparation cleanup and event notifications; reduces temporary allocations and avoids constructing verbose log text when disabled. Adds compatibility-signature diagnostics, regression coverage and Chinese code comments; retains legacy fields only for migration.
- Existing development runs passed **645/645 across 16 suites**, an additional LifeForce-absent **108/108** variant, and the latest UI batch's **124/124** restriction-core cases with a clean Release build. These are separate historical runs, not a newly executed 2.3.1 release build. The maintainer confirmed gameplay, UI, upgraded-save reloads, mid-job saves, rule changes before/after scene start and commonly used compatibility combinations.
- Research-based activation, more visible contextual rejection feedback and arbitrary third-party standalone-driver support remain outside this update. Existing validation tooling and the auxiliary diagnostics panel are documented separately; their initial development is not attributed to this session.
