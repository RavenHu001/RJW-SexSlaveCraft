## 正式产物与发布校验流程

按[发布与打包指南](../../Maintenance/发布与打包.md)执行以下门禁，任一失败即停止公开发布：

1. 提交版本元数据、文档、测试适配和重建 DLL，从干净工作区生成 `Releases/Published/2.3.2/RJW-SexSlaveCraft-TieJin-Modify-2.3.2.zip` 与 `.zip.sha256`。
2. 正式打包再次运行同一组 18 套回归，报告写入 `.builds/release-2.3.2/published-validation/summary.json`；包内清单记录实际计数、提交和工作区状态。
3. 核对单层根目录、版本、每个载荷文件大小和 SHA-256，以及提交来源。只包含运行文件和文档，不包含源码、测试、PDB 或第三方 DLL；结果保存于 `.builds/release-2.3.2/published-package-validation.json`。
4. 推送发布提交，创建对应提交的 `v2.3.2` 草稿，上传 ZIP 和校验文件；核对 GitHub 返回的附件大小及摘要后转为正式最新版本。
5. 再核对公开状态、标签提交、最新版本及两项附件；公开元数据记录于 `.builds/release-2.3.2/github-release-final.json`。Discord 等外部公告不在本次发布操作内。

本地报告与正式安装包不提交进 Git；公开下载以 Release 附件为准，校验值以随包 `.sha256` 为准。
