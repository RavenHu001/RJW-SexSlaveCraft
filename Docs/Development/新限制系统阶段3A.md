# 新限制系统阶段 3A：普通任务接管

开发日期：2026-09-21。基于 `8eb7afe`，未发布、不改版本号。行为约定见[开发规划](../Design/新限制系统开发规划.md)。本批接管 **RJW 普通双人、单人自慰、人格排泄专用任务**及其关联接收任务；阶段 2 的界面、配置迁移和指定者协调继续保留。

本机同步后，维护者实机测试反馈“基本起到了效果”，并授权提交；此反馈不代表下方全部场景均已逐项验收。

## 已实现

- `SSCRestrictionJobContext` 将任务转换为统一请求。优先读取 RJW 的 `Partner`（含 `PartnerPawn` 和目标布局），区分发起与接收驱动；共享接收任务沿指回自己的发起任务确定用途。`isRevese` 只表示姿势，不反转发起方向；冲突的 `SexProps` 不会被拿来伪造主人关系。
- 明确的 `JobDriver_Masturbate` 才使用单人规则。其他任务缺少目标不会自动归类为自慰；涉及受限角色但方向或用途不足时由统一入口拒绝。人格排泄使用普通非强制双方条目，不附加日常调教身份、指定者或调教许可门槛。
- `SSCRestrictionJobGuard` 调用既有 `SSCRestrictionPolicy`。已接管路径不再读取旧开放例外和旧分项全局值，不保留玩家强制指派豁免或公交车整次放行；装备只通过已声明的强制条目生效。主人直接通过、双向检查、总开关及来源合成仍由同一核心决定。
- 预约补丁覆盖 RJW 派生驱动自己重写的方法。每次进入新步骤前及 `Start` 前复查，覆盖行走后修改规则和新参与者加入；接收端使用同一请求。身体条件、研究、正常预约、寻路及原任务失败条件仍执行。
- 玩家命令在 `TryTakeOrderedJob` 修改当前任务和队列前检查，拒绝时提示并保留原工作。AI 在 `ThinkNode_JobGiver.TryIssueJobPackage` 产生候选后检查，拒绝的候选释放预约并回收，让思考树继续其他工作；不借预约失败触发原版异常提示或同栈重新找相同任务。
- 实际 `Start` 成功后记录有向参与者、用途和开始状态；凭据随驱动保存。内存状态同时绑定 Job 引用与 `loadID`，避免对象池复用、换目标或新任务继承之前的通过结果。已开始场景正常收尾，新加入者单独检查。
- 按真实加载顺序处理：`LoadingVars` 时驱动尚未接回 Pawn/Job，后续回接引用不能清空已读状态；升级旧存档时先捕获实际计时进度，避免 `PostLoadInit` 重建 RJW 步骤和计时后丢失证据。准备阶段仅有 `SexProps` 或提前登记参与者不算开始。旧版本没有凭据且尚无计时证据的场景仍重新校验；本版 Start 后即使尚未计时便保存，也可准确恢复。
- 拒绝未开始任务时，移除本次参与者关联；属于本次且已无其他参与者的标准/SSC 接收任务以失败条件结束。不会终止其他已开始参与者或后来替换的新任务。人格排泄解除本次家具关联并记录原有验证冷却，不伪造成功结算。
- 快速双人任务另外记录准备回调新建的移动、排队等待编号。被拒绝时只撤销这些任务，保留原有或之后新建的任务；目标和编号随驱动保存，读档后也能清理。
- 界面说明更新为本批已生效范围；拒绝诊断包含用途、方向、原因、规则和具体来源。AI 不刷拒绝消息，玩家命令提供提示。

## 后续批次边界

日常调教、仪式、公交车交易/特化事件的调度预检和专项兼容仍需继续接管。`Harmony_ProtectSexSlave` 对这些用途保留阶段边界，已接管请求会先转交新入口，不再执行下面的旧规则。`SSCSexInteractionPolicy` 暂留给后续用途，阶段 4 再清理；这不是新系统最终保留的例外。

- LifeForce 的两个旧白名单任务明确留给专项适配，接收方沿发起任务一起识别，不能把它们混入已完成范围。
- 原版 `Lovin` 在 RJW `override_lovin` 开启后转换成普通 RJW 任务，转换后的任务受本批规则约束。关闭替换时的独立原版驱动仍待后续补齐，不能视为已经覆盖。
- 本批覆盖继承这些 RJW 预约/开始入口的普通任务，不宣称任意第三方独立驱动或自有调度器均已验证。人格排泄使用现有家具桥接，但常驻家具接收任务不被当作本次独占任务强行结束。
- 同床、身份、绑定、指定调教员资格及旧 UI 清理没有在本批扩展。
