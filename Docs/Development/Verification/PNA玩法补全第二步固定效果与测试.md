## 实机复测建议

1. 重启后确认无新增 XML／翻译报错。选无链非主人，先清负荷，再用已有 PNA 调试动作准备约 8%、20%、48%（20+20+8）、78%（70+8）和满值五种负荷，逐档检查健康效果与对应 +1／+2／+4／+6／+8 心情。每档短暂运行后再看思绪，避开恰好落在阈值上的自然消退。
2. 对有有效锁链的非主人重复上述五档：应显示微弱／稳定／深度／强烈／极限活化，能力为正面效果，满足收益对应五档，心情 +2／+4／+6／+8／+10。单纯 SSC 性奴身份不能替代有效锁链。
3. 普通满值仍因末期意识限制倒地；有链满值不应因 PNA 末期规则晕倒。检查 Hediff 自身效果，最终能力和催情还会受到锁链、成瘾、装备与其他来源影响。
4. 已成瘾角色停用所有 PNA，必要时用 clear load 隔离普通负荷惩罚；等纳米流体渴望降至 1% 或以下，检查戒断催情 ×1.75、操控能力 ×0.85、性脆弱度 +0.30 和 -18 心情。再次真实服药后应回普通成瘾档，新增戒断减益撤销。
5. 绑定／解绑时，原位负荷转换后应改用对应五档效果与心情，不同时保留两套负荷心情；清负荷后对应正面心情随原版查询刷新消失。主人依旧清药免疫。
6. 保存重载有普通／性奴负荷及戒断的角色，检查阶段、效果和心情正常；切换四语检查新阶段及心情名称、说明和占位符。

本批没有新增真实性交补给或更容易高潮的行为，不以性交新增负荷或高潮次数变化作为验收条件。

## 戒断悬停异常修正

维护者反馈第二步基本通过，但戒断时悬停成瘾 Hediff 出现 `Error getting tip text`，异常引用 `94611988`。检查本机 Player.log 找到完整首条堆栈：`HediffStatsUtility.SpecialDisplayStats → Hediff.TipStringExtra → Hediff_Addiction.TipStringExtra`；启动日志同时明确记录 `No RimWorld.StatDef named GlobalWorkSpeed ... (null stat)`。

根因是本批将工作速度 DefName 误写为 `GlobalWorkSpeed`，导致戒断档的 StatModifier.stat 为 null；普通档没有这个修饰，进入戒断并显示效果时才触发空引用。本机原版 `Stats_Pawns_WorkGeneral.xml` 定义的真实名称为 `WorkSpeedGlobal`，现已改正，倍率仍为 0.85，其他确认数值和机制不变。未新增空引用补丁、异常吞噬或显示层替代实现。

原版 DLL 的 `HediffStatsUtility.SpecialDisplayStats` 已确认会直接读取阶段修饰的 stat，因此只检查 XML 格式和自定义数值断言不足以发现这类错误。静态检查现额外对照本机 Core 与 RJW 源定义，核对四个实际属性引用：SexFrequency、SexSatisfaction、Vulnerability、WorkSpeedGlobal；没有运行代码回归，也没有重编 DLL。原始日志节选保存在 `.builds/pna-effects-step2/withdrawal-tooltip-fix/original-error.txt`。

修正后 397 份运行 XML 和四个属性引用核对通过，325 份语言镜像仍一致。已重新同步到本地测试目录，本次仅成瘾 XML 一份内容有变化；覆盖前备份 `.builds/pna-effects-step2/installed-backup-20261015-031101-67f5e77f`，安装摘要核对通过，DLL 保持第一步版本。

维护者已反馈“没有问题了”，确认上述悬停修正有效。随后要求将戒断的全局工作速度减益替换为操控能力 ×85%。
