## 1. 结果与实现边界

四档统一从当前有效身体状态读取XML倍率，已在原有RJW两处、动画Prefix一处、UAP两处写回桥中接入。默认2／4／8／16，允许XML使用合法小数或极大有限倍率；不硬编码最短等待，不增加第四档特殊循环。原计数写入完成后先发布不可变原始样本，再应用本模块补充，随后继续原有Orgasm调用及其第三方补丁。

计算采用 `x = carry + raw × (r - 1)`，取整数额外推进并最多抵达当前阈值，只保留同周期的小数余数。先比较饱和界限再乘，避免极值溢出；不保留跨周期整数超额，不按倍率／理论次数循环。原始量为零不凭空推进，原写回已经跨过阈值时不把计数抬回阈值。场景时长、原完成／中断、高潮计数、体液／经验／恶堕与原专用完成收益仍由原链负责。

`SSCOrgasmAdvanceRuntime` 将运行余数、已提交终态和每操作去重凭据归属于具体驱动／任务／周期。`SSCOrgasmProgressSampling` 另记已知补充终态，公共结果仍是原始写回前后值；后续消费者读取原始量不会看到倍率污染，也不会补采或再次加速。同tick的两次真实操作分别处理。

档位、有效倍率、身体／锁链／主人／训练Comp／人格token／SexProps或任务改变，以及未知原生计时改写、新周期、真实事件与清理，均使旧执行状态失效。普通UI／心情／脆弱度刷新、不改变有效档位的锁链阶段变化不清小数余数。主人仅死亡仍按既有有效锁链指令生效；身体选择继续只存原Hediff。

原始写入保持一次，位于SSC容错范围外，保留原异常；SSC失配只停本模块效果。未修改Organic Sexuality／MultipleOrgasm的高潮处理，也未新增可选Onahole计时适配或日常刺激框架。

## 2. 保存与恢复契约

`JobDriver_Sex.ExposeData` 附加深存节点 `sscOrgasmAdvanceState`，由 `SSCOrgasmAdvanceSaveState : IExposable` 序列化；运行时弱表只索引实例。仅合法、仍属已知终态且大于零的小数余数生成有效载荷。

| 格式1字段 | 用途 |
| --- | --- |
| `schemaVersion`、`carry` | 明确格式1；double有限且0≤carry<1，缺版本按0拒绝，缺节点按零 |
| `jobLoadId`、`driverType` | 原任务ID和实际驱动类型；不以同名JobDef代替 |
| `actor`、`body`、`chain`、`master` | 标准Scribe引用确认角色、身体记录、锁链和主人；本人／主人引用允许已死亡对象 |
| `level`、`multiplierBits` | 实际生效档位与float倍率位表示；只校验当前XML，不作为倍率来源 |
| `counter`、`threshold`、`startCounter`、`duration`、`orgasms`、`toilIndex` | 原周期最终计时、计数及Toil阶段，结合真实重设事实验证 |

不序列化原始样本、操作号、待应用命令、进程人格token或旧SexProps引用，也不从保存指纹反写原生计时／身体选择。保存前核对此前已知终态，不能用未知改写后的计时重新制作合法指纹。

LoadingVars时原驱动尚未绑定Pawn／Job，只保留待恢复节点；子节点的交叉引用和回调由标准Scribe独立调度，不递归调用子节点ExposeData。待恢复载荷与运行余数分开，构建期真实重设仅记录事实。

`JobDriver.SetupToils` 新增正常try离开锚点：实际枚举和Dispose均成功才标记；内部catch捕获异常后到达共享ret不算成功。外围Prefix／Finalizer按原调用帧记录成功／恢复候选，内层成功不能替外层失败作证明；空Toil列表、跳过原方法、加载期误推进或最终阶段不合法都拒绝旧余数。

SSC自我调教在既有快照恢复分支完整枚举结束、仍为当前有效任务时发出恢复候选；仍需外层成功及最终计时一致。普通驱动实际初始化新周期而未恢复原周期时，即使数字碰巧相同也丢弃旧余数，不恢复旧计数。

首次真实推进前或加载完成后的安全保存边界执行同一套身份／配置／周期校验，合法时绑定本进程新凭据，只接续小数余数；无旧操作重放。未推进即再次保存也可保留合法余数。载荷缺失、坏版本／非有限余数／引用或指纹失配均清零，当前新推进仍可按当前配置正常工作。
