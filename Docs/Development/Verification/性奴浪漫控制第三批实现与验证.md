## 1. 本批交付

第四阶段可从“行为限制 → 浪漫控制”选择执行者自己的求爱、求婚或分手／离婚命令，选择具体目标后预览，再提交一次性任务。有效命令覆盖执行者本次主动许可、仅主人规则和主动意愿；目标被动规则及普通接受判断继续独立适用。求婚仍要求当前 Lover，分手／离婚仍要求存在对应关系。没有新增永久指定目标或指定接受规则。

行为限制侧栏和详细窗口的编辑页均有“性行为控制”“浪漫控制”两个独立标题和边框，单一外层滚动。七项浪漫选择使用原有独立保存与提交接口，不加入通用能力字典；旧总开关不再隐藏整个侧栏。屏幕不足以容纳 260 像素侧栏时，入口打开复用双板块的详细窗口。

### 2.1 原请求与原任务

原菜单固定存档、Pawn、Comp、锁链、实际主人、人格 token、授权世代及目标人格。切换目标/行为保留原执行者凭据；提交后上下文已消费，不能通过再次派生目标上下文恢复。点击先校验旧上下文，再调用已有 `TryAuthorize`，登记必须早于调度，以支持同步启动。

`TryTakeOrderedJob` 的 true 不一定接纳了传入的新 Job；原版“已有相同任务”分支会直接返回 true。本模块检查确切原实例进入当前/队列，或已经同步产生终态。同步完成时窗口显示实际结果，不再宣称“互动尚待执行”。重复在途请求拒绝登记。

本构建 `UniqueIDsManager.GetNextID` 先返回当前值再递增，第一个合法 Job 编号为 **0**。记录缺失编号使用 -1，不能用 `> 0` 过滤真实第一项。`Job.Clone()` 会复制 loadID，运行时还必须比较原实例；加载后同编号对应多个不同 Job 时全部拒绝恢复。

### 2.2 授权与结算边界

只有实际当前原驱动领取的原 Job 能创建一次性调用票据。普通互动即使处于命令 Job 期间，也不获得豁免；嵌套 tracker 调用有独立帧，不能借用外层票据。当前记录、Job、驱动、目标、行为、人格和授权都必须相符。最终路径/策略查询可能触发外部回调，完成这些查询后再次核对目标人格与必要关系。

状态区分 Pending、Claimed、Executing、Completed、Cancelled、Failed、Indeterminate。Executing 在进入 tracker 前占用；通过原生交互条件后，在首次思想/经验前设置 `effectsStarted`。原生 worker、关系、记忆、床位、姓氏和信件仍由原版完成，Cleanup 不再结算。

`TryInteractWith == true` 只说明发生互动。求爱/求婚还记录实际接受 bool、worker 正常完成及期望关系；分手没有接受判定。拒婚附带分手仍记 Rejected，保留原 40% 比较。异常、外部跳过或结算结果不一致进入不可自动重放的 Unconfirmed，不通过再次调用“补成功”。实际异常继续交给原版错误处理，不吞掉其他模组异常。

关键 IL 适配失配或必要 Prefix/Postfix/Transpiler/Finalizer 被卸载时，命令明确停用。能力检查同时核对匹配标志和实际补丁记录；这不能证明其他模组改变方法语义后的全面兼容。

### 2.3 存读档与人格

命令组件只保存本存档记录；原 Job、驱动、队列和进度继续由原生 tracker 保存。既有完整 `FinalizeInit` 出口在角色/绑定恢复后对账，合法 Pending/Claimed 原 Job 才通过 `TryResume` 重建运行时授权。Executing、已结算或已取消请求不重放，旧阶段/同主重绑/同主换链/换主均不能恢复旧世代。

人格替换开始经 `InvalidatePersonality` 取消执行者和以旧目标人格为对象的请求；正常读档不调用该事件。目标普通偏好/主人变化按执行时当前规则处理。普通人格/凝胶仍只迁移偏好，新克隆仍恢复默认且不继承命令。结束记录在原 Job 离开当前及队列后按需清理，不持有无限历史。

## 3. 原版及 DLC 取证

游戏 **1.7.4985 rev1269**；Assembly-CSharp MVID `d368493b52bd4740bc7507c1b0386895`，SHA-256 `0be7a7ea4b3111d4430f45b36c234a5e43287880b0514b23915f2ef9a0629e16`。仍使用前两批同一本机 RJW 和游戏 Harmony 3。没有当前项目运行时 Def 快照，不把作者 XML 当成实际补丁合并结果。

- Ideology：原求婚公式有双方意愿判定。局部 Transpiler 只包装发起者对应的第一个 bool；目标意愿和原数值公式保留。未全局拦截 `DoerWillingToDo`，旧关系清理仍走原规则。

## 6. 第三批提交前复核（2026-10-24）

逐项对照规划的第四阶段覆盖边界、原任务/调用帧、持久状态、人格/绑定失效、双板块及窄屏实现，复核发现并修正四类问题：

| 问题 | 修正及回归 |
| --- | --- |
| 已取消/完成记录在全局失败条件中被当作继续，接近目标阶段仍可能沿旧路径移动 | 使用原生 `AddEndCondition` 返回明确终态；完成为 Succeeded，其余终态立即 Incompletable，不再执行后续接近 toil。验证实时换主/退阶/目标人格，以及真实 Scribe 恢复后的完成/取消任务；合法在途任务仍为 Ongoing |
| 原驱动领取后缓存记录，运行中 Job 目标或互动 Def 被替换时没有在接近阶段再次检查 | 每次核对当前驱动、原 Job 实例和原目标/行为；任务资格/路径查询回调后再次核对，防止原生接近 toil 读取被替换的目标 |
| 同一目标切换命令行为重新捕获目标人格 token，使旧预览可能获得目标新人格的凭据 | 同一 Pawn 的行为切换沿用原目标 token，只有选择不同目标才捕获对应凭据；三种行为均验证旧目标人格不能续权 |
| 恢复时终态绕过格式验证，缺状态或未知状态/版本可能保留 None 或假定 Completed | 终态同样验证版本、编号、请求及结果字段；异常记录进入 Indeterminate/Unconfirmed，保留版本和诊断原因，不重放，也不显示未翻译的 None 结果 |
