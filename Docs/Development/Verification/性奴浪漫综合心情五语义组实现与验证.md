记忆持有者由自己的列表隐含，键为“保存对象引用＋事件语义”。新增独立 `SSCRomanceSemanticGroup`，原 Short／Long 仅表示期限及保存载体。

| 语义组 | 对应事件 | 同对象上限 |

| 被动求爱回应 | E01、E03 | 1 |
| 受命求爱结果 | E06、E07 | 1 |
| 被动求婚回应 | E02、E04 | 1 |

真实新事件采用本次完整分支及期限，允许更弱、正负转换、跨短／长期载体；不再让旧负面或较强值阻挡新事件，也不继承旧剩余时长。同分支再次真实发生会重新开始本次期限；重复回调不刷新。

未知／缺失对象不能靠人物名字或当前主人补猜，恢复时不把多个丢失引用当作同一对象合并。仍能解析的已销毁原对象引用，在 SSC 人格历史恢复中保留，其他记忆仍走原有处理。

## 4. 准入、零值与实际提交

新非零记忆经原版准入后暂存候选，旧历史延后到后置回调结束才删除。请求中的待提交计划记录同组及阶段写集，最终重查原人格、Comp、心情／记忆处理器、冻结候选、历史集合及原版撤销证据。

所有可回调读取完成后，最终段只执行已经核对的原版逆向账本和 SSC 列表变更。失败时只移除本请求候选，不复活外部清掉的旧历史、不覆盖回调已完成的更新事件，也不向接管身体的新人格写回历史。

零值仍由事件确定语义组，执行同组结清及本次阶段清理，但不创建零值思想。合法零值与技术失败区分：定义／证据／人格失效不会伪装为结清，也不会吞掉原版反馈。两端各自提交，一端失败不阻止另一端合法结算。

实际回执包含事件顺序、语义组、期限分类、阶段、旧值与剩余期限，以及实际删除的分支及原因。新增／更新／刷新、零值结清、自然阶段清理与技术拒绝分别记录；“旧值更强而保留”不再属于正常新事件结果。

## 5. 关系阶段与自然事件

清理只依据完整互动正常结束及已确认最终关系，不按心情正负推断，不在任意关系增删、读档或人格重建时执行。

| 已确认结果 | 同对象 SSC 历史 |
| --- | --- |
| 求爱被拒 | 更新本次方向的求爱组，保留其他经历 |
| 求爱成功建立恋人 | 清理旧五组，保留本次非零求爱结果 |
| 拒婚但保留恋人关系 | 清理旧求爱两组，更新本次方向求婚组，保留另一方向求婚经历 |
| 求婚成功建立婚约 | 清理旧五组，保留本次非零求婚结果 |
| 关系结束 | 清理旧五组，只保留本次非零关系结束结果 |

受控方把阶段清理与本次记忆合并提交，非零准入失败不再降级走自然清理。没有本人受控事件的自然侧只清理旧 SSC，不获得受控心情、不撤销原版反馈；普通自然拒绝且关系未推进时不据此发新 SSC 记忆。

成功求爱的旧伴侣在副作用前捕获原对象／人格／载体，结算时只处理最终真实结束的旧关系，并按双方自己的列表清理。不追加命令分手心情，也不影响幸存旧伴侣或其他对象。

## 6. 保存、历史与人格边界

`OccurrenceOrder` 是可保存的真实事件顺序。独立游戏组件保存水位，同 Tick 也可区分先后；它不使用诊断编号、命令或人格 token。没有 Game 的隔离宿主使用独立测试运行期水位，不冒充游戏存档。

顺序在真实结果确认时分配，早于思想准入回调；双端同一真实事件共用发生顺序。回调内较新的事件不能被稍后返回的旧外层覆盖；正常零值及阶段清理也维护运行期顺序保护。

历史恢复按对象语义保留最新整条，不再比较强度或到期时间。相同顺序的副本只作稳定选择，不拼接分支与有效期；最新条目已经过期时，不复活更早但更长的条目。未知／损坏新格式保留最小保护，不伪造发生顺序或进行未发布旧版迁移。

普通保存、人格采集／加工／植入、凝胶复制及原生 CopyNeeds 保留分支、值、对象、顺序、年龄、实际期限及实例修正。恢复只观察已有顺序水位，不分配新顺序、不续期、不按当前人物重算，也不补做关系阶段清理。新克隆浪漫控制配置恢复默认，历史心情仍按既有复制边界保留；命令、授权及待结算不复制。

准入后置回调可以立即采集人格、复制身体或强制存档，候选暂时入列不能被视为完成获得。采集跳过未提交候选，原生复制传递仅供丢弃的临时标记并在收尾删除。强制存档只保存“本实例应丢弃”的布尔标记，读档收尾删除该实例，不保存或重放请求／计划／授权；既有已提交历史保持原年龄及期限。
