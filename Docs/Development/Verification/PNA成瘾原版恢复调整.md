## 核查与最终决定

维护者反馈 P2 大部分内容有效，希望成瘾尽可能复用原版。此前确认低负荷和戒断门槛确实生效，随后明确取消这两个额外条件，也取消“补给不重置恢复进度”保护，按照原版成瘾机制执行。

- 原版 `HediffComp_SeverityPerDay` 根据 XML 速率持续更新，不以负荷或戒断作为准入条件；原版健康更新与暂停规则决定是否调度。
- 原版 `CompDrug.PrePostIngested` 给已有成瘾增加物品配置的 `existingAddictionSeverityOffset`，默认 +0.1；之后按原版体型／耐受修正补充化学需求。一次摄入事件增加一次，不按摄入份数增加成瘾严重度。
- 原版 `Hediff_Addiction.LabelInBrackets` 显示 `(1-D)` 的已恢复百分比，D 是剩余依赖；普通档应无阶段标签。
- `Need_Chemical` 满足度 ≤1% 才是戒断，截图约 6% 属于渴望。这个区别决定戒断标签和 -18 心情，最终规则下不影响恢复。先前误读截图为 0% 的结论已纠正；只读存档的 0.0567000248 仅代表那个保存时点，没有修改存档。

证据来自本机 Assembly-CSharp.dll，MVID `61e4173561894da49d210260257b5097`：`CompProperties_Drug`、`CompDrug.PrePostIngested`、`Thing.Ingested`、原版严重度组件及成瘾／需求类。原版摄入顺序是 `PrePostIngested → outcomeDoers → PostIngested`。无运行时合并 Def 快照，不宣称第三方补丁排序已经验证。

## 最终实现

1. XML 使用原版 `HediffCompProperties_SeverityPerDay`，保留已确认 -0.125/日和原版恢复天数显示。删除专用恢复组件及项目引用，撤销恢复速率门槛补丁，共保留五个 PNA Harmony 目标。
2. 未成瘾的适配物品继续用满负荷首次建立依赖，避免未满随机成瘾；已有依赖直接放行原版药物入口，原版负责加深成瘾及需求补充。
3. 专用 Doer 仍计算实际摄入份数的身体剂量。若本次已有依赖已由原版成瘾品补充需求，共享输入不再重复补充；无缓存、历史事件表或另写服药算法。
4. 有效链保护、普通／性奴负荷同严重度转换、两档 ×1.25、戒断 -18、首次新需求设满和旧档合法值保留不变。枪械及普通侵蚀继续按已确认规则补充需求，不额外设计成瘾严重度增量。
5. 初始化仅将原组件已保存旧速率校正为当前 XML 值，保留 D 和已有满足度，旧满无依赖不补建。四语及源码镜像统一去掉恢复门槛文案。

完全断供后 D=1 约 8 个有效健康更新日解除，与身体负荷衰减并行。在现有 -0.125/日、原版默认 +0.1/次参数下，每日一次服药仍净下降约 0.025；每日两次约净增加 0.075（受 Def 上限限制）。无需额外设计“有摄入就暂停恢复”的规则。
