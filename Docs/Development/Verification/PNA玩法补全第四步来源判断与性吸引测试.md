## 游戏内测试步骤与预期

1. 完全退出后重启游戏，加载测试档。开启开发模式及 RJW 的 `DebugAttraction` 选项。准备两名适配的成人角色 A、B：A 非主人且无有效链，B 通过开发工具添加 `SSC_Purple_HyperLactation`（标签“催情纳米液产出(阴道)”）。选中 A，右键 B，进入 `Explain attraction A -> B`，注意不要选反方向。
2. A 没有 PNA 成瘾时分别打开 For Fucking、For Rape 和 General：都不出现“渴求 PNA 来源”条目，其他 RJW 评价保持。
3. 选中 A，使用既有 SSC 调试 `PNA P2: fill load (can create dependence)` 建立成瘾，再用 `PNA P1: clear load` 隔离负荷；确保其纳米流体渴望仍高于戒断线。重新打开 General、For Fucking、For Rape：三者的 Physical 中都出现本项 ×1.25。清负荷不清成瘾，不会妨碍该项。
4. 停止所有 PNA 输入并检查药物政策，等 A 的需求满足度 ≤1% 且健康栏显示戒断；也可用已有需求调试工具调至 0。每次重新打开解释：本项变为 ×1.50。补给解除戒断后回到 ×1.25；完全去除成瘾后条目消失。无须等待成瘾严重度发生大幅变化。
5. 移除 B 的产出状态后，本项消失；B 只有普通 PNA 负荷或成瘾时也不出现。重新加普通产出后恢复。不要求产出进度满，进度接近 0 时仍有效；反向 B -> A 不因 B 自己产出就自动获得偏好。
6. 将 A 绑定有效锁链：成瘾按既有规则清除，本项消失；切为主人也不出现。将 B 设为主人但保留普通产出，换回合法成瘾观察者后仍应被偏好；只有主人身份而无产出的 B 不构成来源。
7. 暂停游戏，记下 A 的负荷、成瘾、需求和 B 的生产进度，反复打开解释；数值不因查看而改变。检查每次只有一条本项；显示的乘数只作用一次。检查本条目即可，不要求总吸引分或最终选择概率恰好乘同样倍数；其他原生分项及最终处理仍生效。
8. 切换四语后重新打开解释，确认条目已翻译、参数完整，没有内部 key 或未替换的花括号；保存重载后效果一致。若已有兔分身历史测试档，其低效产出单独不应成为来源；不为此启用废弃入口。检查启动及操作日志无新增红字。

以上仅测试第四步吸引评价；本步性交不会额外调用新的 PNA 补给入口，来源实际接触与主人侵染留待后续开发。
