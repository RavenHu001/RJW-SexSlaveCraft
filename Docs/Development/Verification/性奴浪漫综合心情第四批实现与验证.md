## 1. 十四个持续分支

保留 `SSC_Romance_Control` 一个情境思想 Def，九个旧数值阶段改为十四个独立分支阶段。`SSCRomanceContinuousMood` 用显式稳定 ID 映射索引，复用目录 `TryResolveControl`；相同基准值不合并阶段或文案。没有事件、对象或好感条件，不保存另一份配置或持续状态。

| 状态 | 阶段 | 普通 | 有效受虐狂 |
| --- | --- | ---: | ---: |
| A | 二阶 | −3 | −1 |
| A | 三阶 | −1 | +1 |
| A | 四阶 | +1 | +3 |
| B | 三阶 | −2 | 0 |
| B | 四阶 | 0 | +2 |
| AB | 三阶 | −3 | −1 |
| AB | 四阶 | +2 | +4 |

A：二阶起，任一主动行为关闭，或者至少一种求爱／求婚可用时存在对象类别限制；B：三阶起，任一普通接受关闭或任一强制接受开启。三保证逻辑或只算一次 B，A/B 同时成立只取 AB。没有有效限制、一阶、无有效身份／绑定、死亡、空壳、人格写入或加载中不生效；命令能力本身没有持续奖励。零值 B 分支仍返回 Active，不套用零事件不生成记忆的规则。

`Thought_SituationalSSCRomanceControl` 从原生已缓存阶段取同一个分支的独立名称／描述，复用 `SSCRomanceMoodText`；不在三个显示 getter 中重新选择人物分支，不缓存翻译文本。标准情境思想继续负责原版准入、倍率及屏蔽，描述保留人物格式化、文化来源和屏蔽说明。十四阶段值或载体不匹配时只停用本持续思想，不猜一个合法阶段；不配置消失后生成记忆。

持续思想只表达当前控制状态，条件结束后消失；不写入短／长期历史、不续期已有事件。零值分支的原版列表显示仍由游戏 UI 决定，本专项验证其 Active 状态。

## 2. 有效特质与生命周期刷新

`SSCRomanceMoodRefresh` 弱引用缓存改为完整分支 ID，并比较原人格 token、训练 Comp、心情需求及情境处理器。同值不同文案仍失效，同分支换处理器也会清缓存；不扫描世界、不保存缓存或通知作用域。

本机原版 `HasTrait` 排除 `Suppressed`。`GainTrait`／`RemoveTrait` 已有通用思想失效，而 `RecalculateSuppression` 自身只写抑制状态。新增 `Harmony_SSCRomanceMoodTraits` 观察这三项，以及基因实际添加、移除、覆盖检查和 `Gene.OverrideBy`；同 Pawn 的嵌套通知归并至外层完成，再查询原版有效受虐狂。原方法成功、失败和异常均释放深度，异常不被观察器吞掉；旧 TraitSet 或旧人格回调不向新载体发布分支。

现有配置、链阶段、身份、换主、解绑、空壳及人格完成通知继续使用。人格写入开始先使旧情境缓存失效，写入中间不输出状态事件，完成后按最终状态协调。读档初始化明确标记 `LoadBaseline`；历史恢复不发新事件。

查询前后及缓存回调后复查原人格／组件／处理器；通知故障不提交成功签名，下一次通知仍能重试。特质查询期间回调换人格、组件、链或阶段，不发布旧查询分支。

外部模组不走这些入口、直接改任意原始字段时，不承诺即时通知；原版后续思想重算仍按当前有效状态查询。这不扩大为所有模组字段写入的追踪。

## 4. 控制台诊断

复用 SSC 总日志与详细日志开关，通过 `SSCLog.Verbose` 输出 `[SSC RomanceMood]`。详细日志默认关闭；打开后可在游戏开发日志与 Player.log 定位。正式玩家文案仍占位，没有新增玩家通知或第二条社交互动日志。

| 类型 | 内容与时点 |
| --- | --- |
| `control` | 有效分支选择发生变化才输出旧／新 ID、基准值、原因及 baseline；表示当前控制分支选择，不宣称通过原版准入后获得思想 |
| `event` | 每名受控本人一条，实际请求结束后输出事件、原始／最终接受结果、拒婚分手、规则、冻结阶段／特质／好感、分支值、组及标准／实际期限 |
| 合并字段 | 旧分支、旧基准值、旧剩余期限取实际组内 Winner 和合并回执；未进入合并时不猜一个 Winner |
| 原版字段 | 只有真实撤销成功才写 committed；按已封存操作记录 undoAdd／undoRenew／restoreCapacity，不用净差异或计划冒充执行 |
| `finish`／`attempt` | 确认完成、判定未变、普通自然互动、原人格失效、原生钩子不支持、worker 跳过／异常／不确定、未到 worker 和命令终态原因 |

同次真实互动两端共用运行期递增关联编号，分别记录各自结果。命令在寻路阶段取消也有运行期编号；编号及终态输出标志不保存、不参与授权、命令去重或重放。重复清理不重复输出终态。正常零值／较强历史挡住与技术失效区分，后者明确记录原版保留。

实际 `SSCRomanceMoodResult` 增加只读旧分支／剩余期限，Request 附加运行期退出原因，业务 Completed 仍完全沿原回执。日志只格式化已有冻结事实；不重新查询好感、不重捕人格、不抽随机、不重试准入。思想查询、UI、历史查看、每 Tick 不输出事件；没有分支变化的重复通知不输出 control。日志投递异常不改变已经完成的结算，也不覆盖原 worker 异常。

样例详见隔离目录 `DiagnosticSamples.log`：包含十三类事件、零值、准入未完成、原版续期／容量恢复、同值长期保留较晚期限及双方共享关联编号。
