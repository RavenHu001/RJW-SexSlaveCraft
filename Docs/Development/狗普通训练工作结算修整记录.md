# 狗普通训练工作结算修整记录

记录日期：2026-10-06。基线：`b2b72c6`，分支：`codex/cat-dog-specialization`。

## 问题与实现范围

此前 [动物训练补丁](../../Sexslavecraft/ThePatches/Harmony_DogSpecialization.cs)在原版 `JobDriver_Train.MakeNewToils` 末尾追加成长步骤，没有确认 `TrainAttempt` 是否实际发生。本机 RimWorld 1.6 的 `Toils_Interpersonal.TryTrain` 在动物未生成、未醒或 `TryInteractWith` 返回 `false` 时也可以正常返回，原追加步骤因而可能在没有实际训练互动时发奖。本轮依据源码与游戏程序集修整入口；尚未记录游戏内复现或验收。

本轮只修整普通动物训练的结算事实与时机。训练基础成长 `0.004`、驯服尝试基础成长 `0.006`、进度倍率 `1 + 当前有效进度 × 0.5`、完成容差及现有工作后事件参数沿用现值。己方动物终极训练分支及培养速度调整仍待开发。

## 结算流程与代码职责

- 删除 `JobDriver_Train.MakeNewToils` 末尾追加的发奖步骤，改为在原版 `Toils_Interpersonal.TryTrain` 工厂返回后包装其 `initAction`。原动作继续执行原版互动、成功率判定、动物训练进度及反馈。
- 同一个 `Pawn_InteractionsTracker.TryInteractWith` Postfix 分别处理 `TrainAttempt` 与 `TameAttempt`。`__result=true` 只代表互动实际发生，不代表动物已训练或驯服成功。Harmony 直接注入 tracker 的真实 `pawn` 字段，不再为每次驯服通知使用 `Traverse`。
- 每次训练动作执行时创建独立的同步作用域，记录动作开始时的发起者与目标。只有匹配双方且成功发生的 `TrainAttempt` 才认领该动作；重复观察同一动作仍只奖励一次，独立动作分别结算。
- 互动回调只记录事实，不提前发奖。原版动作正常返回后，先恢复外层作用域，再调用 [狗工作工具](../../Sexslavecraft/common/DogSpecializationUtility.cs)结算成长和现有低频事件。嵌套动作相互隔离；原动作抛异常时恢复作用域并不发奖。
- 驯服尝试继续沿用原有互动结束后的通知入口。狗终极技能调用 `DoRecruit`，不进入原版 `TryTrain` 包装，仍不增加普通工作成长或触发工作后事件。

原版训练在 `TryInteractWith(TrainAttempt)` 返回后才读取 `TrainAnimalChance` 并抽取随机值。若在该互动 Postfix 立即发奖，成长跨阶段可能改变同次成功率，事件抽签会提前消费随机数，事件任务还可能提前抢占工作。包装原动作收尾能保留原版这段计算和反馈的顺序。

## 对游戏行为的影响

1. 实际训练互动发生且原版动作正常结束时获得一次成长，随机训练失败仍属于有效尝试。动物睡眠、互动被拒绝、没有执行到训练动作或提前取消时不发成长，也不消耗工作后事件抽签冷却。
2. 原版训练结果在 `initAction` 内已结算，随后有 `100 tick` 的收尾等待。成长现在在实际训练结果产生后立即结算，比旧末尾追加步骤提前约 `100 tick`；此后取消收尾等待仍保留已经完成尝试的成长，工作后事件也可以在该时点启动。
3. 原版成功率与训练进度先完成，狗成长、阶段同步和事件随后发生。同一次训练不会使用刚获得的新阶段属性，也不会先为工作后事件抽签。
4. 现有公共资格继续保证只增长当前可培养的普通狗；普通完成、终极狗、跨方向及无效对象维持既有规则。终极狗仍可进入既有低频工作后事件，但不增长普通进度。
5. 未新增任务、存档或人格字段；同步作用域不跨 tick 保存，存读档不迁移该事实。原版动作后的 `100 tick` 等待期间存档已经包含本次成长，读档不再通过旧追加步骤补发。
