## 复核结论与改动

五项依旧分别读取人格字典、原缰绳、Comp 泌乳字段、子宫开发记录和凝胶外观组件。`ClearPersonalityState`／`RestorePreference` 只替换人格字典；采集与加工复制独立容器，植入的泌乳字段仍按来源 bool 覆盖，不建立第二保存源。

原生命周期行为没有发现需修改的生产执行逻辑。第三批对以下位置补充函数／关键代码块注释：`Comp_AbilityToggles`、`SSCAbilityToggleState`、人格 token 与作用域、加载协调器、健康／死亡／复活补丁、采集／植入及克隆边界。并更正原组件注释中“所有定义缺省关闭”的过度概括：缺键应回到各定义默认，默认 true 能力不能被统一强制关闭。

本批修正两处**验证接线**：

- `PersonalityTraits -p:SscUterusBoundary=true` 会启用 1.7 身体标签过滤，但原共享宿主也因此错误要求链接全部五类后端，改造后的该变体原先无法编译。共享 target 现声明 `SSC_ABILITY_TOGGLE_SCOPED_TEST`，模型宿主只注册明确链接的后端；生产 1.7 不定义该常量，仍注册全部五项。
- 原生局部 XML 在 DefOf 初始化后加载，泌乳后端所用 DefOf 引用原先未绑定。现在显式指向真实已加载泌乳 Def，避免以 null Def 夹具验证载体；身体和组件仍执行真实生产实现。

CultureNative／CosmeticNative 另复用第二批已有的 `SscAssemblyPath` 可选引用方式，整套机制验证共同加载本次隔离候选，避免各宿主的 ProjectReference 重建仓库正式 DLL。默认项目引用模式保留；统一发布检查没有新增跳过布局门禁的选项。
