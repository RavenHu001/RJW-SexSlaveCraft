## 实现复查

- 两条途径共用已确认的本人真实高潮事件、额度裁剪与恶堕需求写入。若同一事件符合两条途径，先结算凝胶，再复核传道的原参与资格及需求。单场额度只记入实际增加量。 [共同观察入口](../../../Sexslavecraft/common/SSCCorruptionGelSceneRuntime.cs) · [统一结算](../../../Sexslavecraft/common/SSCCorruptionGainUtility.cs)
- 各途径从独立 XML Def 读取数值。冷却按对象和途径保存绝对截止 tick，单场额度按对象的当前 RJW 任务和途径保存。换场只重置后者。同一 Job 更换驱动或同场读档沿用原累计。 [XML 配置](../../../1.7/Defs/SSCCorruptionGain.xml) · [冷却存档](../../../Sexslavecraft/common/Culture/SSCCulturePartnerCorruptionGameComponent.cs)
- 旧存档继续读取凝胶已发额度和传道冷却，新增记录从空值开始。修改配置并重启后，已有冷却继续按原截止 tick 到期。新上限低于已发额度时，本场余额为零。
