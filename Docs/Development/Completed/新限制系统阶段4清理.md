# 新限制系统阶段 4：前半清理

开发日期：2026-09-21。承接已提交并经过基础实机测试的阶段 3C。本批只做旧系统清理；后半界面完善等待维护者额外指导。版本号不变，未发布。维护者已授权提交本批清理；具体实机复测场景未逐项记录，不据此宣称全部场景均已验收。

## 清理范围

- 删除 `SSCSexInteractionPolicy` 及结果类型，移除生产项目和交互测试的编译引用。当前 `Harmony_ProtectSexSlave` 保留其补丁身份和实际接管职责，内部只调用统一限制守卫，不再存在旧算法或回退路径。
- 删除无运行作用的 `CompSSRapeCheck` / `CompProperties_SSRapeCheck` 及恶堕战衣 XML 中的旧组件声明。该组件没有自己的保存字段；战衣的 `SSCRestrictionEquipmentExtension` 保留，只强制“接受非主人强制行为”为禁止。实际主人直接通过仍由统一入口优先处理。根目录与源码内嵌 Def 副本同步。
- Mod 设置删除四项旧开关；ITab 删除“允许其他人调教或进行性交”。删除相应本地化键、旧保护模式提示和字符串入口，修正总开关及日常启停提示的过时含义。保留新规则编辑、测试入口及既有布局，不进行后半界面设计。
- 特化切换和人格特化恢复不再改写旧例外，克隆准备不再显式复制旧例外。公交车仅通过统一生命周期应用两项被动默认/强制值；新克隆继续由已有初始化入口建立独立配置。
- 绑定函数不再根据旧例外临时指定主人，移除随后恢复旧指派的 Harmony 前缀及状态参数；绑定完成只通知新系统协调。读档时也不再用旧字段提前覆盖指定者，等迁移和引用恢复完成后按新调教条目协调。

这些改动不扩展阶段 3C 之外的兼容范围；家具机器自身刺激和任意第三方独立驱动等仍不属于本轮新接管内容。身份、研究、身体、路径、预约、同床、工作排班及结算条件保持各自职责。

## 保留的数据及原因

| 数据 | 当前用途和读写边界 |
| --- | --- |
| 四项旧全局设置 | 移入限制设置 partial，缩为程序集内部字段；仅序列化和迁移捕获读取。模组设置跨存档共享，因此保存时继续保留原键和原值，避免之后打开另一份旧存档时丢失迁移输入。 |
| 旧个体例外 `allowOthersForTrainingOrSex` | 移入个体限制 partial，只在 `LoadingVars` 读取旧键，在 `PostLoadInit` 捕获迁移快照；新存档不再写此键。运行许可、关系和特化均不读写它。 |
| `legacyRestrictionInput` | 保留尚未成功迁移的角色输入。新档不写旧例外键后，延迟迁移仍能从此独立快照继续，不能提前删除。 |
| 存档级 `sscRestrictionLegacySettings` | 固定每个存档升级时的全局快照；离图或延迟恢复角色继续使用同一份值。 |
| 新配置、生命周期标记和任务开始凭据 | 按阶段 1—3 的约定继续保存。已有新配置优先，不因旧值不一致而重迁移；已开始场景仍正常收尾。 |
| `enableSexSlaveProtectionRules` | 名称沿用旧序列化键以保留用户总开关选择，现为统一系统的有效总开关，不是迁移专用数据。 |

移除 `AllowsOthersForTrainingOrSex` 旧公开属性；不保留可被旧调用方误当作运行许可的接口。旧“保护模式”也不恢复为新的训练模式。

## 验证

- 本机 RimWorld/RJW 依赖 Release 编译：零警告、零错误。
- 统一回归 **16 套、610/610**；InteractionProtection 104、RestrictionCore 110、TrainerIdentity 41、SharedBed 93，其余沿用阶段 3C 基线。报告：`.builds/restriction-stage4-cleanup/validation-final/summary.json`。
- 迁移新增回归覆盖：改变新默认并保存设置后再打开另一旧档；旧键缺失时的历史默认；已有新模板优先；关闭限制时保留旧档指定者，重新开启再按新条目协调。
- 扩展待迁移快照往返测试：新保存节点无旧个体例外键，快照中的开放值和公交车状态仍能恢复。
- 绑定回归直接执行生产绑定服务，确认第三方和空指派不再被旧字段覆盖；特化恢复回归确认旧例外不被方向切换写入。完整生命周期时序仍需实机复测，模型不等同于 Unity/Scribe 实际往返。
- 核对本机编译产物与游戏依赖的 **19 个补丁签名、14 个预约覆写入口**；旧策略、结果类型和装备标记类型均不再存在，旧字段 IL 访问仅限构造、序列化和迁移捕获。
- 全部修改 C# 文件的 **293 个函数**保留或补充中文 XML 注释；迁移数据保留原因、加载顺序、绑定协调及新克隆初始化边界另有说明。
- 扫描生产引用，旧字段仅出现在序列化/迁移范围；旧策略及旧装备组件无剩余项目或 Def 引用。核对本机已安装模组的 XML/源码，未发现其他模组引用被删除的装备组件。

## 本轮实机复测重点

1. Mod 设置不再出现四项旧保护开关，调教 ITab 不再出现个体开放例外；新规则右侧展开、测试入口及默认模板仍可使用。
2. 装备战衣的角色仍显示装备提供的强制来源；非主人请求按条目受限，实际主人请求仍直接通过。穿脱后保存值不被改写，旧服装实例能正常读档。
3. 已允许非主人调教的角色，在重复绑定、切换特化或保存读档后保留合法第三方指定者；禁止非主人调教且总开关开启时仍锁定实际主人。
4. 用升级前旧档检查个体例外和全局旧设置的一次性迁移，再保存重载；已有阶段 1—3 配置保持原值。总开关关闭时不提前改写指定者。

本批同步使用 `.builds/restriction-stage4-cleanup/Sync-LocalMod.ps1`：先核对目标模组标识，生成差异清单，备份替换文件，再校验复制后的哈希；实际结果保存在同目录 `sync-result.json`。
