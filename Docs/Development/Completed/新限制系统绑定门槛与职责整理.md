# 新限制系统绑定门槛与职责整理

日期：2026-09-21（本地时间）。基于 `968ab22` 的复盘实施，未发布；维护者已确认测试没有问题并授权提交。本轮按维护者确认修改绑定生效范围和指定调教员操作，同时落实已确认修复及局部职责整理。

## 行为修正

### 必须已有主人绑定才生效

`SSCRestrictionResolver.IsApplicable` 现在以实际绑定关系为启用门槛。只有性奴身份、指定了调教员、已有配置、特化或穿戴装备，均不会单独启用限制。

- 未绑定时不初始化新配置、不应用一次性特化默认；有历史配置或待迁移输入则保留。
- 首次实际绑定时初始化或迁移；解绑后暂停生效，重绑时沿用已有个人选择。
- 旧锁链关系仍可识别，不额外要求先修复成某个身份枚举。
- 未绑定对象不会因为自己的配置、装备或特化被限制，但与它互动的另一方若已经绑定，另一方的对应条目仍有效。
- 首次绑定准备仍检查合法候选、指定者及正常工作资格；这不是提前启用六项个人限制。
- 未绑定侧栏仅展示保留选择，不将装备/特化标为正在生效的强制来源。

未来科技赋予的启用条件应扩展这个集中入口，本轮没有擅自增加研究要求或科技开关。角色配置的保存和是否当前生效继续分离。

### 指定非主人调教员时同步授权

维护者确认被拦截的是调教员发起的普通互动，并选择“指定时同步授权调教，普通互动仍按原条目检查”。因此本轮没有把调教员变成第二个主人，也没有增加普通互动豁免。

菜单允许直接选择合格非主人。候选检查先在个人规则副本中把 `ReceiveTraining` 设为允许，再解析强制来源；只有有效值允许，才把个人规则和指定者一起提交。菜单中需要同步授权的候选附短提示，悬停说明调教授权范围。

装备或特化若强制禁止调教，指派失败且不修改任何个人选择。当前自带防护服只禁止接受非主人强制互动，不影响调教；此处也覆盖以后 XML 新增的调教强制条目。

自动日常仍只给当前有效指定者；具备调教员身份并不代表可任意接替。普通互动仍检查双方主动/被动规则；若调教员自己也是已绑定性奴，它自己的主动限制也适用。

总限制关闭时，有效配置仍保存这次明确授权；缺失或不支持的配置原样保留，只更新指定者，不能借坏配置重新制造指派禁令。重新开启后的损坏数据处理继续遵守统一校验。

### 已确认问题修复

- 协调指定者时不再把刚清除的死亡/销毁主人重新写回；所有权和许可规则保留。
- 人格恢复作用域内解绑仍能按原约定清除原主指派；所有权清理直接写引用，不经过玩家编辑锁。已有第三方指派及 `clearAssignedTrainer=false` 的保留语义不变。
- 开发只读预览更名并删除“实际任务仍使用旧规则”的过时提示。
- 详细日志先检查 `SSCLog.VerboseEnabled`，关闭时不拼接高频诊断字符串。不声称已测得帧率改善。

## 特化与装备如何长期保存

目前已经是 **XML 定义 + 角色存档 + 运行时解析**，不需要再迁成另一套配置格式。

| 内容 | 位置 | 生效方式 |
| --- | --- | --- |
| 特化默认及强制条目 | `Defs/SSCRestrictionProfiles.xml` 中的 `SSCRestrictionProfileDef` | 启动时由游戏加载为 Def；根据当前特化/有效状态匹配 |
| 装备强制条目 | 对应 ThingDef 的 `SSCRestrictionEquipmentExtension`，如 `Defs/ThingsDefs/SexSlave_EvilFallOutfit.xml` | 查询时从当前穿戴装备读取扩展 |
| 个人六项选择、版本、对象偏好、一次性默认标记 | Pawn 的 `sscRestrictionConfig` 存档数据 | 随角色保存/恢复，独立于 XML 强制结果 |
| 全局模板与开关 | Mod 设置存档 | 模板在初始化时复制；全局开关实时决定是否启用相应强制层 |

公交车定义示意（当前文件即采用这种结构）：

```xml
<SexSlaveCraft.SSCRestrictionProfileDef>
  <defName>SSC_Restriction_Bus</defName>
  <specialization>Bus</specialization>
  <defaults>
    <receiveConsensual>Allow</receiveConsensual>
    <receiveForced>Allow</receiveForced>
  </defaults>
  <forced>
    <receiveConsensual>Allow</receiveConsensual>
    <receiveForced>Allow</receiveForced>
  </forced>
</SexSlaveCraft.SSCRestrictionProfileDef>
```

`defaults` 在规定的初始化/首次取得/显式重置事件写入个人选择；`forced` 每次解析当前有效值，不写回个人选择。装备只有 `forced`，现有防护服声明 `receiveForced = Deny`。

未声明条目表示不覆盖。正常覆盖优先级仍是装备 > 已启用特化强制 > 个人保存；同层取较严格值。实际主人向其绑定对象发起时仍在 Policy 中整次直接允许。

XML 内容随模组文件长期保存，加载后的定义由代码使用，不会每次查询重新读磁盘。修改 XML 后应重新启动游戏加载定义；更改强制值会影响符合条件的后续请求，但修改默认值不会追溯覆盖已有角色。当前后续首次取得默认专门支持公交车；将来增加其他特化的取得默认，需要相应生命周期支持，不能仅加 XML 就假定全部事件已接入。

根目录和 `Sexslavecraft` 内的打包副本仍保持一致，本轮没有修改现有装备/特化实际许可值。

## 代码职责整理

| 部分 | 本轮结果 |
| --- | --- |
| `SSCRestrictionConfigurationBuilder`（新增） | 从模板/特化构造独立候选；成功或失败都不改输入配置。Lifecycle 决定最后提交 |
| `SSCRestrictionResolver` | 保留只读有效值解析及可共享的匹配/同层合成逻辑；移出配置构建与写入 |
| `SSCRestrictionTrainerAssignment`（新增） | 只读预检和原子指派授权，个人许可与指定者同步提交 |
| `SSCTrainingAdmission` | 明确整体工作准入、Policy 许可、工作失败枚举；原因文字按需生成。删除旧多 out 参数接口 |
| `SSCRestrictionJobPreparation`（新增） | 管理本请求准备 Job 的编号、保存及精确清理 |
| `SSCRestrictionJobEvents`（新增） | 候选 Job 到运行驱动的交接，以及实际开始后的一次性通知 |
| `SSCRestrictionJobGuard` | 保留检查时机、场景开始凭据、拒绝与旧场景恢复，委托准备/事件职责 |
| `SSCRestrictionCompatibilityDiagnostics`（新增） | 可选类型缺席安静；存在但继承/方法签名不匹配一次性诊断；Lovin 回调布局异常提示 |
| `SSCBondUtility` | 绑定完成后显式 Notify，明确指派入口显式授权；删除相应 Bind/Assign Harmony 接线 |
| `WorkGiver_Training` | 候选枚举只读粗筛；HasJob 检查不再创建临时 Job，实际 Job 创建前仍重检 |
| `TrainerAssignmentUtility` / `TrainingJobUtility` | 用命名明确完整准备中的状态修复与兼容迁移，保留必要 LifeForce 冲突处理 |

原任务状态保存键、枚举值、准备归属、Job/loadID 校验、事件通知去重和已开始场景的收尾边界没有改变。两个新职责对象仍在原序列化层级写既有键，不要求升级任务存档结构。

本次只将绑定与指派这两个自有事务改为显式调用；其他必要 Hook 继续存在。建立锁链的 Hook 仍可能在绑定内部较早通知，当前流程幂等且不依赖缰绳，不声称将全部通知改成了一次事务提交。

没有引入跨 tick 许可缓存或通用事件框架；没有为了减少重复校验而削弱公开入口对坏数据的检查。交易和宠物的概率、成长、冷却、特有等待流程仍留在各自业务入口，共同事件交接已收拢。
