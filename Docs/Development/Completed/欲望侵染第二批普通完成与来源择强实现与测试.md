## 关键实现与生命周期

`SSCDesireInfestationUtility` 处理侵染准入及恶堕。`SSCOrdinarySexOutcomeUtility.Context` 只在单次完成调用中存在：捕获参与者、原组件／身份、人格 token、恶堕需求和两个方向的资格，适配器提供 Job 归属检查、持久化认领和临时占用释放。上下文自身也封住分发重入，不进入 Pawn／凝胶存档。

普通 RJW 在现有 `SSCTrainerInitiatedSexProgressHook` 增加 Prefix／Finalizer，前后共用只读完成候选校验；仍保存 `sscTrainerSexProgressClaimed`。原方法被跳过或异常不提前认领；正常返回后先消费原场认领，再检查人格有效性，防止换人格后重放旧场。合法普通奖励先走既有训导官入口，再逐方向结算。原结算、奖励、PNA 和恶堕回调后均复查原归属。

Lovin 复用当前配对及旧档恢复，新增 `sscLovinOutcomeClaimed`；只有原发起端真正开始、原配对和任务编号匹配、倒计时结束且 Cleanup 成功才能认领。健康／人格快照先于 RJW Cleanup 前缀取得，使用 `[HarmonyBefore("rjw")]` 和高优先级。`isCoreLovin` 不从普通完成入口领取；RJW override 替换后的旧 Lovin 也不能补发。接收端不认领，两端状态一起标记已处理。

普通／Lovin 的临时占用均由 Finalizer 释放，不吞掉原异常。运行时 token 不存档；进行中的任务加载后，到真正完成时重新捕获恢复后的当前人格，不新增整场持续开启或时长累计要求。

PNA 保留原四参数输入 API，增加带 `continuationGuard` 的重载；普通产出者原两参数 API 同样保留。核心不反查 Job 或主人偏好，调用方提供只读继续条件。健康协调、负荷写入、成瘾及需求重建等回调边界失效时，停止余下写入；已合法输入的身体负荷不回滚，也不回退再发一次弱来源。PNA 单分量没有效果而侵染整体仍有效时，恶堕独立结算。

## 原实机测试顺序与预期

以下保留交付时的复测清单，不将每一项分别补记为专项测试通过：

建议使用测试存档并暂停观察，先选没有普通 PNA 产出能力的主人，目标为有恶堕需求的非主人；这样容易区分侵染和既有补给。PNA 会自然衰减，尽量比较同一次完整行为前后。

1. **基础与双向。** 开启侵染，分别让主人作为发起方和接受方完成普通 RJW 行为。目标负荷应增加约 8 个百分点（原始严重度 +0.16），恶堕额外 +1 个百分点；未绑定对象通常最容易隔离观察。多次高潮不应按高潮次数重复发这一整场收益。
2. **需求与已有成瘾。** 将目标已有成瘾严重度设为 0.40、需求设为 20%。负荷 20% 时完成应约为 28%、成瘾 0.42、需求满；负荷 90% 时完成约为 98%、成瘾 0.62。成瘾已经 1 时会受上限限制；原版括号可能显示恢复进度，观察时不要把它当成成瘾严重度。未成瘾且负荷未满不应提前创建成瘾。
3. **恶堕上限与链保护。** 新评分无链目标在 11.5% 恶堕时，本项最多补至 12%，后续仍可输入 PNA。有效链对象走正面保护负荷、不建立普通成瘾，同时保留合法恶堕增量；检查原绑定主人不变。
4. **来源择强与关闭。** 主人兼有普通产出能力时，开启仍只输入 8%，不能变成 10%；关闭后，普通 RJW 只剩原普通产出者的 2%／需求 +10%。没有普通产出能力的主人关闭后不再施加本项收益。双方都是主人时整套侵染豁免。
5. **原版 Lovin 与替换。** 关闭 RJW 的 Lovin 替换设置，实际完成原版 Lovin，检查与普通侵染相同的 8% 输入；接收端收尾不应再加一次。只具有普通产出能力而未开启侵染时，原版 Lovin 无新增补给。重新启用替换后，确认普通 RJW 分支仍只发一次。
6. **中断与专用任务。** 行走／准备或行为中途取消，不应产生本项完整侵染；日常调教、仪式、自我调教和人格排泄不额外发本项 8%。这些流程原来自己的收益保持，不能把其原收益误当作侵染。
7. **存档与人格回归。** 进行中保存并读档，正常完成后只领取一次；完成后再存读档不补发。沿用第一批已测开关、人格凝胶和身份启停，检查没有新红字或重复标记。
8. **来源偏好。** 用有普通成瘾的观察者查看 RJW 对象吸引解释，纯侵染主人开启时应出现原来源项；正常／戒断分别 ×1.25／×1.50。关闭后纯侵染来源项消失，兼有普通产出能力时仍保留来源项，双来源不叠乘。

反馈时说明普通 RJW／原版 Lovin／替换模式、主人在哪一端、双方身份与链归属、开启状态，以及行为前后的负荷／成瘾严重度／需求／恶堕。遇到红字请保留 Player.log；本批暂不要求验证第三／四批尚未接入的部位与记忆收益。
