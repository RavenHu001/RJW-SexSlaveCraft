## 实现变化

| 热点 | 改动前 | 当前实现 |
| --- | --- | --- |
| 飞船定位 | 每个尚未解析位置的关联角色各扫一次成员与货物 | 一次查询先收集位置请求，再对每船最多做一次成员／货物索引；不在逐行定位中枚举飞船 |
| 地图容器 | AllPawns 递归地图持有树，尸体补充再次递归 | 独立读取已生成 Pawn／Corpse，再对持有树同时筛选 Pawn 与 Corpse；地图、世界、飞船共享持有者去重表 |
| 普通容器货物 | 引擎递归临时列表与概览候选副本形成中间集合 | 使用 IThingHolder 的直接内容及子持有者接口，边访问边筛选，不复制整批普通货物 |
| 世界候选 | 完整角色快照、候选列表和多份 HashSet | 流式消费原版集合，只保存实际匹配的 Pawn／锁链；完整候选去重表清空后复用 |
| 行位置路径 | 每名离图对象新建两份 HashSet | 查询内共用循环检测集合，位置请求字典只含关联角色、位置主体及祖先 |
| 快照列表 | 再复制一次已经构建的行引用列表 | 查询器转移新列表的所有权并加只读包装；空快照共用只读空数组 |

核心入口仍为 [Build](../../../Sexslavecraft/common/SSCBondOverviewUtility.cs) 和原有 IsCurrent。位置描述、归属、阶段、指定调教员、排序和计数契约保持；GetBoundSlaves、绑定维护、社会奖励及身份流程未改动。

飞船内容有两个不同职责的线性访问：一次用于发现候选，存在待解析位置时再一次用于建立稀疏位置索引。因此物品访问上限由每行重复的 O(R×T) 降为本次查询 O(T)，不是宣称总共只访问每件货物一次。已在地图／世界持有树中确定位置或没有关系时，不做第二次飞船索引。

## 临时缓冲与只读边界

[World 查询上下文](../../../Sexslavecraft/common/SSCBondOverviewWorld.cs)通过 Rent／Dispose 使用缓冲，每线程最多保留一个已经清空的上下文。它只复用容器容量，不跨查询保存候选、绑定或游戏对象；using 确保成功与异常退出均清空集合引用。超出 65536 项／容量阈值的集合放弃保留，该阈值不是精确的字节上限。

缓存只涉及空的临时集合，快照仍由调用者持有，不能长期静态保存。这里没有保存归属索引、Game 缓存、Scribe 或人格存储，也没有把地图／世界 API 移到后台线程。第二批仍必须控制 Build 的频率，并在关闭视图和切换存档时释放快照。

首次查询或容量增长仍会分配，性能表反映预热后的稳态。全体候选仍要查锁链，成本仍随世界人数、Hediff 数量及容器内容增长；本批没有声称完整查询变成常数时间。

## 回归结果

BondRelations 在原有 94 项上新增 **16 项**，当前 **110/110 通过**。保留原来两种方向、坏链、漏项／陈旧索引、死亡／复活、外部改绑、CE 删除、同主新链、只读、加载和跨存档用例，新增验证：

- 独立世界存活／死亡、临时存活／死亡、运输成员及反向独占来源的并集；多来源重复不重复成行。
- 地图一次遍历发现活体和嵌套尸体，地图／世界／飞船重叠的持有者只读取一次；独立组件子持有者也可达。
- 200 名未解析离图角色与 20000 条货物，货物合计访问 40000 次，而非按行扫描；地图行和空关系列表只做候选收集的那一次货物遍历。
- 只有飞船成员、普通 ThingComp parent、不同祖先命中不同飞船时的优先级、位置变化后重建索引。
- 只读空快照、成功与异常退出后的 Pawn 弱引用回收，防止复用缓冲保留旧对象。

首次扩展回归为 108/110：复用后已存在但为空的请求字典导致地图行／空关系仍多做一次索引。已补充 Count==0 门槛，最终 110/110；未将这两项初次失败记录为通过。

只读断言继续对照健康对象及顺序、严重度、锁链 target、缰绳列表引用及顺序、身份、指定者、特化、社交关系／缓存通知及承伤偏好。测试仍有引擎替身边界，不证明真实存档或第三方容器已经实机验收。

## 同机性能对比

比较脚本从 Git 提取 `d8b354d` 的三个概览生产文件，与当前文件分别构建。两侧共用同一套引擎边界和同一份基准程序，Hediff 查找边界已按实际引擎改为不分配闭包的线性查找；原版递归器的替身复用临时缓冲。没有拿前一次不同边界的采样数值直接比较。

使用 .NET SDK **9.0.308**、net9 模型，每版本交替执行 3 轮；每场景预热 16 次后采样 31 次，表内耗时为三轮中位数的中位数，分配为当前线程每次查询分配的中位数。七场景共 21 组前后配对的候选数量、顺序及状态摘要全部一致。该实验是生产查询加模型边界，**不代表目标 1.7 实机耗时、FPS 或 TPS**。

| 场景 | 优化前 ms | 优化后 ms | 优化前分配 B | 优化后分配 B |
| --- | ---: | ---: | ---: | ---: |
| 100 候选、8 名地图关联角色 | 0.0201 | 0.0076 | 21488 | 2496 |
| 10000 候选、各 30 个 Hediff、8 名关联角色 | 3.1226 | 2.4997 | 1748832 | 2496 |
| 10000 候选、各 30 个 Hediff、无关联角色 | 2.2529 | 1.2809 | 1587048 | 336 |
| 200 名未解析离图关联角色、无货物 | 0.1412 | 0.0906 | 138216 | 42456 |
| 同上，增加 20000 条飞船货物 | 47.3357 | 0.7947 | 349808 | 42776 |
| 200 名地图关联角色、20000 条飞船货物 | 0.4756 | 0.4193 | 239096 | 42952 |
| 200 个地图容器、10000 条普通内容、200 名关联角色 | 0.8470 | 0.5432 | 169336 | 58760 |

结构计数更直接说明热点变化：离图压力场景的飞船物品访问从 **4020000 → 40000**；容器场景的地图遍历 **2 → 1**、持有者读取 **800 → 400**。模型中的计时与分配受替身实现、JIT、缓冲预热和机器状态影响，不能换算为玩家存档的固定收益。

可复现入口见 [compare_overview_performance.py](../../../Tests/BondRelations/compare_overview_performance.py) 与 [基准程序](../../../Tests/BondRelations/BondOverviewBenchmark.cs)。原始三轮输出、构建日志、当前生产文件与边界文件 SHA-256、完整基线提交和汇总保存在 `.builds/bond-overview-opt/performance/`；复跑会重建两侧并检查摘要一致性，不修改生产文件。
