## 实现与取舍

| 改动 | 现行行为 | 边界 |
| --- | --- | --- |
| 可见行文字 | 展示对象只预生成标题、计数和调教员文字；窗口可见行、主人文字或卡片悬停时才生成该行姓名与详情 | 每份展示最多缓存 64 行，FIFO 淘汰；完整只读快照、候选、排序及计数保留 |
| 截断缓存 | 以全文、宽度、`Text.Font`、`Prefs.UIScale` 共同索引原版截断结果 | 每个视图最多 256 项；更换快照、语言、地图、来源及释放视图时废弃，不长期积累所有滚动行或尺寸 |
| 翻译模板 | 最多缓存 128 个概览模板，语言对象改变时废弃 | 只持有字符串和语言，不持有 Pawn、Game 或窗口；行提示保留未截断全文 |
| 统一刷新预算 | 自动、手动、旧行、换来源、换地图、重新打开都由同一 Update 排队 | 完成后全会话至少间隔 2 秒，预算为 `min(30, max(2, 10 × 查询耗时))`；空卡片自身仍至少间隔 5 秒 |

[视图与文字](../../../Sexslavecraft/UI/SSCBondOverviewWidgets.cs)、[卡片](../../../Sexslavecraft/UI/Gizmo_SSCBondOverview.cs)、[窗口](../../../Sexslavecraft/UI/Dialog_SSCBondOverview.cs)及[会话](../../../Sexslavecraft/common/SSCBondOverviewSession.cs)补齐缓存键、容量、惰性生成、释放与共享预算的代码块注释。缓存命中不更新链表，避免为热路径增加节点分配。卡片与窗口同源共享展示缓存，宽度不同仍分别命中；两份异源视图最多各保留一组有界缓存。

原版 `GenText.Truncate(string,float,Dictionary<string,string>)` 的可选字典只按文字索引，不能直接跨宽度复用。本轮复核本机 Assembly-CSharp 的逐字缩短逻辑，以及 `Prefs.UIScale` 的实际属性；缺失时继续调用原版截断，不改变省略结果。缓存不拥有原版肖像纹理，不调用 SetDirty，也不替换肖像参数。

统一预算会增加快速换来源、打开异源窗口或手动刷新的等待：快查询至少等到全会话的 2 秒截止，两个持续活跃来源轮换时各约 4 秒；空结果自身 5 秒，慢查询预算最多 30 秒。显示等待期间，新来源不会借用旧来源快照；旧关系仍逐行复查，实际点击仍走原导航重新解析当前位置，不能绕过改绑／死亡／换船检查。无使用者时停止查询，关闭重开不清空会话预算，时钟回退仍重设截止时间，不补跑周期。

预算测量完整查询耗时；原版字体测量、肖像生成及 GPU 绘制没有计入该耗时。惰性文字与可见行裁剪限制每次冷绘制的工作量，但不把同步查询拆帧，也不能消除首次可见长文字的截断成本。

## 同机前后对比

可复现入口为 [Compare.py](../../../Tests/BondOverviewUI/Performance/Compare.py)，驱动为 [PerfEntry.cs.txt](../../../Tests/BondOverviewUI/Performance/PerfEntry.cs.txt)。隔离导出基线生产源码，对照当前生产源码；两侧使用逐字节相同的替身、计数器及复位入口。使用 SDK **9.0.308** / net9 运行模型，三轮交替先后顺序，每项预热 16 次、31 次取中位数；冷项每次更换展示代次，热项重复同一视区。实际发布 DLL 的 net10 编译单独验证。

下表为每次调用的托管分配量，三轮一致时记单值；仅模型边界，不包含原版字体、原版肖像或 GPU 的内部分配。

| --- | ---: | ---: |
| 无使用者 Update | 0 B | 0 B |
| 冷展示，10 / 500 / 5,000 条 | 7,032 / 304,952 / 3,040,960 B | 656 / 656 / 672 B |
| 冷卡片，500 / 5,000 条 | 305,752 / 3,042,104 B | 1,848 / 2,208 B |
| 冷窗口，10 / 500 / 5,000 条 | 7,808 / 305,728 / 3,042,256 B | 5,896 / 5,896 / 5,912 B |
| 热窗口，任一上述人数 | 776 B | 0 B |
| 热卡片，10 / 500 / 5,000 条 | 72 / 800 / 1,144 B | 0 / 0 / 0 B |
| 500 条、160 字符长姓名，冷窗口 | 590,896 B | 291,064 B |
| 同一长姓名视区，热窗口 | 285,944 B | 0 B |
| 地图导航 / 20,000 货物飞船导航 | 56 / 184 B | 56 / 184 B |

普通窗口热测 31×64 次事件，原版形状的截断调用从 **33,728 次降至 0**；长姓名窗口 31×32 次从 **16,864 次降至 0**。两侧窗口都保持每次 6 个可见肖像，卡片保持 5 个；GUI 事件均零新增地图查询。5,000 条冷窗口分配约减少 **99.81%**，长姓名冷窗口仍有约 291 KB 首次截断分配，后续相同上下文复用结果。

CPU 耗时存在明确取舍：最终三轮长姓名热窗口模型中位数由 **0.0384–0.0454 ms** 降至 **0.00383–0.00395 ms**，5,000 条冷窗口由 **1.233–1.495 ms** 降至 **0.0111–0.0314 ms**。短文字热窗口则由约 **0.00077–0.00247 ms** 增至 **0.00323–0.00470 ms**，10 条冷窗口由约 **0.0083–0.0092 ms** 增至 **0.0109–0.0115 ms**：有界字典查找多花少量时间，换取重复事件零文字分配。计时受 JIT、调度及同时进行的全量回归影响；模型以固定字符宽度代替真实 Text.CalcSize，不能据此预测实际字体性能。导航生产代码完全相同，其计时波动也不解释为导航变化。

| 5 秒受控时钟场景 | 基线查询次数 | 优化后 |
| --- | ---: | ---: |
| 正常自动刷新 | 3 | 3 |
| 每轮手动请求 | 20 | 3 |
| 每轮切换来源 | 20 | 3 |
| 查询耗时 0.5 秒、持续手动 | 7 | 1 |
| 查询耗时 0.5 秒、持续换来源 | 7 | 1 |

次数包含首次查询；循环按完成后推进 0.01 秒，耗时也推进时钟，因此不同于固定帧端点的简单除法。回归另以固定 0.01 秒帧验证连续触发在 0–5 秒恰为 3 次。查询内容保持不变，降低的是允许查询的频率，未缩减货物、容器或反向漏项候选。
