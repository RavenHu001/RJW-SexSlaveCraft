日期：2026-10-25；仅 1.7。维护者已实机确认无问题，本轮验收关闭；提交前复核完成，按要求未重跑回归。前期主体与布局验收见[完成记录](../Completed/性奴浪漫控制主体与三项修正实机验收.md)，不覆盖本次机制扩展。

## 需求与方向

维护者明确：“都是单个性奴侧的，且影响的都是目前这个性奴”，并确认控制 A 向其他性奴发起，以及 A 接受其他性奴。按[现行规划](../../Design/性奴浪漫行为控制开发规划.md#13-同伴身份控制扩展2026-10-25已实现未验证同步)，一阶无自身控制，二阶主动，三阶被动，四阶精准命令；等级以当前锁链阶段为准。

| 配置 | 默认 | 阶段／作用 |
| --- | --- | --- |
| allowInitiateToSexSlave | true | 二阶；关闭阻止本人向 SSC 性奴求爱／求婚 |
| alwaysAcceptSexSlave | false | 三阶；开启保证本人接受其他 SSC 性奴的求爱／求婚 |
| initiateOnlyMaster（原有） | false | 从三阶提前到二阶，仍只筛选求爱／求婚目标 |
| alwaysAcceptMaster（原有） | false | 保留三阶被动归属 |

新增两项默认值采用兼容既有行为的实现选择，不记为独立实机结果。对方身份由 SSCIdentityUtility.IsSexSlave 判断，不检查同主或同阵营，不把原版奴隶身份当成 SSC 性奴。受控本人仍需通过原 Resolver 的人格、有效绑定和阶段资格；对方参与互动仍受原执行条件约束。

## 实现及边界

Config 追加两项字段与枚举值，旧枚举编号及版本 1 保留；Scribe 缺字段按默认值读取，IsDefault 包含新增值，Copy 的标量副本自然携带。普通人格迁移、清源、覆盖和新克隆初始化继续复用原流程，不添加第二份保存源或通用能力字典键。新克隆清配置后回默认；降阶仅暂停，保留原选择。

Resolver 改为按设置显式返回二／三阶，不再依赖枚举排列。Policy 统一接入自然、手动及命令入口：主动许可先于仅主人及性奴目标筛选，开启目标许可不重新开放其他禁止；真实有效四阶授权仍只为本次命令覆盖执行者限制。被动主人保证及性奴保证都优先于本人的普通被动禁止，但不能解除另一方主动禁止。分手／离婚不读取新增两项。

没有新增 Harmony 锚点或更改原版概率／随机取样：实际接受 bool、原版关系结算、菜单资格及消息去重继续复用既有适配。UI 保留固定单列和已验收居中横线样式，主动五项、被动四项，新增两项独立悬停说明。四语各新增五键，运行资源与源码镜像一致。
