# 训导官特化复盘修复

日期：2026-09-25。复盘基线：`70754e1`。

状态：本轮修复及自动验证完成，维护者于 2026-09-25 复测后反馈未发现问题，并授权提交；尚未正式发布。阶段 1—5 主体及前两项附带缺陷此前已获维护者实机确认。

## 1. 终极化配方的消耗边界

原先的第二次资格检查放在 `Recipe_PSTagWorker.Notify_IterationCompleted`。本机 RimWorld 1.6 的最终制作步骤先计算并消耗原料，再通知账单完成；生产账单还会在调用配方工作者前扣减重复次数。因此，仅在工作者中返回会造成“无产物，但凝胶和账单次数已经消耗”。

新增 `Harmony_TrainerRecipeCompletion`，包装 `Toils_Recipe.FinishRecipeAndStartStoringProduct` 返回步骤的 `initAction`。步骤实际运行时读取当前 Job，在原动作开始前检查训导官终极配方：

- 普通来源读取 `placedThings`；半成品来源按原版顺序优先读取 Target C 的原料容器。
- 必须有且仅有一个人格凝胶，使用数量和实体堆叠数均为 1，数据满足普通完成条件，并可映射到加工产物。
- 缺失、失效、重复和异常堆叠来源结束当前 Job，保留材料、半成品和账单次数；正常原料执行完整原版动作。
- 配方工作者保留输出前的最终资格检查，但它不承担消费回滚职责。

保护仅针对训导官终极配方。模型按核对过的原版顺序执行消费和账单计数，覆盖加工期间资格变化、缺失来源、异常数量、额外凝胶、半成品优先、正常产物及其他配方。当前 XML 限制凝胶单件，实体堆叠检查用于阻止异常输入分堆后丢失人格数据。

## 2. 完成阈值与只读查询

- 新增共享常量 `CompSexSlaveTraining.SpecializationCompletionProgress = 0.999f`，训导官状态显示与终极化配方使用同一容差。公交车、奶牛和宠物原有 `0.999f` 判断改为引用同一常量，数值不变。
- 用实际单精度累计验证 `0.2 + 32 × 0.025`、`100 × 0.01` 以及阈值两侧，避免数值显示 100% 却仍显示基础解锁。
- 一次持续资格查询共用同一个锁链引用，绑定和阶段不用重复扫描；阶段边界仍集中在身份工具。引用不跨帧缓存。
- 身份区本次绘制只读取一次任职资格，复用到标签、提示和按钮可用状态；点击提交仍经过正式资格入口。

上述优化减少已知重复读取，未新增全图轮询。没有进行 Tick 或帧耗时测量，因此不声明具体性能提升比例。

## 3. 界面与翻译

- 身份区按实际 Small 字体、文字宽度及复选框占位测量高度，滚动范围与绘制共用结果。限定单列，长译文换行后下方接收状态仍留在当前栏。
- 保留失格时保存的开启选择，仍允许玩家主动关闭；没有资格时不能重新开启。
- 补齐繁中、英文、俄文三种训导官健康状态的名称、说明及普通状态两阶段名，每种语言 8 项。简中使用 Def 原文。
- 翻译用例从实际 Def 提取所需字段，再检查实际语言注入目录中的唯一、非空值；不使用源码字符串匹配代替行为测试。

## 4. 补足集成验证

新增 `TrainerIntegration` 并接入统一验证，10 个用例共同运行真实恢复作用域、身份与绑定、特化历史、凝胶标签工具和训导官生命周期，覆盖临时无绑定、最终失格归档、宿主残留清理、四种终极状态组合、零进度、嵌套释放及异常退出。

`RitualLifecycle` 改为直接编译生产 `TrainingJobUtility`，引擎接口模型只提供任务安装、传送通知、到达信号和预约存储。新增四个用例验证同一调教员连续接管两名目标、同步位置时预约消失、保留其他 Job 的预约，以及重复交接不重复释放。错误释放会使测试失败，避免先前无条件成功的工具替身掩盖红字。
