## 故障和行为契约

维护者确认，关闭 SSC 行为限制总开关后 UAP 手动群交可以启动。原 UAP 先安装共享接收任务，SSC 此时找不到运行中的发起者而拒绝；后续发起者也可能被真实个人规则拒绝。`StartJob` 未抛异常不代表安装成功，原 UAP 启动器仍返回成功，形成聚集后不进入行为的现象。

本次只修改 SSC 的 1.7 接入；UAP 安装文件不改。新增全局设置 `allowUapManualGroupRestrictionOverride`，默认 false、旧配置缺字段同样 false，界面名称“UAP 手动群交忽略 SSC 行为许可”。它不属于个人能力开关，也不改写个人规则、默认模板、特化或装备数据。

关闭豁免时，兼容层仍补齐准备方向，整组逐对遵守原许可。开启时，仅由 UAP 窗口本次手动下令取得豁免，忽略 SSC 普通主动／接受／仅限主人及同类覆盖许可。UAP 匹配、身体条件及原驱动的有效性条件仍生效；不推广为所有 `playerForced` 或所有 UAP 任务的白名单。

## 实现

- `common/Uap/SSCUapGroupApi.cs`：软依赖类型、方法、字段类型及静态入口核对；反射访问集中于此。缺 UAP 安静跳过，安装失败卸载本 owner 的整套补丁，停止豁免并给出诊断。
- `common/Uap/SSCUapGroupRuntime.cs`：关联 Game、Map、发生点、请求、session 对象及编号、机械配对、原 Comp／人格 token／锁链／主人，以及各 Job 引用与 loadID。候选记录不会提前领取真实 Start 或结算凭据。
- `ThePatches/Harmony_UapGroupCompatibility.cs`：从窗口捕获精确手动来源，关联请求、集合和实际会话。初次匹配及集合后的最终计划均预检；只在可追溯请求内由 SSC 协调分配，继续调用原 UAP session 构造、原驱动及动画／计时／结算。
- 原 `SSCRestrictionJobContext`／`SSCRestrictionJobGuard` 仅在 `SSC_RW17` 条件下增加接入：准备方向、准入前票据验证、专用豁免、真实 Start 后登记、未开始 End 拒绝及完成归属验证。通用 Policy 与既有保存字段保持原契约。
- `SSCSettings.UapGroup.cs` 保存新设置；主模组设置页在 UAP 接口可用时显示。新增四语各5键及源码镜像；不修改 1.6／Common。

### 启动及失败

下令时记录豁免选择，不允许后来开启设置给旧请求补发许可；集合期间撤销原豁免则在启动前拒绝。整组安装后提交的场景按本次选择继续，关闭设置影响后续请求。

先构造并登记全组 Job，在原 UAP 步骤前插入等待提交步骤。每个 `StartJob` 使用允许准入失败的调用方式，返回后核对实际当前 Job、驱动、会话及首个等待步骤，全部成功才放行。失配时停止后续分配，回收尚未分配的候选，取消已安装的本场任务。

所有任务安装成功之前不进入真正的 UAP 初始化步骤。提交后的各初始化仍按顺序执行，不能承诺初始化异常时撤销已发生的 RJW Start 或物品消耗；本轮不实现跨模组事务。

失败先封闭票据，再比较移除映射、停止仍属于本场的动画并清理精确任务。旧集合任务、新命令及其他会话通过对象与编号区分。初始化及 DriverTick 作用域把同步回调绑定旧工作，旧 `AbortSessionForPawn`／完成通知不能改用新会话。已真正开始的同一场保留必要 End，取消或过期数据不能追加 ProcessSex 或重复领取 SSC 完成效果。
