## 1. 实际事件接入

复用共同入口 `BeforeEffects`、`SSCRomanceMoodFrame`、原 worker Prefix／Postfix／Finalizer 和接受覆盖的 `Observe`。不从菜单、配置提交、概率查询或命令创建发放心情，也不增加随机取样。

互动前先固定原人格 token、Comp、心情需求、记忆处理器及关系载体，再读取阶段、实际主人、有效受虐狂、原始好感和互动前关系。原版 `HasTrait` 排除 `Suppressed`，综合目录顺序仍为事件 → 阶段 → 有效受虐狂 → 三档好感。事件不再读取恶堕；持续思想旧入口尚待第四批切换。

## 2. 原版精确替换与变更记录

新增 `SSCRomanceNativeMood` 和 `Harmony_RomanceNativeMood`。只从三个已核对的原 worker 调用点建立来源，原 Def 重载入口在工厂回调前消费一次来源，再将其绑定到该 Def 方法实际传入 object 重载的实例。所有 Def／object 调用压独立帧，原生 `thoughtToMake` 只从精确父调用继承对应子来源，直接调用和重入不借外层事件身份。

| 本人事件 | 匹配心情 |
| --- | --- |
| 命令求爱失败 | `RebuffedMyRomanceAttemptMood` |
| 命令求婚失败 | `RejectedMyProposalMood` |
| 被控拒绝求爱 | 实际产生的 `FailedRomanceAttemptOnMeLowOpinionMood` |
| 有可证明来源的同因关系损失 | `BrokeUpWithMeMood`／`DivorcedMeMood`；不凭 Def 名或对象相同猜测来源 |

当前原版非婚姻分手给接收者失恋心情，命令发起者的综合损失通常为新增；当前离婚 worker 没有直接发 `DivorcedMeMood`。未登记外部回调即使使用同名心情也不会自动取得替换来源，不据此删除它或虚构一次原版获得。

原生准入后，在真实 Add、基类合并中的 Renew 及容量 Remove 调用点逐条记录操作；以调用前／后冻结实例事实校验操作投影。仅前后列表净差异不能取得本次原因。外部新增、删改、后置异常、未知派生记忆类型或额外关联效果使本人的接管失败，保留原版反馈。

最终撤销只移除本次新增实例、还原本次 Renew 的年龄、恢复本次容量淘汰的原实例及位置。`Renew()` 本机原版仅将年龄归零。原版社交父记忆、关系、传说、信件、床位及指定历史清理继续原流程；不扫描删除历史，不重放任何原版获得调用。

## 3. 提交边界与回退

`SSCRomanceMoodRequest` 新增内部原上下文入口，真实事件不在结算时重捕获人格。综合目录、工厂及原生准入仍沿前两批实现。全部回调返回后，再核对 SSC 实例、原人格和原版逆序计划；最终原版撤销置于请求返回前，只有经过验证的局部列表／年龄写入，没有外部处理器回调。

- 新增／替换／刷新成功：撤销本次匹配原版心情的对应影响。
- 合法零值：不生成 SSC 记忆，仍撤销本次对应原版影响。零值也检查两个载体结构，缺失／损坏定义不是合法零值。
- 被较强综合历史挡住：原历史及年龄不变，仍按已完成综合结算处理本次匹配原版影响。
- 原版来源未准入、SSC 未准入或被其他 Prefix 跳过：不伪装成替换完成，不强制获得，不删除合法原版反馈。`NotAdmitted` 不单独授权接管。
- 缺锚点、实际卸载关键补丁、格式或定义失配、原人格失效、异常及原版见证冲突：不接管原版；已写入的本次 SSC 按第二批局部撤销契约处理，不覆盖后来事件。

安装就绪同时检查唯一锚点和实际 Harmony 登记。所有关键 native 观察就绪才允许综合事件接管；任一关键点失效则保留原版反馈，既有浪漫许可及关系结算不依赖这些心情观察而改变。
