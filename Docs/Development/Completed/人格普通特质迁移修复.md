## 状态与范围

本次处理普通人格特质的保存、复制、加载和植入。性奴特质继续按历史最高恶堕重建，其余人格数据的迁移规则不在本次修复范围内。

## 问题与修复行为

原先 `StorePawnData()` 保存了 `storedTraits`，但 `InheritEverything()` 未使用该列表。A 的凝胶植入 B 后，B 的普通特质仍然保留；植入仍报告成功并消耗凝胶。同体回填时，由于提取没有移除原身体的普通特质，容易误以为它们已被恢复。

植入现在按凝胶快照完整替换普通人格特质。同体回填也恢复提取时的快照，提取后对原身体普通特质所作的修改不会保留。宿主基因及其授予特质留在身体上，快照中的普通特质根据新身体的基因重新处理抑制关系。

| 场景 | 修复后的行为 |
| --- | --- |
| A 的凝胶植入 B | B 的普通人格特质替换为 A 的快照 |
| 提取后修改 A 的普通特质，再植回 A | 恢复提取时快照 |
| 接收身体存在基因授予的特质 | 保留基因及对应特质 |
| 普通特质在提取时受基因抑制 | 仍保存其定义和等级，植入后按宿主基因处理 |
| 合法空特质快照 | 清除接收身体的普通特质，仍保留基因来源特质 |
| 特质快照缺失（`null`） | 在修改接收者之前拒绝植入，凝胶不消耗 |
| 凝胶经过人格编辑配方复制 | 保留普通特质快照及格式版本 |

性奴特质属于由历史恶堕派生的状态，不使用普通特质快照决定最终等级；PE 空壳标记也不作为普通人格特质恢复。

## 快照格式和旧档

新快照使用版本 `1`，仅保存 `sourceGene == null` 的普通特质，包括当前受到基因抑制的普通特质。定义、等级和 `ScenForced` 随条目保存，复制凝胶时使用独立的特质对象；快照版本也随复制和 Scribe 存档保留。

旧凝胶缺少版本字段，按版本 `0` 读取。旧格式遍历了全部特质，但没有保存 `sourceGene`，因此无法可靠判断某条特质原本由基因授予还是由人格持有。本次按旧凝胶已有条目作为人格特质恢复，不按特质名称猜测来源，同时保护接收身体的基因。旧凝胶中原本由基因授予的特质可能因此成为恢复的人格特质，这是旧数据缺失造成的兼容边界。

缺失列表与合法空列表分别处理，避免把损坏或不完整的凝胶误判为“人格没有普通特质”而清空接收者。已经植入并消耗的旧凝胶无法由此修复追溯还原；需要尚存的凝胶、原身体快照或旧档提供原始数据。
