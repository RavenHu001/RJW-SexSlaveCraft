# 浪漫文案专项与总回归门禁隔离修复

2026-10-26。范围依据维护者确认：只修复总回归误继承文案专项模式，身份及被动接受逻辑保持现状；只跑相关专项，复核后提交，不执行完整回归或游戏同步。

## 问题与实现

独立浪漫宿主以 `SSC_ROMANCE_TEXT_ONLY=1` 选择文案专项，并输出 `SCOPE: romance text only; ...` 和通过摘要。此前总入口继承此环境变量，只检查摘要中通过数与总数相等，因此可能将仅文案结果当成浪漫完整套件通过。发布脚本调用同一总入口，也受此编排问题影响；这不表示现有其他发布门禁已经满足或被绕过。

[Test-All.ps1](../../../Scripts/Test-All.ps1) 增加两层保护：

- 保存调用者的 `SSC_ROMANCE_TEXT_ONLY`，在任何套件执行前从当前进程环境移除，让构建和宿主子进程均继承完整套件模式；成功或异常退出时由原 `finally` 恢复。
- 在浪漫宿主的摘要判定前拒绝仅文案 `SCOPE` 标记，沿原套件异常处理写入 `Failed`、原因和日志；已有汇总及发布阻断继续生效，不写死历史用例总数。

清除与恢复采用 `NullString`：PowerShell 7.6／新版运行时区分空串和未设置，普通 `$null` 传给 .NET 字符串参数可能成为空串。原环境恢复循环同样保留所有已保存变量的这一区别。只操作进程环境，不修改用户或系统环境。

独立宿主仍可显式选择仅文案模式；总入口忽略该选择，运行结束后恢复调用者原值。生产 C#、身份互斥、主动对象过滤、被动强制接受、心情／社交日志、译文和保存格式均未修改。
