## 实现与边界

完整主人／从属提示由行文字缓存首次悬停时合并，调教员完整提示由展示对象首次悬停合并，后续事件直接复用。仍受原 64 行缓存、当前视图、语言及展示代次的失效和释放约束，不为全名单预生成提示。极窄主人按钮也使用相同缓存，原头像、悬停高亮和鼠标时序不变。

局部查询仍按两秒真实时间读取缰绳并核链，直接字段变化及失效行请求继续即时触发局部读取。新增完整事实比较：游戏／来源／地图、身份、实际主人、从属引用与顺序、姓名、阶段、特化、生命状态、位置种类／主体／容器／世界对象／名称及世界格值、调教员引用／姓名／生命／有效状态都必须相同，才保留整份旧快照及其行成员索引、展示和截断缓存，不增加展示代次。语言变化仍独立清空翻译和文字缓存。

姓名、位置名称及世界格值在构建时捕获，避免前后快照通过同一个可变对象读到相同“当前值”而漏掉变化。名称、阶段、特化、死亡、移图、容器／世界对象改名、世界格变更及指派状态变化都会按原直接或定时路径更新。保留旧快照不保留旧关系许可：绘制与点击仍检查现时锁链，导航仍实时重解位置；同主新链可复用相同展示，改绑不能借旧快照导航。

同一次构建内，主人兼调教员、调教员同时属于从属等情况复用已经解析的位置及位置请求。没有新增跨查询位置缓存或静态 Pawn 表，后续移动、死亡／复活及点击定位继续走原路径。

开发诊断改用 `SSCBondOverviewUtility.Diagnose`，与完整查询共用候选有效性、引用去重及锁链过滤；先统计缰绳，再在同一去重上下文枚举其他候选，输出值类型计数。候选地图、世界、临时、旅队、容器、尸体及飞船覆盖不减，不创建展示快照、条目、位置、排序或额外成员集合，也不建立只供位置定位使用的飞船索引。完整只读 `Build` 保留作取证和回归，生产开发按钮调用计数入口。

开发模式及 SSC 调试按钮双开关、点击时来源／游戏／地图复查、异常报告和与普通视图的隔离不变。诊断仍只在明确点击时运行，不自动补漏、不修复索引或写入普通名单。批选的筛选、候选物化、逐人复查和原版选择调用源码保持基线；绑定服务、完整候选遍历器与导航文件也保持基线。

## 性能对比

新入口 `python Tests/BondOverviewUI/Performance/CompareLocal.py` 默认比较 `776b8af` 与当前工作区。三轮交替、**41 场景**：两侧使用相同边界、基线 Reset 宿主、基准及编译配置；仅在复制的健康查询和模型构造中加入相同整数计数，保留生产输入／编译副本哈希及原始 JSONL。普通候选扫描与头像请求次数不减少，批选分配和查询计数相同；诊断不再构造展示对象，稳定缓存不再替换。原历史 `Compare.py` 默认阶段及证据保持原范围。

下表为每次操作的模型分配，取三轮中位数；预热肖像边界只计调用，不执行原生渲染。

| 场景 | 基线 | 本轮 | 说明 |
| --- | ---: | ---: | --- |
| 3／10 人卡片预热悬停 | 112 B | 0 B | 完整提示不再逐事件拼接 |
| 方形主人预热悬停 | 112 B | 0 B | 含大头像按钮路径 |
| 调教员预热悬停 | 144 B | 0 B | 完整调教员提示复用 |
| 3 人无变化局部刷新＋展示 | 1968 B | 1168 B | 减少约 40.7% |
| 10 人无变化局部刷新＋展示 | 3600 B | 2880 B | 减少 20% |
| 30 人无变化局部刷新＋展示 | 7536 B | 7136 B | 减少约 5.3% |
| 主人与调教员同人时局部构建 | 472 B | 448 B | 位置构造 2 次→1 次，仅本次复用 |
| 地图 104 人、3 名从属批选 | 232 B | 232 B | 锁链查询仍 106 次，行为不变 |
| 同地图开发诊断 | 3168 B | 744 B | 2 份快照、6 条目、6 位置→全部为零 |
| 含 200 件货物飞船的诊断 | 3488 B | 936 B | 货物遍历 2 轮→1 轮，候选来源不减 |

普通预热非悬停绘制仍为模型零分配，N 个有效头像对应 N 次关系复查及 N 次肖像请求。无关系普通角色模拟 60 秒只构建首次本地快照，世界扫描为零。开发按钮本身的构造仍沿原入口，未扩大为新的命令缓存。

本轮减少展示缓存反复冷启动，没有消除局部事实构建：新快照／条目／位置仍先创建以完整比较，再决定是否保留旧快照。因此纯三人快照构建由 1104 B 增至 1168 B，增加的是捕获姓名等比较事实所需空间；局部刷新加展示的总分配仍下降。完整事实比较也增加 CPU 工作，十人稳定刷新模型约 3.21→3.68 微秒；三人约 2.22→2.18 微秒，亚微秒差异受模型和运行波动影响。刷新按两秒执行，不能把分配下降写作每条路径 CPU 都更快。

这些数字只反映同边界模型的分配、调用和计时，不证明原生字体、首次肖像生成、实际存档或帧率改善。既有依赖组合与极端人数仍按维护者要求暂不安排。
