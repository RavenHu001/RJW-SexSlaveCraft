状态：2026-10-21 维护者已确认开关与演化点结算实机正常，并授权提交本批修改。当前发布版仍为 2.4.3；本项属于发布后的开发增量，尚未打包发布。

## 规则与范围

- 仅更新 1.7；1.6 与 Common 冻结。全局模组设置默认关闭，旧配置缺键也关闭，所有存档共享偏好。
- 开启后，仅 SSC 契约仪式支持演化点收益。当前原版随时举办曲线为糟糕／平庸／成功／完美 0／0／1／2 点，仍须满足流变文化及原版发展条件，遵守改革点数上限。
- 结算时读取当前开关。关闭不调用演化点结算，不显示这项奖励说明；已有点数与仪式其他结算保留，不补发历史收益。
- 沿用整场 `TryClaimOutcome` 一次性认领，六阶段不分别发点；无需增加角色、仪式或人格保存字段。
- 本批不扩展模因／戒律／职位，不增加奖励冷却，不改变重复举办的质量惩罚。

## 实现

1. `SSCSettings.RitualDevelopmentPoints.cs` 保存独立字段；`Settings.cs` 接入序列化与仪式区域复选框。
2. 1.7 `SSC_BindingRitualOutcome` 显式声明 `givesDevelopmentPoints=true`；生产 worker 的 `GivesDevelopmentPoints` 同时检查 Def 和当前偏好。
3. `Harmony_RitualDevelopmentPoints` 修补原版曲线查询，只识别实际 SSC worker。关闭返回空曲线，开启且原结果为空时为随时举办模式读取原版共享曲线；保留其他提供者已返回的非空曲线，不修改共享曲线。
4. 曲线私有字段只缓存反射元数据；字段不可用时停止新增收益并只记录一次错误，不硬编码替代公式。新文件列入权威 Compile 清单，由既有 PatchAll 注册，不额外重复注册。
5. 整场 Apply 的演化点分支再次检查设置；信件使用加点前后实际差值，修正接近上限时名义奖励大于实际增量的问题。
6. 四语为简中、繁中、英文、俄文，运行文件位于 `1.7/Languages/*/Keyed/SSC_RitualDevelopmentPoints.xml`，同步 `Sexslavecraft/Languages` 镜像。新增逻辑有类／方法及代码块注释。
