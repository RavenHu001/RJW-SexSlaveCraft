重布局已经提交为 `3dbf13a`（`refactor: split 1.6 baseline and 1.7 development layout`）。本页将其与后续四项兼容修复一起登记，保留先前执行与验收的先后关系。

- 1.6 仅保留现有 2.4.1 成品，不再开发、重编或要求恢复旧版游戏环境。原包的 **531 个运行文件**包含共享贴图，均以哈希冻结；连同 `BASELINE.json` 共 **532 个文件**在本批修复和注释阶段保持原字节。
- `LoadFolders.xml` 使 1.6 只读取 `Common + 1.6`，1.7 只读取 `Common + 1.7`，每版只有一个 `Sexslavecraft.dll`。原 packageId、程序集身份、DefName 和存档身份保持。
- 后续开发面向 1.7；如需替换基础贴图，应放在 `1.7/Textures` 的同名路径，保留 Common 冻结文件。PSD 与 Shader 工程源迁入 Source，不作为开发资料整体打包。
- 新增独立 `.NET 10` 工程及 `Build-Mod.ps1`，构建仅输出 1.7；工作区可携式 SDK **10.0.402**补齐开发环境，系统 SDK 9 和模型测试宿主继续保留。SDK 选择优先级为显式参数、环境变量、工作区 SDK、PATH。
- 测试区分仓库源码、所选版本资源和 Common；1.6 入口只检查冻结成品及 XML。发布脚本按运行目录和玩家文档白名单收集，开发资料链接在随包副本中改为仓库链接，并分别记录两版 DLL 来源。

## 本批四项兼容修复

| 问题 | 修复后的行为 | 验证方式 |
| --- | --- | --- |
| 凝胶化同轮先成功后失败 | 以具体临时 Hediff 的附着状态判定有效性；先移除过程再结算，剩余组件和旧调试按钮不能再次成功或失败，不增加存档字段 | 默认进度完整竞赛、双阈值、失败优先、外部移除、死亡及新旧过程隔离 |
| 1.7 自定义 Shader 非空伪成功 | 明确使用内置 `TransparentPostLight`，不以非空或 `isSupported` 判断旧 ShaderLab 已移植成功 | 伪成功 Shader 边界下仍选择内置透明 Shader |
| SizedApparel 角色读取失效 | 从 `node.tree.pawn` 获取角色；空节点或渲染树安全跳过，服装记录保留原来源 | 渲染树角色、空对象、服装变体及普通服装保护 |
| 兼容验证脚本误判 `__state` | 按同补丁类 Prefix 确定状态类型，再核对 Postfix／Finalizer；普通参数检查不放宽 | 正反两类状态签名断言及真实 DLL 元数据核验 |

凝胶化双重结算是迁移前已经存在的逻辑缺陷；SizedApparel 缺失字段在当前 1.7 与本机依赖中已确认，未凭缺少的旧游戏程序集断定首次引入时间。此次实现只进入当前 1.7 开发源码和 DLL，冻结的 1.6 成品不回移修复。
