# 新限制系统最小测试界面

开发日期：2026-09-21。初版基于阶段 1 提前提供设置与测试；目前[阶段 2](新限制系统阶段2.md)已接入自动初始化、旧档迁移、默认模板、批量应用和调教页右侧规则栏，[阶段 3A](新限制系统阶段3A.md)已让 RJW 普通双人、单人及人格排泄任务采用这些规则，其余入口待后续接管。不改版本号。

## 打开与操作

1. 重启游戏加载更新后的 DLL，载入存档并进入有角色的地图。
2. 打开 **选项 → Mod 设置 → SexSlaveCraft 设置**，在旧版性奴保护与限制选项末尾（“自愿性行为仅限主人”下方、日志设置之前）点击 **行为限制：设置与测试**。无需开发者模式、基础调教研究或预先选择角色；有选中角色时优先使用，否则使用地图上的首个可配置角色。未进入地图或没有可配置角色时按钮置灰并显示提示。调教页右侧规则栏用于日常编辑，独立的双方许可测试仍从此按钮进入。
3. 在“个体规则”页选择需要配置的角色。正常适用角色已由生命周期建立或迁移配置。自动初始化失败时，修正默认数据后可点击 **重试建立默认配置**；已有配置和待迁移输入不会被覆盖。
4. 点击六项规则各自的“保存值”按钮切换选项。编辑立即写入角色，保存游戏后持久化；每项下方显示实时生效值和来源。
5. 打开“许可测试”页，选择发起者、接收者和用途。结果实时调用新系统统一入口，显示允许或拒绝、原因、相关角色和条目来源；不会启动任务。
6. 可交换双方测试方向，也可直接进入发起者或接收者的规则页。单人用途忽略接收者，其他用途不会把缺失接收者当成单人。

编辑页不会在打开、切换对象、查询或关闭时自动创建配置。不适用角色的已有配置只读；未知版本、非法值或缺失规则不会被静默修复。选择下拉选项时写入的是打开该菜单时的角色，避免后续切换对象造成串写。

核心复盘修复后，任一保存条目损坏会使需要读取该角色配置的测试返回“配置无效”，与界面校验一致。初始化遇到非法默认时会显示具体条目及全局模板/特化默认来源，不写入半成品。主人直接放行及总开关关闭仍优先；详见[核心复盘修复](新限制系统核心复盘修复.md)。

## 规则与全局开关

- 主人对自己的绑定对象发起请求仍在统一入口中立即放行；界面不会将这条关系许可写成角色的六项“全部允许”。
- 装备与特化强制仍按阶段 1 的顺序解析。可以修改被覆盖条目的保存值，但当前生效值继续服从强制来源；脱下装备或关闭特化强制后重新显示有效结果。
- 两个开关均为全局设置，修改后保存到 Mod 设置。总开关同时控制已接管任务和剩余旧保护路径；特化开关只控制新规则的特化覆盖，不控制装备。
- 角色配置随游戏存档保存。界面不修改旧的允许他人开关、身份、绑定或任务状态；调教许可改变后按当前新规则协调指定者。

## 建议测试

| 操作 | 新系统界面中的预期结果 |
| --- | --- |
| 普通绑定对象初始化，第三人发起普通行为 | 按默认保存值拒绝 |
| 把接收者相应许可设为允许 | 测试结果实时变化；若发起者也适用，仍需其主动许可满足 |
| 主人向自身对象发起，再交换方向 | 正向显示主人直接放行；反向检查发起者规则 |
| 巴士对象穿防护装备，修改“接受非主人强制行为” | 显示保存值与装备强制禁止；脱下后改用特化覆盖 |
| 关闭特化强制 | 装备仍生效，无装备时恢复保存值 |
| 保存游戏并重新读档 | 已建立配置及个体选择保留，不重新套用默认 |
| 未建立配置的角色参与测试 | 如本次需要其规则，则显示配置缺失，并可直接进入对应编辑页 |
