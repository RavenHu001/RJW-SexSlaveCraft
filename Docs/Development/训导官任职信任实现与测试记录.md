# 训导官任职信任（受到主人信任）实现与测试记录

实现日期：2026-10-10。分支：`codex/trainer-duty-feedback`。仓库版本仍为 2.3.8，属于未发布的开发叠加。

本轮实现 [受训者对训导官身份差异反馈开发规划](../Design/受训者对训导官身份差异反馈开发规划.md) 第 10 节：训导官对**实际绑定主人**的反向好感与自身心情。这是首版职责反馈的镜像方向，与已实现的受训者弱记忆套相互独立。

## 1. 实现摘要

| 想法 | 获得者／对象 | 效果 | 类型 |
| --- | --- | --- | --- |
| `SSC_TrainerOfficer_TrustedByOwnerSocial` | 训导官对实际绑定主人 | +5 好感 | `Thought_SituationalSocial` |
| `SSC_TrainerOfficer_TrustedByOwnerMood` | 训导官本人 | +3 心情 | `Thought_Situational` |

两者都是**条件性想法，不是记忆**：不设 `durationDays` 与 `stackLimit`、不写记忆列表、不进人格凝胶、不叠加实例；条件失效即消失，恢复即重新生效。

共同条件复用首版只读资格，不另建一套判定：

- 训导官通过 `TrainerOfficerFeedback.IsActiveOfficer`（SSC 性奴 + 个人开关 + 持续资格；普通 20%、普通满进度、有效终极跨方向均适用）。
- 实际绑定主人存在、非自身、存活未销毁未丢弃、且具 SSC 主人身份。

## 2. 本机程序集核对

实现前核对本机 `Assembly-CSharp.dll`，确认条件性想法的接线方式：

| 结论 | 依据 |
| --- | --- |
| 条件性心情用 `Thought_Situational` + `workerClass`，阶段取 `baseMoodEffect` | 原版 `JoyousPresence` |
| 条件性社交用 `Thought_SituationalSocial` + `workerClass`，阶段取 `baseOpinionOffset` | 原版 `Joyous`；本仓库已在用的 `SSC_TrainerOfficer_Appraisal` |
| 社交 Worker 收到 `(pawn=持有想法者, otherPawn=候选对象)` | `Thought_SituationalSocial::CurrentStateInternal` 调用 `Worker::CurrentSocialState(pawn, otherPawn)` |
| `ThoughtState.Inactive` 把 `curStageIndex` 置为 -1，`Active` 由它派生 | `Thought_Situational::RecalculateState` 与 `get_Active` |
| 条件性想法不用 `durationDays`／`stackLimit` | 两个原版样例均未设置 |

因此心情 Def **必须显式声明** `thoughtClass=Thought_Situational`：首版的 `Appraisal` 只写 `workerClass` 也能工作，是因为它会按社交形态解析；心情条若沿用该写法有被解析成社交想法而不进心情栏的风险。回归用例专门断言这一点。

## 4. 文案

| 键 | 简体中文 |
| --- | --- |
| `...TrustedByOwnerSocial.stages.0.label` | 受到主人信任 |
| `...TrustedByOwnerSocial.stages.0.description` | 主人把别的性奴交到我手上。这是只有被信任的性奴才拿得到的差事。 |
| `...TrustedByOwnerMood.stages.0.label` | 主人的器重 |
| `...TrustedByOwnerMood.stages.0.description` | 主人把调教别的性奴的差事交给了我。被主人这样用着，比被放着不管更让我安心。 |

要点：心情条写成**"被主人用着"本身带来的安定与价值感**，不与职责心情的"完成工作的满足／发情"重叠；社交条写成**授权即信任**。四条新文案全篇不使用性别代词，与上一轮去性别化口径一致。

## 5. 自动验证

`Tests/TrainerIdentity` 新增 6 项，套件由 112 项增至 **118 项，全部通过**：

| 用例 | 覆盖 |
| --- | --- |
| 任职信任定义与四语文案完整 | 两条 Def 的类名、Worker 类型、+5／+3、无时长容量；镜像与四语 8 键完整 |
| 有效任职训导官对实际主人获得反向好感与心情 | 两条同时生效、阶段为 0、不写记忆列表 |
| 反向信任只指向实际主人 | 其他主人／受训者／自身／空对象都不生效；原评价方向保持 |
| 关闭任职、切向、退阶、解绑与终极禁用同步失效并恢复 | 五种撤销路径；重开后恢复且无历史实例 |
| 主人死亡、销毁、丢弃或不再是 SSC 主人 | 信任加成立即消失；无主与无效输入不生效 |
| 倒地、离图与工作暂停保留信任 | 沿用首版语义；资格查询不写入锁链或健康状态 |

**统一回归**：25 套、**1512/1512 项通过，0 失败**。上一基线为 1506（24 套时代的 1492 加上受训者弱记忆套 14 项）；本轮 `TrainerIdentity` 由 112 增至 118，即本文件新增 6 项，其余套件计数不变。汇总与逐套日志见 `.builds/trainer-training-memories/validation/summary.json`。

**主工程 Release 构建**：使用本机真实 RimWorld 1.6、RJW 核心、动画框架与 Harmony 引用，**0 警告、0 错误**。

核查过程中修正一处测试宿主缺陷：`Tests/TrainerTrainingMemories` 的 `ThoughtWorker` 替身原先只有社交入口，生产新增非社交心情 Worker 后该套件编译失败；已补齐 `CurrentStateInternal` 与非社交查询入口，两套宿主的替身形状现与生产一致。

## 6. 实机测试清单（待执行）

1. 有效任职训导官在社交栏对自己的实际主人出现 +5「受到主人信任」；对其他主人、受训者与指定调教员都不出现。
2. 心情栏常驻出现 +3「主人的器重」。确认这一条常驻是否会显得吵；若偏吵，可考虑降为社交条目或调整数值。
3. 关闭个人任职、切走普通方向、锁链退阶、解绑、终极禁用后，两条随之消失；重新开启后恢复，且**不产生**任何历史记忆。
4. 训导官倒地、工作暂停、离图、旅行时两条保留。
5. 完成日常调教当天，职责心情 +3 与信任心情 +3 同时存在（合计 +6），职责心情次日自然到期而信任心情仍在。
6. 人格抽取／植入后，信任项按**接收身体**的实际绑定与资格重新判断，不继承原身体的主人配对。
7. 检查四语显示与社交气泡，确认无乱码、无占位符问题。

## 7. 交付边界

- 训导官任职信任是独立增量，不改变已实现的受训者弱记忆套数值口径与分流规则。
- 不新增信任等级、关系类型、存档字段、工作成绩记录或额外完成事件钩子，不扫描全地图。
- 首版主人对训导官的 +5 评价与训导官完成工作的 +3 职责心情均保持原规则。
- 自动回归与真实依赖 Release 构建通过；实机验收尚未开始。
