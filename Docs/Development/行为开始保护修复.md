# 行为开始保护修复

**状态：修复完成，归入 `2.2.12`。** 2026-09-14，维护者经过验证确认修复有效，并授权更新版本文档、提交及上传。本项与恶堕衰减设置运行时翻译修复共同组成 `2.2.12`，版本构建与检查记录见 [2.2.12 版本验证](../Releases/2.2.12/2.2.12版本验证.md)。

## 已确认的问题

维护者使用 A（主人）、B（已绑定目标）、C（非主人）复现：开启保护、禁止非主人强制行为时，C 单独发起会被拒绝并产生 `TryMakePreToilReservations() returned false ...` 黄字；A、B 已开始后，C 却能加入。

原因是 `Start_Prefix` 缺少 `[HarmonyPrefix]`，未被 `Harmony.PatchAll()` 注册。原预约补丁作用于 `JobDriver_Sex` 的基类方法，RJW 发起者覆盖预约方法且不调用基类。首次发起时，新创建的接收任务被预约保护拒绝；加入现有接收任务则没有这次检查，因而绕过限制。黄字来自创建接收任务之后才拒绝，不能据此判断保护完全失效。

## 修复内容

- 显式注册 `Start()` 前缀，继续使用现有共享保护策略。
- 在发起者进入下一步骤之前检查，包括初始步骤与行走之后；不允许的任务在创建接收任务或进入行为初始化之前结束，避免上述接收任务预约黄字。
- 玩家强制指派同样接受检查。识别强制行为时同时参考驱动类型和接收者驱动，不仅依赖固定 JobDef 名单。
- 拒绝只结束对应的发起任务，不修改 B 的接收任务或参与者列表；不在同一调用栈立即重新选择 AI 任务，避免重复选择被拒绝任务造成递归。
- 成功开始后保留正常收尾。对于被兜底拒绝、尚未开始的场景，拦截 RJW 原生 `End()`，防止访问未初始化数据。SSC 日常训练、PE 和仪式调用 `Start()` 后检查自身是否仍为当前任务，避免继续发送开始通知或推进状态。
- 读档后的已有场景可根据初始化数据和参与者状态恢复收尾。接收方 `DoSetup()` 会提前登记首位参与者，因此不能仅凭名单成员身份就把已观察到的准备阶段标记为开始。

本次没有改变主人、总开关、允许非主人、防护装备、公交车状态及他人训练许可的策略含义；已经开始的场景不被追溯取消。

```powershell
dotnet Tests/InteractionProtection/bin/Release/net9.0/InteractionProtection.dll
```

已使用 Harmony 2.4.2 验证真实补丁注册和执行。测试中的动画收尾探针仅模拟本机动画模组的 `End` 前缀签名，不运行 Unity、实际动画或完整游戏调度器，不能替代游戏内验证。

Harmony 跳过原方法并不会跳过所有外部回调，也不能让调用方在一个 `void Start()` 返回后停止执行。因此首次发起和加入两条实际任务路径必须由步骤前检查拦截，不进入 `Start` / `End` 及其外部回调。直接调用 `Start` 的单独探针仅验证 SSC/RJW 原生兜底，不能据此声称任意第三方绕过任务步骤直接调用的路径都无副作用。
