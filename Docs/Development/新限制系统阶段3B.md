# 新限制系统阶段 3B：日常调教与仪式

开发日期：2026-09-21。基于 `62b62a9`，未发布、不改版本号。行为约定见[开发规划](../Design/新限制系统开发规划.md)。本批接管日常调教、绑定仪式各阶段及其共用接收任务；普通双人、单人和人格排泄继续使用阶段 3A 入口。

## 已实现

- 上下文按发起驱动识别日常、仪式和首次绑定准备，共享接收任务沿实际发起者确定用途；不根据姿势或普通强制接收类型改变调教分类。
- 行为许可交给 `SSCRestrictionPolicy`。实际主人发起时直接通过；其余已绑定对象只查询接收方调教条目，不查询普通主动/被动条目。旧开放字段和公交车不再单独放行，现有防护装备只影响其已声明条目。
- `SSCRestrictionTrainingUtility` 适配资格及工作关系。自动日常工作只派给有效指定者，空指派、停用和暂时无法工作不开放自动接替。主人手动发起或主持不因空指派或指定别人被排除。身体、身份、排班、研究、冷却、可达性及预约等正常条件继续执行，总开关停用也不取消这些条件。
- WorkGiver 在目标兼容修复和创建任务前检查。日常驱动沿用统一派生预约、步骤和 Start 守卫，不再重复一套许可判断。命令前缀显式传入命令来源，因为原版在 `TryTakeOrderedJob` 内才设置 `playerForced`；前置检查不修改原队列。
- 仪式两端共用配对检查。实际主人和获准的有效指定者（包括开启调教员身份的 SSC 性奴）均可主持，先后选角一致。界面角色改称“主持者”，内部 ID 仍为 `master`。
- 首次无绑定目标使用 `BindingPreparation`，仅允许指定且具 Master 身份的候选者，不授予实际主人最高许可。绑定服务仍要求合法主人且拒绝覆盖原归属；可主持不等于可新建或替换所有权。
- 每个仪式阶段创建及占用前重新检查。准备中或下一阶段被拒绝时，对匹配场次调用原版 `LordJob_Ritual.Cancel()`，走取消及生命周期清理；不发送完成 memo，不领取仪式成果或日常冷却。迟到旧驱动不能取消新场。
- 已开始当前场景/阶段正常收尾，新 Job 和参与者重新检查。凭据按任务、双方和场景用途保存；首次准备中途建立绑定不会改变当前场景用途。升级阶段 3A 存档时，日常依据加载时捕获的真实计时进度恢复，仪式额外沿用精确 `phaseSceneStarted` 标记；单有 SexProps 或接收准备不算开始。
- 日常驱动保存占用目标并注册整份 Job 清理，覆盖行走和准备失败；未开始不执行原生 End 或成功结算。迟到收尾不清理新任务或新仪式占用。指派锁定直接使用新条目，移除阶段 2 替换旧方法的临时补丁。

## 验证与边界

- 本机 RimWorld / RJW / 动画框架引用 Release 构建：零警告、零错误。
- 统一回归 16 套 **566/566**：交互限制 **76**（真实 Harmony PatchAll）、身份/工作/选角 **40**、日常/仪式生命周期 **50**。报告：`.builds/restriction-stage3b/validation-final/summary.json`。
- 身份套件直接编译生产规则、WorkGiver、角色及绑定代码；交互套件验证生产守卫和存档边界；生命周期套件直接执行生产日常与仪式驱动。游戏调度、Scribe 引用解析、原版取消信号图、实际收益和动画由最小模型代替，不能视为实机验收。
- 核对本机命令设置强制位的时机及仪式取消信号；沿用 9 个固定 Harmony 签名、13 个预约覆写的元数据核验。修改及新增 C# 文件的函数均有中文 XML 注释。
- 旧日常存档若恰好在 Start 后、第一次计时前保存且尚无新凭据，仍会重新检查；旧仪式已有精确标记，不存在这一证据缺口。
- 交易/特化事件预检、独立原版 Lovin、LifeForce 等专项兼容及旧界面/系统整体清理继续后续阶段。已有 Onahole 训练桥接保留，本批不宣称接管独立家具接收任务。

## 本机测试

维护者初步实机测试反馈“没有明显问题”，并授权提交；此反馈不代表下列全部场景均已逐项验收。后续可从可回退存档继续验证。

1. A 为实际主人，B 为其绑定目标，C 为合格调教员。B 开启非主人调教并指定 C：自动工作交给 C，A 仍可手动发起；清空指派或停用 C 不让其他人自动补位。
2. 禁止 B 接受非主人调教，C 的手动与自动请求均拒绝，A 仍可发起。普通条目、旧开放字段或公交车不能放开调教，现有保护装备也不能额外禁止已允许的调教。
3. C 采用开启调教员身份的 SSC 性奴，B 允许非主人调教并指定 C。分别先选 B、先选 C 组建仪式；A 也可主持。完成后确认 B 仍属于 A，C 身份及自身绑定不变。
4. 走位或准备未开始时收紧规则，停止请求并清除占用；实际场景/阶段开始后收紧，当前段正常结束，下一仪式阶段取消整场，不发成功奖励。
5. 未绑定目标指定合法候选主人，保持默认禁止条目，仍能首次准备；未指定者或仅开启身份的性奴调教员不能借此成为新主人。
6. 在日常行走、实际场景、仪式准备和已开始阶段分别存读档，检查准备重查、当前场景收尾、新阶段重查，以及取消后恢复工作。
