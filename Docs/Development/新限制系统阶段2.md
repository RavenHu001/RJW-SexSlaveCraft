# 新限制系统阶段 2：初始化、迁移与设置界面

开发日期：2026-09-21。基于 `ded43cf`，未发布、不改版本号。行为约定见[开发规划](../Design/新限制系统开发规划.md)。维护者已确认界面有效，随后要求规则栏改为向右展开、主 ITab 保持原位；调整后已同步本机游戏目录，维护者确认无问题并授权提交。阶段 2 已实现配置生命周期和两处设置界面；实际行为许可的全面接管仍属于阶段 3。

## 配置生命周期

- `Comp_Train.Restrictions` 保存独立的生命周期标记与待迁移输入。旧字段全部载入后、旧关系修复前捕获角色的开放选择和有效公交车状态；不复用调教员身份标记。旧档尚不适用的角色只完成识别，之后首次适用时采用新模板。
- `SSCRestrictionGameComponent` 将升级时能取得的旧全局值固定为当前存档的快照，先完成既有调教员身份迁移，再处理配置与指定者。延迟恢复的旧角色使用同一快照；不能还原此前已经丢失的历史全局设置。
- `SSCRestrictionLegacySettings.Convert` 按[阶段 1 迁移表](新限制系统阶段1.md)逐项转换。关闭总开关不等于把保存值全部放开，装备强制不写入配置。已有新配置优先，不再被旧字段覆盖；未知版本与异常数据保持原样。
- 新角色在身份启用、有效锁链建立或生成后立即复制当前模板。初始化不依赖研究、打开界面、发生行为或总开关开启。默认模板本身在旧 Mod 设置缺少新字段时按旧全局值建立，已保存模板保持不变。
- 当前方向、基础或保留的终极公交车状态都算有效条件。首次真正取得时只合入公交车声明的默认，写入规则与已处理标记作为一次完整提交；非法默认不产生部分修改。重复选择、认领、升级、离开后重获、读档和强制开关变化不重复写默认。
- 人格植入使用嵌套恢复作用域，将中间身份、绑定、特化事件延后。已有接收身体配置保持原值，最终有公交车时记为默认已处理；未初始化接收者在完整恢复后初始化。异常也会释放作用域并按实际留下的状态刷新。人格物品不保存限制配置。
- 新兔克隆在身体准备完成、生成到地图前清除复制来的配置及迁移、默认标记，再独立初始化。来源配置不受影响。已经存在的旧克隆走自己的旧档迁移。
- 装备的有效来源继续由解析器实时读取，穿脱不需要保存值改写或缓存失效操作；实际旧装备保护补丁留待阶段 3 接管时替换。

事件桥接集中在 `SSCRestrictionLifecycleHooks`：身份、特化、对账、绑定、直接锁链、人格、克隆、生成和公交车健康状态。许可查询不调用写入生命周期。

## 设置与指定者

- Mod 设置保留原测试按钮的位置：旧保护设置末尾。按钮下方新增特化强制开关、主动/被动/调教三类默认，以及全存档批量应用。未进入存档仍可修改模板，批量操作不可用。
- 批量操作先快照模板、当前存档和目标集合，确认后执行；覆盖地图、世界、临时角色、商队和运输集合，复制原版临时列表并去重。逐个完整创建后才替换；失败保留原配置并继续其他对象，最后报告成功、跳过和失败数量。已应用结果清除待迁移输入，不会被迁移队列覆盖。
- 调教页顶部可向右展开规则栏，主调教栏保持原位置和宽度；两边独立滚动，使用原生窗口范围处理输入，宽高随屏幕可用区域收缩。同一游戏会话保留展开状态，新存档初始收起。切换角色仅重置滚动，不初始化或改配置。
- 右侧显示角色、全局状态、保存值、实时有效值及具体来源，研究完成前可编辑；不适用角色只读已有配置。测试窗口复用同一编辑控件，并保留双方、方向、用途的许可测试。
- 新配置禁止非主人调教且有实际绑定时，将指定者改为主人并锁定选择；允许后解除锁定，等待玩家改选，不恢复隐藏历史人选。停用或临时不能工作的指定者保留，死亡/销毁引用清理。身份、自由殖民者、工作及身体资格仍由原接口检查。
- 总开关关闭时解除新限制带来的指派锁定，保留有效指派；重新开启后统一协调。配置编辑、批量应用、全局开关和绑定完成会触发协调。已有配置读档时跳过旧强制主人赋值，避免先丢失有效的新指派。

关系设置已经接入新调教条目；自动工作、仪式及其他实际行为仍含旧许可与旧例外。阶段 3 才统一替换这些入口、实行唯一自动指派语义，并移除相应旁路。本阶段的界面和测试结果不代表全部实际任务已采用新许可。

## 验证与实机测试

- 使用本机 RimWorld 1.6、RJW、动画框架和 Harmony 引用构建 Release 成功。统一验证 16 套、497/497 通过，其中限制核心及生命周期 107/107；右侧布局调整后的最终报告在 `.builds/restriction-stage2-right-panel/validation-final/summary.json`。
- 通过语法树核对本次新增或修改文件的 156 个函数中文注释；通过编译产物元数据核对 11 个生命周期补丁目标签名和注入参数。后者不代替游戏内 Harmony 执行验证。
- 限制套件直接编译生产迁移、生命周期和游戏组件，覆盖全部 64 组旧开关组合、固定快照、重复加载、人格嵌套/异常恢复、新旧克隆、跨集合批量、失败原子性、装备穿脱和指定者协调；原核心许可回归继续执行。
- 自动测试的 Pawn、Scribe 和世界集合使用边界模型，不替代 Unity 中的引用恢复、Harmony 执行及实际界面测试。修改或新增代码文件的函数均有中文注释。

建议重启游戏后按以下顺序检查：

1. 载入旧档，核对普通角色、旧开放角色、公交车的迁移值；手工修改后保存、重载，确认没有被旧字段覆盖。
2. 修改全局模板，再新设一个性奴身份；核对新角色使用新模板、已有角色保持选择，关闭总开关时也能完成初始化。
3. 在调教页展开右栏，检查滚动、切换角色、低分辨率和中英文显示；检查非主人调教项对主调教栏指定者锁定及重新开启总开关的影响。
4. 首次选择公交车后修改两项被动保存值；切换方向、强制开关、保存重载、穿脱装备，确认保存值不被重复重写。
5. 分别向已有配置和未初始化的身体植入人格，并生成新兔克隆，核对配置归属、独立性和默认标记。
6. 在备份测试存档中确认批量应用，核对其他地图、商队及运输中的角色，检查结果计数和两个全局开关保持原样。
