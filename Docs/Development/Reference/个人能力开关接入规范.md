# 个人能力开关接入规范（1.7）

基线：通用框架三批专项，2026-10-24，约定范围已完成并获维护者实机认可；暂不发布。本规范用于现有五项开关和后续同类布尔能力，不迁移工作／任职／排程、全局设置或枚举配置。1.6／Common 保留冻结产物。

本文件是后续开发继续使用的接入规范；专项规划与验收记录归档后仍适用。仓库级约定见 [AGENTS.md](../../../AGENTS.md)。框架统一个人布尔能力的声明、读取、提交及共用 UI 行，各 ITab 区域继续负责自己的布局。身份选择、任职、训练启停、排程、行为许可、全局设置、枚举、颜色／透明度等按各自业务语义处理；依赖／互斥、批量模板及旧字段迁移另行设计。

## 1. 先确定唯一保存源

展示分组不决定保存归属。已有字段继续由其原载体保存；给它声明稳定能力 ID，并通过后端适配，不能再向人格字典保存一个同名 bool。

| 稳定 ID | 唯一保存源／缺省 | 归属及生命周期 |
| --- | --- | --- |
| `SSC_MasterDesireInfestation` | `sscAbilityToggles/enabledById` 字典键，缺键 false | 人格：提取／加工独立复制，成功提取后清字典，植入精确覆盖，新生克隆回定义默认；身份／空壳／替换只暂停实际准入 |
| `SSC_MasterDamageSharing` | 缰绳 `shareDamageEnabled`，新实例／缺字段 true；无缰绳查询 false | 关系：不进入人格字典，不自动将原缰绳选择搬给新缰绳；实际分伤仍检查原目标和伤害条件 |
| `SSC_MilkProduction` | Comp `milkProductionEnabled`，初始／缺字段 true；无 Comp 的原生产读取 true | 原历史字段随人格采集、凝胶保存／加工并在植入时覆盖；通用清字典不重置原体残值，克隆也不额外套用字典清理 |
| `SSC_UterusFertility` | 子宫开发 Hediff 的 `sscUterusFertilityEnabled`，缺字段 false | 身体：只读使用原有效 `FertilityEnabled`，人格标签过滤开发记录；健康复制沿原进度规则，新记录不开启生育，既有选择仍受复制后完成度规范化约束 |
| `SSC_GelRendering` | 外观组件 `sscGelRenderingEnabled`，新身体 true | 身体：旧档缺个人字段仅一次继承旧全局设置；明确 true／false 强制保存。身体外观复制走原工具，成熟不覆盖已有 owner 的选择，不进入人格能力快照 |

历史例外需要保留：`StorePawnData` 仅在来源有训练 Comp 时复制泌乳字段；复用凝胶采集无 Comp 的身体时，旧字段沿既有条件分支保留。不要将普通生产 getter 的“缺 Comp 默认 true”擅自套到这条采集路径。完整克隆还受原版 Duplicate、SSC 健康复制及关系修复顺序影响，不能把“清人格字典”解释成重置全部五项。

未来**真正属于人格**的新能力可以复用原字典；缺键按声明默认值查询，明确 false 和未知键都要保留。新增默认 true 能力的新生克隆应回到 true，而非统一写 false。已有字段迁移必须另立版本与旧档迁移方案，本框架不执行隐式迁移。

## 2. 实现适配器与注册描述

沿 [SSCAbilityToggleBackend](../../../Sexslavecraft/common/SSCAbilityToggleFramework.cs) 实现以下职责；可以直接参考[泌乳](../../../Sexslavecraft/common/SSCMilkAbilityToggleBackend.cs)、[生育](../../../Sexslavecraft/common/SSCUterusAbilityToggleBackend.cs)、[凝胶](../../../Sexslavecraft/common/SSCGelRenderingAbilityToggleBackend.cs)或[缰绳](../../../Sexslavecraft/common/SSCBridleAbilityToggleBackend.cs)后端。

| 接口 | 契约 |
| --- | --- |
| `GetEnabled` | 只读唯一保存源，保留其旧默认和缺组件回退，不创建组件／Hediff／字典键 |
| `ActivationFailure` | 描述能力当前通用准入，不重做某一次生产、伤害或渲染事件的完整业务判断 |
| `ChangeFailure(pawn, definition, target)` | 按**目标值**委托原权威检查，返回可翻译的具体原因；不把身份、研究、绑定或空壳条件从其他能力照搬过来 |
| `CaptureOwner`／`IsOwnerCurrent` | 捕获并核对同一载体实例，禁止以同 Def、同 ID 或重新查询的新实例替代旧请求凭据 |
| `SetEnabled`／`TrySetEnabled` | 只写原载体；原 setter 会拒绝时覆盖带 bool／原因的入口，回传实际结果。健康通知、快照发布、Revision、局部刷新与同值幂等仍交给原业务模块 |

注册 `SSCAbilityToggleDefinition` 时填写稳定 ID、Group、Identity、原翻译键、DefaultEnabled、Backend，以及必要的 Order／VisibleRule／目标值或提示规则。`Identity` 对默认人格后端有实际含义；身体后端不能仅因它是 `Unset` 就新增“必须未设身份”的门槛。

`Group` 只决定展示区域；`VisibleRule` 只决定当前行是否出现，不代替提交校验。`DetailRule` 仅供只读从属信息，现用于原泌乳充盈度，不在查询中结算生产或新增重复进度行。没有 marker 的能力必须保持 `MarkerDefName=null`。

新增生产文件只纳入 1.7 工程。模型宿主通过 `AbilityToggleProduction.targets` 启用 `SSC_ABILITY_TOGGLE_SCOPED_TEST`，再显式链接并启用对应 BODY／GEL／MASTER_SHARE 能力；实际 1.7 不定义该测试常量，始终注册五项。不要为了满足部分宿主编译而给其他载体编写假业务后端。

## 3. 复用 UI 上下文提交

按区域调用 `BuildAbilityToggleRows`，在同一次 GUI 事件中复用测量和绘制快照。身体区域按注册顺序生成行；当前凝胶区域只选取渲染行，颜色／透明度和弹窗继续由原外观模块维护。未来新增外观控件应提供适合自己的区域，并复用公共行／提交，不能假定它会自动变成现有调色窗口的一部分。

现有主人／性奴／身体区域按组生成行；`BuildAbilityToggleRows`、`DrawAbilityToggleRows`、`TrySetAbilityToggleRow` 是 `ITab_SexSlaveTraining` 的私有成员，供该 partial 类的各区域复用。其他 ITab 可使用公共 `GetView`／`TrySet` 查询与提交；需要共享绘制器时另行提取，不假定当前私有方法已是跨 ITab 的公共页面接口。

提交使用捕获行的 `SSCAbilityToggleContext`，由 `TrySetAbilityToggleRow` 再进入 `SSCAbilityToggleUtility.TrySet`。上下文包含原 Pawn、定义、Comp、人格 token 及 owner；允许无训练 Comp 的原外观入口继续保存 null Comp 凭据，但组件后来改变时仍失效。禁止点击时重新调用 `GetView` 来重拍凭据，否则会把旧请求授权给替换后的载体。

公共入口按原上下文检查、目标值预检、写入前再查、原 setter 及回调后再查的顺序执行。失败不承诺完整事务回滚。`CanChange` 是下一次反向切换的显示资格；外层 GUI 禁用、原版复选框 disabled、选中角色和提交入口都要保持保护。

旧 `TrySetEnabled(pawn, id, enabled, expectedComp, token)` 仅兼容人格字典后端。身体与关系必须传完整上下文。展示 Enabled、通用 Active 和当前可编辑资格不能混为一个 bool。

## 4. 实际消费者与通知来源

消费者应复用同一保存源读取，但保持原事件规则。普通泌乳／牛储液／牛特化走原字段公共 getter；分伤走原缰绳 getter。凝胶绘制继续用原不可变快照及 `ShouldRender`，不在热路径遍历注册表或写状态。生育直接走原身体工具，完成度、妊娠和健康计算不复制到框架。

| 事件 | 当前协调范围 |
| --- | --- |
| 完整读档／新游戏初始化 | `SSCAbilityToggleGameComponent.FinalizeInit` 一次性遍历既有地图／世界角色，协调派生 marker，不预填字段或新增 Tick 轮询 |
| 身份改变 | `SSCIdentityUtility` 的原 setter／恢复入口按最终身份同步；身体和关系字段不随人格资格失效被清空 |
| 人格提取／植入／清源／克隆 | `ClearPersonalityState`、`RestorePreference` 和 `MutationScope.Dispose` 协调最终 marker；Begin 立即换 token，实际人格收益查询在替换期间暂停 |
| 健康 AddHediff／RemoveHediff | 现补丁只监听通用／注册 marker 和空壳；自身通知合并为最多四轮，清孤儿、去重并按最终偏好协调 |
| 死亡／成功复活 | 原 Postfix 协调 marker；失败复活不伪造恢复，偏好保留 |
| 身体阶段、妊娠、owner 替换 | 原 getter／权威 setter 即时查询，旧上下文失效；三项新后端没有独立 marker，无需新增全图健康监听 |

marker 是派生显示结果，不是实际收益的保存源。若未来注册能力依赖新的资格事件，接入者必须安排该事件的 `SyncMarkers`，不能假定现补丁监听任意字段赋值、直接改健康列表或外部自定义规则。对未发事件的原始修改，实际消费者仍查询最终资格；读档初始化可再协调显示，但不要以此替代正确通知。

人格替换是作用域保护，不是通用身体冻结。身体后端沿各自原 setter 检查；不能为“所有开关一致”而新增统一的人格暂停规则。异常和提前退出均应释放已有作用域，保持原流程既有的失败／清源顺序。

## 5. 接入验收与维护

- 旧档缺节点／缺字段、明确 true／false、未知键、只读不补建；原字段名、默认和迁移例外保持。
- 来源／宿主四组合，提取清源、凝胶加工副本、植入后的容器独立；身体／关系不被人格字典覆盖。两条提取入口分别覆盖成功、拒绝及异常范围。
- 新生克隆回定义默认，成熟不覆盖后取得的偏好；泌乳和身体复制按原流程建立对照，不能只测一个新的适配器。
- 身份退出／恢复、空壳、死亡／成功与失败复活、加载期、Comp／人格／owner 替换和迟到点击；marker 去重、有界重入与实际准入一致。
- 复用现有宿主扩展用例；真实 Comp／Hediff 序列化与模型 Scribe 要分开登记。实际 Pawn 世界跨引用、完整 RJW、GPU 与第三方组合仍需按明确范围实机确认。
- 原生专项可用 `SscAssemblyPath` 引用当前隔离候选，核对实际加载哈希；生产构建使用匹配的游戏及依赖引用，不覆盖仓库正式产物来伪造通过。
- 同时记录机制回归、统一／发布门禁和实机结果。元数据或其他前置检查失败时不能宣称发布门禁通过，也不能通过改写旧 BUILD-INFO 消除历史差异。

函数注释写清保存源、缺省、目标值规则、owner 和副作用；代码块注释解释顺序与历史例外，不复述语句。后续同类能力只补对应注册／后端／区域接入和必要事件，不逐项改写公共人格提取链。
