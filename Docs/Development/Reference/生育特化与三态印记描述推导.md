# 生育特化与三态印记描述推导

整理日期：2026-10-31。本文是[设定依据](孕母与三态印记设定依据.md)与[文案交接清单](生育特化与三态印记文案交接清单.md)之后的**描述推导**：基于对每项设定的整体理解，推导每处待补写的描述正文「应当写什么信息」与「可以补充的新增信息」，并标注不可写的边界。

本文**只推导信息内容，不提供正式定稿文案**。七处占位正文、五档阶段名及各语言译名仍待起稿、审阅；此前候选稿未被采纳，本文不视为授权改写机制、数值、资格或技能流程。写作风格可参考[文案经验](文案经验/README.md)。

## 0. 总体写作原则

以下原则适用于全部描述正文，个别条目再有补充时在各节标注。

1. **第三人称设定说明，可带色情化意象，不写第一人称自白。** 三态印记与特化的 `description` 是健康页／研究页的说明性文字，采用与「欲望之种」一致的世界观说明写法（如「泛着幽紫光泽……像是在等一个愿意接纳它的人」）；征服的快感、被征服、淫欲、紫色微械等设定意象可以进入正文，但不要把 Hediff 描述写成[心情类文案](文案经验/偏色情化-心情标题与描述.md)的第一人称沉溺自白。
2. **定性不列数值。** 更健康、聪慧、敏感、不老等只作定性；`PsychicSensitivity`、`LifespanFactor`、`fertilityFactor`、`careFactors`、免疫清单等数值与效果以实际 Def 为准，健康详情已有属性展示，描述不另造一套效果表。
3. **避免复述与罗列。** 描述体现设定定位，不反复复述属性信息；具体操作、资格、数值由既有功能说明与健康属性展示承担（设定依据 §5）。
4. **不借文案变更机制。** 名称与描述可补充设定表现，但不改变数值、资格、人格保存归属、绑定／解绑规则、技能流程或胎儿调控的界面归属（交接清单 §5）。
5. **名称／键／参数与四语稳定。** 只改确认范围的文本；DefName、语言键名、`{0}` 参数与 XML 结构保持稳定；中文定稿后三语译名、正文与名称引用成套一致（交接清单 §6）。

## 1. 三态印记（F1，3 处描述）

三态共用互斥 Hediff，核心是「紫色微械的融合程度」与「方向」：初始态未分化，主人态与性奴态是同一彻底融合的两种方向，互相对应、不可混写。描述应体现「同源、两方向、一未分」的整体结构。

### 1.1 淫欲之子（初始印记，`SSC_ImprintInitial.description`）

- **设定核心**：来源是孕母子宫中的紫色微械改造与融合；未分化的微械潜能；儿童期表现限于健康、学习与感知；成年后在征服或被征服的快感中进一步融合而蜕变（设定依据 §2）。

**应写信息**：

1. 出身来源——在孕母子宫中经历紫色微械的改造与融合。
2. 定性表现——比常人更健康、聪慧、敏感（不列数值）。
3. 未分化——体内蛰伏尚未定型的微械潜能，当前仍是初始态、方向未定。
4. 儿童期表现——限于健康、学习与感知（成人征服／被征服设定不提前到儿童期）。
5. 蜕变条件——成年后将在征服或被征服的快感中进一步融合，蜕变为主人态或性奴态，方向由之后的绑定事件决定。

**可能的新增信息**（设定允许、可补的设定表现）：

- 描写紫色微械「尚未苏醒、随成长沉淀」的意象，落实「未分化潜能」。
- 用「与生俱来的敏锐／躁动」表现「敏感」与「潜能」。
- 可含蓄点明印记随人格流转（呼应凝胶与人格迁移，但避免长篇复述）。
- 暗示与主人／性奴的绑定是它分化的契机。

**不可写边界**：

- 不写成已分化、已锁定身份（初始未定型，永久锁是分化态规则）。
- 不写年龄上限／停龄（那是分化态规则，初始态不冻结年龄）。
- 不列数值（心灵敏感 +0.25、学习倍率等）。
- 不写成免疫疾病。
- 不把成人色情设定提前到儿童期。

### 1.2 淫欲之主（主人态，`SSC_ImprintMaster.description`）

- **设定核心**：来源是现有主人由额外欲望之种获得、或成年淫欲之子首次成功绑定性奴时转化；在征服的快感中彻底融合，更健康、聪慧、敏感、不老；以淫欲征服、支配他人；核心是征服、支配、彻底融合（设定依据 §3）。

**应写信息**：

1. 彻底融合——紫色微械在征服的快感中彻底苏醒／融合。
2. 方向——征服、支配他人。
3. 来源——欲望之种（额外一枚）或成年淫欲之子首次成功绑定性奴时转化。
4. 定性表现——更健康、聪慧、敏感、不老（「不老」以停龄落实，不作效果表）。
5. 永久身份锁——主人身份永久，不随解绑解除。

**可能的新增信息**：

- 「微械已完全苏醒，将身体塑成支配者的形态」意象。
- 「以快感为权柄／缰绳征服他人」的表现。
- 与性奴态成对的意象（同源彻底融合、方向相反）。
- 「不老」可含蓄落实为「生理不再自然衰老」的定性（不写具体年龄数字）。

**不可写边界**：

- 不写成免疫一切伤害或疾病（免疫范围仅为伤口感染／肠道寄生虫／肌肉寄生虫，以健康详情为准）。
- 不列数值（心灵敏感 +0.5、寿命 ×3、脆弱度 ×0.25 等）。
- 方向与效果不与性奴态混写。
- 不写「可被解绑解除」，主人锁是永久的。

### 1.3 淫欲之奴（性奴态，`SSC_ImprintSlave.description`）

- **设定核心**：来源是现有成年性奴由欲望之种获得、或成年淫欲之子首次被绑定为性奴时转化；在被征服的快感中彻底融合，更健康、聪慧、敏感，永世为淫欲的奴隶；核心是被征服、臣服、彻底融合，与主人态对应（设定依据 §4）。

**应写信息**：

1. 彻底融合——在被征服的快感中彻底融合。
2. 方向——臣服，永世为淫欲之奴。
3. 来源——欲望之种（一枚）或成年淫欲之子首次被绑定为性奴时转化。
4. 定性表现——更健康、聪慧、敏感。
5. 永久身份锁——性奴身份永久，不随解绑解除（性奴可换主）。

**可能的新增信息**：

- 「身体被微械重塑为取悦／臣服之姿」意象。
- 「只对征服的快感俯首」的表现。
- 与主人态对应的意象（同一彻底融合的臣服一极）。
- 「永世为奴」的宿命感。

**不可写边界**：

- 不写成免疫一切伤害或疾病；不列数值（脆弱度 ×1.5、性频率 ×1.5、高潮频率 ×1.25 等）。
- 方向不与主人态混写。
- 不写成可自愿解除。

## 2. 生育健康状态（F2，2 处描述）

### 2.1 普通孕母（`SSC_Hediff_Fertility.description`）

- **设定核心**：孕母特化使成年性奴完全掌握自身已经完成改造的子宫，更好地养育孩童，让妊娠遵循主人的意志；以完成子宫改造为基础，体现对改造后身体的掌握与养育能力（设定依据 §1）。

**应写信息**：

1. 基础——完成子宫改造为前提。
2. 掌握——驾驭／掌握已完成改造的子宫。
3. 养育能力——更好地养育孩童（育儿、授课、陪玩的定性）。
4. 定位——让妊娠遵循主人的意志（仅作设定定位，不写成新指令／门槛）。

**可能的新增信息**：

- 「子宫被驯化为服从主人意愿的器官」意象。
- 「把孕育化为对主人的侍奉／奉献」的表现。
- 可与紫色微械世界观含蓄呼应（避免越界发明机制）。

**不可写边界**：

- 不列数值（`fertilityFactor` 1～1.8、`careFactors` 等；健康详情／研究功能说明已有）。
- 不凭「按主人意志控制妊娠」新增指令或绑定门槛（交接清单 §5 明确）。
- 普通 Hediff 名与阶段 1 名一致（均为「孕母」），描述不与之冲突。
- 不与终极描述混同。

### 2.2 终极孕母（`SSC_Hediff_Fertility_Final.description`）

- **设定核心**：普通培养完成后在雕刻台加工人格凝胶并重新植入的最终形态；生育、育儿进一步强化，并解锁专属技能。

**应写信息**：

1. 终极化路径定性——普通培养完成后加工人格凝胶并重新植入（一句话，不展开全流程）。
2. 最终形态——子宫的掌握达到极致，生育／育儿能力进一步强化（定性）。
3. 专属技能——获得专属技能「受孕」（一句话，不展开流程）。

**可能的新增信息**：

- 「子宫与人格凝胶／微械深度结合的最终之姿」意象。
- 「完全听命于主人意志的孕育容器」表现。

**不可写边界**：

- 不列数值（`fertilityFactor` 2）。
- 不重塞「成果保留、跨方向生效」等大段解释（交接清单 §5）。
- 不混淆普通与终极。

## 3. 生育研究（F3，1 处设定正文）

`SSC_RES_Fertility.description` 由「设定正文 + 【培养途径】＋【功能概况】＋【终极化】」构成。本次只补开头 `（描述文案待编写）` 的**设定正文**，后三段功能说明原样保留。

- **设定核心**：研发孕母特化，本质是找到训练与进一步改造性奴的方法，使其能够按照主人的意志控制已经完成改造的子宫（设定依据 §1「研究的本质」）。

**应写信息**：

1. 研究本质——发现／掌握训练与进一步改造性奴、使其驾驭已完成改造子宫的方法。
2. 方向定位——孕母特化（掌握改造后子宫 + 养育 + 妊娠随主人意志），作为世界观导言承接后续功能三段。

**可能的新增信息**：

- 「在子宫改造之上，身体还留有一层可被进一步驯服的可能」。
- 点出研究聚焦「驯服子宫、令其为孕育之主（主人）所用」。

**不可写边界**：

- 不列收益数值（研究说明继续不列数值）。
- 不替换、吞并后三段功能说明。
- 自克隆：设定正文不涉及；如触及末尾「自克隆后续开放」预告，须与「自体克隆暂缓」一致，不写成当前可用或近期确定开放（本轮不改该原文）。

## 4. 专属技能（F4，1 处描述）

`SSC_FertilityConception.description` 目前为「（描述暂待编写）+ 功能说明」。需补正式描述，同时**保留准确功能信息、不能丢或改反行为**。

- **设定核心**：全图选同图非敌对成年类人对象 → 实际走近 → 同场性行为正常完成 → 施法者自身受孕；成功起算 7 游戏日冷却；中断不受孕、不扣冷却；孕期及临产禁用（交接清单 §5、完成核对）。工作提示 `reportString` 为「正在采样孕育」，设定语义是「采样」。

**应写信息**：

1. 设定正文——终极孕母专属技能「受孕」的定位：选定对象作为孕育样本，通过同场交合使施法者自身受孕，让妊娠按自身／主人意志发生（可呼应「采样」语义）。
2. 保留功能说明——全图选非敌对成年类人对象 → 走近 → 正常完成性行为 → 使自身怀孕；建孕成功冷却 7 天；中断不受孕、不扣冷却；孕期及临产禁用。

**可能的新增信息**：

- 「采集对方的精华、纳入自身孕育」的色情化意象（呼应「采样孕育」）。
- 「以交合为引，让自身受孕」的表现。

**不可写边界**：

- 不写成远程原地建孕、单独读条或成功后另排性交。
- 自指分支未开放，不写可自指。
- 不改变资格、保存归属或已验收技能流程（7 天冷却为功能事实，保留）。

## 5. 五档阶段名（F2，5 档）

阶段递进须围绕已定「孕母／终极孕母」成套设计，保留「性奴特化（……）」标签格式；阶段 1 名与普通 Hediff 名当前相同，属同套命名的两个落点，**不得起成不一致的名称**（交接清单 §3）。

**命名逻辑推导**：

- 阶段 0（培养中）：未成孕母的进行态，由「生育培养中」自然替换为「**孕母培养中**」。
- 阶段 1：与普通 Hediff 名一致 →「**性奴特化（孕母）**」。
- 阶段 2～4：沿用既有「熟练 → 精通 → 完全」递进，把核心词从「生育」替换为「孕母」：
  - 阶段 2：性奴特化（**熟练孕母**）
  - 阶段 3：性奴特化（**精通孕母**）
  - 阶段 4：性奴特化（**完全孕母**）

**可能的新增信息（命名体系）**：递进可围绕「掌握子宫／养育能力的深浅」，若需更贴合「孕母」语义，可在保持「性奴特化（……）」与既有「熟练／精通／完全」体系统一的前提下微调修饰词；避免另起一套造成不一致。

**不可写边界**：

- 阶段 1 名不得与普通 Hediff 名（孕母）不一致。
- 不得脱离「性奴特化（……）」标签格式。
- 不得继续以「生育」为核心词，与已定「孕母」冲突。
