## 1. 本稿相较 v1 的改动

v1 的主要问题不在机制覆盖，而在**表达与契约**：整稿偏临床说明文，缺少本模组既有文案的色情质感；且夹带了已移除的面板细节、不存在的占位符，以及与现行实现不符的起点／模式结构。本稿按下列口径重写：

| 项 | v1 的问题 | v2 的处理 |
| --- | --- | --- |
| 语感 | 通篇“稳定驻留／器官调节／倍率”的说明腔，读不出“性奴开发”的情色味 | 叙事重点（研究、手术、Hediff 长描述）改用模组既有“微械／恶堕／欢愉／受孕”语域，见第 3 节 |
| 参数契约 | 使用 `{PAWN}`、`{PROGRESS}`、`{STAGE}`、`{RESEARCH}` 等审稿占位 | 只保留代码实际提供的 `{0}`：`Started` 为进度百分比、`Factor` 为倍率数字；其余键不加入未提供的变量 |
| 起点 | 示例用初始 0% | 成功手术后为 1%，`Started` 的 `{0}` 由代码填入“1%” |
| 界面 | U01、U05～U08 及两态预览面板已从身体管理栏移除 | 不恢复独立标题／进度／阶段／收益／生育状态面板；阶段与收益仍由健康页 Hediff 展示 |
| 满级两态 | 当成面板里的“模式名＋描述” | 两态就是 Hediff 的第五、第六个阶段 `label`，须分别定稿，不共用“已完成” |
| 泌乳叠加 | 旧的 SSC 永久泌乳叠加边界 | 采用现行规则：满级且开启生育时 SSC 泌乳抑制临时中和为 ×1，退出后读取当前源配置、保留 HumanCattle ×1 及其他不育因素 |

## 2. 范围与字段映射

本稿覆盖清单第 1 节的 **12 处 Def 文本字段**与**简体中文 32 个 Keyed 键**。四语（繁中／英语／俄语）落地与 DefInjected 新建不在本稿范围，仍按清单第 4 节另行处理。

- **叙事重点**：研究 `description`、手术 `description`、三条三态正文（`SSC_UterusDevelopment_Description*`），以及阶段名与成功消息。
- **配置／失败提示**：保持清晰直接，只做措辞顺滑，不为色情化牺牲“一眼看懂哪里不满足”。
- **禁止出现**：Hediff、Severity、Harmony、字段名、类名、×2.5 当作固定受孕概率、“直接致死概率为 0”写成“完全无风险”、材料与前提清单塞进手术描述。

## 3. 用语与色情化尺度

沿用既有术语：**紫色微械**、**浓缩紫色纳米催情液／浓缩纳米催情液**、**纳米催情液**、**性奴**、**调教**、**欢愉（侵蚀）**、**恶堕／刻印**、**永久泌乳**。

色情化的分寸对照旧六部位（`HediffOfTrain.xml`）：“内部已被纳米微械彻底重构……异常美丽敏感，且能分泌紫色纳米液”一类——用“微械寄生／蛰伏、宫腔、交合、欢愉、受孕、孕宫、主人摆布”营造身体改造与顺从的暧昧感，不堆砌粗口，不出现与玩法无关的强暴／排泄化词。子宫开发是“生育向”而非“肉便器向”，故不借用“肉便器化”。

子宫／花房的语域：正文可用“子宫／宫腔／深宫／花心／花房”，同一篇内不混用过多别称；建议固定“子宫／宫腔”为主、“深宫”仅用于阶段名点缀。研究名因需覆盖胃等后续内脏开发，不采用子宫专属的“深宫”。

## 4. 研究（ResearchDef）

> 字段位置：`1.7/Defs/ResearchDefs/SSC_UterusResearch.xml` 的 `SSC_RES_UterusDevelopment` 的 `label`、`description`。

### R01 研究名称

**纳米催情液内脏改造**

> 与既有“纳米催情液医美应用”同构，直接点明“纳米催情液对内部器官的改造”，并覆盖后续胃等更多内脏开发手术。不把 2000 点／双前置等配置写进名字。

### R02 研究描述

> 用药物把浓缩纳米催情液调成能长久保持惰性的制剂，使药力在送往体内深处的途中不致提前渗散，直到抵达目标器官后才开始起效。如此，便能把这种催情的药力牢牢种在身体最深处，一点一点地改造内部的器官。

（本研究在中世纪即可解锁，描述不使用“微械”一类科幻词汇；研究点数、前置、研究台继续由研究树显示。）

**子宫开发手术**
