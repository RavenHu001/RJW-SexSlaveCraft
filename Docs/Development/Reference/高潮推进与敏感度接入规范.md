# 高潮推进与敏感度接入规范

**核对日期：** 2026-10-28。适用于当前1.7实现；首版及后续界面／通用Stat已获维护者实机认可，见[完成核对](../Completed/个人高潮敏感度系统完成核对.md)。本文记录现行接口与维护边界，历史依据见[归档设计](../../Design/Archive/RJW个人高潮敏感度调节开发规划.md)，独立框架候选仍在[未来规划第27.1项](../../Design/未来内容开发规划.md)。

## 1. 三种数据分开消费

| 数据 | 现行入口与语义 |
| --- | --- |
| 原始推进 | `SSCOrgasmProgressUtility`，只读采样原生计数／阈值的距离变化，不混入SSC补充，不要求SSC身份 |
| 当前最终倍率 | `SSCOrgasmFrequencyUtility.GetMultiplier(pawn)`，读取`SSC_OrgasmFrequency`经原版Stat合成后的最终值；无SSC身体记录也能生效，默认及异常回退×1 |
| SSC身体选择 | `SSCOrgasmSensitivityUtility.GetState(pawn)`，返回保存档位、实际档位、资格及本来源参数；`state.Multiplier`仅是SSC档位倍率，不能当成最终Stat再次相乘 |

`SSCOrgasmSensitivityUtility.GetMultiplier(pawn)`当前转发最终Stat查询；不要仅凭方法所在类名推断它要求敏感度Hediff。Stat最低×1，当前只加速；×1不积累或深存执行余数，逐次推进不为其新建执行状态，但Toil构建／加载仍可建立恢复观察State。它不自动给予所有角色新的增益。

第48项[PNA与五部位属性补全](../Completed/PNA与五部位高潮频率属性补全完成验收.md)已于2026-10-31实机验收：PNA两组五档提供factor，五部位开发提供offset，沿原版先加后乘合成；五部位满级合计+0.50，子宫满级双态相同。最终参数与来源边界见完成记录，其他Hediff候选已撤销。

## 2. 原始推进公共接口

实现位于[SSCOrgasmProgressUtility.cs](../../../Sexslavecraft/common/Orgasm/SSCOrgasmProgressUtility.cs)。在游戏线程、同一次可信写回边界使用：

1. 观察者持有自身发行的`SSCOrgasmObservationContext`，包括来源、发行者实例、非零周期号和操作号；写回前调用`CaptureBeforeAdvance`。
2. 原写回完成后、任何消费者修改计时或触发高潮前，调用`TryGetOriginalAdvance`。当前凭据必须来自发行者当前状态，不能复制旧快照的Context自证有效。
3. 成功后共享不可变的`SSCOrgasmAdvance`，不在倍率写回后再次差分。`RawAdvance = CounterAdvance + ThresholdAdvance`，整数距离使用long；有效零量与采样失败不同，按返回值／Failure判断。
4. 使用前可调用`IsStillCurrent`。自动采样使用无Context重载，核对采样器当前凭据及其认可的SSC补充终态；外部观察者使用带当前Context的重载，只认可`advance.After.Counter`原始终态。自动样本已被SSC补充后，不能用后一个重载验证它。任务、驱动、SexProps、周期变化或加载阶段会使样本失效。

`TryGetLastObservedAdvance`只读取当前自动采样器最近一次仍有效的结果，不提供历史队列，不补采遗漏操作，也不保证高潮事件完成后仍有样本。自动采样会另外记录自身消费者认可的终态，原始After及RawAdvance保持不变。

`External`只有在构造凭据时显式传入`allowThresholdAdvance: true`，才允许观察者声明阈值也参与推进；单独选择该来源仍默认禁止阈值变化。它不是自动适配入口，不能据此向内置倍率消费者注册任意计时器。公共接口本身不写计时、不调用Orgasm、不发行奖励，也不保存执行状态。

## 3. 档位、属性与持续心情

SSC身体选择仅由`SSC_OrgasmSensitivity` Hediff的Severity保存，关闭时不保留该记录；不向人格字典另存枚举或倍率。查询不补建身体记录。保存选择与实际档位分离，降阶裁减实际档位而不改保存值。主人死亡／离图后继续遵循原指令；解绑、锁链或身份失效时撤销SSC效果，外部Stat来源仍按自身规则生效。

UI或其他调用方先`Capture`，用同一上下文执行`CanSet`／`TrySet`。提交复核原Pawn、Comp、人格token、锁链／主人及身体实例；不得在旧菜单点击时重新Capture来取得新载体权限。此枚举不接入个人bool能力存储。外部功能优先调用此入口，不直接写Severity或健康列表。

机制参数来自[Hediff配置](../../../1.7/Defs/HediffDefs/SSC_OrgasmSensitivity.xml)及[持续思想配置](../../../1.7/Defs/ThoughtDefs/SSC_OrgasmSensitivity.xml)：四档倍率2／4／8／16，脆弱度偏移+0.30／+0.75／+1.50／+3.00，阶段上限依次1／2／3／4，心情按实际档位与阶段的十格矩阵派生。身体档位只作为最终Stat的一个factor来源，推进端不再乘一次档位。

档位属于身体，不随人格提取／加工转移。兔分身初生复制一次，成熟不再覆盖分身后来的选择或重建已关闭记录。派生属性与心情不作为第二保存源。

## 4. 统一执行、恢复与适配边界

原始写回已完成，执行端只补`原始推进量×(最终倍率−1)`；合并小数余数后取整，额外整数推进截断到当前阈值，超额整数丢弃、理论小数仍保留。达到阈值不等于确认真实高潮，周期或真实事件变化另行清理。无倍率分档分支、固定最短等待、按倍率循环补发或额外ProcessSex，也不改变场景总时长。

每次操作按发行者／周期／操作去重，同tick多次有效原推进可分别消费。极高倍率的数学运算不按倍率循环；真实高潮事件自身的成本及原事件检查频率仍存在，不能承诺任意频率或任意模组组合的固定开销。

执行余数沿当前JobDriver深存`sscOrgasmAdvanceState`格式1。恢复校验角色／任务、可选SSC载体、最终倍率位指纹及完整周期；SSC引用允许为空。等原生Toil构建和必要的自我调教计时恢复完成后，才接受合法小数；新周期、未知重设、上下文变化或构建失败不重放旧推进。读档后尚未推进就再次保存也须经过同一验证。

当前采样覆盖本机RJW SexTick两处、动画替代Prefix一处及UAP两处真实写回。有效排序、转换集合及恢复屏障失败时，关闭对应采样／恢复能力并保留原流程；第三方独立计时器须按实际写回适配。不能把角色范围通用等同于所有计时mod自动兼容，亦不能以基类Setup补丁推断所有override已覆盖。
