# 训导官弱化记忆套实现与测试记录

实现日期：2026-10-09（续训导官职责反馈）。分支：`codex/trainer-duty-feedback`。起点为已含 `65f67c5` 的 `92739c2`。提交 `a5e73436a1345289b5879f03897979f61fae4994`，已推送到远端同名分支。仓库版本仍为 2.3.8，属于未发布开发内容。

本轮按维护者确认的口径实现：训导官与主人的调教心情／社交记忆**共存**，但训导官效果**较弱**；单次结算**只发一套**。数值口径经维护者在实现前确认：弱化系数 **K=0.5**，弱值**四舍五入到整数**，并对非零基准**保底绝对值 1**。自动回归与真实依赖 Release 构建已通过，实机验收尚未开始。

### 1.1 弱值口径

弱值 = `RoundAwayFromZero(主人运行基准 × 0.5)`，当基准非零而结果被舍入为 0 时取 `±1`。

| 模式／感受 | 主人运行基准 | 弱套值 |
| --- | --- | --- |
| 新模式心情：反感／动摇／适应／沉沦 | -10／+2／+8／+15 | **-5／+1／+4／+8** |
| 新模式社交 | D | `WeakValue(D)`，D=±1 时保底 ±1 |
| 旧模式心情：厌恶／迷茫／极乐 | -10／+2／+15 | **-5／+1／+8** |
| 旧模式社交：反感／适应／沉沦 | -20／**+5**／**+15** | **-10／+3／+8** |

旧模式一列使用**运行基准**：`SSC_Training_Social_Lvl2/3` 的 XML 写的是 +10／+40，由 `SSCThoughtBootstrap` 启动时改写为 +5／+15，因此弱值是 +3／+8。弱套旧社交的 XML 直接写入运行后的整数，**不再进入启动修正**。

## 2. 本机程序集核对

实现与回归期间反汇编本机 `D:\STEAM\steamapps\common\RimWorld\RimWorldWin64_Data\Managed\Assembly-CSharp.dll`（只读元数据，不执行游戏代码），得到以下决定实现的契约：

| 结论 | 证据 |
| --- | --- |
| `ThoughtStage.baseOpinionOffset` 与 `baseMoodEffect` 都是 `Single` | 字段类型反射 |
| `Thought_Memory.forcedStage` 就是 `CurStageIndex` | `get_CurStageIndex` 方法体仅 7 字节，直接读该字段 |
| 阶段以 `stageIndex` 键原生保存 | `Thought_Memory::ExposeData` 中含 `Scribe_Values.Look(..., "stageIndex", 0, ...)` |
| `Thought_MemorySocial::GroupsWith` 只比较定义与对象，**不比较阶段** | 方法体 38 字节，调用基类后仅比较 `otherPawn` |
| 社交记忆不参与合并，每次新增 | `Thought_MemorySocial::TryMergeWithExistingMemory` 直接返回 false（5 字节） |
| **容量由“移除最老一份”维持，而不是刷新年龄** | `MemoryThoughtHandler::TryGainMemory`：合并尝试失败即 `Add`，随后 `while (NumMemoriesInGroup > stackLimitForSameOtherPawn) RemoveMemory(OldestMemoryInGroup(...))`，再对 `stackLimit` 重复同样循环 |
| `opinionOffset` 由 `Init()` 从阶段定义值填入 | `Thought_MemorySocial::Init` 方法体 24 字节 |
| 分组在人物不同时退回标签比较，而该标签含对象短名 | `Thought_Memory::GroupsWith` 方法体 57 字节：先比定义与阶段索引，再比 `otherPawn`，不等时比较 `LabelCap`；`Thought_Memory::get_LabelCap` 会把 `otherPawn.LabelShort` 格式化进标签 |

由此确定：

1. 弱动态社交**必须**覆写 `GroupsWith` 增加阶段比较，否则沉沦与适应会合并。
2. 弱动态社交**不需要**新增任何存档字段。
3. 弱动态社交**不能**只覆写 `LabelCap`：分组兜底依赖含对象名的标签，因此 `LabelCapSocial` 必须把实际执行者短名格式化进去，否则同一受训者面对两名训导官的同档记忆会被误判为同组。
4. 重复训导官工作的容量表现是**移除最老一份**，而不是刷新期限；这一点与首版职责心情（`stackLimit=1` 走 `Renew`）不同，回归按真实语义断言。

## 3. 实现中发现并修正的缺陷

| 缺陷 | 现象 | 修正 |
| --- | --- | --- |
| `Resolve` 把从未任职的普通性奴误判为失格训导官 | 普通性奴执行者本次完全不发记忆，丢失既有反馈 | 改为按“是否明确开启过训导官身份”（`trainerIdentityInitialized`）区分失格与从未任职；旧档未初始化者仍走原套 |
| 覆写 `LabelCap` 破坏原生分组兜底 | 同一受训者的两名训导官同档记忆被视为同组 | `LabelCapSocial` 按原版写法附带 `otherPawn.LabelShort` |

| `Thought_MemorySocial` 覆盖 `TryMergeWithExistingMemory` 直接返回 false | 早期回归模型误以为未到上限时同档会刷新 | 回归模型改为按原生契约移除最老一份，并断言对象方向与档位不被容量维护改变 |

### 3.2 文案基调重写与去性别化（维护者反馈）

维护者随后提出两项要求：文案**色情程度不足、未能体现主奴支配设定**；并且**不得出现“他”这类性别指向词**（本模组含跨性别机制，受训者、训导官与主人的性别都不固定）。据此重写全部训导官文案。

**基调设定（与主人原套对齐）**：露骨但不描写具体动作，保留喘气拟声、身体反应与失神；主线改为**受训者是主人的所有物，训导官只是主人授权的支配工具**，“同为性奴却被压在身下”即该套文案的张力来源。

**去性别化的实现方式**：

| 语言 | 处理 |
| --- | --- |
| 中文 | 删除全部“他／她”，改用角色名（训导官）、指示词（那）或省略主语 |
| 英文 | 删除整词 he／him／his／she／her，改用 the trainer、that、the Master 或复数 |
| 俄文 | 语法性别最复杂：删除代词 он／его／ему／ним；把指受训者或训导官的过去时动词改为现在时、无人称句或关系从句；指主人且与阳性角色名词 `господин` 搭配的词形按既有俄文译文惯例保留 |

俄文用词统一到本项目既有译者的词表：`дрессировка`（调教）、`господин`（主人）、`секс-раб`（性奴）、`член`，不使用自造词。

**同时优化了三条已随 2.3.8 发布的训导官文案**（维护者明确要求一并优化）：

| 条目 | 原方向 | 新方向 |
| --- | --- | --- |
| `SSC_TrainerOfficer_DutyFulfilled`（训导官本人） | “我完成了一次训导工作……感到满足” | 训导官把自己当成主人使唤的工具：替主人把别的性奴操开、管住，并因此发情 |
| `SSC_TrainerOfficer_Appraisal`（主人对训导官） | “这名训导官隶属于我……” | 主人视角：这条性奴是我调教出来的，如今替我去操开别的性奴 |
| `SSC_SharedBedWithTrainer`（与训导官同床，六档） | 单纯“不自在／安心” | 被主人塞到训导官身边过夜，六档从僵着身子到“唯一能安心闭眼的地方” |

**顺带修正的两处既有问题**：

1. 简体中文原先**缺少** `Thought_SharedBedWithTrainer.xml`，游戏内会回退到 Def 源文（源文用的是“调教员”）；本轮补齐该文件并统一为“训导官”。
2. 繁体中文该条目原用“調教員”，英文 `shared a bed with trainer` 一致，俄文原用 `тренер` 与本模组其他文件的 `наставник` 冲突；本轮统一为各自语言的角色名。

**校验**：本轮涉及的全部文件性别词残留 0（中文 `他/她`、英文整词代词、俄文代词）；XML 可解析、镜像逐字节一致、键集与占位符不变。重写过程中回归抓到一处真实缺陷——俄文沉沦档替换时把 `{0}` 占位符一并删除，已修复。`Tests/TrainerTrainingMemories` 14/14 通过。

**同步**：去性别化 6 份、训导官三条 8 份（含简体新增文件）分别以仅文本载荷同步到本机，覆盖前旧版备份在该轮备份根的 `gender-neutral/` 与 `officer-text/` 子目录。
