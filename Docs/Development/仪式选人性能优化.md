# 仪式选人性能优化（未发布）

日期：2026-09-23；基线为 2.3.1（`80aafc2`），本机原版接口核对基于 RimWorld `1.6.9676.17735`。

## 问题与证据

原目标资格函数在普通查询中无条件生成完整诊断。默认模式及 RJW 对应开关开启时，一次调用重复执行四次 `can_be_fucked`，还包含身体信息、RJW-PE 反射查询、翻译和字符串构造。普通候选拒绝会写带报告的 Warning；原版日志可能提取调用栈。

原版建表、自动分配、选角及高亮会重复进入角色判定；`skipReason=true` 原本没有避免这些开销。人口和候选顺序会放大成本，但没有问题存档的实机剖析数据，不能认定它是玩家卡顿的唯一原因，也不能给出毫秒或 FPS 收益。

## 当前行为

| 操作 | SSC 检查 |
| --- | --- |
| 打开窗口、候选列表、角色高亮 | 基础状态、身份、组件、原版年龄条件；不做完整身体、配对许可或 SSC 角色可达性查询 |
| 初次选入一个执行槽位 | 对该小人验证个人条件；另一槽位为空时暂不配对 |
| 补齐另一人、替换或交换 | 验证即将形成的组合和个人条件；失败恢复原选择 |
| 点击开始、直接启动 | 两个执行者必须齐全，重新读取当前条件，失败发生在结束原任务和创建仪式之前 |
| 已开始的仪式及窗口外原有角色查询 | 保留完整资格与统一限制规则 |

两个执行槽位默认留空，玩家手动选择；外部明确传入的强制角色保留，开始时仍验证。观众继续使用原版分配。四种语言新增短说明和缺少执行者提示。

普通资格入口最多调用一次 RJW；`skipReason` 可完全跳过原因生成。原公共详细诊断签名保留，只有显式调用才构造报告。日常任务、仪式任务和调教开关的普通调用同步使用轻量入口，执行异常仍可记录短原因。

## 实现边界

- `BindingRitualSelectionUtility` 用弱引用登记准备窗口；查询结果只在一次同步选人或启动操作中复用，不跨事件缓存。关闭、成功启动及异常退出会清理状态。
- `FillPawns` 仅替换两处自动分配的角色列表读取，剔除 SSC 的两个执行角色；保留原版观众与其他流程。若游戏方法结构不再匹配，补丁明确报错，避免静默替换错误位置。
- SSC 窗口包装 `IPawnRoleSelectionWidget`。首次实际变更才保存分配快照，普通重绘不复制人口列表。原版换人会先移除旧角色，失败后恢复角色、观众和候选顺序，并刷新品质预览。
- 右键菜单回调拥有独立的提交作用域，使用点击时的最新状态。未对原版泛型控件私有方法打补丁，避免 Mono/CoreCLR 泛型共享方法体影响其他仪式类型。
- 原版基础拒绝和统一调教许可仍参与验证，不修改绑定、主人、指定调教员或存档结构。若同时违反多项条件，先显示基础条件/配对拒绝，随后才是可达性/身体拒绝。
- 新增补丁依赖原版窗口字段与方法布局。编译、计数替身测试和本机 IL 核对不能代替其他 UI/仪式模组的实机兼容测试。

## 验证与实机复测

新增 [RitualSelection 套件](../../Tests/RitualSelection/README.md) 53 项；覆盖真实 Harmony 安装、20～1000 人计数、选择顺序、替换/交换/回滚、菜单延迟回调、原版拒绝、开始前状态变化、异常与无关仪式隔离。计数模型中开窗及三轮候选高亮的 SSC 完整检查均为零，合法的单次目标选入和启动各只调用一次 RJW 身体判定。

最终统一回归为 17 套、698/698 通过；验证与打包编排另有 11/11 检查通过。Release 使用本机游戏及模组依赖编译，无警告或错误；开发 DLL 已同步到仓库 `Assemblies`，随后按维护者要求将 DLL、调试符号及四语提示同步到游戏 mod 目录，6 个文件的 SHA-256 校验一致，旧文件已备份。没有调整版本号或创建正式发布包。

维护者已确认优化有效并授权提交（`cb239d8`）。该反馈确认实际改善，但未提供具体耗时或 FPS 数据，不扩展为全部边界及兼容组合验收通过。随后反馈的点击小人红字见下节。

后续仍可记录冷开窗、重复开窗、悬停和换人的耗时，并逐项检查无效候选短提示、换人失败恢复、开始前规则改变，以及开始后正常执行/中断。

## 2026-09-23：点击未分配小人的红字修复

读取本机 Player.log 中两条首次完整堆栈，确认它们属于同一故障链：

- `496FBCB`：`TryAssignAnyRole → TryAssignReplace → TryAssignSpectate → CanEverSpectate` 空引用。
- `D880375D`：后续绘制把空 Pawn 传入 `PortraitsCache.Get`，其字典查询抛出 `ArgumentNullException(key)`。

原版通过 `DragAndDropWidgetOnGUI_AfterWindowStack` 延迟执行头像点击和拖拽；初版仅包装绘制过程及当时创建的菜单，因此实际点击、延迟打开菜单和拖拽可能漏出验证/回滚范围。完整资格拒绝后，原版的第二轮自动试选还会尝试替换空槽位（`replacing=null`）；`RemoveParticipant(null)` 把空引用加入候选列表，随后 `TryAssignSpectate(null)` 抛错，并造成下一帧头像绘制继续报错。

修复复用现有包装逻辑，在 SSC 绘制期间登记点击、右键、落点和组回调，实际执行时建立操作范围；仅在 SSC 准备窗口阻止空 Pawn 进入移除/观众变更入口。满槽第一轮试选的原版拒绝若尚未修改分配，允许继续第二轮替换；实际变更后的失败仍回滚。不吞掉 OnGUI 异常，不恢复全候选完整检查。

新增 8 项测试；修复前先复现空引用、延迟回调漏回滚及满槽误拒绝，再验证修复。此前替身模型未充分反映原版的绘制后回调和满槽探测时序，这是原有测试通过仍漏掉实机问题的原因。专项现为 61/61，全项目 17 套 706/706；Release 零警告、零错误，DLL 与调试符号已同步游戏目录并校验哈希，旧版已备份。

维护者已实机确认本次红字修复有效并授权提交。该确认针对上述点击小人引发的两条红字，不扩展为所有仪式交互或兼容组合均已逐项验收。
