# 新限制系统阶段 1：配置与规则核心

开发日期：2026-09-21。起点：`19d6655` / 2.3.0。阶段 1 核心已实现，未正式发布，不改版本号。随后已提前加入[最小测试界面](新限制系统测试界面.md)，可手动建立和编辑个体配置；阶段 2 的自动初始化、迁移和完整设置界面，以及阶段 3 的任务接管尚未实施。下文实现及验证数字记录阶段 1 交付时的范围。

行为约定仍以[开发规划](../Design/新限制系统开发规划.md)为准。

## 实现范围

- `SSCRestrictionPolicy.Evaluate` 是新系统唯一行为许可入口。实际发起方向已确认且接收方绑定主人就是发起者时，立即返回 `BoundOwner`，不读配置、不执行装备/特化或条目否决。其余请求分别处理单人、普通双人、日常/仪式调教、人格专用任务和首次绑定准备。
- `SSCRestrictionRules` 保存六项选择；主动自愿采用 Deny / OwnerOnly / Allow 三态。`SSCRestrictionConfig` 保存数据版本、规则和公交车默认已处理标记，经 `CompSexSlaveTraining.ExposeRestrictions` 深度保存。null 明确表示未初始化；不借用旧例外或调教员身份标记。
- 全局默认模板和特化强制开关具备独立保存字段，使用现有总保护开关作为系统总开关；尚未增加玩家编辑 UI。查询不会改写保存值、初始化角色、协调指派或修复特化。
- `SSCRestrictionProfileDef` 在文件中分别声明默认和强制条目，本轮公交车仅声明两项被动许可；`SSCRestrictionEquipmentExtension` 在装备文件中声明强制条目，现有防护装备只强制禁止接受非主人强制行为。缺省项为 Unspecified。
- 条目覆盖顺序为装备 > 特化 > 保存值；关闭特化强制不关闭装备，关闭系统暂停全部限制。多件装备或多个同层声明作用于同项时取较严格值（Deny > OwnerOnly > Allow），同值按 defName 稳定选择来源，避免随穿戴顺序变化。
- `CreateInitialConfiguration` 仅创建独立值，复制模板并应用当前特化默认，不把强制值写进保存值，不自动挂到 Pawn。正式生命周期入口由阶段 2 接入。
- 返回值包括允许/拒绝、具体原因、涉及角色和命中条目/来源。适用角色缺配置会返回 `ConfigurationMissing`，损坏或未知版本返回 `ConfigurationInvalid`；不静默重置数据。真正无关的角色不受影响。

旧 `SSCSexInteractionPolicy`、Harmony 保护补丁、工作分配和仪式执行仍运行原逻辑；旧装备标记也暂留给该路径。没有把新旧规则同时用于实际任务。

## 游戏内测试入口

日常测试优先使用 **Mod 设置 → SexSlaveCraft 设置 → 行为限制：设置与测试**，可以编辑保存值并直接测试双方许可；见[界面操作说明](新限制系统测试界面.md)。以下原开发者只读入口继续保留。

1. 重新启动游戏使新 DLL 和 XML 生效，进入存档并开启原版开发者模式。
2. 选中一个角色作为发起者，在开发者动作菜单搜索 `Restrictions stage 1 (read-only)`（SSC 分类）。
3. 选择接收者，或选择 `Solo / 单人`；窗口和日志显示新核心的判断。
4. `Actual` 使用已有新配置。阶段 1 尚未初始化角色，所以普通适用角色出现 `ConfigurationMissing` 是预期结果。
5. `Preview` 对缺配置者使用临时默认值；已有配置则保留其值。预览会读取当前绑定、特化及穿戴装备，但不会写入角色、改变指派、启动任务或发放收益。

建议检查：

| 场景 | 新核心预览应返回 |
| --- | --- |
| 实际主人向自己的绑定对象发起 | 全部列出的行为直接 `ALLOW — BoundOwner`，装备不否决 |
| 第三人向普通绑定对象发起 | 普通自愿、强制及非主人调教均按默认禁止 |
| 绑定对象反向向主人发起 | 自愿按 OwnerOnly 允许；主动强制仍按默认禁止 |
| 第三人向公交车对象发起 | 两项普通被动许可默认允许，非主人调教仍禁止 |
| 上一对象穿上现有防护装备 | 非主人强制行为禁止，来源为 Equipment / Apparel_EFOutfit；普通自愿项不变 |
| 同一对象脱下装备 | 恢复其余来源算出的值，保存值不变 |
| 关闭总保护开关 | 非主人请求显示 `SystemDisabled` 并允许；预览不写配置 |

这是核心预览，不代表新系统已经控制实际行为。后续最小界面已支持显式建立测试配置，尚未完成阶段 2 的自动初始化/迁移及完整设置页；阶段 3 才逐类切换执行入口。

## 阶段 2 的迁移输入与映射表

以下是待实现的迁移约定，不是阶段 1 已执行的迁移。先捕获旧全局值、旧个体例外、有效特化与绑定数据，再在引用和既有身份迁移完成后转换；不能在查询中临时推算迁移结果。

表中的“公交车”指迁移时有效公交车状态，“旧开放”指 `allowOthersForTrainingOrSex`。保留可明确对应的旧选择，不复制旧策略对整次行为的连带放行。

| 新字段 | 旧值映射 |
| --- | --- |
| 单人许可 | 关闭旧自愿主人限制，或旧开放，或有效公交车时允许；否则禁止 |
| 主动自愿范围 | 上述任一条件成立时 Allow，否则 OwnerOnly |
| 主动强制许可 | 公交车采用 `!protectBusAggressorRape`；其余采用 `!protectChainedAggressorRape` |
| 接受非主人自愿 | 关闭旧自愿主人限制，或旧开放，或有效公交车时允许 |
| 接受非主人强制 | `allowSexSlaveRape` 或有效公交车时允许；旧开放本身不放开此项 |
| 接受非主人调教 | 旧开放或有效公交车时允许；实际自动工作仍要求唯一指定者 |
| 系统总开关 | 保留原 `enableSexSlaveProtectionRules`；关闭不等于把所有保存项写成允许 |
| 装备 | 不写入迁移后的保存值，运行时只提供强制条目 |

特化强制开关是新字段，初始开启。已迁移公交车标记默认已处理，避免随后重复写默认。全局初始模板按旧全局设置映射，不套用某个 Pawn 的个体例外/特化；旧档尚不适用的角色日后首次适用时用新模板。

旧全局设置从本次存档能取得的值固定一次快照，不能重建不可获得的历史值。空锁链、无绑定但已选 SSC 身份等历史状态需在阶段 2 与关系修复一同验证；旧“双方无锁链整次跳过”和“公交车接收方整次跳过”不成为新规则。显式批量默认优先于待迁移队列，不能被随后覆盖。

## 后续任务接管清单

| 入口 | 阶段 1 状态 / 后续接入 |
| --- | --- |
| RJW 普通双人及单人 | 仍用旧补丁；阶段 3 补全真实方向、单人识别、预约/开始和接收端 |
| 日常调教 | 核心按 ReceiveTraining 判断；身份、唯一工作指派、身体和排班检查仍在现有工作流程，接管时只替换行为许可部分 |
| 首次绑定准备 | 核心要求无现主、指定候选相符且候选具主人身份；不授予后续普通行为的主人直接许可，阶段 3 明确映射实际准备用途 |
| 仪式 | 核心提供调教许可；阶段 3 同步两侧选角、主持与建绑分离、阶段开始标记和结算 |
| 人格专用任务 | 核心按普通非强制处理；阶段 3 为共用接收驱动携带用途 |
| 公交车交易、狗事件 | 仍为旧调度；阶段 3 在打断工作前预检、真正开始前复检，保持交易收益与冷却语义 |
| 原版 Lovin、LifeForce | 尚未接管；阶段 3 验证实际驱动及方向后调用统一入口，并清除旧白名单 |
| 同床 | 继续独立；新系统不直接接管床位和睡眠记忆 |

阶段 1 未改自动工作候选、身份锁定、绑定或同床；也未把身份资质、工作可执行性检查纳入这六项许可。
