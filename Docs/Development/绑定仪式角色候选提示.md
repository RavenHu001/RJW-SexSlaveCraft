# 绑定仪式角色候选提示（未发布）

实现日期：2026-10-07；维护者实机确认日期：2026-10-08。开发分支为 `codex/binding-ritual-role-markers`，基线为 `main` 的 `8c247ad`（包含 `2a7127b` 的合并）。本轮增加选人提示，不改变仪式资格、绑定关系或存档格式。实现与相关回归已完成，已同步本机游戏 mod；维护者反馈“效果不错”并授权提交，尚未创建正式安装包。

## 要解决的问题

绑定仪式的两个执行槽位需要手动选择。原版头像没有常驻标记，玩家无法提前识别谁具有主持者或仪式目标的基础资格；选入后出现拒绝提示，也难以区分个人资格不足与当前配对不兼容。

候选预览原本有意避免全人口的身体与可达性检查。因此，标记必须区分基础候选、配对条件和完整检查，不能把基础候选都显示为已获准参与的绿色状态。

## 提示含义

| 提示 | 含义 |
| --- | --- |
| 金色“主持”角标 | 满足主持者基础资格；“主持”不代表拥有目标的主人所有权 |
| 紫色“目标”角标 | 满足仪式目标基础资格；不要求已经拥有 SSC 性奴身份 |
| 同时具有两个角标 | 可以分别尝试两种角色；仍需按拟定组合验证 |
| 角标变暗并带斜线 | 当前角色不可选，可能是配对不兼容、原版角色锁定或强制分配；悬停查看实际拒绝原因 |
| 勾选标记 | 已分配到该执行角色 |
| 悬停或拖拽时的绿色／红色边框 | 针对本次拟定分配完成检查后的允许／拒绝状态；拒绝原因通过提示显示 |

角标从头像左上方纵向排列，第二行仍在左侧，避开原版右下角的文化图标；勾选位于头像右上角。角标使用文字以及斜线、勾选，避免只靠颜色传达状态；头像原有姓名、文化图标与角色栏仍保留。英文角标为 `H`／`T`，俄文为 `В`／`Ц`，完整角色名称放在悬停提示中。简体中文、繁体中文、英文与俄文使用同一组翻译键，源目录与安装资源镜像保持一致。

不能担任执行角色的人仍可能担任观众。配对拒绝只影响对应角色提示，不把整个人物置灰，也不阻止原版观众分配。

## 沿用的资格规则

- 主持基础资格读取自由殖民者、有效调教员身份、正常活动状态等现有条件。主持资格与 SSC 主人身份、目标所有权分别判断。
- 首次绑定时，主持者需要 SSC 主人身份，并是目标的有效指定调教员。
- 已有绑定时，实际主人可以主持自己的目标，不因目标指定给其他调教员而被排除；第三方主持需要有效指定关系和对应调教许可。
- 目标基础资格使用支持的原版身份、调教组件、非 SSC 主人身份及原版年龄条件；不额外增加 SSC 性奴身份门槛。
- 可达性、目标身体条件和完整配对许可继续由原有验证入口判断。选人顺序、替换和两个角色交换使用即将形成的最终组合。
- 原版锁定、强制分配和角色容量仍生效。执行槽位已满时，把新人物拖到槽位空白处会拒绝；拖到已有头像上则按替换或交换检查，提示不把这两种落点混为一谈。

界面查询复用现有角色基础判定与统一限制规则。失败提示取实际拒绝原因；没有另设一套仅供界面使用的资格规则。

### 普通小人为何也有目标角标

两个角色的基础资格不是“调教员／非调教员”的互斥划分。[主持者](../../Sexslavecraft/Ritual/RitualRole_BindingMaster.cs)要求自由殖民者及有效调教员身份；[目标](../../Sexslavecraft/Ritual/RitualRole_BindingSlave.cs)要求支持的原版身份、正常活动状态、原版年龄规则、调教组件，并排除 SSC 主人身份，没有要求已设为 SSC 性奴，也没有排除调教员身份。符合条件的性奴调教员可以同时拥有两个角标。

[种族注入](../../Sexslavecraft/common/ITabAddForRace.cs)会为类人种族添加调教组件，因此普通殖民者即使尚未选择 SSC 身份，也可能满足目标基础资格。这沿用首次绑定的候选范围；角标不代表已经成为性奴或已取得完整参与许可。首次绑定仍要求所选主持者具有 SSC 主人身份并是目标的有效指定调教员，实际选角与开始还检查配对、可达性和身体条件。

## 检查与性能边界

| 时机 | 检查范围 |
| --- | --- |
| 常驻角标与候选提示 | 基础身份和角色条件；补充当前配对与原版角色锁定状态，不对全人口执行完整身体与寻路检查 |
| 悬停或拖拽相关头像 | 仅针对当前悬停人物或拖拽目标及拟定分配进行完整检查，显示允许或实际拒绝原因 |
| 点击、右键、拖拽提交 | 继续执行既有选人验证与失败恢复；提示结果不代替提交时的最新状态检查 |
| 点击开始或直接启动 | 重新验证两个执行者必须齐全及当前完整条件 |

基础与配对提示使用 0.35 秒缓存，主持者或目标分配变化时立即刷新。完整检查结果按当前人物的角色分别缓存；这些视觉缓存不进入提交验证，实际选入与启动始终读取当时的条件。

扩展仅作用于 SSC 绑定仪式的准备窗口。沿用原版选人控件与原有拖拽、点击、右键菜单流程，接入非泛型原版登记方法，并在已登记窗口最外层滚动视图结束前绘制提示。没有对原版泛型控件的共享私有方法安装全局绘制补丁。拖拽失败使用原版立即绘制提示窗口的相同 ID 展示完整拒绝原因，保留单个失败提示窗口。其他仪式的选人界面保持原版行为。
