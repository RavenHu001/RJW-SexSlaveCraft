## 要解决的问题

绑定仪式的两个执行槽位需要手动选择。原版头像没有常驻标记，玩家无法提前识别谁具有主持者或仪式目标的基础资格；选入后出现拒绝提示，也难以区分个人资格不足与当前配对不兼容。

候选预览原本有意避免全人口的身体与可达性检查。因此，标记必须区分基础候选、配对条件和完整检查，不能把基础候选都显示为已获准参与的绿色状态。

## 提示含义

| 提示 | 含义 |

| 金色鞭子图标 | 满足主持者基础资格；表示主持及调教职能，不代表 SSC 主人身份或目标所有权，合格的性奴调教员也可获得 |

| 悬停或拖拽时的绿色／红色边框 | 针对本次拟定分配完成检查后的允许／拒绝状态；拒绝原因通过提示显示 |

## 当前标记与实际准入规则

- 主持基础资格读取自由殖民者、有效调教员身份、正常活动状态等现有条件。主持资格与 SSC 主人身份、目标所有权分别判断。
- 首次绑定时，主持者需要 SSC 主人身份，并是目标的有效指定调教员。
- 已有绑定时，实际主人可以主持自己的目标，不因目标指定给其他调教员而被排除；第三方主持需要有效指定关系和对应调教许可。
- 紫色目标候选角标要求 SSC `PawnIdentity.Slave`，同时保留支持的原版身份、正常活动状态、调教组件及原版年龄等基础条件。原版殖民者、囚犯或奴隶身份不能代替 SSC 性奴身份。
- 实际目标角色准入仍只排除 SSC 主人，并检查原有基础与完整条件；本次未在选角、提交或开始时新增性奴身份硬性检查。可视化候选范围与实际准入范围的统一仍属未来开发。
- 可达性、目标身体条件和完整配对许可继续由原有验证入口判断。选人顺序、替换和两个角色交换使用即将形成的最终组合。
- 原版锁定、强制分配和角色容量仍生效。执行槽位已满时，把新人物拖到槽位空白处会拒绝；拖到已有头像上则按替换或交换检查，提示不把这两种落点混为一谈。

界面查询复用现有角色基础判定与统一限制规则，目标候选角标额外要求 SSC 性奴身份。失败提示仍取实际拒绝原因；视觉结果不代替提交或启动验证。

### 目标身份收紧与双资格

两个角色不是“调教员／非调教员”的互斥划分。[主持者](../../Sexslavecraft/Ritual/RitualRole_BindingMaster.cs)要求自由殖民者及有效调教员身份；当前目标候选角标要求 SSC 性奴身份和原有目标基础条件，没有排除调教员身份。符合条件的性奴调教员可以同时拥有鞭子和项圈两枚图标。

[种族注入](../../Sexslavecraft/common/ITabAddForRace.cs)会为类人种族添加调教组件，因此旧版 `a7629ea` 中未设置 SSC 身份的普通殖民者也可能出现目标角标。维护者确认正常指派界面要求性奴身份后，要求视觉候选也按此收紧；普通小人现在不再获得紫色目标候选角标。

实际[目标角色](../../Sexslavecraft/Ritual/RitualRole_BindingSlave.cs)的准入规则在身份收紧及图标替换两轮均未改，仍使用非 SSC 主人等既有条件。首次绑定继续要求所选主持者具有 SSC 主人身份并是目标的有效指定调教员；选角与开始还检查配对、可达性和身体条件。未来统一受调教门槛时，需要将上述界面与后台差异一起处理，不能只依赖候选角标或设置区域隐藏。

## 检查与性能边界

| 时机 | 检查范围 |
| --- | --- |
| 常驻角标与候选提示 | 基础身份和角色条件；补充当前配对与原版角色锁定状态，不对全人口执行完整身体与寻路检查 |
| 悬停或拖拽相关头像 | 仅针对当前悬停人物或拖拽目标及拟定分配进行完整检查，显示允许或实际拒绝原因 |
| 点击、右键、拖拽提交 | 继续执行既有选人验证与失败恢复；提示结果不代替提交时的最新状态检查 |
| 点击开始或直接启动 | 重新验证两个执行者必须齐全及当前完整条件 |

基础与配对提示使用 0.35 秒缓存，主持者或目标分配变化时立即刷新。完整检查结果按当前人物的角色分别缓存；这些视觉缓存不进入提交验证，实际选入与启动始终读取当时的条件。

目标角标、普通头像悬停焦点及附加候选提示在显示时直接读取 SSC 性奴身份，不等待缓存过期；即使人物已经选入或被强制分配为目标，撤销该身份后也不再画目标角标及其勾选。该显示检查不取消角色分配或绑定。拖放边框继续依据实际准入结果反馈。

扩展仅作用于 SSC 绑定仪式的准备窗口。沿用原版选人控件与原有拖拽、点击、右键菜单流程，接入非泛型原版登记方法，并在已登记窗口最外层滚动视图结束前绘制提示。没有对原版泛型控件的共享私有方法安装全局绘制补丁。拖拽失败使用原版立即绘制提示窗口的相同 ID 展示完整拒绝原因，保留单个失败提示窗口。其他仪式的选人界面保持原版行为。
