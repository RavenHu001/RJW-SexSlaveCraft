# 旧兔特化分身机制全面核对

**日期：2026-10-30。源码基线：`018c10f2`，目标1.7.4990 rev1069。状态：源码与实际DLL取证，未开发、未运行机制测试或进游戏验证。** 本文供维护者完整判断旧机制取舍，不将未开放的旧功能记作已实机可用，也不把此前的新分支实现建议当成已采用方案。

维护者本轮明确：功能设定是**性奴生下一个与自己精神相通的分身**。本文使用“本体／分身／分身分娩”；旧代码里的RabbitClone、Clone和原版Duplicate是技术名称，不由此推导两个精神完全独立的人，也不反推已经实现共享全部意识。后续规划见[精神相通分身](../../Design/生育特化自克隆分支规划与取证.md)；[生育性奴主体阶段](../Completed/生育性奴主体阶段完成核对.md)已经关闭，本轮不重开。

## 2. 创建与分娩的完整流程

入口位于[RabbitCloneUtility](../../../Sexslavecraft/common/RabbitCloneUtility.cs)，主要调用顺序如下：

1. RJW已经进入GiveBirth时，读取**分娩当时**的兔状态和繁殖模式；没有受孕时的克隆孕次标识，也没有提前保存整个人格。
2. CanCreateRabbitClone核对本体存活、未销毁、在地图上、类人、不是分身、具有兔特化及来源Comp，且有效存活分身少于两个。
3. 原版Find.PawnDuplicator.Duplicate根据本体当时的数据生成新Pawn。
4. PrepareFreshRabbitCloneBody降龄、清理健康状态、写入少量SSC字段，清主人资格／成长并协调新个体默认。
5. 在本体附近半径3格寻找可站立且未迷雾的位置；找不到时用本体位置，调用GenSpawn.Spawn。
6. 为分身添加来源链接，记录本体、出生Tick、初始年龄；本体来源Comp登记分身。
7. 成功返回后销毁并Discard该妊娠原先准备的**全部**babies，清空列表，移除妊娠并发消息；原GiveBirth被跳过。

每次成功替换创建一只分身，不按原babies数量逐个创建。本体数据取分娩／创建当时；另一个亲代的数据不参与这次Duplicate。它不是把已经生成的某个婴儿变成分身，也不是受孕时就锁定本体状态。

创建资格本身不检查SSC性奴身份、性别、成年、生殖器官、子宫改造、生育开关、怀孕、终极化或冷却；普通／终极兔来源Comp均可，不要求20%或100%进度。它们有些在正常妊娠过程受到环境约束，但不是旧创建服务自己的门槛。兔指特化名字，Humanlike检查不要求特定兔耳物种。

旧机制没有主动自指受孕技能。DEV直接创建也没有材料或冷却；新生育技能的七天冷却不是旧分身原有的属性。

## 3. 分身出生时究竟带着什么

原版复制器先生成Adult阶段请求，随后复制若干数据；SSC再将其生理年龄降到幼体。以下是本机实际Duplicate实现与SSC准备方法组合后的事实，不是对所有第三方自定义字段的完整复制承诺。

| 数据 | 实际处理与分身特点 |
| --- | --- |
| Pawn实例 | 新Pawn、新ID、新需求／技能等实例；不是让两个身体引用同一个Pawn对象 |
| 物种与性别 | 请求使用本体kindDef和gender；没有读取普通胎儿调控，也没有随机挑另一亲代物种。HAR自定义变体／额外Comp仍取决于其自身生成或复制回调 |
| 阵营 | 使用本体Faction，SSC准备时再SetFaction一次 |
| 殖民者／囚犯／原版奴隶 | 不显式复制本体GuestStatus；又因跳过RJW正常出生，不执行其给婴儿恢复殖民地囚犯／奴隶身份的分支。不能把SSC性奴等同原版法律奴隶 |
| 姓名 | 复制本体姓名；旧SSC没有自动追加分身编号或改名 |
| 生理年龄 | 原版先按本体生成，SSC再设为max(1 tick, min(本体年龄, 0.01岁)) |
| 历法年龄 | 原版请求取min(本体历法年龄, 本体生理年龄)，SSC降龄只改生理年龄；不是按分身刚出生另清零历法年龄 |
| 技能 | 复制各技能等级、热情、当前等级经验及当日经验字段；不是零技能婴儿。后续各自学习，不持续同步 |
| 背景 | 复制童年／成年背景及喜好颜色；分身降龄不会在SSC代码中主动清这两项，RJW普通出生重设背景也被跳过 |
| 特质 | 原版先复制，SSC再按来源Def／Degree／ScenForced重建；性奴派生Trait不原样复制，最后由分身自身最高恶堕重新协调 |
| 基因 | 原版复制内源／外源基因Def与覆盖关系及异种相关显示信息；不是双亲自然遗传，不是把每个Gene实例的内部资源／自定义字段全部序列化复制 |
| 原版外观 | 复制头型、体型、发型、发色、基础／覆盖肤色、毛发、胡须；有Ideology时复制纹身。降龄后的实际外形还受生命阶段和种族绘制影响 |
| 凝胶外观 | SSC对保留下来的对应健康状态显式调用FullGelAppearanceUtility.Copy，值独立，不共享可写配置；成熟时既有外观不被本体后续改色覆盖 |
| 衣服、装备、物品栏 | 未复制来源物品；原请求forceNoGear。第三方生成额外物品不在此代码保证范围 |
| 需求现值 | 原版为每个来源Need新建对象、SetInitialLevel再写CurLevel；这不等于复制每个需求的私有历史数据。SSC末端再按资格增删需求并初始化合法PNA需求 |
| 历史记忆 | 原版逐条MakeThought／CopyFrom到分身，改owner；不是与本体共享同一个记忆列表。SSC浪漫历史另有副本收尾，待提交事件／命令不重放 |
| 社交关系与亲子 | 原请求禁止生成随机关系，没有复制全部关系网络；旧SSC也不添加“分身是本体孩子”的Parent关系。记忆可能仍指向原来的其他Pawn，不等于取得对应关系 |
| 能力 | 原版复制能力Def集合，另外移除来源头衔授予的能力；不复制原Ability冷却。能否使用仍取决于各能力资格 |
| 工作／时间表／床位／任务 | 没有复制这些来源配置或正在执行的任务；由新Pawn默认与游戏环境决定，不是同步控制 |
| 其他记录 | 没有完整复制records、头衔或所有模组Comp。末端Notify_DuplicatedFrom允许各Comp自行处理；SSC训练Comp没有以此完整复制自身字段的实现 |

Anomaly启用时，原版还写入本体和分身的duplicateOf归组信息；这是原版复制体识别，不能将其当作SSC的精神相通实现。其完整DLC／第三方附加反应本轮未实机验证。

### 3.1 SSC训练数据并非整份继承

旧准备方法手工写入当前specializationType、当前specializationProgress、selectedTrainer、pawnIdentity和rabbitReproductionMode，关闭分身的slaveTrainerEnabled并标记资格迁移完成。原版CopyFrom不是对CompSexSlaveTraining做存档级拷贝。

因此多方向进度字典、培养余量、日程、训练运行状态、旧训练冷却、泌乳开关等不能仅凭“Duplicate了Pawn”认作已继承。泌乳字段的声明默认true，而旧准备注释称原版已复制旧字段；本机Duplicate只调用各Comp的Notify_DuplicatedFrom，SSC训练Comp没有相应覆盖，**这条注释不能作为泌乳选择已被复制的证据**。

主人永久资格及主人成长记录在新生时清理；来源为Master时，旧清理将新分身身份置Unset。来源为Slave或Unset则沿手工复制值，**旧流程没有“所有新分身强制为Slave”的初始化**。

### 3.2 恶堕历史与记忆不是一回事

[Need_Corruption](../../../Sexslavecraft/common/Need_Corruption.cs)独立保存highestCorruptionLevel；SetInitialLevel将其归零。原版CopyNeeds只写CurLevel，不调用RestoreCorruption，所以来源历史最高恶堕不会跟着完整恢复。例如本体曾达0.95、当前0.20，按这条复制路径分身只得到当前0.20及新需求历史，不能据本体旧0.95推定同档性奴派生Trait或装备历史里程碑。这里是字段／调用推导，不冒充已运行该例的实机结果。

已有SSC浪漫记忆则走[Thought_MemorySSCRomance.CopyFrom](../../../Sexslavecraft/common/Romance/SSCRomanceMoodMemory.cs)及[复制后历史整理](../../../Sexslavecraft/ThePatches/Harmony_RomanceMoodHistory.cs)，明确深拷贝保存的数据，清除临时授权与未完成事件；历史对谁的记忆可以保留，但并未因此复制实际绑定或社交关系。

## 4. 身体与健康状态的实际清理

这里有两层过滤，不能把旧分身描述成“本体所有身体改造精确复制”：

1. 原版CopyHediffs先清新Pawn健康列表，只复制duplicationAllowed且部位有效的状态；非有机AddedPart／Implant另有排除与部位恢复规则。
2. SSC的RemoveNonSscHediffs再按ShouldKeepSscHediff筛选：先排除PNA身体状态、能力派生marker及主人阶段，再保留SSC前缀、链／缰绳或归属SSC模组的状态；剩下的全部移除。

原版Hediff.CopyFrom只复制严重度、年龄等基础字段；HediffWithComps进一步调用同类型Comp.CopyFrom，而Comp基类实现为空。不覆写CopyFrom的子类／Comp不会因拥有ExposeData就自动复制自定义字段。

| 当前结果 | 证据与边界 |
| --- | --- |
| 普通非SSC疾病、伤口及功能状态 | 不在SSC保留范围的会被移除；以后仍能正常受伤、生病，也可能在快速过生日时得到年龄病，不是永久健康或通用治愈能力 |
| RJW器官 | 普通Penis／Vagina／Anus／Breasts等Def不属于SSC，进入该清理列表；旧流程没有清理后的显式器官恢复。这是明确过滤风险，实际游戏中是否被其他模组再次补回未验证 |
| RJW个人数据 | 新Comp在Pawn生成时有自己的初始化；旧SSC没有将来源RJW取向或PawnData完整搬运，不能宣称对应数据与本体完全一致 |
| 已完成子宫开发 | Hediff及Severity可进入SSC保留范围，但[子宫类](../../../Sexslavecraft/Hediff/Hediff_SSCUterusDevelopment.cs)未覆写CopyFrom；生育bool与三项胎儿预设不会靠基类复制，默认关闭／自然／自然／无初始印记 |
| 敏感度身体记录 | 初生按原复制继承，成熟补复制已明确跳过，避免覆盖分身自己后来修改或关闭 |
| PNA负荷／成瘾／普通生产状态 | [身体排除清单](../../../Sexslavecraft/common/SSCPnaExposureUtility.cs)先排除；不继承来源PNA满足度、产出进度或普通生产能力。成熟另加旧低效生产状态 |
| 三态人格印记及终极成果 | 当前SSC前缀过滤会保留；旧代码没有专门建立分身性奴印记或清互斥来源印记，这是与新生育方案衔接时的冲突，不是旧机制已经完成新规则 |

RJW本机CompRJW在生成时调用Sexualize，常规DoUpkeep没有本次清理后的器官复制步骤；MapCom_Injector的已核对加载修复也只更新**已有**器官位置。不能把“RJW有初始化”当作已证明器官会按来源重建。HAR额外部件、月经Comp或其他模组修复路径仍属于未实机核验的组合范围。

## 5. 初生、三天成长与成熟

| 阶段 | 实际行为 |
| --- | --- |
| 初生 | 生理年龄至多0.01岁，仍保留来源技能／背景等；链接Severity为0.01，未成熟状态给Consciousness offset −0.05，是意识减5个百分点，不是意识只剩5% |
| 成长计时 | bornTick保存实际游戏Tick；进度clamp((当前Tick−bornTick)／180000, 0, 1)，名义三游戏日到终点 |
| 年龄目标 | 每次读取本体**当前**生理年龄，在起始年龄与目标间计算期望值；目标不在出生时固定 |
| 年龄推进 | 差值大于0时调用AgeTickMothballed，负值不即时倒退；分身仍有普通年龄推进，不是仅一条自定义年龄曲线 |
| 成熟 | 一次性将生理年龄直接设为本体当时年龄，添加低效PNA，补复制SSC健康状态，再将mature置true、Severity置1，刷新需求／marker／绘制并发消息 |
| 成熟以后 | 不再定期补复制技能或全部健康，不继续永久跟随本体年龄；其后沿自身年龄与健康机制运行。当前若持有分化印记，另受25岁规则约束 |

### 5.1 “三天成体”不等于严格线性改龄

本机AgeTickMothballed会调用TickBiologicalAge，后者再乘儿童／成人衰老倍率及基因年龄因子，并进行CalculateGrowth和逐岁BirthdayBiological。旧SSC传入的是“期望年龄差”，没有将其换算回真实时间间隔。因此在年龄倍率不等于1时，实际可能提前越过期望值或延后，三天时再由直接赋龄校正；不能把插值公式当成严格生理年龄曲线。

BirthdayBiological还会处理生命阶段工作解锁、成长时刻／热情／特质和年龄疾病等。旧代码没有跳过这些；带着成人技能的幼体仍可能经历原版成长处理。这是与“纯粹长成同一份分身”不同的实际副作用，不等于本轮已经验证所有成长信件、基因与HAR年龄组合。

直接赋AgeBiologicalTicks会重新计算成长比例与生命阶段，不清掉来源童年／成年背景，也不是重跑全部生日。旧机制没有独立25岁上限；接入已完成印记后，快速成长和最后赋龄必须另核对，不能依靠源代码常数三天推断已经兼容。

## 6. “精神相通”目前到底共享了什么

共享由本体的HediffComp_RabbitCloneSource按80Tick哈希间隔触发；分身的链接负责登记和成长。完整代码见[来源／链接Comp](../../../Sexslavecraft/Hediff/HediffComp_RabbitClone.cs)与[SyncRabbitCloneNeeds／PropagateSourceMentalState](../../../Sexslavecraft/common/RabbitCloneUtility.cs)。

| 项目 | 是否共享 | 实际含义 |
| --- | --- | --- |
| 休息 | 是，双向平均 | 对本体和有效存活分身各自存在的rest取CurLevelPercentage平均，再写给所有参与者，不共享同一个Need实例 |
| 心情现值 | 是，双向平均 | 同样平均mood当前比例；不是合并思想或把每个人的心情来源改成同一套 |
| 本体精神异常 | 单向尝试传播 | 本体处于任意精神状态时，对尚正常分身尝试Wander_Psychotic；不是复制本体原精神状态，不覆盖分身已有精神状态 |
| 分身精神异常 | 没有直接反向传播 | 分身的低心情可经平均间接影响本体，但没有“分身疯了直接让本体疯”的调用 |
| 技能／经验 | 不持续共享 | 只出生时复制，后续各自学习、各自等级变化 |
| 新记忆／社交变化 | 不持续共享 | 出生后各自获得与失去记忆、产生关系，旧机制不广播事件 |
| 饥饿、性需求、PNA等 | 不共享 | 休息、心情之外没有组内同步，生产食物成本仍由分身自己承担 |
| 疼痛、伤势、疾病、伤害 | 不共享 | 无共同生命值、伤害分摊或共同器官。若有SSC主人分伤是另一个独立机制，不是分身链接提供 |
| 工作、移动、施法、选择 | 不共享 | 各自Pawn和Job，玩家可分别安排，没有远程附身／同步操作 |
| 死亡／复活 | 无连带生死 | 旧链接不使另一方跟着死亡、复活或转移意识；第三方及原版通常死亡心情不属于该链接的特效 |

例如本体休息90%、分身30%，下一次有效同步双方变成60%；再有一个0%的分身则平均40%。这是按需求实例的比例平均，不按体型或最大需求容量加权；缺某一Need者不参与那一项。初生若无休息／心情Need，也不会凭链接强行新建对应Need。

本体恢复正常时，没有主动结束分身精神游荡的代码；分身自行恢复后，若本体仍异常，下次同步又可尝试游荡。TryStartMentalState的成功仍取决于游戏原有条件。

组内没有距离、同地图、同阵营或视线过滤；但前提是本体来源Comp实际获得正常健康Tick。离图、旅队、世界Pawn休眠不保证同频Tick，不能把“没有距离判断”写成“任何世界状态都实时同步”。

这套实现已经有部分“精神相通”的玩法表达，**没有共享完整持续人格、技能、所有思想或统一控制的系统**。维护者新设定不自动把缺失部分变成必须开发的清单，先据此决定相通程度。

## 7. 成熟时第二次复制的准确范围

CopySscHediffsFromSource只遍历本体当时的健康列表：用同一SSC保留过滤，另跳过排泄中／空壳、分身链接、低产状态及1.7敏感度记录。分身缺少某Def则AddHediff，已有则直接将其Severity写成来源值；新加的凝胶外观可初始化，已有外观保留。

因此：

- 不是再次复制Pawn、人格、基因、技能、记忆、训练Comp或工作配置。
- 可把本体**出生后新取得**的允许SSC状态补给分身，或把分身自身的同Def进度覆盖为本体值；不是只补出生时那一份快照。
- 不会删除“本体没有但分身后来自己有”的普通保留状态；PNA与敏感度已有精确例外。
- 链／缰绳、当前三态印记及很多终极成果仍可能通过宽泛过滤；补一个Hediff不等于复制它的自定义目标、选择或人格数据。
- mature标记在这些调用后才写；没有发生异常时可防重复成熟，异常／重入中途的统一事务与回滚并未建立。

新分身的独立选择应保留哪些、哪些成果仍要在成熟时从本体补给，属于待判断内容，不能用“沿用旧机制”掩盖这一次额外继承。

## 8. 绑定、人格与分身限制

来源链接中的source是身体Pawn引用，与性奴锁链的主人target是两种关系。旧流程没有调用SSCBondUtility.Bind，也不把本体当作分身主人。

[Hediff_ChainOfSexSlave](../../../Sexslavecraft/Hediff/Hediff_ChainOfSexSlave.cs)继承HediffWithTarget，当前基类没有CopyFrom覆盖；普通Hediff复制不传target。缰绳的targets列表也没有专用CopyFrom。结果不能视作“自动归本体同一主人”，复制出的无目标链还可能按ShouldRemove被删除。selectedTrainer虽然被手工复制，也不能替代实际双向绑定。

分身Link存在时，下列SSC入口禁止人格排泄：手术可用查询、WorkGiver目标、JobDriver_PE持续检查、最终DoExcretion，以及开发添加准备状态按钮。旧初始化也移除复制来的准备及空壳状态。它不是以“持有性奴印记”识别分身，而是认Link；来源死亡不会自动移除Link，所以不会因此自动恢复人格排泄资格。

“不能再生成分身”也不等于“禁止普通受孕／生育”：旧代码只在分身创建资格处拒绝Link持有者，分娩替换失败又放行原后端；没有统一不育状态。若身体和环境的普通受孕条件得到满足，可沿普通路线处理，器官被旧清理删除则是另一项实际问题。旧Link也不直接锁Master／Slave方向，身份仍受原资格、绑定和当前印记控制；“出生即性奴且永久性奴锁”是新分支已定例外，不是旧Link原有的能力。

本体的人格没有与分身共享保存对象；若本体后来迁移人格，source引用不会自动跟到新身体。来源列表又挂在兔特化Hediff，而非独立身体载体：状态被移除时同步可能停止，分身链接却仍在。精神联系究竟随身体、人格还是另一个本体标识走，旧代码并未实现可迁移的一套语义；前轮“固定身体”只是建议，不能代替本轮设定判断。

## 11. 分娩替换还跳过了哪些事情

本机RJW GiveBirth通常会放置每个baby、处理本体的殖民地囚犯／奴隶状态继承、添加Parent关系，再执行PostBirth。旧前缀成功后直接跳过这些；它自己的完成工作只含分身创建、待产列表销毁、移除妊娠和消息。

已核对的PostBirth还会调用BabyPostBirth重设新生背景、复制活动区域限制、生成羊水污物／叫声，并给母方增加对应出生记录。这些没有被旧SSC显式补做；不能把“从GiveBirth进入”当成“普通出生全套副作用仍然执行”。外部其他Harmony前后缀是否另做事情取决于实际补丁组合，本轮没有据此承诺。

旧GenSpawn不经过第四步用于普通活产观察的PawnUtility.TrySpawnHatchedOrBornPawn包装，因此当前分娩培养消费者不会仅凭克隆GiveBirth被调用就记活产。原版复制器内部的Adult生成请求也不会触发第四步只针对Newborn的胎儿调控。新规则要求的性奴印记、出生培养及出生关系若要存在，必须另作明确决定／接入，不能宣称旧代码已有。

## 13. 供设定判断的分项
