## 已实现

### 统一许可与兼容分类

- 运行中的旧 `Harmony_ProtectSexSlave` 已缩减为统一守卫转接：删除 LifeForce 白名单、玩家命令预约豁免及旧策略回退。实际主人仍由 `SSCRestrictionPolicy` 在入口内直接通过，装备只按声明条目参与解析。
- RJW 派生驱动继续通过预约、步骤和 Start 检查；上下文不足的真实行为提交 `Unknown`，由统一策略判断，不按第三方程序集身份回退旧系统。
- 本机 `rjw_genes_lifeforce_randomrape` 使用 `JobDriver_RandomRape`，按强制行为接入。基因清理及 `LifeForceConflictUtility` 保持原有生命周期，不在许可查询中触发副作用。
- `RJW_Genes.JobDriver_Seduced` 实际是独立的准备任务：任务执行者为接收者，TargetA 是施法者；交接时由施法者创建 `sex_on_spot`。后者继承普通 RJW 发起驱动并使用普通接收者，因此准备与实际场景均按 RJW 非强制分类，不依据能力名称或 `rape_enabled` 开关猜测用途。
- Seduce 能力的 `Valid` 和 `Apply` 均检查统一许可。Apply 拒绝发生在原模组 `StopAll`、提示气泡及启动准备任务之前；走近后的步骤检查发生在取消施法者征召、增加记忆及启动场景之前。后续场景及接收任务继续由 RJW 守卫接管。
- 可选能力/驱动通过完整类型名及实际方法签名发现，不增加基因程序集硬引用。可选类型缺席时 `Prepare` 跳过补丁类，避免 Harmony 对空目标集报错。此兼容以本机已核对版本为依据，不宣称适配任意未来改版。

### 事件的准备、开始与取消

- 公交车交易先生成真实 Quickie / RandomRape Job 并检查许可，再创建 600 ticks 等待；预检拒绝不打断双方原工作。普通分支由公交车发起，强制分支由商人发起。保留现有身体、忙碌、地图距离及预约寻路条件。
- 成功成交成长仍按原分支及终极状态规则发放。许可拒绝或之后调度失败不撤销成交、不重掷概率、不改走另一分支。行为收益仍由真实行为结算。
- 宠物狗事件按最终选择的床上普通驱动或地面强制驱动检查。工作成长与掷骰冷却保持原规则，拒绝不退还冷却、不取消已完成的工作成长；直接启动避免 Shift 排队使事件延后，失败只移除本次候选。
- “行为已发生”消息改到原生 Start 成功之后发送一次，登记和去重标记跟随运行驱动保存；仅收到任务、走位、准备接收者都不发送。自动事件后期被拒绝不刷玩家命令提示，手动请求显示统一拒绝原因。
- **预检缓存驱动不是运行驱动。** 本机原版 `GetCachedDriver` 用于预检，`StartJob` 调用 `MakeDriver` 另建实例。因此待调度通知和等待归属先按 Job 引用、loadID、发起者登记，运行驱动查询时领取，不能把状态仅留在缓存驱动上。未被接收时移除待领取登记。
- 准备阶段被拒绝、寻路失败或外部取消时，仅回收该请求创建的等待及排队任务。Quickie 的 Goto/Wait、宠物床上任务的 GotoMindControlled 均记录实际新增编号；新替换工作及无关队列保持。已开始的场景正常收尾。

### 原版 Lovin 与家具边界

- 原版 Lovin 双方各有一个相反目标的 Job，不能按各自 pawn 重复判断主动方向。在原版同步创建接收任务期间传递唯一方向，配对成功后才给双方写开始凭据；凭据包含双方、Job 编号，不授予后来的新任务。
- 预检、预约、走床后初始化前均检查。开始后修改规则不打断当前场景，下一任务重新检查；床位、睡眠和同床许可继续原规则。
- 不插入或删除原版 Toil，保留存档步骤索引。包装的是本机 RimWorld 1.6 直接声明在 Lovin 驱动上的配对初始化回调；新存档保存精确方向和开始标记。旧档到达躺卧场景后根据双方任务及计时量级恢复，接收端的哨兵计时已经减少、发起端计时恰好归零也能正确恢复；仅走床不恢复开始。
- 未开始的 Lovin 以 `Incompletable` 结束。在 RJW 正常优先级 Cleanup 前缀之前修正错误的 `Succeeded` 条件，避免被拒绝或被替换的原版任务领取成功结算。RJW 开启原版替换后生成的普通任务继续由原有统一守卫检查，原版迟到回调不运行。
- Onahole 的 BeOnahole 常驻任务兼有家具占用和睡眠。没有实际发起者时不虚构双人行为请求；有真实发起者时必须按其用途进入统一许可。拒绝解除本次参与者并终止发起任务，保留常驻家具和其他原参与者。LifeForce 的专用临时接收者则在本次独占准备失败时一并清理。
- 这里验证的是已支持的双人/调教桥接，不扩展家具机器自身刺激、第三方独立非 RJW 驱动等玩法。旧界面、旧字段及不再调用的旧策略定义的整体移除仍属于阶段 4。

## 建议实机测试

1. 用普通公交车角色与同图商人完成非空交易：主动仅限主人时拒绝非主人自愿分支，双方原工作不被等待打断，交易成长保留；放开主动后正常调度，走位阶段不提前出现发生提示。
2. 在交易强制分支验证接收条目及装备：非主人被装备禁止，实际主人仍通过；走位时收紧条目，等待及排队任务清除，消息不虚报。
3. 宠物狗分别有床/无床完成动物训练或驯服，验证普通/强制主动条目独立；拒绝保留工作成长，当天不会反复抽签。
4. 关闭 RJW 的原版 Lovin 替换，验证主人、反向发起和非主人双方条目；走床期间收紧会拒绝，开始后收紧保留本次结束。再开启替换验证普通 RJW 场景，没有双份提示或结算。
5. LifeForce 主人、非主人分别使用 Seduce；准备行走时改规则，拒绝时不进入交接；实际开始后改规则，当前场景正常结束。随机强制任务同样受装备及条目限制。
6. 分别在事件等待、Lovin 走床及已开始、LifeForce 准备及已开始时存读档，核对等待清理、方向、当前场景收尾及通知不重复。
7. 家具待机仍可保持占用；主人使用/调教正常，第三方被拒绝后不解绑、不取消已开始场景。移除可选基因模组的独立测试配置能正常加载 SSC。
