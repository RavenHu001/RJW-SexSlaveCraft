## 1. 已确认数值与行为

维护者确认采用阶段四分析中的整组数据，正式名称为“战斗超频”。

| 项目 | 数值 |
| --- | ---: |
| 近战伤害 | ×1.30 |
| 近战冷却 | ×0.75 |
| 远程冷却 | ×0.80 |
| 承伤 | ×0.75 |
| 移动速度 | ×1.25 |
| 疼痛 | ×0.50 |
| 持续时间 | 2500 ticks，1 游戏小时 |
| 冷却 | 10000 ticks，4 游戏小时，从成功发动时开始 |

只有终极化并植入后的角色获得技能，普通培养 100% 不授予。玩家征召角色后手动对自身发动，无额外资源、疲劳或自动施放。解除征召隐藏按钮并阻止后续发动，已经发动的强化持续至到期。

主动效果与终极被动相乘：仅计算本特化时，承伤为 `0.80 × 0.75 = 0.60`，近战冷却为 `0.85 × 0.75 = 0.6375`。远程冷却不修改瞄准时间或连射内部间隔；身体培养、装备等仍按原版属性规则叠加。

## 2. 实现与复用

`SSC_Hediff_Combatant_Final` 显式使用 `HediffWithComps`，挂接共用 `HediffComp_GiveAbility` 授予 `SSC_CombatOverdrive`。授予沿用每 60 ticks 的检查周期，不因征召、解绑、退阶或方向切换移除重加技能。

`Ability_CombatOverdrive` 继承原版 `Ability`，仅在 `CanCast` 及 `Activate` 前补充终极记录、征召和有效施法者检查。正常冷却与使用条件仍委托原版。实际发动前的复查发生在原版 `PreActivate` 之前，避免排队后解除征召或抽取人格时产生效果或消耗冷却。

效果使用原版 `CompAbilityEffect_GiveHediff`，限定自身且替换同类临时状态。`SSC_Hediff_CombatOverdrive` 的五个属性倍率与阶段 `painFactor` 实现六项效果，使用 `HediffComp_Disappears` 计时。

已核对本机 RimWorld 1.6：效果组件会覆盖 `ticksToDisappear`，其持续时间单位为每秒 60 ticks。因此同时将能力显示时长与效果的 `durationSecondsOverride` 配置为 `41.666668`，经原版 `SecondsToTicks` 舍入得到 2500；临时 Hediff 的消失时间同样为 2500。固定 override 避免角色持续时间倍率改变约定时长。

技能图标复用原版 `UI/Commands/Attack`，不增加 DLC 资源依赖。定义发布入口仍为根目录 `Defs` 和 `Languages`。

终极对账保留原实例。共用授予组件移除回调新增同类有效标记检查：删除重复终极标记时，不撤销仍由保留标记授予的技能；移除最后一份时正常撤销。这避免已有去重逻辑意外刷新冷却。

## 3. 人格与存档

`CombatantSpecializationGelUtility.RemoveAllStates` 在抽取与植入清理时移除普通、终极、临时强化和对应技能。两个抽取入口仍先保存快照再清理身体，植入先清除宿主状态再导入源人格。

临时强化只参与清理，不属于 `IsCombatantTag`，也没有凝胶配方标签，故不随人格采集、加工或恢复。终极成果和方向历史保持阶段三行为。

正常保存读取沿用原版 `Ability` 的 `inCooldown`、`cooldownEndTick`、`cooldownDuration` 和消失组件的 `ticksToDisappear`。没有新增存档字段或自定义计时器。人格迁移后通过终极标记重新授予新技能，冷却按原版新实例初始化；不搬运旧冷却或正在运行的强化。

## 5. 实机验收步骤

1. 普通培养拉满仍无技能；凝胶终极化并植入后，等待最多 60 ticks，征召显示“战斗超频”，解除征召隐藏。
2. 发动时核对六项变化、1 小时持续和 4 小时冷却；到期只移除强化，终极被动保留。分别检查近战、单发远程和连射。
3. 施放命令排队后解除征召，应取消发动且不新增冷却；正常发动后解除征召，强化继续计时。
4. 强化和冷却运行中存读档，检查剩余时长保持；反复征召、切换培养方向及关系变化不刷新技能。
5. 强化期间抽取人格，旧身体的技能和强化消失，凝胶只保存终极成果。跨身体及同身体植入均恢复终极技能，但不恢复临时强化或旧冷却。
6. 将无战斗员成果的人格植入原终极战斗员，确认宿主原有被动、技能与强化全部清理；其他特化保持既有行为。


## 6. 首轮实机反馈修复与确认

维护者报告植入后 `Ability.Initialize` 报 `ArgumentNullException: type`，且发动技能不产生强化 Hediff。已确认两者同源：`CompProperties_AbilityGiveHediff` 的原版构造函数不设置 `compClass`，初版 XML 遗漏显式效果类型，导致原版捕获初始化异常后跳过该效果组件。技能本身仍被授予并能进入冷却，但没有施加强化的组件。

已在能力效果配置中补上 `<compClass>CompAbilityEffect_GiveHediff</compClass>`。本次运行时改动仅为 XML，不修改倍率、冷却或 DLL。补充定义回归，先确认旧配置失败，再确认修复后战斗员套件 49/49 通过。此前全套 854/854 结果仍是阶段四初版记录，不代表覆盖了这个遗漏。

另外使用本机游戏程序集实际构造配置类、按生产 XML 指定类型实例化效果组件并调用原版 `AbilityComp.Initialize`，确认初始化成功。这项独立检查不运行完整游戏 XML 加载、完整 `Ability.Initialize` 或实际 Hediff 施加；维护者随后完成实机复测，确认修复有效。记录见 `.builds/combatant-stage4-fix/component-audit.json` 和 `combatant-tests.log`。

修复同步结果与备份路径记录于 `.builds/combatant-stage4-fix/sync-result.json`。需完全退出并重新启动 RimWorld，重新加载 XML；原版 `Ability.ExposeData` 在读档时会重新初始化组件，无需重新制作或植入凝胶。先前空放已产生的正常冷却仍会保留，应待冷却结束后复测，或使用游戏已有调试功能结束冷却。
