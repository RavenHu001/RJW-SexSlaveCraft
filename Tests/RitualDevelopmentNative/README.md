# 仪式演化点原生专项

目标为当前安装的 RimWorld 1.7。项目使用 .NET 10、本机 `Assembly-CSharp.dll`、`UnityStubs.dll` 和测试用 net9.0 Harmony；无需联网或启动游戏。

直接编译生产仪式结果处理器、观众组件、设置 partial 和演化点补丁。结果处理器仍继承真实 `RitualOutcomeEffectWorker`，避免用错误的 `FromQuality` 测试替身绕过本次兼容问题。

## 覆盖范围

- PatchAll 实际安装一次；默认关闭、设置未初始化、Def 禁用、其他仪式与非随时举办模式隔离。
- 读取并复用原版共享曲线；四档名义收益 0／0／1／2，保留其他提供者的非空曲线。
- 真实原版 tracker 的信徒条件、实际点数增长、改革上限、改革通知及收益文化归属。
- 真实文化来源查询在运行中开关后的变化；普通原版来源保持可用，固定文化不列来源。
- 1.7 实际 Def、四语键完整性和源码语言镜像一致性。

只隔离语言翻译、消息和信件投递，并直接设置文化的信徒查询缓存。曲线获取、原版类型判断与累计算法没有被替换。其他 SSC 领域后果使用会抛异常的编译边界，禁止本专项假装执行整场仪式。

整场生产 `Apply` 的中断、重复、回调重入、恢复已领取状态、结算时偏好及信件真实增量，另由 `RitualLifecycle/Program.RitualDevelopmentPoints.cs` 覆盖；设置 partial 的缺字段及往返采用该宿主的 Scribe 字典模型。两套都不等于真实游戏存读档或 UI 渲染验收。
