# 主人资格道具与研究接入回归

在仓库根目录运行：

```powershell
dotnet restore Tests/MasterQualificationItem/MasterQualificationItem.csproj --configfile Tests/NuGet.Config
dotnet run --project Tests/MasterQualificationItem/MasterQualificationItem.csproj --configuration Release --no-restore -- .
```

已登记到 `Scripts/Test-All.ps1`，不依赖 NuGet 包或 Harmony。直接编译生产资格字段、资格服务及道具 partial、使用效果、调试生成服务和设置按钮 partial。

40 项用例组覆盖（第二批 31 项与 3B 来源 9 项）：

- 首次授予、单个与堆叠消耗、SSC 性奴及重复使用拒绝、原版奴隶可用、手动主人仍可取得资格；死亡、销毁、非人形、空壳、缺组件、损坏身份和道具拒绝。
- 菜单通过后身份变为 SSC 性奴、其他入口已授资格或道具失效，生产效果在结算前重新检查；成功提示只在授予及消耗后出现。
- 有／无 Royalty、蓝图缺口与需求已满、两名角色分别使用、零／部分／完成研究进度不变、研究边界抛异常时不授资格或消耗。只读检查不改变旧版本标记。
- 真实设置按钮在主菜单、无地图、缺 Def 及外层 GUI 禁用时不生成，恢复 GUI 状态；生成一个、选中同图对象附近与地图中央回退、放置失败清理、并入现有堆叠的提示目标。
- XML 始终加载、原版 `UseItem`、单一 SSC 效果控制消耗、Royalty 条件研究字段、独立原版蓝图未被替换、四语与源码语言镜像。
- 3B 停止贸易库存、心灵枪任务奖励标签、神殿高价值组追加、普通房间单件神器等效权重、增强房间/安全箱与心灵枪同组、两个可选池独立缺失、其他 Def 不改、必需 Core 目标缺失报告失败。XML 补丁模型只核对配置及 XPath；真实原版 Apply 另由实库审计脚本执行。

边界：存根只提供 Pawn、研究管理器、物品拆分、放置和 GUI 的宿主接口；SSC 的检查、授予、消耗和按钮代码直接执行。原版 `JobDriver_UseItem`、蓝图生成器、旧档 `BackCompatibility.ResearchManagerPostLoadInit`、实际 DLC/XML 条件加载、纹理显示和真实存档往返没有在此套件执行，须结合真实依赖构建及实机验证。研究不增加智识经验以 SSC 仅调用 `AddTechprints` 的生产路径为依据，不将存根当作原版引擎证明。3B 的完整游戏 Def 加载、交易/奖励随机生成及自然遗迹产出亦须实机确认。

## 3B 原版实库审计

在独立 PowerShell 7 进程中运行：

```powershell
pwsh -NoProfile -File Scripts/Test-MasterQualificationSources.ps1 -GameRoot 'D:\STEAM\steamapps\common\RimWorld'
```

脚本只读本机游戏文件，用真实 `PatchOperationSequence/Add/Conditional.Apply` 对实际 Core XML 执行补丁，分别核对不含可选池及含 Ideology 增强房间/安全箱两种输入；删除模块追加后原定义须完全一致。随后用原版 `StockGenerator_Tag.HandlesThingDef` 与 `TradeabilityUtility.TraderCanSell` 验证贸易排除，并核对实际心灵枪和模块共用的任务奖励标签。报告保存到 `.builds/master-sources-3b/native-source-audit.json`，包含输入哈希及验证边界。

补丁字段由反射填充，模块仅填充交易识别所读字段；未调用完整游戏 XML 加载或 ThingDef 图像构造。独立进程只在内存补足分析器所读的 Prefs，不读取/保存玩家设置。此审计不执行随机库存、奖励生成或玩家存档。

## 第 4 批资格展示实机测试

1. 同步第 4 批新 DLL 和四语 `SSC_MasterQualification.xml`，完整重启游戏。若同时验收 3B，另同步资格物品 Def 与 `Patches/SSC_MasterQualificationSources.xml`。本批没有新增保存字段；旧版本 DLL 无法显示新行。
2. 准备已取得资格者 A 和未取得资格者 B；打开“调教”页，分别显示“永久主人资格：已取得／未取得”。默认手动赋予开启时，让 B 选择主人，B 仍显示未取得。切换设置后悬停说明随之更新，但 A/B 保存值不变，现有主人身份不被移除；B 退出后重新选择继续受资格门槛限制。
3. A 退出主人身份、保存并读档，仍显示已取得；让 B 正常使用模块后，B 更新为已取得，当前身份不自动改变。持有锁链或有效绑定的角色仍受身份锁定约束；SSC 性奴即使保存有资格，也不能借该行绕过身份锁定或重复使用检查。
4. 抽取 A 的人格，检查凝胶页显示已取得；另取未取得资格来源的凝胶，应显示未取得。复制／加工、保存／读取后显示保持；切换选中两份凝胶不串状态，滚动特质列表不移动资格摘要。
5. 使用已取得资格凝胶植入原未取得宿主，再检查角色显示已取得；使用未取得资格凝胶替换原已取得人格，显示未取得。真实克隆显示未取得，读档不因复制了主人身份而补资格；全局研究不随这些操作改变。
6. 分别切换简中、繁中、英文、俄文；在正常和较大 UI 缩放下查看两种状态。角色身份区的调教员开关、性奴状态及后续节框不重叠；凝胶多特质滚动、锁链／关系／记忆摘要和分配按钮仍可使用。长状态完整换行，悬停说明可读。

## 3B 实机测试

1. 同步本批 `Defs/ThingsDefs/SSC_MasterQualificationItem.xml`、`Patches/SSC_MasterQualificationSources.xml` 和四语物品说明，完整重启游戏。3B 不改运行 C#，继续使用已验证的 3A DLL。现有库存、任务奖励与已生成遗迹不会追溯补发，需生成新的来源。
2. 使用基础调教研究**已完成**的测试档，关闭直接手动赋予身份，准备一位未取得永久资格的非 SSC 性奴。已有主人也可以，长期来源不依赖初次任务自动条件。
3. 开启开发者模式，在调试输出 `Thing set maker possible defs`（对应 `ThingSetMakerPossibleDefs`）中找到 `SSC_MasterQualificationItem`。它应属于 `Reward_ItemsStandard`、`MapGen_AncientTempleContents` 和 `MapGen_AncientComplexRoomLoot_Default`；启用 Ideology 时也属于 `MapGen_AncientComplexRoomLoot_Better` 和 `MapGen_AncientComplex_SecurityCrate`。这是候选池检查，不要求每次随机都出模块。
4. 用开发者动作 `Spawning → Spawn thing set` 分别选择上述生成器，在测试地图生成并检查无红字。神殿先抽原有高价值组，再从有效物品中抽模块；增强房间/安全箱与心灵枪同组，保留组权重 0.05/0.5，单件概率还要除以组内有效候选数。普通房间模块权重为 0.002，属于低概率入口，少量尝试不出现很正常，优先验证候选池而非要求很快抽到。普通奖励与心灵枪使用同标签，实际数量与单件机会仍由原版预算决定。
5. 刷新新的商队、城镇和商船库存，确认模块不作为商人出售物品出现。移除贸易标签并设置 `Sellable`，只保留玩家卖出已有模块的能力；没有新的购买来源。3A 免费任务和调试按钮仍按原规则可用。
6. 从这些来源取得模块后，让测试角色正常使用：成功消耗一个并解锁主人选项，研究保持已完成；原有主人资格和其他角色身份不改变。
7. 在无 Royalty 的游戏配置下重启并复查候选池/生成/使用；无 Ideology 时不应出现增强房间/安全箱缺失的 Patch 报错，Core 来源继续可用。有 Ideology 时加测两个可选池。

常规游玩还应确认新生成的真实任务奖励和新探索遗迹能够出现模块。调试生成检查与候选池检查不等同于自然事件逐项验收；稀有来源需要多次观察，现有设置的“生成一个模块”按钮不验证 3B 投放。

## 第二批实机测试

### 准备

1. 将第二批 DLL、`Defs/ThingsDefs/SSC_MasterQualificationItem.xml`、`Defs/ResearchDefs/ResearchProjectDef.xml` 和根目录四语 `Languages` 同步到本机安装目录，再完全退出并重启游戏。仓库中的已验证 DLL SHA-256 为 `E1F1202BAF1D2A70482A82E1708020DBA03E40E8CBFDD882582DAF2A8AA4A0BD`；本机同步结果可核对 `.builds/master-qualification-stage2/sync-result.json`。
2. 使用测试存档，准备两名未解锁资格、SSC 身份未设置且没有绑定的小人 A、B。旧档原有主人已由第一批迁移补齐资格，适合验证重复拒绝，不适合验证首次获取。
3. 在 SSC 模组设置关闭“允许直接手动赋予主人身份”。先确认 A、B 的主人选项不可选；这才是观察道具是否真正解锁资格的起点。
4. 选中地图上的 A，在设置调试区点击“生成 1 个主人资格模块”三至五次。该按钮无需开启调试 Gizmo；模块应出现在 A 附近，打开物品信息应有图像、说明与使用菜单。

### 核心流程

| 操作 | 预期结果 |
| --- | --- |
| 选中 A，右键模块并使用，等待约 10 秒（正常游戏速度） | 成功提示；总数量减少 1；A 的 SSC 当前身份保持未设置，主人选项变为可选。 |
| A 再次尝试使用另一个模块 | 显示已取得资格，使用选项禁用，数量不变。 |
| 检查尚未使用模块的 B | B 的主人选项仍受资格限制，证明研究蓝图与个人资格没有混为一项。 |
| B 开始使用后，在读条完成前征召或下达移动命令取消 | 模块数量不变，B 仍不能选择主人；稍后可以重新正常使用。 |
| 将无绑定的 B 设为 SSC 性奴后尝试使用 | 显示 SSC 性奴无法使用，数量不变；退出 SSC 性奴身份后才能继续首次使用测试。 |
| B 正常使用一个模块 | B 独立取得资格；A 的资格保持；已补齐的研究蓝图不再重复增加。 |
| A 选择主人，再退出为未设置，保存、退出并读档 | 手动赋予仍关闭；A 可再次选择主人，已解锁者仍拒绝重复使用；物品数量保持保存时结果。 |
| 开启手动赋予，让一个新的未解锁角色 C 选择主人，再让 C 使用模块 | C 仍能首次使用；说明手动身份没有提前写永久资格。随后关闭手动赋予、退出主人后仍可重选。 |

原版奴隶与 SSC 性奴分开判定。如要加测前者，准备原版奴隶但 SSC 身份未设置、未解锁的角色，应能通过 SSC 道具准入；实际使用仍须满足原版身体、预约与接触条件。

### 研究与 DLC

以 Royalty 启用、基础“调教”研究零进度的测试存档开始，记录研究数值后使用一个 SSC 模块：蓝图条件从缺少变为满足，研究数值不增加，也不直接完成。仍须安排研究员正常研究。模块操作者的智识经验不因该效果增加；观察时排除同期其他工作带来的经验。

| 场景 | 预期结果 |
| --- | --- |
| Royalty 启用，零进度且未应用蓝图 | 新要求生效；使用 SSC 模块后条件满足，进度保持原值。 |
| Royalty 启用，原版独立蓝图已应用 | 操作者仍没有个人资格；之后仍可使用 SSC 模块授予个人资格，不重复补研究计数。 |
| 升级前旧档已有部分研究进度 | 首次加载第二批时原版自动补齐新增蓝图要求，已有进度不丢失，可继续研究。 |
| 升级前旧档研究已经完成 | 保持完成，已有解锁内容可用；未取得个人资格的角色仍可使用模块。 |
| 独立无 Royalty 测试配置／新存档 | 不要求调教蓝图；模块仍授个人资格并消耗一个，不改研究进度。 |

旧档兼容应使用升级前保存的零进度、部分进度和已完成存档分别验证；仅在新版本运行后临时改研究进度不能证明加载兼容。原版独立蓝图可通过开发者生成 `Techprint_SSC_RES_BasicTraining`，再按原版应用流程测试；它保留原版自己的经验与重复应用研究加速规则，不能把 SSC 模块“只补蓝图计数”的验收标准套到它身上。

### 生成按钮与反馈

- 选中同图对象时在该对象附近生成；未选中或选择异图对象时，在当前地图中央生成一个。主菜单和无地图状态下按钮禁用。
- 每次点击只增加一个，已有同类堆叠时可能合堆；提示应指向实际物品。不同放置位置的数量按所有堆叠总数核对。
- 第二批尚无初次免费任务或长期投放，实机测试使用设置生成按钮。
- 反馈可按“场景／操作／实际结果／预期结果”记录；如有红字，附首次出现的完整错误及堆栈。优先确认核心流程，再分别确认 Royalty、旧档兼容和独立原版蓝图。
