# 新限制系统核心与生命周期回归

从仓库根目录运行（.NET 9，无第三方依赖）：

```powershell
dotnet run --project Tests/RestrictionCore/RestrictionCore.csproj --configuration Release `
  -p:RestoreConfigFile="完整仓库路径/Tests/NuGet.Config" -- .
```

当前共 115 项测试（其中一项枚举全部 64 组旧开关组合）。套件直接编译生产配置、文件定义、条目解析器、唯一许可入口、界面写入入口和两个存档扩展，已加入 `Scripts/Test-All.ps1`。

原 80 项核心测试覆盖主人整次行为直接放行（包括缺配置/未知用途）、显式方向和用途映射、双向许可、单人规则、日常/仪式独立条目、首次绑定准备、人格专用任务、公交车两项覆盖、装备优先级、同层冲突稳定性、总开关、模板隔离、只读预览、整份配置缺失/损坏和序列化往返。界面写入测试覆盖显式及重复初始化、适用性、非法配置、强制期间编辑保存值、保存读档和中英文键完整性。

优化回归重点检查：特化错误不被合法装备覆盖、同层非法项按定义名稳定报告、多个特化与稀疏条目的组合、初始化失败返回原始坏项且不写入角色、预览遇到坏默认安全拒绝、编辑与许可共用整份配置有效性，以及主人和总开关优先于坏配置。静态条目目录必须覆盖全部枚举，未知条目在解析入口安全拒绝。

夹具扫描实际 `Defs` 目录中全部 XML，读取所有 `SSCRestrictionProfileDef`，按 `defName` 定位公交车规则，支持多个文件及多份定义；逐一检查特化文件与源码内嵌副本一致。单个用例的初始化异常计入失败汇总，不会跳过其余用例。

游戏对象及 Scribe 使用边界模型，XML 字段由测试读取，不声称代替 Unity 中的原生 XML 加载、Scribe 引用恢复、Harmony 时序或界面操作。`InteractionProtection` 套件直接编译统一限制核心和实际任务守卫，覆盖已接管入口。

阶段 2 新增生产迁移、生命周期及 GameComponent 的直接测试，覆盖 64 组旧开关组合、加载时输入捕获和全局快照、首次激活、重复读档、公交车默认一次性处理、人格嵌套与异常恢复、新旧克隆、跨地图/世界/商队/运输集合的批量应用及失败原子性、总开关与指派协调。阶段 3 已接管实际任务，其场景生命周期由相应套件覆盖。见[最小测试界面说明](../../Docs/Development/新限制系统测试界面.md)与[阶段 1 开发记录](../../Docs/Development/新限制系统阶段1.md)。

阶段 4 清理新增跨存档保留旧全局值、缺失旧键/已有新模板优先级、关闭限制时保留旧档指定者回归；待迁移角色保存后不再写旧个体例外键，仍可从迁移快照恢复。

阶段 4 后半新增 5 项对象偏好回归：关闭/重复关闭/存读档/重新开启、旧字段缺失兼容、默认复制和设置往返、坏偏好回退，以及偏好不能改变实际许可。UI 控件名称与逐项悬停键加入中英文完整性检查；鼠标和字体布局仍需实机验证。
